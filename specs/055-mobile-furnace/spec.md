# Feature Specification: 移动熔炉（右区工具，点一下打开原版熔炉界面，背包里也能"后台烧"）

**Feature Branch**: `055-mobile-furnace`

**Created**: 2026-11-17

**Status**: Draft

**Input**: 用户（2026-11-13）的三个移动工具需求中的最后一个。054 之后确认的决策：**工作台与熔炉都走做法 A（服务端打开原版界面）**；熔炉"按建议补算"（后台烧用补算、不 tick），先查了旅行者背包的做法；**只做普通熔炉**；每种右区最多一个；不考虑每档背包的限制；配方中等以上难度（见下）。全部规划见 [docs/plan/mobile-tools.md](../../docs/plan/mobile-tools.md)；054 已经建好通用的"打开工具"请求与决策表（[specs/054-mobile-crafting-table](../054-mobile-crafting-table/spec.md)），本 feature 复用并加上熔炉。

## Clarifications

### Session 2026-11-13（可行性分析阶段，用户已确认）

- Q: 嵌进面板还是打开原版界面？ → A: **做法 A**：点工具后服务端打开原版熔炉界面，客户端是原版 `FurnaceScreen`，浮动面板照常叠在上面；不在面板里自己画熔炉格、不自己实现界面。
- Q: 熔炉能不能在界面关掉后继续烧？ → A: **能，按"补算"实现**：不在后台每 tick 推进，而是把状态连同"游戏时间"一起记住，下次打开（或读取）时按过去了多久一次性推算烧了几个、燃料还剩多少、进度到哪、产物与经验各是多少。旅行者背包也是这个思路（存完成时间戳）。
- Q: 做哪种熔炉？ → A: **只做普通熔炉**（不做高炉、烟熏炉）。
- Q: 状态存在哪里？ → A: **记在工具物品自己的数据上**：熔炉里的三格东西、烧制进度和时间戳随这个物品走；工具被拿出背包、放进别的背包，状态不丢。
- Q: 新物品？放哪里、放几个？ → A: **新物品** `mobile_furnace`（移动熔炉）；**只在右区生效，右区里最多一个**；左区、下区放得下但不生效、不计入限制；不做每档背包的限制。

## 背景

浮动背包的右区已有垃圾桶（021）、移动唱片机（053）、移动工作台（054）。本 feature 加第四个右区工具：**移动熔炉**。左键点它，打开一个**原版的熔炉界面**（原料格、燃料格、产物格、火苗与进度箭头）；在任何地方都能烧东西，不用放下熔炉方块。

与工作台不同的是熔炉**有状态也有时间**：烧一块东西要 10 秒，一份燃料能烧很久。玩家的期望是"放进去、关掉界面、去干别的，回来取"，所以界面关闭后它要"像在继续烧"。做法是**补算**：不让背包里的熔炉在后台每 tick 运转（那会让每只背包都有开销，并且物品栏里的物品没有 tick），而是记下状态与时间，下次打开时一次算清楚。从玩家角度看，效果与放在地上的熔炉一样；唯一不同是"没人看的时候不会真的有东西在动"，而这不可观察。

界面本身、取产物的手感、经验的发放、JEI / EMI 的配方转移等都是原版的。

## 物品与配方

- 物品 `mobile_furnace`：中文"移动熔炉"，英文 "Mobile Furnace"；堆叠 1；创造物品栏放在移动工作台之后；进 `never_trash`；16×16 手绘占位贴图（用户之后可用同名文件替换）；提示文字说明"放进右区，左键点它打开熔炉；关掉界面后还会继续烧"。
- 配方（有序，`category: misc`，不加解锁进度）：`IRI` / `CFC` / `ILI`，`I` 铁锭、`R` 烈焰棒、`C` 煤炭块（两个）、`F` 熔炉、`L` 岩浆桶；**合成后岩浆桶退回一个空桶**。需要下界（烈焰棒）、约 18 煤，属于中等以上难度。

## 使用方式

1. 把移动熔炉放进面板右区（右区最多一个）。
2. 光标为空时左键点它（与 054 一样；右键仍是拿起）：服务端校验后打开原版熔炉界面，标题为原版的"熔炉"；界面里是**这个工具自己的**三格内容与进度。
3. 像普通熔炉一样用：往原料格放东西、往燃料格放燃料，烧好的东西出现在产物格，取走时按原版规则给经验。
4. 界面开着时再左键点右区的移动熔炉：关掉界面。
5. **关掉界面后它继续烧**：燃料还够就接着烧原料，直到原料烧完、燃料烧完或产物格放不下；下次打开（不论隔了多久）看到的就是"过了这么久之后"的样子。
6. 打开期间，如果移动熔炉离开了右区（被拿走、换了背包）：界面被关掉；格子里的东西与进度**跟着这个物品走**，不丢、不复制。

## 已查证的事实（读 1.21.1 源码与本仓库，plan 阶段还要逐项再核）

- 原版熔炉界面 `FurnaceMenu(id, 背包, Container, ContainerData)` 是公开的：容器 3 格（原料、燃料、产物），`ContainerData` 4 个整数（燃烧剩余、燃烧总时长、烧制进度、烧制总时长），客户端用 `MenuType.FURNACE` 对应的原版 `FurnaceScreen` 显示。
- 原版熔炉的推进逻辑在 `AbstractFurnaceBlockEntity.serverTick`，它在点燃与熄灭时会 `level.setBlock` 把熔炉方块的"亮着"状态写进世界——工具没有方块，所以不能复用，烧制规则要自己写（配方取 `RecipeType.SMELTING`，燃料取原版燃料表）。
- 054 的"打开工具"请求（`OpenToolPayload(byte)`）、种类枚举（`MobileTool`）与决策表（`ToolOpenPlanner`）已存在，本 feature 加一个种类；`stillValid` 由服务端每 tick 询问，可用来"工具不在了就关"。
- 数据修订现在是 5，协议号现在是 20。
- 旅行者背包的熔炉升级存的是"绝对游戏时间"的完成时间戳（`getBurnFinishTime`、`getCookingFinishTime`），状态在升级物品自己的数据组件里。

## 尚未验证（plan 阶段先查证；验证前不得声称已满足）

- `ContainerData` 四个字段如何由补算结果正确填充，使火苗与箭头的显示和原版熔炉一致。
- 工具物品的数据组件如何存三格内容与时间戳、如何随背包同步到客户端、经背包的保存路径（`BackpackGate`、`BackpackInventory`、030 快照）时不被冲掉。
- 界面开着期间状态如何落盘：每 tick 写回、变化时写回、还是只在关闭时写回；服务端崩溃、玩家下线、背包被拿走时分别是什么状态（见需求 FR-012）。
- 补算的各种边界（时间回退、跨世界、燃料中途烧完、产物堆叠满、原料与燃料同时变化、配方在数据包里被改）。
- 经验：原版把"每个配方烧出过几个"记下来，取走产物时才发经验（含小数部分的概率进位）；本 feature 如何记录并在取出时发放，且在补算后也一致。
- 界面开着时工具被拿走：界面关闭，格子里的东西与进度去向要正确（状态随物品而不是随背包）。
- 协议号是否变化：054 已有通用的"打开工具"包，若不新增包则协议号不变；数据修订 5 → 6（新的只能存在背包里的物品种类，且工具物品上有新的数据）。
- 对历史测试的影响：写死修订 5 的断言需要同改。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 移动熔炉物品：合成、放进右区、每区一个 (Priority: P1)

玩家用配方合成移动熔炉（岩浆桶退回空桶），放进面板右区；右区最多放一个；放在左区或下区没有效果。

**Why this priority**: 没有物品就没有工具。

**Independent Test**: 创造栏取到；按配方合成（核对岩浆桶退回空桶）；放进右区；再放第二个被拒并提示；放在左区或下区点它没有反应。

**Acceptance Scenarios**:

1. **Given** 配方表，**Then** 有一个有序配方，图样与材料与上面一致，结果 1 个；合成后岩浆桶位置退回空桶；不加解锁进度。
2. **Given** 右区已有一个移动熔炉，**When** 再放第二个，**Then** 被拒并提示"右区已经有一个移动熔炉了"；同格替换允许；旧背包已有多个时保留、不能再加。
3. **Given** 移动熔炉在左区或下区，**Then** 点它不打开界面（也不计入右区的限制）。
4. **Given** 右区同时有垃圾桶、移动唱片机、移动工作台、移动熔炉，**Then** 四者的限制互相独立，各能放一个。
5. **Given** 中英文界面，**Then** 物品名与提示都有对应的语言键。

---

### User Story 2 - 点一下打开原版熔炉界面，像熔炉一样烧东西 (Priority: P1)

玩家左键点右区的移动熔炉，打开原版熔炉界面；放原料与燃料，烧出产物，取走时拿到经验。

**Why this priority**: 这是功能的目的。

**Independent Test**: 造一只右区带移动熔炉的背包；点它，界面打开；放 1 块铁矿石（原料）与 1 个木棍或煤（燃料）；等待烧制，产物格出现铁锭；取走时得到经验；记录没验证的。

**Acceptance Scenarios**:

1. **Given** 右区有移动熔炉、光标为空，**When** 左键点它，**Then** 打开原版熔炉界面（原料、燃料、产物格，火苗，进度箭头），标题为原版的"熔炉"。
2. **Given** 界面开着、原料与燃料都有，**Then** 火苗与箭头按原版节奏动：燃料点燃，进度随时间推进，一份原料烧完变成产物放进产物格，用掉相应燃料；烧制时间与燃烧时间与放在地上的普通熔炉一致。
3. **Given** 放进的东西没有熔炉配方，**Then** 不烧；燃料格只接受能当燃料的东西（与原版熔炉格的限制一致）。
4. **Given** 产物格有东西，**When** 取走，**Then** 按原版规则得到经验（该配方烧出的个数 × 配方经验，小数部分按原版的概率进位）。
5. **Given** 产物格已满（或会混入不同的产物），**Then** 暂停烧制（燃料不被白白消耗地等待，与原版一致），取走后继续。
6. **Given** 燃料是岩浆桶之类有剩余物的燃料，**Then** 烧完后剩余物（空桶）留在燃料格，与原版一致。
7. **Given** 创造模式或开着物品栏 / 箱子等别的界面，**Then** 同样能打开（别的菜单被关掉并退还光标物品，同 054）。

---

### User Story 3 - 关掉界面后继续烧（补算） (Priority: P1)

玩家放进原料与燃料后关掉界面（或离开很远、退出游戏再回来），再次打开时看到"过了这么久之后"的结果。

**Why this priority**: 这是"移动熔炉"区别于"随手开一次的原版界面"的价值，也是本 feature 最容易出错的地方。

**Independent Test**: 放 8 块原料与足够的燃料，关界面；快进或等待若干秒再打开，看到已烧好的数量、剩余燃料与当前进度符合时间；分别测"燃料中途烧完""原料烧完""产物格放满""隔了很久"。

**Acceptance Scenarios**:

1. **Given** 界面里有原料与燃料，**When** 关掉界面并过了 T 个游戏刻后再打开，**Then** 已烧好的个数、剩余原料、剩余燃料与当前火苗 / 进度，等于一个放在地上的普通熔炉在同样时间后的结果（同一份燃料、同一批原料）。
2. **Given** 燃料在中途烧完，**Then** 到那一刻为止烧好的都算，之后不再前进；再打开看到的是熄灭的状态，进度按原版规则随时间回退（与原版熔炉熄灭后进度缓慢后退一致）。
3. **Given** 产物格放满了，**Then** 补算在放满的那一刻停止，不丢任何东西，不让产物溢出或消失。
4. **Given** 原料与燃料都很多、间隔极长（例如很多个游戏日），**Then** 打开不卡顿（补算的开销只与烧了多少件有关，不与过了多少刻有关），结果仍正确。
5. **Given** 熔炉在背包里被带到别处，**Then** 补算只依赖游戏时间，与玩家在哪个位置、哪个维度无关。
6. **Given** 玩家退出游戏后重新进入，**Then** 熔炉的状态与进度仍在，并按过去的游戏时间补算（离线期间游戏时间不走，所以离线的这段时间不算在内）。
7. **Given** 界面开着，**Then** 熔炉由原版界面的节奏实时前进（不依赖补算）；关掉时把当前状态与时间记下来。
8. **Given** 界面开着、此时玩家被服务端关闭或下线，**Then** 重新登录后熔炉的三格内容不丢失、不复制，进度与"一直没中断地烧"的结果一致（plan 阶段的结论：进度由"记录的状态 + 记录时的游戏时间"推出，玩家每动一次格子就写回，所以没有"进度落后"）。

---

### User Story 4 - 再点一下关掉；工具不在了就关掉，状态随物品走 (Priority: P2)

界面开着时再点一下就关掉；移动熔炉离开右区时界面被关掉，格子里的东西与进度跟着这个物品走。

**Why this priority**: 不让"工具已经不在了，界面还开着"成为漏洞，也不让熔炉里的东西因拿走工具而丢失或复制。

**Independent Test**: 界面开着再点一下关掉；界面开着把右区的移动熔炉拿出来，界面在 1 秒内关掉，拿出来的物品再放回右区或放进另一只背包，打开后三格与进度仍在；换了背包、背包丢了也关掉。

**Acceptance Scenarios**:

1. **Given** 移动熔炉的界面开着，**When** 再左键点右区的移动熔炉，**Then** 界面关掉，状态已记下。
2. **Given** 界面开着，**When** 移动熔炉被拿出右区（或右区没有了），**Then** 服务端在 1 秒内关掉界面，三格与进度已写在这个物品上（不论它现在在光标、物品栏还是别处）。
3. **Given** 一个带着状态的移动熔炉被放进另一只背包的右区，**When** 打开，**Then** 看到原来的三格与（补算后的）进度。
4. **Given** 界面开着时背包被换（按 B 解析出的变了）或丢了，**Then** 界面被关掉，物品不丢不复制。
5. **Given** 玩家死亡，**Then** 熔炉里的东西不额外掉落成散件，随工具物品一起按原有的死亡规则处理（物品栏里的背包随玩家掉落）；不复制。

---

### User Story 5 - 数据与版本兼容 (Priority: P2)

新物品与它的新数据让数据修订 5 → 6；协议号按 plan 阶段的结论（预计不变）；老背包照常载入；快照（030）能保存与恢复带熔炉状态的背包。

**Why this priority**: 项目一贯的数据与联机底线。

**Acceptance Scenarios**:

1. **Given** 本 feature，**Then** 数据修订递增（5 → 6）并在 DELIVERY 写明理由，同改 `DataRevisionTest` 与写死 5 的历史测试；如果没有新增网络包，协议号保持 20（并在 DELIVERY 写明）。
2. **Given** 旧背包与旧工具，**Then** 照常载入、功能不变；没有状态的移动熔炉等同"空熔炉"。
3. **Given** 带熔炉状态的背包做快照与恢复，**Then** 三格与时间戳一致。
4. **Given** 更新版本保存的背包（040 的保护），**Then** 沿用现有保护规则，不新增例外。

### Edge Cases

- **请求被伪造**（客户端发"打开熔炉"但右区没有）：服务端校验失败就什么也不做（054 已有的路径），不报错。
- **游戏时间回退或来自别的世界**（把工具带进另一个存档，那个世界的游戏时间更小）：补算的经过时间取"不小于 0"，即视为没有时间经过，并把时间戳校正到当前时间，不让熔炉"倒着烧"，也不出现负的进度。
- **配方被数据包改了**（烧制时间、产物变了，或配方消失）：补算按当前的配方表重新算；原料不再有配方就不烧，不丢原料。
- **燃料格里的东西不再是燃料**：同上，不烧、不丢。
- **产物格里已有一种东西，而新烧出的是另一种**：与原版一致，不烧，等玩家取走。
- **原料与燃料在补算窗口内一起烧完 / 同时不足**：补算以"逐件"推进，每件的开始条件与原版一致（要有原料、有可烧的燃料、产物能放下）。
- **堆叠上限**：产物堆叠到上限（通常 64）就停；补算不超过上限。
- **一次补算的上限**：补算次数与原料数量成正比，原料格最多一组（≤ 64）；不会因为时间很长而变慢。
- **打开时玩家光标上有东西、已开着别的菜单**：同 054（原版 `openMenu` 关掉旧菜单并退还光标物品）。
- **受保护的背包**（更新版本保存的，040）：工具状态的写回是"改工具物品"，会修改背包数据，**按 040 的保护规则被拒绝时界面不打开**，并给一条提示；不对受保护的背包做任何写入。
- **服务端崩溃**：玩家每动一次格子就写回，所以三格内容不丢不复制；写回的是"状态 + 时间戳"的一致快照，崩溃后再打开按补算推出进度，与没有崩溃时一致。
- **多个玩家**：状态在各自的工具物品上，互不干扰；不存在两人同时打开同一个熔炉。
- **与别的模组**：只开原版熔炉菜单，不碰别的模组的界面；别的模组如果改了熔炉配方或燃料表，补算与界面都读同一个来源，结果一致。
- **降级**：不支持（口径不变）。

## Requirements *(mandatory)*

### Functional Requirements

**物品、配方与放置**

- **FR-001**: MUST 有物品 `mobile_furnace`（堆叠 1），中英文名与提示；创造栏在移动工作台之后；进 `never_trash`；16×16 手绘占位贴图与模型。
- **FR-002**: MUST 有一个有序配方：`IRI` / `CFC` / `ILI`（`I` 铁锭、`R` 烈焰棒、`C` 煤炭块、`F` 熔炉、`L` 岩浆桶）；岩浆桶合成后 MUST 退回一个空桶；`category: misc`；不加解锁进度。
- **FR-003**: 移动熔炉 MUST 只在**右侧工具区**生效；右区里 MUST 至多放一个（沿用 `ToolSingleRules`，服务端校验，客户端预览同口径，被拒时有提示 `limit.mobile_furnace`；同格替换允许；旧背包已有多个时保留、不能再加）；放在左区或下区放得下但不生效、不计入限制；该限制 MUST 与垃圾桶、移动唱片机、移动工作台的限制互相独立。

**打开与关闭**

- **FR-004**: 左键点右区的移动熔炉（光标为空、无 Shift / Ctrl / 拖拽）MUST 向服务端发 054 已有的"打开工具"请求（种类为熔炉）；右键 MUST 仍是拿起；MUST NOT 为熔炉新增另一种包。
- **FR-005**: 服务端收到请求 MUST 校验：按 B 解析出的背包（`BackpackRef.resolve`）的右区确有这个工具；通过才打开，**不通过什么也不做**。打开决策沿用 054 的决策表（打开 / 关闭 / 忽略）。
- **FR-006**: 打开的 MUST 是原版 `FurnaceMenu`（`MenuType.FURNACE`，标题为原版的"熔炉"）：容器是这个工具自己的三格，`ContainerData` 提供火苗与进度；客户端 MUST 是原版 `FurnaceScreen`；MUST NOT 在面板里画熔炉格或自己实现界面。
- **FR-007**: 界面的有效性 MUST 由"按 B 解析出的背包的右区仍有移动熔炉"决定；不再满足时界面被关闭，并且在关闭前 MUST 把当前状态写到**这个工具物品**上。
- **FR-008**: 熔炉界面开着时，再次收到"打开熔炉"请求 MUST 关掉这个界面。
- **FR-009**: 界面里的一切交互（放入与取出、快速转移、格子的物品限制、燃料剩余物、经验发放）MUST 保持原版熔炉的行为。

**烧制与补算**

- **FR-010**: 烧制规则 MUST 与放在地上的普通熔炉一致：配方来自原版熔炉配方（`RecipeType.SMELTING`）、燃烧时间来自原版燃料表、需要"有原料 + 有燃料 + 产物放得下"才烧、燃料点燃后即使原料没了也烧完这一份、熄灭时进度回退；经验与"烧出个数"的记录与原版一致。MUST NOT 往世界里写任何方块。
- **FR-011**: 状态 MUST 记在**工具物品自己的数据**上：三格内容、燃烧剩余与总时长、烧制进度与总时长、已烧出的配方计数（用于经验）、以及记录这些状态时的游戏时间；状态随物品走（不随背包）。没有状态的移动熔炉等同空熔炉。
- **FR-012**: 界面开着时 MUST 按原版节奏实时推进，并 MUST 把状态写回工具物品：**每次三格的内容变化（玩家放入、取出、取走产物）、打开、关闭时立即写回**，写回的是"状态 + 该状态对应的游戏时间"；界面里因时间自然前进产生的变化（进度、燃料、烧出的产物）不需要定期写回，因为它们可以由写回的状态与时间推出（与补算同一套逻辑）。这样在服务端崩溃、玩家下线、工具被拿走、背包被换时，三格内容不丢失不复制，再打开的进度与没有中断一致。
- **FR-013**: 界面关闭后再次打开（或读取状态）时 MUST 按"当前游戏时间 − 记录的游戏时间"补算：烧好的个数、剩余原料、剩余燃料与剩余燃烧时间、当前进度、产物与应得经验，等于普通熔炉在同样时间后的结果。补算的开销 MUST 与烧了多少件有关、与经过多少刻无关；MUST 在产物放满、原料烧完、燃料烧完时停止；MUST 以"逐件"推进，每件的开始条件与原版一致。
- **FR-014**: 补算的经过时间 MUST 取"不小于 0"；时间戳比当前时间更新（跨世界、时间回退）时视为没有时间经过并校正；补算中遇到配方消失、燃料不再是燃料、产物不匹配时 MUST 停止烧制且不丢任何物品。
- **FR-015**: 经验 MUST 在取走产物时按原版规则发放；补算烧出的产物所应得的经验 MUST 与逐刻烧出的一致。

**数据与兼容**

- **FR-016**: MUST NOT 新增网络包（复用 054 的"打开工具"包）、配置项、依赖、mixin；数据修订 MUST 递增（5 → 6）并在 DELIVERY 写明理由，同改 `DataRevisionTest` 与写死 5 的历史测试；协议号保持 20（若 plan 阶段发现必须新增包，则同步升协议号并写明）；011～054 的其余测试不改。
- **FR-017**: 工具物品上的新数据 MUST 在背包的各条保存与同步路径里被保留：保存、读取、同步到客户端、快照（030）与恢复、升级背包的配方（若会复制工具）、受保护背包的拒写；MUST 有测试覆盖"工具带着状态被取出与放回仍在"。
- **FR-018**: 旧版本（没有本 feature）读到带熔炉状态的背包会把移动熔炉当未知物品：沿用 040 / 041 的降级保护，不新增机制，发布说明里提醒备份。

**测试与文档**

- **FR-019**: 补算（纯逻辑：给定三格、燃烧与进度、记录时间、当前时间、配方表与燃料表，得出新状态与经验）与"打开 / 关闭 / 忽略"决策（沿用 054）MUST 有单元测试，并与"逐刻推进"的结果做对照测试（同样的输入，补算一次 = 逐刻推进 T 次）；物品、模型、贴图、配方、语言键用资源测试；接线用源码文本检查；游戏里验证打开、烧制、关闭后继续烧、拿走工具时关闭与状态随物品走（宪法 V）。
- **FR-020**: 文档 MUST 更新：`README.md` / `README_CN.md`（移动熔炉一节）、`docs/plan/mobile-tools.md` 的状态、本 feature 的 `DELIVERY.md`。

### Key Entities *(include if feature involves data)*

- **移动熔炉（Mobile furnace）**：新物品；右区生效，每个背包右区至多一个；自带"熔炉状态"。
- **熔炉状态（Furnace state）**：三格内容（原料、燃料、产物）、燃烧剩余与总时长、烧制进度与总时长、各配方已烧出个数（经验用）、记录时的游戏时间；记在工具物品上，随物品走。
- **补算（Catch-up）**：把"状态 + 经过的游戏时间"一次性推算为新状态与经验的纯计算；与逐刻推进结果一致。
- **打开工具请求**：054 已有，本 feature 增加种类"熔炉"。
- **移动熔炉菜单（Mobile furnace menu）**：服务端的 `FurnaceMenu`，容器与数据来自熔炉状态，有效性由右区的工具决定。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 补算与逐刻推进的对照测试：对一组代表性输入（单件、多件、燃料中途烧完、原料中途烧完、产物放满、有剩余物的燃料、时间为 0、时间极大），补算一次的结果与逐刻推进到同一时间的结果完全一致（三格、燃烧、进度、经验）。
- **SC-002**: 游戏里（容器自动验证）：点移动熔炉打开原版熔炉界面；放原料与燃料后产物按时间出现；取走得到经验；关界面、过一段时间再开，状态等于补算结果；右区放第二个被拒；左区、下区点了没有反应；开着时把工具拿出右区，界面在 1 秒内关闭，工具带着三格与进度被放回后状态仍在；记录没验证的。
- **SC-003**: 保存与读取、快照与恢复、退出再进入后，熔炉的三格与进度不丢不复制（容器里 Save and Quit 转储玩家数据核对）。
- **SC-004**: `./gradlew compileJava test` 通过；`DependencyRulesTest` 通过；数据修订为 6；协议号保持 20（或按 plan 结论）；011～054 的测试除写死 5 的断言外不改而通过。
- **SC-005**: 关界面后经过很长时间（例如 100 万个游戏刻）再打开，界面打开不出现可感知的卡顿（补算是一次性的、开销与经过的时间无关）。

## Assumptions

- 配方是第一稿，用户可以只改一个 JSON；贴图是占位手绘，用户之后替换。
- 经过时间按**游戏时间**（`getGameTime`）算：服务器关闭期间游戏时间不走，所以不算在补算里；睡觉与 `/time set`、`/time add` 只改一天里的时刻、不改游戏时间，熔炉不会因此多烧（与放在地上的熔炉一致）。（plan 阶段查证 1.21.1 源码后更正：本稿原先写成"睡觉会让熔炉按跳过的时间补算"，不对。）
- 背包里的熔炉不会被别的东西（漏斗、红石）自动喂入或取出，只在玩家打开界面时交互。
- 打开界面时材料取自玩家自己的物品栏（原版行为）；用面板把背包里的东西拖进熔炉格仍可用。
- 工具物品的提示文字不显示熔炉的实时状态（不在物品图标上画火苗或进度）；这是后续的可选增强，不在本 feature。
- 不做高炉、烟熏炉、每档背包的限制、对熔炉的外部自动化。
- 补算只对"工具物品上的状态"有意义；工具在不同玩家之间转交时，状态随物品走，经验在**打开并取走产物的玩家**身上发放。
