# Quickstart: 背包编号与登记表（精简版）验收步骤

按宪法 V，玩家可见行为都要在客户端会话里验证；单元测试和编译不能代替。未验证的项在 tasks/DELIVERY 里保持"未验证"。

## 准备

```bash
pgrep -f "fml.modFolders=mcfloatingbackpack" || echo "没有游戏在跑"   # 有就不要启动第二个，也不要杀用户的游戏
./gradlew test
./gradlew runClient
```

创造模式世界。**没有服务端配置，没有数量上限。**

## A. 显示与来源

- **Q1** 工作台合成一只皮革背包：悬停有"编号：XYZ"（首位大写字母不含 I、O，后两位大写字母或数字 2～9）；打开面板，标题栏背包图标右侧显示同一个编号，不遮挡关闭按钮。
- **Q2** 面板拖到最窄：编号被截断，悬停编号处显示完整编号；图标悬停仍是等级名称。
- **Q3** 合成第二只、关闭再打开、放进箱子再取出、锻造台升级：编号都不变（两只不同背包偶然同号也正常）。
- **Q4** 创造栏拿一只、`/give` 一只：悬停显示"未登记（首次使用时登记）"；打开后变成有编号。
- **Q5** `/give @s mcfloatingbackpack:leather_floating_backpack 50`：都没有编号；只打开其中 2 只，第三只仍没有。
- **Q6** Shift 点击工作台一次合成 5 只：5 只都有编号。
- **Q7** 旧存档里升级本模组之前保存的背包：第一次打开时有了编号，里面的物品、标签、垃圾桶内容、黑名单一点不丢。

## B. 不限制数量，复制品

- **Q8** 一个玩家持有 30 只各自使用过的背包：每只都能打开，**没有任何数量提示**。
- **Q9** 创造模式复制一只背包得到 X、Y：两只都能打开，编号相同；各自放进不同的物品并保存，两只仍都能打开。
- **Q10** 另一名玩家捡起或从箱子取出并打开一只背包：能用；（需要两名玩家，没有条件写"未验证"）。

## C. 升级与墓碑

- **Q11** 皮革背包放几样东西，锻造台逐档升级 4 次：编号始终不变、内容不丢。
- **Q12** 墓碑只有单元测试覆盖；游戏里没有写入墓碑的办法（命令在之后的 feature）。

## D. 持久与回归

- **Q13** 登记几只背包，退出重进：编号与之前一致（栈上的标识随存档保存）。
- **Q14** 回档：备份世界文件夹，使用几只新背包，再用备份替换回去进入：世界正常加载，没有报错。
- **Q15** 回归 011～025 的验证项（点击、拖动、转移、标签与标签总览、垃圾桶与 022、自动拾取、020 兼容开关、宿主界面）：结果与之前一致；没有编号的背包第一次使用时先分配再操作。
- **Q16** 图集度量（先 `pgrep`，再 `design/demo/tools/check_atlas_budget.sh`）：仍为 2048×1024。
- **Q17** 成本粗测：一次自动拾取 64 个不同物品时 `saveInventory` 的额外耗时与世界保存时登记表编码耗时，记录；测不了就写"未测量"。
