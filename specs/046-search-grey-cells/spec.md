# Feature Specification: 搜索结果的灰格样式

**Feature Branch**: `046-search-grey-cells`

**Created**: 2026-11-12

**Status**: Draft

**Input**: 用户（2026-11-12）要求调整搜索结果的 UI：仍然是和主区域一样的网格布局，只是没有搜索结果的格子置灰、不可点击。用户设想过"在主区域上盖一层新的不透明网格面板"（类似标签管理器的遮罩），分析后用户选定**方案 C**：保持 042 的结果映射（结果紧凑排在前面、照常滚动与操作），只把搜索时没有结果的格子也画成灰色格子底。

## Clarifications

### Session 2026-11-12

- Q: 用覆盖层还是保持 042 的映射？ → A: **保持 042 的映射**（方案 C）。覆盖层若只读会丢掉结果里的操作；若可操作，等于把 042 的映射在另一处重写一遍（选区、拖拽、Ctrl 转移、Delete 都按主区域的位置判断）。画面上两者一样：结果紧凑排在前面，其余是灰格。
- Q: 空格子（没有物品的格子）怎么处理？ → A: 搜索期间也是灰格、不可点（与"没有结果的格子"一样）；结果集里被拿走物品后"留位"的格子**仍是结果**，保持正常底色、可点（便于放回）。
- Q: 要不要自动滚到第一个命中？ → A: 不需要：结果紧凑排在前面，第一个命中就在最上面。
- Q: `/hidden`（只有摘要文字、没有格子）？ → A: 摘要是一整片**不透明遮罩**盖住主区域（颜色与边和标签面板一致，下面的灰格看不到），文字写在遮罩上；未知指令整片灰格、无文字。（2026-11-12 修订：最初实现只在文字下面垫一块刚好包住文字的底色，文字块右边与下面露出灰格，被用户指出；改为整片遮罩。）

## Out of Scope（本阶段不做）

- 覆盖层面板；改变 042 的结果映射、滚动、选区、"拿走再放回"、Esc/`×`、焦点规则；工具区（命中只加框，不置灰）；命中框的颜色。
- 灰格的悬停提示；新贴图、语言键；服务端、网络包、协议号（仍 17）、配置、依赖。

## 已查证的事实（读本仓库源码；规格要尊重）

- 042 搜索时，主区域按结果的槽位号列表紧凑排布：`PanelLayout.slotIndex(MAIN, ordinal)` 对超出结果数的格子返回 -1（填充格）；`PanelLayout.hit` 对填充格返回 null；渲染对 `index < 0` 的格子直接 `continue`（画成面板底色），所以没有结果的位置现在是一片平地，不是格子。
- 点击、选区、拖拽、Ctrl 转移、Delete、双击聚拢都经 `PanelSlots.indexAt` / `PanelLayout.hit`，对填充格都得不到槽位，所以灰格**本来就点不了**；本 feature 不增加任何输入逻辑。
- 没在搜索（`SearchState.isFiltering()` 为假）时，填充格（超出容量、最后一行的尾部）仍必须是面板底色（037/042 既有规则：面板保持一个矩形，不凭空造格子）。
- 045 的 tooltip 对填充格不弹（`hit` 为 null），灰格自然不弹。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 搜索时看到完整网格，结果亮着、其余灰着 (Priority: P1)

玩家搜索时，主区域仍是一个完整的网格：命中的物品紧凑排在前面（照旧有蓝色命中框），后面所有没有结果的格子是灰色格子底，一眼看出哪些是结果。

**Independent Test**: 背包放十几种物品，搜索 `pick`：主区域前面 2 格是镐，其余每一格都是灰色格子（包括最后一行的尾部）；清除搜索后恢复原样（填充格仍是面板底色）。

**Acceptance Scenarios**:

1. **Given** 搜索框有查询且主区域有结果，**Then** 结果格正常显示（含命中框），其后的每个格子（直到可见区域的末尾）都画成灰色格子底；格子的位置与大小与普通格子一致。
2. **Given** 结果比可见格子少，**Then** 可见区域被灰格填满；结果超过可见区域时照常滚动，滚动后可见区域内没有结果的位置同样是灰格。
3. **Given** 没有任何结果（如 `zzzz`），**Then** 主区域整片灰格。
4. **Given** 清除搜索（Esc 或 `×`），**Then** 灰格消失，填充格（超出容量的部分）恢复为面板底色，与搜索前一致。

---

### User Story 2 - 灰格不可点，结果与"留位"照旧 (Priority: P1)

灰格上点击、Shift 选区、Ctrl 点击、拖拽、Delete、双击都不起作用；光标上拿着物品点灰格，物品不会放进去。结果格与"拿走后留位的格子"（仍是结果、正常底色）的操作与 042 完全一致。

**Independent Test**: 光标拿一组物品，点灰格：光标上仍拿着、背包没变；点结果格里的物品拿起，那格留位，再点它放回，物品回到原槽位。

**Acceptance Scenarios**:

1. **Given** 光标上有物品，**When** 点击灰格，**Then** 没有任何变化，也不发请求。
2. **Given** Shift 点或拖选经过灰格，**Then** 灰格不被选中。
3. **Given** 拿走一个结果格里的物品，**Then** 那格留位：不是灰格（仍是结果的位置），点它能放回（042 的行为）。
4. **Given** 悬停灰格，**Then** 没有物品 tooltip，没有悬停高亮。

---

### User Story 3 - `/hidden` 与未知指令 (Priority: P2)

输入 `/hidden`：一整片不透明遮罩盖住主区域（与标签面板同色同边），摘要文字写在遮罩上，清晰可读，下面的灰格不露出；输入未知指令：整片灰格、无文字。

**Independent Test**: 有隐藏物品时输入 `/hidden`、`/hidden fish`（无匹配）、没有隐藏物品时输入 `/hidden`、`/foo`：文字可读、灰格铺满；最窄面板里文字不溢出。

**Acceptance Scenarios**:

1. **Given** `/hidden` 且有隐藏物品，**Then** 遮罩盖满整个主区域（四边没有灰格露出），标题、类别行、说明写在遮罩上，文字清晰。
2. **Given** `/hidden` 无隐藏物品或过滤后无类别，**Then** 同样是整片遮罩，对应的一句话写在上面。
3. **Given** 未知指令，**Then** 整片灰格，没有文字。

---

### Edge Cases

- **标签面板或拾取黑名单页展开**：它们盖住主区域，灰格不画（与现在盖住结果的规则一致）。
- **面板最窄（3 列）或很高**：灰格铺满可见区域，不溢出矩形，不盖住滚动箭头（箭头画在格子之上）。
- **扩展行（037）**：结果里的扩展行格子保持行底色；灰格不带行底色、不带分隔线与角标。
- **选区（Shift）与灰格**：选区本来只含结果格，不受影响。
- **没有搜索时**：任何画面都与 046 之前逐像素一致（尤其是填充格仍是面板底色）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 搜索时（`SearchState.isFiltering()`），主区域中没有对应槽位的格子（`PanelLayout.slotIndex(MAIN, ordinal) < 0`）MUST 画成灰色格子底（与普通格子同位置同大小，颜色比普通空格子更暗，一眼可分）；这些格子 MUST NOT 带命中框、行底色、分隔线、角标、悬停高亮、选框。
- **FR-002**: 不在搜索时，填充格 MUST 仍是面板底色（逐像素与 046 之前一致）。
- **FR-003**: 灰格 MUST NOT 响应任何输入（点击、Shift 选区、Ctrl 点击、Alt 点击、拖拽、Delete、双击聚拢、滚轮之外的手势）；MUST NOT 发任何请求；本 feature MUST NOT 新增或修改输入逻辑（靠 `hit` 为 null 保证，并由游戏内验证）。
- **FR-004**: 结果格与"留位"的格子的显示与操作 MUST 与 042 一致。
- **FR-005**: `/hidden`：摘要 MUST 是盖满整个主区域的不透明遮罩（颜色与边同标签面板），摘要文字（标题、类别行或"没有隐藏的物品"/"没有符合的隐藏类别"、说明）画在遮罩上，下面的灰格 MUST NOT 露出；放不下时的取舍（`HiddenSummaryFit`）、悬停完整提示（037）不变。未知指令 MUST 整片灰格、不画文字。
- **FR-006**: 标签面板或拾取黑名单页盖住主区域时，MUST NOT 画灰格。
- **FR-007**: MUST NOT 新增服务端代码、网络包、协议号变化（仍 17）、配置项、语言键、依赖或贴图；011～045 的测试不改而通过；`DependencyRulesTest` 照常通过。
- **FR-008**: "哪些格子置灰"的规则 MUST 写成不依赖 Minecraft 类的纯逻辑并有单元测试；渲染接线用源码文本检查覆盖；README 两份的搜索一节补一句（搜索时没有结果的格子是灰色的）；`DELIVERY.md`（中文）。

### Key Entities

- **灰格**：搜索期间主区域里没有对应槽位的格子（填充格）；只是画法，不是数据。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 搜索 `pick`、`zzzz`（无结果）、空结果以外的 `@minecraft`（结果多于一屏）各一次，**每次可见区域里每个没有结果的位置都是灰格、每个结果位置都不是**（容器截图逐项对照）。
- **SC-002**: 清除搜索后主区域与搜索前**逐像素一致**（截图对比；填充格仍是面板底色）。
- **SC-003**: 灰格上的 5 种操作（点击带物品的光标、Shift 点、Ctrl 点、Delete、悬停）**全部无效、无请求**（游戏里验证点击与悬停；其余由 `hit` 为 null 与 042 的输入测试保证）。
- **SC-004**: `/hidden` 的 3 种情形（有隐藏、无匹配、未知指令）画面与预期一致，遮罩四边没有灰格露出，最窄面板里文字不溢出（截图）。
- **SC-005**: 服务端与网络协议**零改动**（协议号仍 17）；`./gradlew compileJava test` 通过；011～045 的测试不改而通过。

## Assumptions

- 灰格的具体色号在游戏里对照后定（要求：比普通空格子 `0xFF8B8B8B` 明显更暗、仍保留格子的立体边）；写入 DELIVERY。
- 命中框（深蓝）与灰格同时出现时不冲突：框只画在结果格上。
