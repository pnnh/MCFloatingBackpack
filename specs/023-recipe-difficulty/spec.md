# Feature Specification: 背包配方难度调整（材料统一为"块"、升级加锻造模板、皮革背包配方微调）

**Feature Branch**: `023-recipe-difficulty`

**Created**: 2026-11-07

**Status**: Implemented（实现完成；2026-11-07 用户已在客户端验证四档升级与内容保留、旧世界、JEI 显示、皮革新配方；仍未验证：旧格式（无 `template`）数据包配方、局域网协议版本，图集度量未做，见 DELIVERY.md）

**Input**: User description: "升级铁背包需要铁块、升级金背包需要金块，而升级钻石背包只需要单个钻石、升级下界合金背包只需要单个下界合金锭，后两档获取难度偏低，统一改成'块'。另外在锻造台升级配方里增加模具（锻造模板）要求，整体提高背包获取难度，最好不同等级配方用不同模具。皮革背包的获取难度也稍微提示一点，把其中一两个皮革换成别的材料。"

## 背景与已确认的决策

006 把背包分成皮革、铁、金、钻石、下界合金五档，升级走锻造台：**模板格必须为空**，基础是低一级的背包，材料是一个物品，内容保留。现状：

| 升级 | 当前材料 |
|---|---|
| 皮革 → 铁 | 铁块 |
| 铁 → 金 | 金块 |
| 金 → 钻石 | **1 个钻石** |
| 钻石 → 下界合金 | **1 个下界合金锭** |

皮革背包的工作台配方是 7 个皮革 + 1 根线 + 1 个箱子（`LSL / LCL / LLL`）。

用户发现后两档比前两档容易太多，并希望整体再难一点。已确认的决策（来自用户，不重新讨论）：

1. **材料统一为"块"**：四个升级的材料依次是**铁块、金块、钻石块、下界合金块**。
2. **升级要求锻造模板**：锻造台的模板格从"必须为空"改为"必须放入指定的模板"；模板和材料一样，升级时**被消耗 1 个**（与原版锻造模板的行为一致）。
3. **不同等级用不同模板**；**只用原版已有的锻造模板**，本模组不新增模板物品、不新增贴图（不影响宪法 VI 的图集预算）。下界合金这一档使用原版"下界合金升级模板"；其余三档各用一种原版盔甲纹饰模板，具体对应在 plan 里定。
4. **皮革背包配方**：把 7 个皮革中的 **2 个换成铁锭**（底行两个角），其余（5 个皮革、1 根线、1 个箱子）不变。

## Out of Scope（本阶段不做）

- 新增本模组自己的模板物品、贴图或合成方式。
- 容量、外观、面板、垃圾桶、标签管理器、工具区等任何非配方的内容。
- 标签管理器与垃圾桶的合成配方（021 / 018 已定，本次不动）。
- 数据包之外的配方来源（战利品、村民交易）。
- 对已经存在的背包做任何转换：旧存档里造好的背包原样保留。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 四档升级统一要"块"，并多一个锻造模板 (Priority: P1)

生存玩家想把背包从皮革逐级升到下界合金。每一级都要：低一级背包 + 该级对应的**材料块** + 该级对应的**锻造模板**，三样都放进锻造台才产出，模板与材料各消耗 1 个，背包内容完整保留到新背包。

**Why this priority**: 这是本次改动的核心，没有它就只是改了几个数字。

**Independent Test**: 创造模式取出四种背包、四种材料块与对应模板；逐级在锻造台升级，核对只有"背包 + 对应块 + 对应模板"三者齐全才有产出，产出后背包内的标记物品还在。

**Acceptance Scenarios**:

1. **Given** 铁背包、金块、对应模板，**When** 放入锻造台，**Then** 产出金背包；取出后金块与模板各少 1 个，原背包的物品全部保留。
2. **Given** 金背包、钻石块、对应模板，**When** 升级，**Then** 产出钻石背包。
3. **Given** 钻石背包、下界合金块、下界合金升级模板，**When** 升级，**Then** 产出下界合金背包。
4. **Given** 皮革背包、铁块、对应模板，**When** 升级，**Then** 产出铁背包。
5. **Given** 缺模板（模板格为空）、或缺材料、或材料不是"块"（例如单个钻石或下界合金锭）、或放了别档的模板，**When** 尝试升级，**Then** 不产出，原物品留在锻造台。
6. **Given** 任意一档升级，**When** 玩家寻找降级配方，**Then** 仍然不存在。

---

### User Story 2 - 配方在 JEI 里可见且完整 (Priority: P2)

玩家在 JEI（有装时）里查背包配方，每档升级都能看到完整的锻造台配方：模板、基础背包、材料块、结果。

**Why this priority**: 配方变复杂后，不靠 JEI 玩家很难知道每一档要哪个模板；但没有 JEI 也不影响功能。

**Independent Test**: 开 JEI，查铁、金、钻石、下界合金背包的配方，四条都能看到且三格都有物品。

**Acceptance Scenarios**:

1. **Given** JEI 已安装，**When** 查某档背包的配方，**Then** 看到锻造台配方，模板格显示该档要求的模板（不是空格）。
2. **Given** JEI 没安装，**When** 游戏运行，**Then** 一切正常，没有报错。

---

### User Story 3 - 皮革背包配方多用 2 个铁锭 (Priority: P2)

玩家在工作台用 5 个皮革、2 个铁锭、1 根线、1 个箱子合成皮革背包，摆法是原来的格子里底行两个角换成铁锭。旧摆法（7 个皮革）不再产出。

**Why this priority**: 只是微调起点难度，不影响其它功能。

**Independent Test**: 工作台按新摆法得到 1 个皮革背包；按旧摆法得不到；JEI 里能看到新配方。

**Acceptance Scenarios**:

1. **Given** 工作台摆 `皮革 线 皮革 / 皮革 箱子 皮革 / 铁锭 皮革 铁锭`，**When** 合成，**Then** 得到 1 个皮革背包。
2. **Given** 旧摆法（7 个皮革），**When** 合成，**Then** 没有产出。

---

### User Story 4 - 老存档与已有背包不受影响 (Priority: P1)

已经造好的任何等级的背包（含内容）原样保留，行为不变。新规则只影响之后新做的和新升级的。

**Why this priority**: 不能因为平衡调整让玩家丢东西或需要补材料。

**Independent Test**: 用改动前保存的存档打开，里面的各档背包与内容都在，仍可使用；新配方立即生效。

**Acceptance Scenarios**:

1. **Given** 改动前保存的世界里有各档背包，**When** 加载新版本，**Then** 背包与内容完整、可打开。
2. **Given** 上述世界，**When** 玩家升级其中的背包，**Then** 按新配方（块 + 模板）进行，内容保留。

---

### Edge Cases

- 模板放进了**基础格**或**材料格**（位置放错）→ 不产出。
- 同时放了对应的模板和别档的模板（只有一个模板格，不可能同时）。
- 锻造台里材料块堆叠数量 ≥ 2 → 只消耗 1 个，其余留在格子里（与原版锻造一致）。
- 玩家手里没有模板 → 升级不可用；这是本次改动想要的难度，不提供替代途径。
- 数据包作者自行改配方 → 允许，规则不阻止；本模组自带的数据是新配方。
- 与 020 兼容开关（FULL / GENERIC / OFF）无关：配方是原版机制，不属于对第三方模组的适配。
- 多人同服：配方由服务端数据决定，客户端只负责显示；服务端和客户端版本不一致时，JEI 显示可能与实际不符，以服务端为准。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 四个升级配方 MUST 依次要求材料**铁块（皮革→铁）、金块（铁→金）、钻石块（金→钻石）、下界合金块（钻石→下界合金）**，每次消耗 1 个。
- **FR-002**: 每个升级配方 MUST 要求锻造台**模板格**放入该档指定的锻造模板，升级时消耗 1 个；模板格为空或放了别档的模板 MUST NOT 产出。
- **FR-003**: 四档升级使用的锻造模板 MUST 互不相同，并且 MUST 全部是**原版已有**的锻造模板；下界合金档 MUST 使用原版"下界合金升级模板"，其余三档使用三种不同的原版盔甲纹饰模板（具体对应在 plan 里定）。
- **FR-004**: 升级 MUST 继续保留背包内全部内容（主区域、三个工具区、标签、垃圾桶、光标等 006 起所有已保存的数据），新增格子为空；升级后的背包 MUST 是低一级背包的直接升级（同一物品实例的数据延续）。
- **FR-005**: 不存在降级配方；缺材料、缺模板、模板或材料放错位置、放错档的模板 MUST 不产出。
- **FR-006**: 皮革背包的工作台配方 MUST 改为 5 个皮革、2 个铁锭、1 根线、1 个箱子，摆法为 `皮革 线 皮革 / 皮革 箱子 皮革 / 铁锭 皮革 铁锭`；旧的 7 皮革摆法 MUST NOT 产出。
- **FR-007**: JEI 已安装时，每档升级配方 MUST 能在 JEI 里看到，模板格 MUST 显示该档要求的模板；JEI 未安装时 MUST 无报错、无功能影响。
- **FR-008**: 本 feature MUST NOT 新增任何贴图、模型或物品，MUST NOT 修改任何背包的容量、外观、面板、垃圾桶、标签管理器等行为。
- **FR-009**: 已经存在的背包（任何档位、任何内容）MUST NOT 被改动；新配方 MUST 对旧存档立即生效，不需要迁移。
- **FR-010**: 升级配方的数据格式变化（增加"模板"）MUST 在 `specs/006-tiered-backpacks`、`docs/MCFloatingBackpack.md` 里被记录，使文档与实际配方一致。

### Key Entities

- **升级配方**：基础（低一级背包）、模板（该档指定的原版锻造模板）、材料（该档的块）、结果（高一级背包）。一次升级各消耗模板与材料 1 个。
- **锻造模板分配表**：四档升级各自对应的一种原版锻造模板（下界合金档固定为下界合金升级模板）。
- **皮革背包配方**：5 皮革 + 2 铁锭 + 1 线 + 1 箱子，固定摆法。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 四个升级逐一验证：**缺任一项（背包 / 材料块 / 模板）都不产出，三样齐全都产出**，共 4 × 4 = 16 个正反用例全部符合预期。
- **SC-002**: 升级前后，同一只背包的所有内容零丢失、零重排（至少验证主区域、工具区、标签、垃圾桶各一次）。
- **SC-003**: 用改动前保存的存档加载，所有已有背包 100% 可用，无报错，无内容变化。
- **SC-004**: JEI 里四档升级与皮革配方共 5 条，在 JEI 里各能找到一次，且模板格不是空的。
- **SC-005**: 从零开始（生存）获得下界合金背包所需的材料总量，按"块"计、含四个模板，比改动前明显更高；"明显更高"以 plan 里列出的材料成本对照表为准。
- **SC-006**: 没有新增任何资源文件（贴图、模型、物品）；图集度量仍为 2048×1024（宪法 VI）。

## Assumptions

- "模具"指原版的**锻造模板**（smithing template）。
- 四档模板的具体对应表已在 [plan.md](./plan.md) 与 [research.md](./research.md) D2 里定（哨兵 / 沙丘 / 眼 / 下界合金升级），当时需满足：全部互不相同、都能在生存里获得、尽量避开会让玩家误以为是装饰的歧义。
- 升级配方不使用配方书；本模组的配方书与进度相关内容不在范围内。
- 材料从"块"改为"块"之外的替代品（例如 2 个钻石）不在本次范围。
- 创造模式取物不受影响。
- 已有的本模组测试里若有配方数据的断言，需要随新配方更新。
- 文档（006 spec、`docs/MCFloatingBackpack.md`）要同步；不要修改 `docs/ideas`。
- **026 补充**：皮革背包的工作台配方类型改为 `mcfloatingbackpack:backpack_crafting`（继承原版有序配方，图案与材料不变），用于在合成结果上先盖一个待登记的内部标识，详见 `specs/026-backpack-id/`。
