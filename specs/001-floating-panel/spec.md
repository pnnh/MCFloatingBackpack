# Feature Specification: 可见可拖动空面板

**Feature Branch**: `001-floating-panel`

**Created**: 2026-10-23

**Status**: Draft

**Input**: User description: "依据 docs/MCFloatingBackpack.md 的 M1：实现可见、可拖动的空浮动背包面板。快捷键开关；面板始终可浮在画面上，打开原版物品栏或其他容器时不关闭；位置可持久化。本阶段尚无真实物品格子交互与服务端库存。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 快捷键开关浮动空面板 (Priority: P1)

玩家进入世界后按下绑定的开关快捷键，屏幕上出现一块可辨认的浮动空面板（占位背包外观，无需真实物品）。再按同一快捷键，面板隐藏。默认键可在控制设置中查看与改绑。

**Why this priority**: 没有可开关的可见面板，后续拖动与共存都无从验证。这是 M1 的最小可用切片。

**Independent Test**: 只装本模组，`runClient` 进入世界，按默认开关键看面板出现与消失；在控制设置中确认类别与键名存在。

**Acceptance Scenarios**:

1. **Given** 玩家已进入世界且面板当前隐藏，**When** 按下开关快捷键，**Then** 屏幕上出现浮动空面板。
2. **Given** 面板当前可见，**When** 再次按下同一快捷键，**Then** 面板隐藏。
3. **Given** 玩家打开控制设置，**When** 查看本模组键位分类，**Then** 能看到「开关浮动背包」类条目并可改绑。

---

### User Story 2 - 拖动面板并记住位置 (Priority: P2)

面板可见时，玩家按住面板的标题栏（或明确的拖动区域）拖动，面板跟随指针移动。松开后位置保留；退出世界再进入（或重启客户端后再进同一配置环境）后再次打开面板，仍出现在上次放下的位置。

**Why this priority**: 「可拖动」是 M1 相对纯 HUD 开关的核心差异；位置持久化避免每次重开都要重摆。

**Independent Test**: 打开面板，拖到屏幕一角，隐藏再打开确认位置；重启客户端后再打开仍在该位置。

**Acceptance Scenarios**:

1. **Given** 面板可见，**When** 玩家在拖动区域按下并移动指针后松开，**Then** 面板停在新位置。
2. **Given** 玩家已将面板拖到非默认位置，**When** 隐藏后再打开，**Then** 面板仍在该位置。
3. **Given** 玩家已保存过非默认位置，**When** 完全退出客户端后再次启动并打开面板，**Then** 面板仍出现在上次位置。

---

### User Story 3 - 打开其它界面时面板仍在 (Priority: P3)

面板已打开时，玩家按 E 打开原版物品栏，或打开箱子等容器界面。浮动面板保持可见，不被关闭；关闭物品栏/容器后，面板仍按当前开关状态显示。玩家仍可用快捷键在这些界面打开时隐藏或再次显示面板。

**Why this priority**: 这是整模组相对普通背包 Screen 的关键承诺；M1 用空面板验证共存，不要求物品互拖。

**Independent Test**: 先打开浮动面板，再按 E；确认两套 UI 同时可见。再打开一个箱子重复确认。在物品栏打开时按开关键可隐藏面板。

**Acceptance Scenarios**:

1. **Given** 浮动面板可见，**When** 玩家按 E 打开物品栏，**Then** 浮动面板仍然可见，物品栏也正常打开。
2. **Given** 浮动面板可见，**When** 玩家打开箱子界面，**Then** 浮动面板仍然可见。
3. **Given** 物品栏已打开且浮动面板可见，**When** 玩家按下开关快捷键，**Then** 浮动面板隐藏，物品栏保持打开。
4. **Given** 浮动面板可见且物品栏已打开，**When** 玩家关闭物品栏，**Then** 浮动面板仍保持可见。

---

### Edge Cases

- 面板被拖到屏幕外时，重新打开或下一帧应将面板钳制回可见区域，避免永久丢失。
- 更改 GUI 缩放后，面板应仍可拖动且大致保持相对屏幕的可用位置；允许轻微像素偏差，但不允许完全不可见。
- 聊天界面打开时，开关快捷键不应把输入内容打乱到无法预期；若冲突，以不向聊天发送该键字符或在聊天打开时忽略开关为准（实现选定一种并在 quickstart 说明）。
- 本阶段面板内没有可点击的真实物品槽；点击面板非拖动区域不应打开或关闭原版 Screen，也不应移动玩家物品。
- 未进入世界（主菜单）时，开关快捷键不显示面板。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 玩家 MUST 能通过可配置快捷键在已进入世界时显示与隐藏浮动空面板。
- **FR-002**: 打开浮动面板 MUST NOT 关闭或替换当前已打开的容器/物品栏界面。
- **FR-003**: 打开原版物品栏或标准容器界面 MUST NOT 自动关闭已显示的浮动面板。
- **FR-004**: 玩家 MUST 能通过拖动区域移动面板位置。
- **FR-005**: 面板位置 MUST 在客户端本地持久化，并在之后的游戏会话中恢复。
- **FR-006**: 面板被拖出可见区域时，系统 MUST 将其钳制回屏幕可见范围。
- **FR-007**: 本功能 MUST NOT 提供真实物品存取或跨容器拖放（留给后续里程碑）。
- **FR-008**: 浮动面板 MUST 在视觉上可与 HUD/其它界面区分（至少有边框或标题栏）。
- **FR-009**: 默认快捷键 MUST 在控制设置中可查看；玩家 MUST 能改绑。
- **FR-010**: 在已打开其它 GUI 时，开关快捷键 MUST 仍能切换浮动面板显示状态。

### Key Entities

- **浮动面板**: 客户端可见的空背包占位窗口，含可见状态、屏幕位置、拖动区域。
- **面板布局偏好**: 玩家本地保存的面板坐标（及可选的缩放，若本阶段实现），与具体存档世界无强绑定要求。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在一次客户端会话中，玩家能在 10 秒内完成「打开面板 → 拖到新位置 → 隐藏 → 再打开仍在新位置」。
- **SC-002**: 在浮动面板已打开时按 E，观察者能同时看到浮动面板与原版物品栏，且关闭物品栏后浮动面板仍在。
- **SC-003**: 完全退出并重启客户端后，再次打开面板时位置与退出前一致（允许 ±2 GUI 像素误差）。
- **SC-004**: 将面板拖向屏幕外后松开，面板仍有可点击的可见区域留在屏幕内。
- **SC-005**: 本阶段验证不要求服务端安装本模组以外的特殊配置；单人 `runClient` 即可完成上述检查。

## Assumptions

- M1 只交付空面板 UX，不包含服务端库存、槽位点击、与精妙/旅行者背包互拖、JEI 专项兼容。
- 默认开关键沿用工程骨架中的 `B`；最终以控制设置显示为准。
- 面板外观可用简单矩形 + 标题栏占位，不要求最终美术资源。
- 「浮在其它界面上面」在 M1 至少做到：与其它 GUI 同时可见，且拖动区域可被操作；不要求完美的全局 z-order 击败所有第三方 Overlay。
- 位置持久化使用客户端本地配置即可，不要求按世界/服务器分别存储。
- 文档 `docs/MCFloatingBackpack.md` 中的 M2–M5 不在本规格范围内。
