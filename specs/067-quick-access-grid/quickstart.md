# Quickstart: 快捷访问网格

验证分成自动测试和一次客户端会话。自动测试不加载 Minecraft。会话用 `./gradlew runClient`。本 quickstart 不包含实现代码。

## 自动测试

```bash
./gradlew test
```

预期：0 失败。其中与本 feature 直接相关的：

- `QuickCandidatesTest`：空格跳过；主区域在扩展行之前；可见扩展行计入、隐藏行不传入就不出现；超过一半时只留前面的；五档上限 18/27/36/45/54；同一种多组都在；没带 `quick` 的不在。
- `QuickViewportTest`：物品 32、格子 40；大窗口是 9×4；内容更少时缩小且不留空行；窗口只够 1×1 时仍是 1×1 且原点在画面内；滚动夹取；滚到头没有对应方向的「还有内容」；最后一行不满时命中落在靠左的格子上，右边点下去是视口外。
- `HandSwapPlaceTest`：空手用被点格子；被点格子能放就用它；否则用名单里第一个其它空位；没有空位或下标非法则返回 -1。
- `PresetTagsTest`：22 个预设，`quick` 在末尾，前面 21 个顺序不变，`quick` 通过 `TagRules.isValid`。
- `DataRevisionTest`：`CURRENT == 7`。
- `QuickAccessWiringTest`（源码文本）：`versioned("25")`；`quick_swap` 与 `quick_swap_result` 已注册；`DataRevision.CURRENT = 7`；按键默认 Z 且 `IN_GAME`；`QuickAccessScreen` 的 `isPauseScreen` 为假；两处 `ToolSingleRules.check` 的目标区是下方；`never_trash` 含 `quick_access`；没有 mixin、`setAccessible`。
- 历史测试里写死 `versioned("24")` 或 `CURRENT = 6` 的断言已改成 25 和 7（名单见 [research.md](./research.md) R7）。版本检查仍是 `versioned("1").optional()`。

## 游戏内（宪法 V）

准备：皮革背包一只，下方区放标签管理器和快捷访问。给几组物品（含一组 64 的食物、两把不同附魔的钻石剑、一瓶药水）打上「快捷」。主手拿一把剑，背包在物品栏或身上，不在主手。

1. **门禁**：拿走快捷访问，在游戏画面按 Z，快捷栏上方提示先放上它，没有网格。放进主区域再按，仍是这句。放回下方区，提示消失。
2. **只在游戏画面**：打开物品栏、箱子、暂停、按 B 打开浮动面板、按 U 打开联合背包（若穿着）、打开快照页，各按 Z 一次。网格不出现，也没有那句提示。关掉这些之后按住 Z，网格出现，按住期间不闪；松开 Z，网格消失。
3. **外观**：网格在画面中央，背后世界不发暗。没有窗口和滚动条。物品大约是原来的两倍，格子之间有空隙。鼠标停在物品上有与物品栏相同的提示。正中那格可以立刻有提示，但不交换。点在网格外网格仍在。
4. **数量与滚动**：皮革上不超过 18 组。换成下界合金并放上超过 36 组带「快捷」的物品：一次看见 4 行，滚轮能看到后面的，上下边缘在还有内容时出现小三角，三角点不下去。把窗口拉得很小：网格变少行少列，仍完整在画面里，只能上下滚。
5. **交换**：点一组食物。剑进那一格，食物整组到手（64 就是 64），网格关闭。再按 Z，剑不在网格里。点另一把钻石剑，两把对调，网格里仍有钻石剑（种类有标签）。
6. **分类行改放到空位**：把一组带「快捷」的食物放进只收食物的扩展行，主手换成剑，背包里留一个能放剑的空格，按住 Z 点那一组。食物到手，剑进那个空格，食物行那一格变空，网格关闭。把能放剑的空格都填满再点：物品不动，网格还在，快捷栏上方说明没有能放下手上物品的空位。浮动面板里对同一格 Alt+左键，结果相同。
7. **主手是背包**：把这只背包拿到主手再按 Z。不打开，提示先背上或放进物品栏。
8. **改键**：把快捷键改成 F。游戏画面按 F 只开网格，主手和副手没有对调。改回 Z。
9. **限放**：下方区已有一个快捷访问时，再放第二个被拒绝，格子不变。标签管理器、灯笼、罐子可以同时留在下方区。
10. **标签**：下拉里有「快捷」。给一种已经有 10 个标签的物品再加，加不上。搜索 `#quick` 能命中。

做不到的项记在 `DELIVERY.md`，不把没进过游戏的界面说成已验证。两份 README 和 `docs/plan/quick-access.md` 的状态在交付时改。
