# Feature Specification: 联合背包 · 单背包标签

**Feature Branch**: `065-combined-backpack-tabs`

**Created**: 2026-11-24

**Status**: Draft

**Input**: 用户（2026-11-24）提出"联合背包"玩法并逐轮确认方案，全文见 [docs/plan/combined-backpack.md](../../docs/plan/combined-backpack.md)（决策已定，本规格不重新讨论）。本 feature 是第一期：**物品 + 成员表 + 标签栏 + 单背包标签**；"全部"标签（聚合网格、跨背包寻址、显示用搜索与整理）是 066，**不在本期**。相关：032/061（穿戴来源与专用槽位）、026/040（身份与保护）、053（移动唱片机）、024（自动拾取）、064（嵌套规则）、019（宿主界面）。

## 背景

- 玩家可以同时带多只浮动背包：手上、胸甲槽、物品栏、Curios/Accessories 槽位。按 B 始终只能打开其中一只（查找顺序：手 → 穿戴 → 物品栏）。要看另一只，只能把它拿到手上或移走前面的。
- 联合背包是一个**无数据的虚拟物品**：穿在身上时，把身上的浮动背包联通成一个整体，在专属界面里用**标签**在各只背包之间切换，每个标签就是那只背包的**完整面板**（主区域、左右区、底部功能区、搜索、整理等都照旧）。
- 联合背包自己不存任何东西，所以没有数据膨胀、快照、保护、嵌套的问题；它只是"成员表 + 一个会话里的当前目标"。
- 服务端现状：所有面板请求（点击、快速转移、垃圾桶、标签、整理……）都用 `BackpackRef.resolve(player)` 找背包，即"B 会打开的那只"；点击包带着"声称的引用"，但服务端不采信。本 feature 在服务端加**会话目标**，让面板请求落在标签选中的那只背包上。
- 唱片机播放、自动拾取已经只读"B 会打开的那只"，不读面板里显示的背包；本 feature 不改它们。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 穿上联合背包，按 U，在标签间切换背包 (Priority: P1)

玩家穿着联合背包，身上有几只浮动背包。按 U 打开联合界面：顶部是联合标题栏（图标 + 标题 + 档位），下面是标签栏，每只成员背包一个标签；点某个标签，下面的面板就是那只背包的完整面板，所有操作都照旧作用在那只背包上。

**Why this priority**: 这是整个 feature 的价值：不用把背包搬来搬去就能存取身上任何一只。

**Independent Test**: 游戏内穿联合背包、物品栏放 3 只背包，按 U，逐个标签点击、放入、取出、整理、Ctrl+点击，核对物品落在被选中的那只背包里。

**Acceptance Scenarios**:

1. **Given** 穿着联合背包，物品栏里有背包 A、B、C，**When** 按 U，**Then** 打开联合界面，标签栏有 3 个标签，默认选中"B 会打开的那只"所对应的标签，下面显示它的完整面板。
2. **Given** 联合界面已打开，**When** 点背包 B 的标签，**Then** 面板换成 B 的内容（主区域、左右区、底部功能区、标题栏的编号），期间不接受点击，收到 B 的内容后才可操作。
3. **Given** 选中了 B 的标签，**When** 放入、取出、拖动分摊、Shift/Ctrl 点击、整理、搜索、垃圾桶、标签管理，**Then** 全部作用在 B 上，A 和 C 的内容不变。
4. **Given** 选中的不是"B 会打开的那只"，**When** 再按 B 键，**Then** B 键的行为与以前一样（按手 → 穿戴 → 物品栏的顺序打开那一只），不受联合界面影响。
5. **Given** 联合界面已打开，**When** 再按 U（或关闭面板的现有方式），**Then** 联合界面关闭，行为与现有面板关闭一致（含宿主界面的释放）。

### User Story 2 - 标签随身上的背包实时变化 (Priority: P1)

联合界面开着时，玩家拾起一只新背包、扔掉一只、把背包在物品栏里挪了位置，标签栏在一秒内跟着更新；正在看的那只被挪走时界面不会错位、不会把操作落到别的背包上。

**Why this priority**: 自动连接的代价是成员会变；没有它，界面会和实际脱节，操作可能落错背包（数据安全问题）。

**Independent Test**: 开着联合界面，在物品栏里拖动、丢弃、拾起背包，观察标签栏与面板；并在目标背包被挪动的那一刻点击，核对没有物品落到别的背包。

**Acceptance Scenarios**:

1. **Given** 联合界面开着，**When** 拾起一只新的背包，**Then** 一秒内标签栏多出一个标签；丢掉一只则少一个。
2. **Given** 正在看背包 B 的标签，**When** B 在物品栏里被挪到另一格，**Then** 界面按身份找回 B（唯一匹配时悄悄改目标，面板不闪）；找不到或有多只相同身份时回到第一个标签并重新同步。
3. **Given** 正在看背包 B，**When** B 被丢掉或放进箱子，**Then** 面板回到第一个标签（没有背包则关闭联合界面），在此之间到达的点击**不会**作用到别的背包。
4. **Given** 成员数超过 16，**Then** 只连接顺序里的前 16 只，标签栏提示"另有 n 只未连接（超过 16 只）"。
5. **Given** 联合背包是皮革档，身上有铁档背包，**Then** 铁档背包不出现在标签里，提示"n 只背包档位过高未连接"。
6. **Given** 某只背包的存档比本版本新（040 保护中），**Then** 不进标签，提示"n 只背包因版本过新未连接"；它不会被重写。

### User Story 3 - 获得、穿戴、升级联合背包（五档） (Priority: P1)

联合背包有皮革、铁、金、钻石、下界合金五档，和现有背包档位对应。皮革联合背包只连接皮革背包，铁的连接铁和皮革，……下界合金的连接全部。可以穿在胸甲槽，或 Curios/Accessories 的浮动背包专用槽位。可以合成，也可以用锻造台升档。

**Why this priority**: 没有物品就没有玩法；档位限制是它不过早成为"终极道具"的关键。

**Independent Test**: 游戏内合成各档、在锻造台升档、穿到胸甲槽与专用槽位，核对连接范围。

**Acceptance Scenarios**:

1. **Given** 一只同档位**空**背包、四颗末影珍珠、四份该档位材料，**When** 按配方合成，**Then** 得到对应档位的联合背包；**Given** 那只背包里有任何物品（主区域、工具区、垃圾桶、光标、隐藏行……），**Then** 配方**不匹配**，不会吃掉内容。
2. **Given** 低一档的联合背包、对应的锻造模板与材料块，**When** 在锻造台升档，**Then** 得到高一档的联合背包。
3. **Given** 联合背包，**When** Shift+右键，**Then** 与背包一样可换到胸甲槽（顶掉胸甲）。
4. **Given** 装了 Curios/Accessories 且 061 的专用槽位开着，**Then** 联合背包只能放进"浮动背包"专用槽位，放不进 `back`、`charm`。
5. **Given** 联合背包放在物品栏或手里，**When** 按 U，**Then** 不打开，动作栏提示"需要穿戴联合背包"。
6. **Given** 同时穿着多个联合背包，**Then** 取**档位最高**的那个；同档位取查找顺序靠前的。
7. **Given** 联合背包，**Then** 背上不画任何模型，物品只有平面贴图。

### User Story 4 - 不容易出错的细节 (Priority: P2)

- 手里（面板光标/菜单携带物）拿着东西时不允许切标签，提示"先放下手里的物品"。
- 在不是"B 会打开的那只"的标签里，右区里的移动唱片机、移动工作台、移动熔炉控件灰掉，悬停提示"移动工具只对按 B 打开的背包生效"。
- 自动拾取仍只对"B 会打开的那只"生效，与正在看哪个标签无关。
- 联合背包不能放进浮动背包（064 的规则认它）。
- 服务端配置 `[combined].enabled = false` 时物品仍存在但不起作用。

**Why this priority**: 都是防止困惑或损失的边界，不影响主流程。

**Independent Test**: 逐条在游戏里或单元测试里验证。

**Acceptance Scenarios**:

1. **Given** 光标上有物品，**When** 点另一个标签，**Then** 不切换，动作栏提示，光标上的物品不动。
2. **Given** 选中的背包右区有移动唱片机、移动工作台或移动熔炉且它不是 B 激活的那只，**Then** 这些控件灰掉、悬停有提示、点击不起作用；**Given** 它就是 B 激活的那只，**Then** 控件照常。
3. **Given** 当前看的标签不是 B 激活的那只，**When** 地上掉落物被拾取，**Then** 仍只按"B 会打开的那只"的自动拾取规则处理。
4. **Given** 把联合背包点向任何浮动背包的面板区域，**Then** 被拒绝（同 064）；`canFitInsideContainerItems` 对潜影盒等返回 false。
5. **Given** `[combined].enabled = false`，**When** 按 U，**Then** 不打开（提示"联合背包已被服务器关闭"），物品、配方、既有成员不受影响。

### Edge Cases

- **身份**：成员表只读，不给没有身份的背包分配身份；选中某个标签时才 `acquire`（会给它一个身份）。身份只用来校验"这个位置的背包没被换掉"，**不**用来找背包：复制出来的背包共享身份，成员表允许同一身份出现多次，寻址靠引用（来源 + 下标）。
- **主手**：主手背包就是物品栏里被选中的那一格；成员表只按物品栏下标列，不单独列主手，避免同一只列两次；副手单独列。
- **同一请求顺序**：同一连接上的包按序处理；切标签之前发出的点击在切换前处理，之后发出的在切换后处理。唯一的缝是"客户端已切标签、还没收到新内容"，由客户端"加载中"状态与服务端的"声称引用与目标不一致则拒绝并重同步"共同堵住。
- **在容器界面上叠加**：联合界面与现有面板一样可以叠在箱子、网络终端等界面上；容器 → 面板的转移落在当前标签的那只背包。
- **面板请求入口多**：约 30 处解析；漏一处会让点击落在"B 会打开的那只"而不是标签里的那只。用接线测试断言每个面板类处理器都经过统一解析。
- **没有联合背包 / 没有成员**：U 提示；成员为 0 时标签栏为空并提示，不报错。
- **启用开关**：`enabled=false` 时已存在的联合会话在下一次检查（每秒）时结束，面板回到现有单背包行为。
- **降级**：旧版本没有联合背包物品，加载时是未知物品（按现有对未知物品的处理）；物品无数据，不写新的存档字段。
- **语言键**：提示、标题、标签提示的中英文各一份。
- **UI 高度**：标签栏 + 联合标题栏让面板多约两行高；小分辨率下位置钳制必须把它算进去，不能让面板跑出屏幕。

## Requirements *(mandatory)*

### Functional Requirements

**物品与获取**

- **FR-001**: 系统 MUST 新增五个物品 `<档位>_combined_backpack`（皮革、铁、金、钻石、下界合金；注册名以此为准，显示名"联合背包 / Combined Backpack"可随时改），堆叠 1，**无数据组件**，不是容器，不是 `FloatingBackpackItem`，只有平面物品贴图，**没有背部模型**。
- **FR-002**: 联合背包 MUST 可穿胸甲槽（与背包一致，顶掉胸甲）；Curios/Accessories MUST 只允许放进 061 的"浮动背包"专用槽位（标签加在该槽位，不加在 `back`、`charm`）；放在物品栏或手里时 MUST 不起作用，按 U MUST 提示"需要穿戴联合背包"。
- **FR-003**: 同时穿多个联合背包时，系统 MUST 取档位最高的；同档位取穿戴查找顺序靠前的。
- **FR-004**: 合成配方（草案，数值以规格评审为准）：同档位背包居中，四角末影珍珠，四边该档位材料（皮革 / 铁锭 / 金锭 / 钻石 / 下界合金锭）；难度至少是同档位背包的 2 倍；配方 MUST 只接受**空**背包（主区域、工具区、垃圾桶、光标、隐藏行、液体存量等一切内容都为空），任何非空背包 MUST 使配方不匹配。
- **FR-005**: 升档 MUST 可用锻造台，沿用现有背包升级的模板与材料块，底料换成低一档的联合背包；因无数据，升级就是换物品（plan 修订：用原版 `smithing_transform` 配方即可，不需要自定义类；合成配方才需要自定义类型以检查"空背包"）。
- **FR-006**: 064 的嵌套规则 MUST 认联合背包：不能放进浮动背包（主区域、工具区、垃圾桶），`canFitInsideContainerItems` MUST 返回 false。

**成员表**

- **FR-007**: 系统 MUST 提供纯逻辑的成员表：穿戴槽位里**所有**浮动背包（按穿戴来源顺序，不止第一只）→ 副手 → 物品栏 0～35 下标升序；主手背包按物品栏下标列且去重；每项含（引用、身份、档位、位置说明）。
- **FR-008**: 成员表 MUST 排除并分别计数：档位高于联合背包的；040 保护中的；超过 16 只的（取顺序里前 16 只，16 不开放配置）。计数 MUST 显示在联合界面里。
- **FR-009**: 成员表 MUST 只读：不给没有身份的背包分配身份、不改任何物品栈；允许同一身份出现多次，寻址靠引用。

**服务端会话目标**

- **FR-010**: 服务端 MUST 在玩家的面板会话里记录**目标**（成员引用 + 身份）；MUST 新增统一解析（暂名 `PanelTargets.resolve(player)`）：有联合会话、目标仍在成员表里且身份仍对得上 → 返回目标；否则退回 `BackpackRef.resolve`。
- **FR-011**: 所有面板类请求处理器（点击、光标手势、快速转移、容器 → 面板、网络终端取出、垃圾桶（含发送）、标签与标签总览、整理、拾取黑名单、合并光标，共 13 处，清单见 plan 的 contracts/panel-targets.md）MUST 改用统一解析；自动拾取、背部渲染、B 键打开、版本诊断、灯笼光、管子、**移动工具（工作台、熔炉的打开与状态）与唱片机**等"B 会打开的那只"语义的调用 MUST 保持 `BackpackRef.resolve` 不变（plan 修订：读码确认移动工具与唱片机本来就按 B 的那只找，不属于面板类请求）。MUST 有接线测试断言每个面板类处理器都经过统一解析。
- **FR-012**: 服务端 MUST 对带"声称引用"的请求（如点击包）做校验：声称引用与会话目标不一致时 MUST 拒绝并重新同步，MUST NOT 悄悄改用别的背包。
- **FR-013**: 切标签与 U 键打开 MUST 用新包 `CombinedSelectPayload(op, 成员下标, 身份)`（C→S；`op` 为 OPEN 或 SELECT，OPEN 忽略下标与身份，默认目标取 B 会打开的那只、不在表里则第一个成员）：服务端校验（联合背包仍穿着、联合会话有效、下标在成员表内、该处身份对得上或该背包尚无身份）后改会话目标，**随后发一次现有的整包同步**；校验失败 MUST 回退并重新同步成员表。第一次选中尚无身份的背包时 MUST 通过现有 `acquire` 路径给它身份。
- **FR-014**: 目标背包被挪动时 MUST 按身份在新成员表里找回：唯一匹配 → 悄悄改目标；找不到或多个相同 → 回到第一个标签并重新同步（没有成员则结束联合会话）。
- **FR-015**: 服务端 MUST 只对**开着联合界面**的玩家每秒重算一次成员表；成员列表（引用 + 身份 + 档位 + 位置 + 自定义名）变了才推 `CombinedMembersPayload`（S→C）；请求处理中的校验只验证目标（O(1)：仍是浮动背包、身份对得上、档位不超、不在保护中、联合背包仍穿着且启用），MUST NOT 每次请求重算整张表；"目标在前 16 位"只在选标签与每秒检查里强制。
- **FR-016**: 光标非空时 MUST 拒绝切标签（服务端权威，客户端同样不发），动作栏提示"先放下手里的物品"。

**客户端与界面**

- **FR-017**: U 键 MUST 作为新的按键映射（可在控制设置里改）；宿主界面（019）的按键路由 MUST 认它；穿戴联合背包且启用时打开联合界面，否则提示。
- **FR-018**: 联合界面 MUST 由联合标题栏（图标 + 标题 + 档位）、标签栏、现有面板（含它自己的标题栏）自上而下叠成；标签栏**不显示"全部"标签**（066 才有），MUST NOT 留空占位。
- **FR-019**: 每个背包一个标签：色块 + 名称（铁砧改名优先，否则档位图标 + 4 位编号），悬停提示位置（胸甲 / Curios 专用槽 / Accessories 专用槽 / 副手 / 物品栏第 n 格）与容量；标签过多时标签栏 MUST 可横向滚动；被排除的背包按 FR-008 提示数量。色块先按成员在标签栏中的位置取色，与 066 的"全部"标签将共用同一张颜色表。
- **FR-020**: 联合标题栏与标签栏 MUST 贴在现有面板上沿之上，**不改变现有面板的几何**（plan 修订：不给 `PanelLayout` 加 `topExtra`，改为像垃圾桶页那样挂在面板外沿，先于面板认领点击与滚轮）；位置钳制 MUST 在联合模式下保证它完整可见（面板顶边不得小于条形高度），JEI 排除区 MUST 多算这一块；非联合模式的面板行为与测试 MUST 不变。
- **FR-021**: 客户端现有的背包视图（单例）MUST 始终镜像当前标签的那一只；新增的联合状态（成员表、当前标签、加载中标志）MUST 独立；切标签后到收到整包前，客户端 MUST 不发任何面板请求。
- **FR-022**: 当前标签的背包不是"B 会打开的那只"时，右区里的**移动唱片机、移动工作台、移动熔炉**三个控件 MUST 灰掉并提示"移动工具只对按 B 打开的背包生效"；唱片机播放、移动工具的服务端打开、自动拾取 MUST 不变，仍只读"B 会打开的那只"。客户端 MUST 每帧（仅联合界面可见时）用自己的 `BackpackRef.resolve`（归一化 `MAIN_HAND` → 物品栏被选中那格）与当前标签成员比较，MUST NOT 依赖服务端推送（滚动快捷栏时成员表不变）。

**配置、协议、约束**

- **FR-023**: 系统 MUST 提供服务端配置 `[combined].enabled`（默认 true）；关闭时联合背包物品与配方仍在，但 U 不打开联合界面，已有联合会话在下一次检查结束。
- **FR-024**: 协议号 MUST 22 → 23（新包 `CombinedSelectPayload`、`CombinedMembersPayload`）；`DataRevision` MUST 不变；MUST NOT 使用 mixin 或反射；Curios/Accessories 一侧 MUST 只改标签与槽位验证数据（沿用 061），第三方类型只允许在现有 `compat/` 包里。
- **FR-025**: 系统 MUST 有自动测试：成员表（顺序、去重、同身份多次、档位过滤、前 16 截断、保护排除）、统一解析（目标有效/身份对不上/成员表变了/退回）、布局顶部高度（命中与滚动）、配方拒绝非空背包、五档物品注册与语言键、接线测试（面板类处理器都用统一解析、非面板的保持不变）、嵌套规则认联合背包。**游戏内验证**：见 quickstart（穿戴、U 打开、标签增减、切标签后点击落点、目标被挪动、非激活背包唱片机控件灰掉、`enabled=false`、各档连接范围）。
- **FR-026**: 文档 MUST 同步：README 两份（新物品、U 键、档位规则、自动拾取与唱片机只对 B 打开的那只）、`docs/plan/combined-backpack.md` 的状态、DELIVERY 写清已验证与没验证的。

### Key Entities *(include if feature involves data)*

- **联合背包物品**：五档，无数据；档位决定连接范围（连接不高于自身档位的背包）。
- **成员**：（引用、身份、档位、位置说明）；由成员表现算，不存盘。
- **成员表**：有序、最多 16 项，附带三类"未连接"的计数（档位过高、版本过新、超过 16 只）。
- **联合会话**：玩家级、服务端内存：联合背包档位、目标（引用 + 身份）、上次发给客户端的成员表摘要；关闭联合界面、下线、停服时清除。
- **联合状态**（客户端）：成员表、当前标签、加载中标志、颜色分配；不存盘。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 玩家穿着联合背包、物品栏里有 3 只背包时，按 U 后**一次点击**即可看到并操作其中任意一只，不需要把背包搬到手上或移走别的背包。
- **SC-002**: 在任何标签里的任何面板操作，**0 次**落在别的背包上（含切标签瞬间、目标被挪动、身份相同的复制背包）；游戏内逐类请求验证。
- **SC-003**: 成员变化（拾起、丢弃、挪动）在 **1 秒内**反映到标签栏；联合界面没打开的玩家**零**额外每 tick 开销。
- **SC-004**: 五档的连接范围正确：皮革只连皮革，下界合金连全部；超出的有计数提示，不静默吞掉。
- **SC-005**: 配方不会吃掉任何非空背包（测试覆盖每一类内容区域）。
- **SC-006**: 新增与既有测试全部通过（0 失败）；`DataRevision` 不变，旧存档无任何改动。
- **SC-007**: 联合界面叠加后，在常见分辨率下面板不超出屏幕（主观项由用户真机确认）。

## Assumptions

- "全部"标签、跨背包聚合存取、显示用搜索与整理、成员上限配置、"不加入联合背包"开关、标签快捷键、两层标题栏合并、背部模型，**都不在本期**（见 docs/plan/combined-backpack.md 的拆分表）；标签栏不为"全部"留占位。
- 成员上限 16 固定，不开放配置。
- 配方数值是草案：四角末影珍珠、四边档位材料、中间空的同档位背包；高档位是否把珍珠换成末影之眼留给评审；升档沿用现有锻造模板与材料块。
- 面板光标仍是各背包自己的光标（持久在背包数据里），所以光标非空时不切标签；跨背包的内存光标是 066 的事。
- Plan 阶段已读码确认（见 research.md R1～R4）：无身份的背包没有过期保护，所以选标签时先 `acquire` 给身份；`OpenToolPayload` 与全部移动工具、自动拾取、唱片机播放本来就按"B 的那只"找，不改；JEI 排除区是 `IGlobalGuiHandler` 返回矩形，垃圾桶页是先例；`MAIN_HAND` 与物品栏被选中那格是同一个栈，成员表与会话目标只用 `INVENTORY(下标)`，比较时归一化。
- 已知限制：Curios/Accessories 的专用槽位大小为 1，同一时刻只能放一只背包**或**一只联合背包（联合背包仍可穿胸甲槽，背包仍可放 `back`/`charm`/胸甲槽）；062 的"被 Accessories 丢掉的背包"只认浮动背包，槽位类型消失时槽内的联合背包不会被找回（本期不做，记入 DELIVERY）。
- 颜色表要在深色界面上看得清，且与灰格、搜索高亮不冲突；这是主观项，由用户真机确认。
- 联合背包在物品栏里"不起作用"只是语义，不做硬限制（不用 mixin 做不到）。
