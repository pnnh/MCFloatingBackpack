# Feature Specification: 搜索词提供者接口

**Feature Branch**: `043-search-terms-provider-api`

**Created**: 2026-11-12

**Status**: Draft（取代最初的"本模组打包 PinIn"版 043，见"方案变更"）

**Input**: 用户确认（2026-11-12）：本模组不实现拼音与多语言搜索，也不打包任何库；只**公开一个很小的接口**，让别的模组把"某个物品还可以被搜到的文字"（别的语言的名字、拼音等）交给背包搜索。别的模组如何接入、接入后联动是否正常，是**那些模组自己的事**，不在本模组的范围内、也不在本 feature 的验收里。没有任何提供者时，搜索只用游戏当前语言的名字和注册名（042 的行为）。建立在 042（`specs/042-backpack-search-core`）之上。

## Clarifications

### Session 2026-11-12

- Q: 本 feature 是否要考虑 MCBilingual 的联动？ → A: **不考虑。** 兼容的主动权在别的模组一侧（被兼容方公开 API，兼容方把它作为可选依赖主动接入）。本模组只负责提供并维护公开 API 与它的契约；不引用任何具体模组的类型，不为任何具体模组写代码、文档推荐、专门的测试或验收项，也不因某个模组存在或缺失而改变行为。
- Q: 接入通道用什么？ → A: 本模组自己的公开 API 包，不用 NeoForge 的 `InterModComms`。
- Q: 接口参数？ → A: `ItemStack`。

## 方案变更（相对于最初的 043 规格）

最初的 043 是：在本模组里读 en_us 与 zh_cn、打包 PinIn、加 `search.chinese` 配置、修订宪法 VII。用户否决，结论**不再重新讨论**：

1. 本模组**不再**打包 PinIn、**不再**有 `search.chinese` 配置、**不再**读 en_us/zh_cn 语言文件、**不再**需要修订宪法 VII。
2. 多语言名字、拼音、声母模糊、汉字拼音混输等能力的范围与演进，**完全由提供者一侧决定**，不卡本模组的发布。
3. 被兼容的一方公开 API，兼容方 `compileOnly` 依赖、运行时可选——本模组只做公开 API 的这一方。

## Out of Scope（本阶段不做）

- 在本模组里读任何语言文件、生成拼音、打包任何第三方库；`search.chinese` 配置；修订宪法 VII 关于打包库的条文。
- 任何具体模组的接入：本模组**不引用任何其它模组的类型**，不为具体模组写专门代码、README 推荐、验收项或联动测试；提供者一侧的实现、规格与验证不归本 feature。
- `@模组`、`#标签`、`/hidden`（044）；Ctrl/Cmd+F。
- 让提供者改变"哪些格子显示"之外的东西：提供者**只增加可被搜到的文字**，不能改变显示名、排序、语法含义（`@`、`#`、`/` 的含义归 044）。
- 服务端与网络协议改动（协议号仍 17）；其它界面（标签总览、黑名单页）的搜索。
- 除"搜索词提供者"外的任何公开接口。

## 已查证的事实（读源码；规格要尊重）

- 042 的匹配入口是 `SearchContext.matcherFor(stack)`：返回 `TextMatcher.ofTexts(当前语言显示名, 注册名路径)`，全部小写；`SearchQuery`/`SearchMatcher`/`SearchResults` 只依赖 `TextMatcher.contains(小写文字)`。043 只扩大这一处的文字集合。
- 本仓库**还没有任何公开 API 包**（现有包：`client`、`compat`、`diag`、`inventory`、`item`、`network`、`snapshot`、`version`、`worldmarker`）。这是第一个，所以要定义它的稳定性规则（FR-009、FR-010）。
- 宪法 VII 的规则是"别的模组可选、第三方类型只在 `compat/<modid>/`、对别的模组的主动交互受 `modLevels` 控制"。本 feature **不引用任何第三方类型**，所以 `compat/<modid>/` 规则不触发；但"本模组调用别的模组交来的代码"仍是与别的模组的交互，必须受 `modLevels` 控制，并在规格里写明每一级的含义（FR-006）。
- 项目的客户端配置在 `config/mcfloatingbackpack-client.toml`，已有 `[compat] modLevels`（模组 id → FULL/GENERIC/OFF）与 `CompatPolicy`。

## 尚未验证（plan 阶段先查证；验证前不得声称已满足）

- **API 类在专用服务器上能否安全加载**：API 包不得引用任何客户端类。
- **缓存的键与成本**：以"物品 + 数据组件（不含数量）"为键缓存的可行性（`ItemStack` 的哈希）与失效时机。
- **注册时机与线程**：模组构造阶段与客户端启动完成阶段注册的差异。
- **`modLevels` 的判定与监视**：沿用现有的 `CompatPolicy` 与配置监视是否足够。
- **游戏内验证方式**：没有真实提供者时，怎样在客户端会话里验证（容器里用临时假提供者？）——假提供者**不得进入发布 jar**。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 有提供者时，背包搜索多出它给的词 (Priority: P1)

某个模组向本模组注册了搜索词提供者。玩家在背包搜索框里输入提供者给的词（别的语言的名字、拼音等），对应物品命中，不管界面语言是什么。

**Why this priority**: 这是 043 存在的理由：接口真正生效。

**Independent Test**: 测试里注册一个假提供者，对钻石镐返回 `["钻石镐", "diamond pickaxe", "zuanshigao", "zsg"]`：当前语言为英文时输入 `zsg`、`钻石`、`diamond` 都命中钻石镐。

**Acceptance Scenarios**:

1. **Given** 提供者对钻石镐返回含 `zsg` 的词，**When** 输入 `zsg`，**Then** 钻石镐命中，与它的当前语言显示名无关。
2. **Given** 同上，**When** 输入当前语言名里的字（042 的行为），**Then** 仍然命中；提供者只增加、不替换。
3. **Given** 提供者的词里有大写字母（`ZSG`），**When** 输入小写 `zsg`，**Then** 命中（本模组统一转小写后比较）。
4. **Given** 042 的语法（空格并且、`|`、`-`、`"…"`），**When** 查询是 `zs gao`、`-zsg`、`zsg|jpg`，**Then** 每一项的命中判断都改为"当前语言名、注册名、任一提供者词中任一命中"，语法含义不变。
5. **Given** 提供者对名字由数据组件决定的物品（药水、附魔书）按 `ItemStack` 返回不同的词，**When** 搜索，**Then** 各格按它自己的 `ItemStack` 取词，不是按物品种类一刀切。

---

### User Story 2 - 没有提供者时与 042 完全一致 (Priority: P1)

没有任何模组注册提供者。搜索行为、性能与 042 **完全一致**：只搜当前语言显示名与注册名；没有额外的警告、成本或界面变化。

**Why this priority**: 绝大多数玩家没有提供者；本 feature 不能让他们付出任何代价。

**Independent Test**: 042 的全部单元测试不改而通过；注册表为空时 `matcherFor` 返回的文字集合与 042 一致（测试断言）；游戏里 042 的验证场景照常。

**Acceptance Scenarios**:

1. **Given** 没有注册任何提供者，**When** 任意搜索，**Then** 结果与 042 一致，没有调用任何外部代码、没有新增日志。
2. **Given** README 与 README_CN 的搜索一节，**Then** 如实写明"默认按当前语言的名字与注册名搜索；其它模组可以通过本模组的公开接口增加可搜索的文字"，并指向开发者说明；**不点名任何具体模组**。

---

### User Story 3 - 提供者出错或太慢时，搜索不受影响 (Priority: P1)

某个提供者抛了异常、返回 `null`、返回了巨大的集合，或者每次调用都很慢。玩家的搜索不崩溃、不卡死，其它提供者与 042 的匹配照常；日志里有一条能定位到那个提供者的 WARN。

**Why this priority**: 接口把本模组的搜索交给了别人的代码；容错是接口站得住的前提。

**Independent Test**: 单元测试里的假提供者分别：抛异常、返回 null、返回空集合、返回含空串与超长串的集合、返回很多个词；断言匹配结果正确、其它提供者不受影响、只记一次 WARN。

**Acceptance Scenarios**:

1. **Given** 某提供者在某个物品上抛异常，**When** 搜索，**Then** 该提供者对该物品没有额外词，其它物品与其它提供者照常；同一提供者的同类错误只记**一条** WARN（含注册它的模组 id 与异常类型）。
2. **Given** 同一提供者累计出错达到上限（plan 定），**Then** 本会话起忽略该提供者并再记一条 WARN 说明"已停用"。
3. **Given** 提供者返回 `null` 或空集合，**Then** 视为没有额外词，不记错误。
4. **Given** 提供者返回空串、纯空白串，**Then** 被丢弃；含空格的词原样保留（查询按空格拆词，所以含空格的词只能被整段 `"…"` 查询命中，契约里建议提供者不要返回含空格的词）。
5. **Given** 提供者一次返回的词数或单词长度超过上限（plan 定），**Then** 超出部分被截掉并记一条 WARN；匹配仍然工作。

---

### User Story 4 - 玩家可以在配置里关掉某个提供者 (Priority: P2)

某个提供者的词让搜索误匹配太多，或玩家就是不想用。玩家在 `[compat] modLevels` 里把注册它的模组 id 设成 `GENERIC` 或 `OFF`，之后搜索忽略它的词，不需要重启。

**Why this priority**: 宪法 VII 要求对别的模组的主动交互受 `modLevels` 控制；对玩家也是应急出口。

**Independent Test**: 注册 id 为 `x` 的假提供者；`modLevels` 里 `x=FULL`（或未列出）时词生效；改成 `GENERIC` 或 `OFF` 后不再生效、也不再被调用；改回 `FULL` 又生效；全程不重启。

**Acceptance Scenarios**:

1. **Given** 提供者的模组 id 未在 `modLevels` 里列出，**Then** 按 FULL 处理（词生效）。
2. **Given** 该 id 为 `GENERIC`，**Then** 词不生效，且提供者**不被调用**。
3. **Given** 该 id 为 `OFF`，**Then** 与 `GENERIC` 相同（本接口没有"在对方界面上显示面板"的含义，OFF 的"面板不显示"不适用；见 FR-006）。
4. **Given** 配置在游戏里被改动（沿用 020 的配置监视与通知），**Then** 从下一次搜索起生效。

---

### User Story 5 - 开发者能照说明使用接口 (Priority: P2)

别的模组作者只读开发者说明就能使用接口：依赖怎么写、在哪个时机注册、提供者的约定（线程、耗时、返回什么）、版本号怎么检查、稳定性承诺。

**Why this priority**: 接口是给别的模组用的；说明不清就没有人能用。

**Independent Test**: 开发者说明与 `contracts/search-terms-api.md` 一致；契约里的包名、类型、方法、常量、上限与代码一致（有测试把契约里的数值与代码常量对照）。

**Acceptance Scenarios**:

1. **Given** `contracts/search-terms-api.md` 与开发者说明，**Then** 给出：包名、类型与方法、注册时机、调用时机与线程、返回值约定与上限、容错行为、`apiVersion()` 的含义、稳定性承诺、一个最小示例。
2. **Given** 说明里的示例，**Then** 它只用本接口与 JDK/Minecraft 类型，不涉及任何具体模组。

---

### Edge Cases

- **多个提供者**：词取并集，不排序；一个提供者出错不影响另一个。
- **注册晚于首次搜索**：允许；注册时丢弃已缓存的结果，下一次搜索起生效。
- **重复注册同一模组 id**：后一次替换前一次；记 DEBUG 日志。
- **注册时 id 为空、提供者为 null**：抛 `IllegalArgumentException`（调用方的编程错误，早暴露）。
- **提供者被调用的线程**：只在客户端渲染线程（搜索重算时）；契约要求提供者不阻塞、不做 I/O、不访问世界。
- **专用服务器**：API 类可以被加载但不会有任何注册、任何调用。
- **空查询**：不调用提供者（042 的"空查询不过滤"）。
- **物品是空气或空堆叠**：不调用提供者。
- **改过名的物品**：当前显示名（含自定义名）仍按 042 搜；提供者以同一个 `ItemStack` 为入参，它决定返回什么。
- **大量格子**：400 格以内一次查询重算仍在下一帧完成；对同一 `ItemStack`（物品加数据组件，不含数量）的提供者结果按会话缓存，资源重载、该提供者被重新注册时失效（`modLevels` 在查询时应用，不影响缓存）。
- **提供者返回的词与 042 的词重复**：无影响。

## Requirements *(mandatory)*

### Functional Requirements

**公开接口**

- **FR-001**: 本模组 MUST 提供公开 API 包 `pnnh.mcfloatingbackpack.api`（plan 可调整名称，但须在 `contracts/search-terms-api.md` 里固定），其中只含：一个"搜索词提供者"函数式接口 `ItemStack → 一组字符串`，和一个注册入口（静态方法，参数是调用方模组 id 与提供者）。API 包的公开签名 MUST 只含 JDK 与 Minecraft 的类型（不暴露本模组内部类型），API 包 MUST NOT 引用任何客户端专用类（实现可委托给本模组内部的通用、非客户端的类）。
- **FR-002**: 注册 MUST 可以在模组构造阶段或客户端启动完成阶段调用，MUST 线程安全，MUST 可在搜索开始之后调用。同一模组 id 再次注册 MUST 替换旧的；id 为空或提供者为 null MUST 抛 `IllegalArgumentException`。
- **FR-003**: 提供者 MUST 只在**客户端渲染线程**、**搜索重算时**被调用，且只对"需要判断的非空格子"调用；空查询 MUST NOT 调用任何提供者。
- **FR-004**: API MUST 提供可在**运行时**读取的整数版本号（本 feature 为 1；用方法 `apiVersion()` 返回，而不是编译期常量，否则会被调用方的编译器内联、失去运行时检查的意义），文档写明稳定性承诺（FR-010）。

**匹配**

- **FR-005**: 042 的"可搜索文字"（当前语言显示名与注册名路径）MUST 保持，**再并上**所有生效提供者对该格 `ItemStack` 返回的词（统一 `toLowerCase(Locale.ROOT)`）。匹配仍是 042 的"小写子串包含"。提供者**只增加词**：MUST NOT 能改变显示名、结果的排序、语法含义、高亮方式。
- **FR-006**: 提供者是否生效 MUST 由 `[compat] modLevels` 里以注册时的模组 id 为键的级别决定：未列出或 `FULL` → 生效；`GENERIC` 与 `OFF` → 不生效且不被调用（本接口没有"面板显示在对方界面上"的含义，所以 OFF 与 GENERIC 在这里相同）。配置变化 MUST 在不重启的情况下从下一次搜索起生效。
- **FR-007**: 没有任何生效的提供者时，搜索 MUST 与 042 **完全一致**：不调用任何外部代码、不新增日志、不新增每帧成本；042 的全部单元测试 MUST 不改而通过。
- **FR-008**: 对提供者返回值 MUST 做防御：`null` 视为空；丢弃空串与纯空白串；限制单次返回的词数与单词长度（上限 plan 定并写入契约）；超出部分截掉并记一条 WARN。

**稳定性与容错**

- **FR-009**: 提供者调用 MUST 被 try/catch 包住：抛异常时该物品没有额外词；同一提供者的同类错误 MUST 只记一条 WARN（含注册它的模组 id 与异常类型）；累计出错达上限（plan 定）MUST 本会话起停用该提供者并再记一条 WARN；任何提供者的故障 MUST NOT 使搜索崩溃或使 042 的匹配失效。
- **FR-010**: 稳定性承诺 MUST 写进契约：API 版本 1 的类型、方法签名与语义**不改变**；新增能力以新增方法或新的版本号提供；**不移除**已发布的版本，破坏性变更需要新的包版本与迁移说明。（宪法是否需要为"公开 API"补一条治理规则由 plan 决定。）
- **FR-011**: 提供者结果 MUST 按"`ItemStack`（物品加数据组件，不含数量）"缓存，在资源重载、该提供者被重新注册时失效；缓存 MUST 有大小上限，按提供者分开；`modLevels` 在**查询时**应用（被关掉的提供者不被调用，缓存内容不受影响，也不必因 `modLevels` 变化而清空）；MUST 保证 400 格以内每次按键重算仍在下一帧完成（SC-003）。

**依赖与范围**

- **FR-012**: 本模组 MUST NOT 新增任何运行时依赖、MUST NOT 引用任何其它模组或拼音库的类型、MUST NOT 打包第三方库；`neoforge.mods.toml` 不变；`DependencyRulesTest` 照常通过。
- **FR-013**: MUST NOT 新增服务端代码、网络包或命令；协议号 MUST 仍为 17。
- **FR-014**: `[compat] modLevels` 的说明（配置注释与悬停提示，中英文）MUST 补一句"对注册了搜索词的模组，`GENERIC`/`OFF` 表示忽略它提供的搜索词"。

**文档与测试**

- **FR-015**: MUST 产出：`contracts/search-terms-api.md`（接口契约）、开发者说明（中文，`docs/api/search-terms.md`，路径 plan 定）、`README.md`/`README_CN.md` 搜索一节补充（默认只搜当前语言名与注册名；其它模组可通过公开接口增加可搜索的文字；**不点名具体模组**）、本 feature 的 `DELIVERY.md`（已验证 / 未验证 / 已知限制 / 测试数）、`docs/plan/backpack-search.md` 的更新。
- **FR-016**: 单元测试 MUST 覆盖不依赖 Minecraft 类的纯逻辑：注册表（注册、替换、非法参数、线程安全的基本保证）、词集归一与防御（null、空、空白、超长、超量）、容错（异常、WARN 只记一次、累计停用）、`modLevels` 的判定、缓存与失效、"无提供者时与 042 一致"、与 042 语法的组合（并且、`|`、`-`、引号）、契约数值与代码常量对照。

### Key Entities *(include if feature involves data)*

- **搜索词提供者**：函数 `ItemStack → 一组字符串`；由别的模组提供，只在客户端被调用；返回的是"这个物品还可以被搜到的文字"。
- **提供者注册表**：模组 id → 提供者；线程安全；注册、替换、按 `modLevels` 过滤出当前生效的提供者。
- **提供者结果缓存**：键是 `ItemStack`（物品加数据组件，不含数量），值是归一后的小写词集合；有上限；在资源重载、该提供者被重新注册时清空；每个提供者各有一份。
- **提供者健康记录**：每个提供者的错误计数与"已警告/已停用"标记；只在会话内存里。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用假提供者，对 10 种常见物品（钻石镐、金苹果、橡木原木、圆石、面包、铁锭、红石、青金石、鞘翅、下界合金锭）各用"提供者给的中文名、英文名、全拼、首字母"四种写法搜一次，**40 次全部命中目标物品**（单元测试覆盖）。
- **SC-002**: 没有生效提供者时，042 的全部单元测试**不改而通过**，且新增测试断言"注册表为空时没有调用任何外部代码"。
- **SC-003**: 一个返回 5 个词的假提供者、400 格背包：每次按键的重算在开发机上**小于 1 毫秒量级**（以单元测试的粗略计时与游戏里无可见卡顿为准；没测就写"未度量"）；同一个物品在同一次重算里提供者最多被调用 1 次。
- **SC-004**: 提供者出错场景（异常、null、超长、超量、累计停用）**全部不崩溃**，WARN 日志每个提供者每类错误最多 1 条。
- **SC-005**: 把 `modLevels` 里某 id 改为 `GENERIC`/`OFF` 或改回 `FULL`，**不重启**，下一次搜索起提供者的词立即停用/恢复；提供者在停用期间的调用次数为 0。
- **SC-006**: 服务端与网络协议**零改动**（协议号仍 17）；`neoforge.mods.toml` 无变化；`./gradlew compileJava test` 通过；`DependencyRulesTest` 照常通过。

## Assumptions

- **职责边界**：本模组只公开并维护 API 与它的契约；别的模组是否接入、怎么接入、接入后效果如何，不属于本模组的责任，也不进入本 feature 的验收。
- 本模组的模组 id 是 `mcfloatingbackpack`，包名前缀 `pnnh.mcfloatingbackpack`；API 包名在 plan 里固定。
- 提供者返回的词是**已经展开好的**：各语言名、拼音写法等；本模组不拆分、不做拼音转换、不识别语言。
- 查询语法（并且、`|`、`-`、`"…"`）的含义归 042；`@`、`#`、`/` 前缀归 044；两者与提供者无关。
- 自动验证：游戏内验证需要一个提供者；没有真实提供者时只做单元测试与（容器里的）临时假提供者；假提供者**不进入发布 jar**，也不留在 `src/main`；游戏内验证的完整性在 DELIVERY 里如实记录。
