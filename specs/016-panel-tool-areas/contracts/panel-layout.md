# Contract: 面板布局、滚动、箭头与输入分派

## 1. 几何

单位：格子 `SLOT = 18` 像素；`PAD_X = 7`、`PAD_TOP = 17`、`PAD_BOTTOM = 7`（不变）。主区域可见 `cols`（3..9）× `rows`（≥3）。

```text
        posX
         ┌───────────────────────────────────────────────┐ posY
         │ 标题栏（拖动条，高 14，图标 + 关闭按钮）           │
         │ ┌──┬─────────────────────────────┬──┐         │ posY + PAD_TOP
         │ │左│                             │右│         │
         │ │区│          主区域              │区│         │
         │ │  │        cols × rows           │  │         │
         │ ├──┴─────────────────────────────┴──┤         │
         │ │      下区（cols + 2 格，一行）        │         │
         │ └───────────────────────────────────┘ ◢ 缩放手柄 │
         └───────────────────────────────────────────────┘
```

- 宽 = `2·PAD_X + (cols + 2)·18`；高 = `PAD_TOP + (rows + 1)·18 + PAD_BOTTOM`。
- 最小：`cols = rows = 3` → 5 列 × 4 行格子（宽 104、高 96 像素）；缩放手柄（右下角 8×8，不变）不能把面板缩到它以下。
- 缩放只改变 `cols`/`rows`；左、右区厚度恒为 1 列，下区厚度恒为 1 行，且恒贴在主区域外侧。
- 屏幕可用空间：`fitCols = (screenW − 2·PAD_X)/18 − 2`；`fitRows = (screenH − BOTTOM_HUD_MARGIN − PAD_TOP − PAD_BOTTOM)/18 − 1`；`MIN_VISIBLE_CELLS = 3` 压过屏幕过小的情况（只挤位置，不挤尺寸）。

## 2. 命中（从上到下，先到先得）

关闭按钮 → 缩放手柄 → 拖动条 → **格子命中 `PanelLayout.hit`** → 面板其余部分（消费但不处理）。已删除"滚动条命中"。

格子命中返回 `(area, 下标)`：
- `MAIN`：流程不变（见 §5）；
- `LEFT`/`RIGHT`/`BOTTOM`：见 §5；
- 填充格、箭头、面板空白：不返回格子（面板内的按下仍被消费，防止漏到下面的界面）。

## 3. 滚动

| 区域 | 方向 | 滚轮朝上 | 滚轮朝下 | 每档 |
|---|---|---|---|---|
| 主区域 | 纵向（行） | 向起点（偏移 −1） | 向终点（偏移 +1） | 1 行 |
| 左区、右区 | 纵向（格） | 同上 | 同上 | 1 格 |
| 下区 | 横向（格） | 向起点（偏移 −1） | 向终点（偏移 +1） | 1 格 |

- 作用对象：鼠标悬停的那块区域；其他区域不动。
- 悬停区域放得下全部内容、或悬停在标题栏/空白处：不滚动，但事件仍被面板消费（沿用现有行为）。
- 偏移夹取到 `[0, 最大偏移]`；缩放/容量变化后重新夹取；关闭面板复位（FR-015、FR-016）。
- 没有滚动条，也没有拖动滚动。

## 4. 箭头与颜色

- 箭头：`canBack`（偏移 > 0）与 `canForward`（偏移 < 最大偏移）各自独立；两侧都有隐藏内容则两个都画；放得下则一个都不画。
- 位置：主区域与左、右区——上边缘中点（朝上）、下边缘中点（朝下）；下区——左边缘中点（朝左）、右边缘中点（朝右）；画在区域内侧，不参与命中。
- 形状：4 条 1 像素高的 `fill` 叠成的小三角（宽 7、5、3、1），深灰色 + 一条浅色描边；常量集中在 `FloatingPanelRenderer` 顶部，游戏里调。
- 底色：主区域保持现有；左区浅蓝 `0xFFB5D3EE`；右区浅绿 `0xFFBFE5B5`；下区浅琥珀 `0xFFF0DDA0`；格子的高光/阴影边框沿用现有常量；填充格画面板底色 `0xFFC6C6C6`。
- 有物品的格子：显示物品与数量，悬停高亮，与主区域一致。

## 5. 输入分派（`FloatingPanelInput` 的格子分支）

| 命中 | 修饰键 | 结果 |
|---|---|---|
| `MAIN` | 任意 | 与 015 完成时完全一致（014 选区 → 011 Ctrl → 013 拖动 → 点击） |
| 工具区 | Shift 或 Ctrl 按着 | 按下被消费并忽略：不拿起、不放下、不转移；不改变主区域选区 |
| 工具区 | 无（含 Alt） | **立即**发 `BackpackClickPayload(area, slot, …)`（左键/右键；Alt 且无界面时 `swapHand`）；不走 013 的"松开才结算"；不清空主区域选区 |

- `PanelDragInput`、`PanelSelectionInput`、`QuickTransferInput` 用的是 `PanelSlots.indexAt`；它保留原签名，改为**只返回主区域的下标**（内部委托 `PanelLayout.hit` 并要求 `area == MAIN`），所以这三个文件**不需要修改**：拖动经过工具区的格子得到 -1，不会进入任何手势（FR-012）。
- 011/012/013/014 的请求与服务端逻辑不变，永远只面对主格子（FR-013）。

## 6. JEI 与屏幕约束

- `FloatingBackpackJeiPlugin` 读 `FloatingPanelState` 的位置与宽高，面板变大后自动包含三个工具区。
- `clampToScreen` 至少保证拖动条在屏幕内（不变）；旧配置文件里的行列偏好现在对应更大的面板，由 `layout()` 与 `clampToScreen` 兜底。
