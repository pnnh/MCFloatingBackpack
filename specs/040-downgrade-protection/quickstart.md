# Quickstart: 验证 降级保护

宪法 V：保护的行为只能在客户端会话里验证。**先 `pgrep -f "fml.modFolders=mcfloatingbackpack"`，已有客户端就不要再启动第二个；不运行专用服务器。** 建议客户端与世界 serverconfig 的 `logging.level` 设为 DEBUG。

## 自动化部分（我在实现时跑，不替代游戏里的验证）

`./gradlew compileJava test`：`RevisionGuardTest`（决策表四种结果、边界 `stored == current`、负数与 0）、`ProtectionWindowsTest`（窗口 60 秒内有效、过期无效、`consume` 后无效、别的玩家与别的背包借不到、`forgetPlayer`）、`DowngradeProtectionResourcesTest`（语言键、入口接线、`STREAM_CODEC` 没有改、协议号仍是 17、保护判定先于分配身份、锻造台 `matches` 读修订、没有新增配置与命令）。

## 一、用调试开关验证（一个客户端、一个世界；先备份世界）

造"更新版本保存的背包"：

1. `./gradlew runClient -Pmcfb.stampRevision=99`，进世界，拿一只背包，打开面板点一个格子（触发一次保存，盖章 99），放几个物品，退出。
2. **不带开关** `./gradlew runClient` 重启，进同一个世界。

- **A. 被拒并提示**：右键（或快捷键）打开那只背包：**面板不打开**，聊天里出现一条提示（写明修订 99 与当前 1、建议升级或备份、60 秒内再次打开表示接受风险），只有自己看得到；日志有 WARN。
- **B. 背包零变化**：被拒后背包的编号、内容、修订都不变（用 `/data get entity @s SelectedItem` 看组件里的 `data_revision` 仍是 99；没有被分配新身份）。
- **C. 60 秒内再次打开**：再次打开：面板正常打开，聊天一条"已接受风险"，日志 WARN；之后这只背包的修订变成 1，不再提示。
- **D. 过期**：另一次被拒后等 60 秒以上再打开：再次被拒并提示。
- **E. 别的背包借不到**：同时带两只被保护的背包：对第一只确认后，打开第二只仍被拒；确认第二只需要它自己的第二次打开。
- **F. 自动拾取**：被保护且未确认的背包（左区有自动拾取）：捡东西：物品进物品栏或掉落，**背包不被改动**，聊天里**没有**提示（刷屏），日志里最多每分钟一条 WARN。
- **G. 锻造台**：把被保护的背包放进锻造台（对应的模板与材料块）：**没有结果**；确认放行后（C）可以升级。
- **H. 面板请求**：（被拒后面板没有打开，伪造请求不好做）以"被拒后背包零变化"为准。
- **I. 不读写内容的操作**：被保护的背包仍可丢弃、放进箱子再取出、创造复制（副本修订仍是 99）。

## 二、正常情形不受影响（回归）

- **J.** 没有标记的旧背包（旧存档里的背包）：照常使用、不提示；保存后修订变成 1。
- **K.** 修订相同、修订更低、新合成的背包：不提示。
- **L.** 035～039 的功能（扩展行、隐藏行、通用扩展、快照、标签、垃圾桶、自动拾取、版本提示）逐项照常；协议号仍是 17。
- **M.** 创造模式：在创造栏里搬动一只被保护的背包再放回：已知局限，修订读作 0（记录结果，不算失败）。

## 三、真实降级实验（决定保护的有效范围；**需要你做，我不会替你操作世界**）

目的：回答 (a) `extension_rows` 是否在旧版本的下一次保存时丢失；(b) 嵌套的物品 id 旧版本没有时是丢一格还是整只背包；(c) 失败时玩家物品栏里的背包会怎样；(d) 存档是否在退出时被覆盖（研究 D1 的 H1/H2/H3）。

1. **备份**：`cp -R "run/saves/New World" ~/Desktop/NewWorld-backup`（你的 038 世界，里面有分类扩展与通用扩展、隐藏行物品的背包；没有的话先在新版本里做一只：工具区放一个食物扩展和一个通用扩展，各行里放些东西，再拿走食物扩展让一行隐藏，退出）。
2. 建旧版本的工作树（辅助脚本 `design/demo/tools/downgrade_experiment.sh`，见任务）：`git worktree add ../MCFloatingBackpack-old e1207ea`（030，早于 035；**不要用 031～034**：它们引用的 `snapshot/net` 包当年被 `.gitignore` 误忽略、从没进过 git，检出后编译不过），把世界**副本**放进它的 `run/saves/`。
3. 先 `pgrep`；在旧工作树里 `./gradlew runClient`，进副本世界：
   - 玩家物品栏里那只背包还在吗？（H3：消失）
   - 日志里有没有 `Tried to load invalid item`？
   - 背包里的内容少了什么？（H2：工具区里的扩展件、嵌套的物品）
   - 打开面板，随便点一格触发保存，退出。
4. 回到新工作树，对比退出后的存档（`level.dat`/`playerdata/<uuid>.dat` 用 NBT 工具查看）：隐藏行的物品、`extension_rows`、`data_revision`（旧版本没有这个字段）是否还在。
5. 把观察逐条写进 `specs/040-downgrade-protection/research.md` 的"实验结果"一节；如果 H3 成立，**建议另开 041**。
