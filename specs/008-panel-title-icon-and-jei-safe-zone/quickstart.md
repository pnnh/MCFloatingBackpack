# Quickstart: 008-panel-title-icon-and-jei-safe-zone

## 自动化校验（纯逻辑，不启动游戏）

```bash
./gradlew test compileJava
```

覆盖范围：标题栏图标命中测试（`hitsTitleIcon`）、`BackpackTier.byCapacity` 既有覆盖（007 已建）。不覆盖 JEI 相关行为——`FloatingBackpackJeiPlugin` 依赖 JEI 运行时环境，纯逻辑测试无法模拟 JEI 的真实渲染/布局行为。

## 客户端会话验证（宪法 V 条要求，必须实际执行）

### 第一部分：标题图标（不需要 JEI）

```bash
./gradlew runClient
```

1. 打开任意等级的浮动背包，确认标题栏显示的是图标而不是文字。
2. 把面板缩小到最窄（3 列），确认图标依然完整显示、不溢出、不裁切。
3. 鼠标悬停图标，确认弹出的提示显示正确的背包等级名称；移开后提示消失。
4. 切换到不同等级的背包，确认图标和悬停提示内容相应更新。
5. 确认 007 已交付的其它功能（缩放、关闭按钮、拖拽转移）不受影响。

### 第二部分：JEI 视觉冲突修复（需要 JEI）

```bash
./gradlew runClientCompat
```

1. 打开一个容器界面（物品栏或箱子），让 JEI 的物品列表正常显示。
2. **排除区域验证**：把浮动面板拖动到和 JEI 物品列表重叠的位置，确认 JEI 不再在面板覆盖的区域内摆放物品格子/弹出提示框（对照 spec.md US2 验收场景 1）。拖回不重叠的位置，确认 JEI 该区域恢复正常（验收场景 5）。
3. **撕裂修复验证**：把浮动面板放在**不盖住任何 JEI 物品**、但靠近 JEI 列表边缘的位置，鼠标悬停会弹出较大提示框的物品（例如名字较长、或者本身就带描述文字的物品），确认提示框背景和文字的叠放顺序一致——要么提示框整体盖住面板对应区域，要么面板整体盖住提示框，不应出现背景被挡、文字却穿透显示的撕裂画面（对照 spec.md US2 验收场景 3，也是复现这次 bug 报告的具体截图场景）。
4. 鼠标悬停浮动面板自身的标题图标、槽位等控件，确认浮动面板自己的提示正常显示，不受 JEI 影响（验收场景 2）。

### 第三部分：无 JEI 环境回归（确认软依赖没有变成硬依赖）

```bash
./gradlew runClient
```

确认不带 `-PcompatRuntime`/`runClientCompat` 的默认启动流程、日志里没有任何 JEI 相关的错误或警告，浮动背包全部功能（含标题图标）正常，和没有本功能之前的默认体验一致。

## 已知限制

- 本阶段只处理 JEI，不支持 EMI 等其它物品浏览类模组（见 spec.md Assumptions）。
- 撕裂修复（`graphics.flush()` 时机调整）是基于读 JEI 源码得出的最小改动假设，如果实测后仍有残留的撕裂画面，需要回到 research.md Decision 4 的"Alternatives considered"重新评估（例如调整事件订阅优先级），不要在这个 quickstart 之外凭感觉再加别的 flush 调用。
