# Feature Specification: 标题栏图标化 + JEI 悬浮遮挡修复

**Feature Branch**: `008-panel-title-icon-and-jei-safe-zone`

**Created**: 2026-11-03

**Status**: Draft

**Input**: User description: "007（浮动背包窗口化改造）已实现并验证完毕。测试中发现两个问题：1) 面板缩小到较窄尺寸时，标题栏按背包等级显示的文字会溢出面板边界；改为标题栏左侧显示一个背包等级图标，悬停图标时弹出 tooltip 显示背包名称，不悬停时不显示任何文字。2) 把浮动面板拖到屏幕上 JEI（Just Enough Items）物品浏览面板所在区域时，鼠标明明停在浮动面板标题栏上，JEI 仍会弹出自己的物品 tooltip，与浮动面板视觉重叠；需要让 JEI 在浮动面板覆盖的区域内不再弹出 tooltip / 不摆放物品格子。这是可选的 JEI 兼容性增强，不能成为硬依赖，没装 JEI 的玩家不受影响。"

> **020 说明**：020 起对第三方模组的主动兼容由客户端配置 `config/mcfloatingbackpack-client.toml` 里的 `compat.modLevels`（每条 `模组id=档位`，FULL/GENERIC/OFF，默认空即全部 FULL）控制，在游戏"模组"列表里可打开配置界面。本文里的 JEI 避让就是目前唯一的"模组专用适配"：FULL 时避让，`jei=GENERIC`（或 OFF）时不避让，改配置无需重启；`FULL` 是专用适配（开启我们为该模组写的专有代码，主动兼容、可视为功能增强）；`GENERIC` 是没有专用适配（关闭这些专有代码，没写过的模组与 FULL 一样），**不决定**面板能否显示、能否与它的菜单 Ctrl+点击转移（取决于该模组自己的实现）；`OFF` 是面板不显示（与该模组的界面二选一，聊天里会有提示）。原版容器不可配置。详见 `specs/020-compat-switches/`。本文其余内容保持写作当时的原样。

## Clarifications

### Session 2026-11-03

- Q: 玩家反馈了另一种情况——浮动面板并没有盖住 JEI 的物品格子，但鼠标悬停 JEI 物品后弹出的提示框范围延伸到了浮动面板下方，此时出现"提示框背景被浮动面板挡住、但提示文字却穿透显示在浮动面板之上"的画面撕裂（背景和文字各自呈现不同的前后顺序）。这个场景要和 US2 一起修复吗？ → A: 要一起修复，属于同一个"浮动面板不应该和第三方物品浏览模组的提示框产生视觉冲突"目标下的另一种触发方式——上一种是"面板盖住了物品格子导致提示框被错误触发"，这一种是"提示框本身的范围越界到了面板区域导致撕裂"，根因不同（前者是鼠标位置判定问题，后者更像是渲染顺序问题：第三方模组很可能把提示框的背景和文字拆成了两次独立绘制、分别排在不同时机，浮动面板的绘制恰好夹在两者中间），具体修复点需要在实现阶段确认，但对外的行为要求是一致的：不能出现背景和文字各自不同叠放顺序的撕裂画面，无论是提示框整体显示在面板之上、还是面板整体显示在提示框之上，二选一保持一致即可。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 标题栏改为图标，不再溢出 (Priority: P1)

玩家把浮动面板缩小到比较窄的尺寸后，发现原本按背包等级显示的标题文字（例如"下界合金浮动背包"）会超出面板边界，显示错位、很难看。玩家希望标题栏改成一个小图标来标识当前背包等级，想知道具体名称时把鼠标移上去看一下就行，不需要始终占地方显示一整行文字。

**Why this priority**: 这是一个已确认会在正常使用中出现的视觉缺陷（面板越小越容易触发），影响对 007 已交付功能的观感，优先级最高。

**Independent Test**: 打开任意等级的浮动背包，把面板缩小到最窄（3 列），确认标题栏不再出现文字溢出；鼠标悬停在标题栏左侧图标上，确认弹出的提示文字显示该背包等级的名称；移开鼠标后提示消失，标题栏只剩图标。

**Acceptance Scenarios**:

1. **Given** 浮动面板已打开，**When** 面板渲染标题栏，**Then** 标题栏左侧显示一个代表当前背包等级的小图标，不再显示背包等级的文字名称。
2. **Given** 面板被缩小到最窄的可调尺寸，**When** 面板重新渲染，**Then** 标题栏内容（图标）始终完整显示在面板边界内，不发生溢出或裁切异常。
3. **Given** 玩家将鼠标移动到标题栏的图标上，**When** 鼠标停留在图标范围内，**Then** 系统显示一个提示框，内容为该背包等级的名称（即原先标题文字的内容）。
4. **Given** 鼠标提示框正在显示，**When** 玩家将鼠标移出图标范围，**Then** 提示框消失，标题栏恢复为只显示图标。
5. **Given** 玩家切换到另一个不同等级的浮动背包，**When** 面板重新渲染标题栏，**Then** 图标与悬停提示文字都相应更新为新背包的等级。

---

### User Story 2 - 浮动面板不与 JEI 的提示框产生视觉冲突 (Priority: P2)

玩家安装了 JEI（物品浏览）这类可选的第三方辅助模组时，会在两种情况下遇到浮动面板和 JEI 提示框叠在一起、看着很乱的问题：一是把浮动面板拖动到 JEI 自己的物品列表所在屏幕区域后，即使鼠标明明停留在浮动面板上，JEI 仍然会弹出它自己的物品提示框；二是浮动面板根本没有盖住任何 JEI 物品，但玩家鼠标悬停在 JEI 物品上弹出的提示框范围延伸到了浮动面板所在位置，导致提示框和面板画面相互穿插、部分内容显示错乱（例如提示框背景被面板挡住、但提示文字却穿透显示在面板之上）。玩家希望不管是哪种触发方式，浮动面板和 JEI 的提示框都不应该产生这种视觉冲突。

**Why this priority**: 只在玩家主动安装了 JEI 这类可选工具时才会出现，属于锦上添花的兼容性打磨，优先级低于 P1 的既有缺陷修复，且本身就是可选增强。

**Independent Test**: 在同时安装了 JEI 的开发/联调环境下，打开一个容器界面并显示 JEI 物品列表：(a) 把浮动面板拖动到和 JEI 列表重叠的位置，确认 JEI 不再在浮动面板覆盖的区域内弹出提示框；(b) 把浮动面板放在不盖住任何 JEI 物品、但靠近 JEI 列表边缘的位置，鼠标悬停会弹出较大提示框的 JEI 物品，确认提示框不会和浮动面板发生背景/文字各自不同叠放顺序的撕裂画面。在未安装 JEI 的环境下验证浮动背包功能和启动流程不受影响。

**Acceptance Scenarios**:

1. **Given** 玩家安装了 JEI 且其物品列表正在显示，**When** 玩家把浮动面板拖动到与 JEI 物品列表重叠的位置，**Then** 浮动面板覆盖的屏幕区域内不再出现 JEI 自己的物品提示框。
2. **Given** 同样的重叠场景，**When** 玩家将鼠标悬停在浮动面板自身的图标、槽位或其它控件上，**Then** 浮动面板自身的提示（如 User Story 1 的标题图标提示）正常显示，不受 JEI 影响。
3. **Given** 浮动面板并未盖住任何 JEI 物品格子，**When** 玩家悬停某个 JEI 物品、其弹出的提示框范围与浮动面板所在区域发生重叠，**Then** 提示框的背景和文字必须以一致的前后顺序显示（要么提示框整体盖住面板对应区域，要么面板整体盖住提示框对应区域），不得出现背景被挡住而文字仍穿透显示的撕裂画面。
4. **Given** 玩家的运行环境没有安装 JEI，**When** 玩家正常使用浮动背包的全部现有功能（打开、拖拽、缩放、关闭等），**Then** 行为与安装本功能之前完全一致，没有新增的错误、警告或性能影响。
5. **Given** 玩家拖动浮动面板远离 JEI 物品列表区域，**When** 面板不再与该区域重叠，**Then** JEI 在该区域恢复正常显示物品和提示，不受影响。

---

### Edge Cases

- 面板被缩小到最窄尺寸（3 列）时，标题栏图标本身的显示位置和大小需要保证不越出面板边界，即便此时面板整体宽度很小。
- 玩家快速连续切换背包等级（例如先后打开不同等级的背包）时，标题栏图标和悬停提示内容要随之同步更新，不残留上一个背包的图标或文字。
- 已安装 JEI 的环境下，浮动面板当前不可见（已关闭）时，JEI 对应区域不应被当作"被遮挡"，即该区域的物品列表和提示应正常显示，不受已关闭面板位置的影响。
- 浮动面板与 JEI 物品列表区域只有部分重叠（而非完全覆盖）时，只有实际被面板覆盖的那部分区域不弹出 JEI 提示，未被覆盖的部分应保持正常可用。
- 浮动面板没有盖住任何 JEI 物品格子，但某个 JEI 物品的提示框因为内容较长/位置靠近面板而在弹出时与面板区域重叠：不得出现提示框背景和文字分别呈现不同叠放顺序的撕裂画面。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须将浮动面板标题栏的内容从文字改为一个代表当前背包等级的小图标。
- **FR-002**: 标题栏图标必须在面板任意允许的尺寸（含最窄尺寸）下完整显示在面板边界内，不发生溢出或裁切。
- **FR-003**: 当玩家将鼠标悬停在标题栏图标上时，系统必须显示一个提示框，内容为当前背包等级的名称。
- **FR-004**: 当玩家将鼠标移出标题栏图标范围时，系统必须隐藏该提示框。
- **FR-005**: 当玩家切换到不同等级的浮动背包时，标题栏图标与对应的悬停提示内容必须同步更新为新背包的等级。
- **FR-006**: 当玩家安装了 JEI 这类提供物品浏览面板的可选第三方模组，且该模组的物品列表或提示框与浮动面板发生屏幕区域重叠时，系统必须让浮动面板覆盖的区域内不再出现该模组自己的提示框。
- **FR-007**: 第三方模组对浮动面板覆盖区域的避让，必须随浮动面板的位置、尺寸、可见性实时变化：面板移动、缩放或关闭后，对应屏幕区域的避让范围必须相应更新或解除。
- **FR-008**: 对第三方物品浏览模组的避让必须是可选增强：玩家未安装该模组时，浮动背包的全部现有功能和启动流程不得受到任何影响，不得因此引入新的错误或硬性依赖。
- **FR-009**: 浮动面板自身的交互（标题图标提示、槽位、关闭按钮、缩放手柄等）不受本功能影响，必须继续按 007 已验证的行为正常工作。
- **FR-010**: 当第三方物品浏览模组弹出的提示框范围与浮动面板发生重叠时（无论触发原因是面板盖住了物品格子，还是提示框本身延伸到了面板区域），提示框的背景与文字必须保持一致的前后叠放顺序，不得出现背景被遮挡、文字却仍穿透显示的撕裂画面。

### Key Entities

- **标题栏显示状态**：标题栏当前应显示的图标来源（对应背包等级）与悬停提示文字，随当前打开的背包等级变化。
- **面板遮挡区域**：浮动面板当前在屏幕上占据的矩形范围（含可见性），作为告知第三方物品浏览模组"此处已被遮挡"的依据。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 玩家在任意允许的面板尺寸下都看不到标题栏文字溢出或裁切现象。
- **SC-002**: 玩家悬停标题栏图标后，能在合理的反应时间内看到对应背包等级的名称提示。
- **SC-003**: 在安装了 JEI 的环境下，浮动面板覆盖的屏幕区域内不再出现 JEI 自己弹出的物品提示框。
- **SC-004**: 在未安装 JEI 的环境下，浮动背包的启动与全部现有功能表现与本功能交付前完全一致。
- **SC-005**: 浮动面板移动或缩放后，第三方模组的避让区域能在玩家下一次与该区域交互前就已经更新到位，不出现明显滞后导致的短暂重叠提示。
- **SC-006**: 即使浮动面板没有盖住任何第三方模组的物品格子，玩家也不会看到该模组提示框背景和文字各自呈现不同叠放顺序的撕裂画面。

## Assumptions

- "第三方物品浏览模组"在本阶段特指 JEI；若后续需要支持 EMI 等其它类似模组，留待新的 feature 规划，不在本阶段范围内。
- 标题栏图标的具体像素尺寸、位置细节属于实现阶段的视觉设计决定，本 spec 只约束"必须是图标而非文字、必须悬停可见名称、必须不溢出"这几条行为要求。
- 悬停提示框的样式复用玩家已经熟悉的原版物品悬停提示观感，不需要额外的自定义视觉设计。
- JEI 避让仅在 JEI 处于运行环境中时生效；"合理的反应时间"与"不出现明显滞后"对标玩家对原版 UI 响应速度的日常观感，不需要额外的数值化性能指标。
- FR-010 描述的撕裂问题，根因很可能是浮动面板与 JEI 提示框各自渲染调用在同一帧内的先后顺序问题，而不是鼠标位置判定问题；具体是调整浮动面板自身的渲染时机/顺序，还是需要依赖 JEI 提供的其它接口，属于技术方案层面的决定，留给 `/speckit-plan` 阶段的 research.md 确认，不在本 spec 里预设具体做法。
