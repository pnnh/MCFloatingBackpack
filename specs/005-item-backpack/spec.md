# Feature Specification: 背包道具化（门禁 / 胸甲背负 / 开发 JEI）

**Feature Branch**: `005-item-backpack`

**Created**: 2026-10-25

**Status**: Draft

**Input**: User description: "初步实现浮动背包道具化（A/C/E）：背包成为可获得物品，持有或装备后才可打开；库存绑定物品实例并丢弃玩家 Attachment；可放入胸甲栏并第三人称可见背负；开发调试用 JEI 仅 runClient。多等级合成/锻造与 OP 指令延后。docs/plan 仅作演进参考。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 无道具则无法打开 (Priority: P1)

玩家进入世界后，若物品栏、双手与胸甲栏都没有浮动背包物品，按默认快捷键（B）不能打开浮动面板；界面可给出简短提示（如 actionbar）。只有拥有该物品后，快捷键才生效。

**Why this priority**: 游戏性门禁是本特征相对旧「人人可按 B」行为的核心差异。

**Independent Test**: 新档空手按 B → 不开；创造取出一只皮革浮动背包到主手后再按 B → 可开。

**Acceptance Scenarios**:

1. **Given** 玩家没有任何浮动背包物品，**When** 按下切换快捷键，**Then** 浮动面板不打开，且有一次可见提示说明需要背包。
2. **Given** 玩家主手持有浮动背包，**When** 按下切换快捷键，**Then** 浮动面板打开或关闭（切换）。
3. **Given** 面板已打开且玩家把最后一只背包从身上全部移除（含胸甲），**When** 下一 tick / 下次交互校验，**Then** 面板关闭或拒绝继续操作，且不能在无背包时继续取放。

---

### User Story 2 - 主手右键与物品栏内快捷键打开 (Priority: P1)

主手持有浮动背包时可右键切换浮动面板。背包在物品栏（含快捷栏）中时，也可按快捷键打开。若身上有多只浮动背包，按固定扫描顺序取第一只作为当前实例：主手 → 副手 → 胸甲栏 → 快捷栏 0–8 → 背包格 9–35。

**Why this priority**: 覆盖生存向「先合成再使用」的主要打开路径。

**Independent Test**: 主手右键开关；背包仅在槽位 12 时按 B 打开；主手与槽位各有一只时始终打开主手那只。

**Acceptance Scenarios**:

1. **Given** 主手持有浮动背包且未打开其它阻塞交互，**When** 玩家右键使用该物品，**Then** 浮动面板切换显示，不打开独占背包 Screen。
2. **Given** 仅物品栏某格有浮动背包、双手与胸甲皆无，**When** 按快捷键，**Then** 打开该格对应实例的面板。
3. **Given** 主手与背包格各有一只浮动背包，**When** 按快捷键，**Then** 绑定主手实例（扫描顺序第一）。

---

### User Story 3 - 库存随背包物品走 (Priority: P1)

浮动背包的格子内容保存在该物品实例上。放入箱子、丢在地上、换手或给其他玩家后，内容仍在该物品中。玩家身上不再有「全局免费背包」。旧版写在玩家身上的 Attachment 库存本特征直接丢弃，不做迁移。

**Why this priority**: 道具化的数据正确性；无此则门禁只是皮肤。

**Independent Test**: 向面板放入物品 → 把背包丢地上再捡起 → 重开面板内容一致；新世界无旧全局背包残留。

**Acceptance Scenarios**:

1. **Given** 某浮动背包内已有物品，**When** 玩家将其丢弃再捡起并打开，**Then** 内容与丢弃前一致。
2. **Given** 浮动背包放入箱子，**When** 另一玩家（或同一玩家）取出后打开，**Then** 仍看到原内容。
3. **Given** 旧开发档曾使用玩家 Attachment 背包，**When** 加载本特征后的模组，**Then** 不再出现该 Attachment 库存；需通过获得新背包物品使用。

---

### User Story 4 - 胸甲栏装备与第三人称背负 (Priority: P2)

浮动背包可以像胸甲一样装备到胸甲栏（与普通胸甲互斥）。装备后，第三人称（含 F5）能看到玩家背上的背包外观（允许简易占位模型）。**【009 修订】** 占位模型已被取代：现在背上渲染的是五档各自的雕刻网格模型（见 009），不再是占位。装备在胸甲栏时，快捷键可打开该实例。

**Why this priority**: 无 Curios 时的背负可见性替代方案，便于调模型与展示。

**Independent Test**: 将背包移入胸甲栏 → F5 见背部模型 → 按 B 打开该背包 → 卸下后无其它背包则不能再开。

**Acceptance Scenarios**:

1. **Given** 玩家手持浮动背包，**When** 将其装备到胸甲栏，**Then** 胸甲槽显示该物品，原胸甲被替换/卸下（原版装备规则）。
2. **Given** 胸甲栏已装备浮动背包，**When** 切换到第三人称，**Then** 能看见背部背包外形（非完全隐形）。
3. **Given** 仅胸甲栏有浮动背包，**When** 按快捷键，**Then** 打开该实例面板。

---

### User Story 5 - 开发环境可有 JEI，发布无硬依赖 (Priority: P3)

开发者使用 `runClient` 启动时，可加载 JEI 以便在创造/JEI 界面查找并取出浮动背包。正式发布的模组包不要求玩家安装 JEI 或其它物品管理器即可游玩；未安装 JEI 时模组照常启动。

**Why this priority**: 降低调试成本，且不违背「正式零硬依赖」原则。

**Independent Test**: 开发 runClient 中 JEI 可用且能搜到浮动背包；默认发布依赖检查不含 required JEI。

**Acceptance Scenarios**:

1. **Given** 开发用客户端运行配置，**When** 进入世界并打开 JEI，**Then** 能搜索到本模组浮动背包物品。
2. **Given** 未安装 JEI 的环境只安装本模组，**When** 启动游戏，**Then** 本模组正常加载，无因缺少 JEI 而崩溃。

---

### Edge Cases

- 打开面板期间背包从当前解析槽位移走（扔出/被抢/换胸甲）：下次点击或快捷键校验失败时关闭面板并提示。
- 右键使用主手背包时，若正在瞄准可交互方块：遵循原版「优先方块交互 / 或 Shift」惯例——默认瞄准方块时不打开面板，潜行右键或未瞄准方块时打开（写入 Assumptions）。
- 面板仍仅在适合操作的 GUI 上下文中可用（与既有「容器 Screen 打开时才显示浮动面板」行为对齐，除非本特征明确放宽；默认保持既有行为）。
- 多只背包内容互不共享；快捷键只操作扫描到的第一只。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供可获得的「皮革浮动背包」物品（创造可取；生存至少有一条基础合成配方）。
- **FR-002**: 系统 MUST 在玩家未持有任何浮动背包物品（双手、胸甲、物品栏皆无）时拒绝快捷键打开浮动面板。
- **FR-003**: 系统 MUST 允许主手持有浮动背包时通过右键切换浮动面板（不替换为独占 Screen）。
- **FR-004**: 系统 MUST 允许在物品栏或胸甲栏存在浮动背包时用快捷键打开，并按扫描顺序主手 → 副手 → 胸甲 → 快捷栏 0–8 → 9–35 选择唯一当前实例。
- **FR-005**: 系统 MUST 将浮动背包主仓内容保存在该物品实例上，容量本期固定为 36 格；服务端权威校验所有取放。
- **FR-006**: 系统 MUST 移除基于玩家 Attachment 的全局背包存储，且 MUST NOT 迁移旧 Attachment 数据。
- **FR-007**: 系统 MUST 允许将浮动背包装备到胸甲栏，并在第三人称渲染背部外观。
- **FR-008**: 系统 MUST 在正式发布依赖中不将 JEI 设为必需；开发客户端运行配置 MAY 包含 JEI 以便取物。
- **FR-009**: 系统 MUST 保持浮动面板为 Overlay，可与其它容器界面共存（既有 001–004 行为不回退为独占 Screen）。
- **FR-010**: 网络层 MUST 标明当前操作的背包来源位置（手/胸甲/物品栏下标），服务端 MUST 验证该位置仍为浮动背包后再改库存。

### Key Entities

- **FloatingBackpackItem**：玩家可获得的背包物品；可装备于胸甲栏；内含主仓。
- **BackpackContents**：绑定在单个物品实例上的格子列表（本期 36）与面板光标状态（若仍使用面板光标）。
- **BackpackRef**：解析结果——指向玩家身上某一具体物品位置，供打开与点击使用。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 测试员在无背包时按快捷键 100% 无法打开面板；获得背包后 100% 能打开。
- **SC-002**: 装有物品的背包经丢弃→捡起或箱存→取出后，打开面板内容一致（抽样至少 5 格含堆叠）。
- **SC-003**: 胸甲装备后，第三人称下目视可确认背部有背包外形（占位模型可接受）。**【009 修订】** 现为雕刻网格模型，不再是占位，该条判定标准不变。
- **SC-004**: 未安装 JEI 时模组可单独启动进入世界；开发 runClient 下可用 JEI 找到该物品。
- **SC-005**: 既有「浮动 Overlay + 与原版容器互拖」主路径在道具化后仍可用（打开条件改为持有背包）。

## Assumptions

- 本期只实现**皮革**一档物品，主仓 **36** 格（4×9）。更高等级格子表仅作预留（见下），不注册多物品、不做锻造升级。
- 预留等级主仓（后续特征）：皮革 36 / 铁 54 / 金 72 / 钻石 90 / 下界合金 108。
- 不实现功能升级、左右侧栏、Curios、OP 管理指令（见 Out of Scope）。
- `docs/plan/` 中的远期设想不构成本特征强制范围。
- 右键打开：未瞄准可交互方块时右键切换面板；瞄准方块时走原版方块交互。
- 保留既有「主要在容器 Screen 打开时展示浮动面板」的客户端行为，除非实现中发现与右键打开冲突再单开澄清。
- 提供一条简单生存合成配方，便于无 JEI 时验收；创造物品栏也可直接取出。
- 背负外观允许白盒/低模；视觉精修不在本期成功标准内。
- 旧世界 Attachment 数据直接丢弃；模组尚未对外发布，无需迁移。

## Out of Scope

- 铁 / 金 / 钻石 / 下界合金多物品与合成或锻造升级链（规划 **B**，延后）。
- OP 管理员指令按玩家名 / 背包 ID 打开（规划 **D**，延后）。
- 功能升级（磁铁、拾取、虚空等）、旅行者式左右侧栏。
- Curios / Trinkets 背部槽集成。
- Attachment → 物品的数据迁移工具。
- JEI 作为正式发布硬依赖或强制推荐依赖。
- 高精度多皮肤背包模型与主题能力。
