# Feature Specification: 背包搜索核心

**Feature Branch**: `042-backpack-search-core`

**Created**: 2026-11-12

**Status**: Draft

**Input**: 用户确认（2026-11-12）的搜索方案，全文见 `docs/plan/backpack-search.md`（第 1、2、3 节的基础语法部分、第 5、6 节）：在浮动面板标题栏放一个放大镜，点击后标题栏变成搜索框，实时过滤主区域并高亮命中格子；基础语法照 JEI（空格并且、`|` 或、`-` 排除、`"…"` 整段）。服务端与网络协议不改（协议号仍 17）。

## 背景与已确认的决策

背包到 108 格加上扩展行后，按名字找东西只能靠肉眼和滚动。本 feature 先做"搜索核心"：标题栏的放大镜与搜索框、实时过滤、命中高亮、基础语法。拼音与多语言（043）、`@模组`、`#标签`、`/hidden`（044）是后续 feature，本 feature 只留好接口、不实现。

已确认的决策（用户，2026-11-12，**不重新讨论**）：

1. **放大镜**在标题栏右侧、快照键左边。点击后，**背包图标右边到右端整段变成搜索框**；背包图标保留，仍是拖动面板的把手；编号、放大镜、快照键在搜索时隐藏；搜索框右端内嵌 `×`（清除）与命中数。
2. **3 列（最小尺寸）时去掉关闭键**（B 键、Esc 已能关闭面板）；其它宽度保留。
3. **实时过滤**，不用回车。键盘规则沿用 018 的标签文本框：有焦点时吞键（B、E、T、Delete 等不触发其它功能），Ctrl+V 粘贴；与标签框不同的是**字符不设限**，中文输入法上屏的字可以进。
4. **Esc 清空并关掉搜索框**；**点结果格子后焦点离开搜索框**（B、E 等恢复可用），文字与结果保留，靠 `×` 清除。
5. 搜索状态**只存在于会话**：关闭面板或退出世界就清空（面板只是被隐藏、没有关闭时保留，见边缘情形）。
6. 主区域：格子映射改为"命中的格子"，紧凑地从左上角排起，滚动按结果行数算；**空格子不显示、不能往没显示的空位放东西**。
7. **区分标识**：命中格子画一圈与 Shift 选框（黄色）**不同颜色**的边框，搜索框边框同色。
8. 左、右、下三个工具区：**只高亮命中格子，不过滤**。
9. 分类扩展行、通用扩展行的格子在主区域里，命中就混在结果中，**保留各自的行底色**。
10. **结果集只在"查询变化"与"面板重开"时重算**：从结果里拿走一组物品后，那格变空但**仍留在原位置显示**；把物品放回就回到原来的格子。
11. **查询变化清空选区**。
12. Shift 选区、Ctrl 移动、Alt 换左手、Delete、双击聚拢等与平时一致（它们按背包格子编号工作，不关心格子画在哪）。
13. 基础语法：空格 = 并且，`|` = 或，`-` 前缀 = 排除，`"…"` 整段；匹配**当前语言的显示名（含改过名的物品）与物品注册名**，大小写不敏感。
14. 放大镜原计划是新贴图；plan 阶段读代码发现关闭键、快照键都是用代码画的、仓库没有 gui 贴图，所以放大镜**用代码绘制、不新增贴图**（见 research D4）；完成后仍按宪法 VI 度量一次图集（现 2048×1024）作回归确认。

## Out of Scope（本阶段不做）

- 拼音与多语言匹配（en_us、zh_cn 名字、PinIn、`search.chinese` 配置）——043。
- `@模组`、`#标签`、`/hidden`（含只读的隐藏行物品格子）、未知指令提示——044。
- Ctrl/Cmd+F 打开搜索；搜索历史；整理（排序、归位）。
- 往没显示的空位放东西、"自动找空位放回"（要新增服务端动作）；服务端与网络协议的任何改动。
- 工具区与扩展行以外的界面（标签总览、黑名单页、快照界面）里的搜索。

## 已查证的事实（读本仓库源码；规格要尊重）

- 面板主区域 3 列时总宽 104 像素（`PanelLayout.width`：左右边距各 7，主区域列数加两侧各一列、每格 18）。标题栏现状：背包（档位）图标在 x=4～20，编号文字从 x=23 起，快照键与关闭键各 10 像素宽、间隔 2、关闭键距右边 3。
- 整个标题栏现在都是拖动把手（`hitsDragBar`），点击关闭键在拖动判定之前处理。
- 点击、选区、Ctrl 转移、Alt 换左手、Delete 发给服务端的都是**背包格子编号**与区域；面板上"第几行第几列对应哪个格子编号"只是客户端的映射。
- Shift 选区的高亮色是黄色（`0xFFFFD34D`）。
- 018 的标签文本框只接受小写字母、数字、`_` 等标签字符，且有长度上限；搜索框需要自己的输入规则（字符不设限）。
- 分类扩展行、通用扩展行的格子在主区域的格子编号空间里（基础容量之后）；隐藏行不在其中（044 才处理）。

## 尚未验证（plan 阶段先查证；验证前不得声称已满足）

- 拖拽分配（013）与双击聚拢在搜索结果里的范围：聚拢是服务端按全背包找，是否会动到没显示的格子，plan 阶段读代码确认；若会，决定是限制还是写进已知限制。
- 窗口很窄、GUI 缩放很大时标题栏各元素的实际像素位置（用布局算术的单元测试加游戏里截图确认）。
- 输入法：中文上屏的字能否经字符事件进入搜索框，容器里的 xdotool 可能无法验证，必要时由用户在真机上验证。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 在背包里按名字找东西 (Priority: P1)

玩家在背包里有几十种物品，想快速找到"钻石镐"之类的东西。点标题栏的放大镜，打字，主区域立刻只剩下名字里含这几个字的物品，命中的格子带彩色边框；找到后点进去拿走。

**Why this priority**: 这就是搜索功能本身，没有它其余都没有意义。

**Independent Test**: 背包放 20 种物品，点放大镜，输入"pick"：主区域只显示名字含 pick 的物品（各种镐），带高亮边框，搜索框右端显示命中数；按 Esc：搜索框关闭，主区域恢复原样。

**Acceptance Scenarios**:

1. **Given** 面板打开，标题栏有放大镜，**When** 点放大镜，**Then** 背包图标右边整段变成搜索框并获得焦点；编号与快照键隐藏；放大镜消失；关闭键按宽度规则保留或不画。
2. **Given** 搜索框有焦点，**When** 每输入或删除一个字符，**Then** 主区域立即按当前文字重算并显示结果，不需要回车。
3. **Given** 搜索框里有文字，**When** 按 Esc，**Then** 文字清空、搜索框关闭、标题栏恢复，主区域恢复完整显示；面板本身不关闭。
4. **Given** 搜索框有文字，**When** 点 `×`，**Then** 同 Esc 的效果。
5. **Given** 搜索框打开但文字为空，**Then** 不过滤、不高亮，主区域与平时一样。
6. **Given** 搜索框有焦点，**When** 输入 `b`、`e`、`t` 或按 Delete，**Then** 它们是搜索框里的字符或编辑键，不触发关闭面板、开物品栏、聊天或删除物品。
7. **Given** 搜索框有焦点，**When** 按 Ctrl+V（macOS Cmd+V），**Then** 剪贴板文字粘贴进搜索框并实时搜索。

### User Story 2 - 窄面板（3 列）也能用 (Priority: P1)

玩家把面板缩到最窄（主区域 3 列，104 像素宽）。标题栏仍能放下放大镜；搜索时仍能打字、看到命中数、清除；面板仍能拖动。

**Why this priority**: 用户明确担心窄面板；不处理好，最小尺寸下搜索不可用或面板拖不动。

**Independent Test**: 缩到 3 列：标题栏右端是 `[放大镜][快照]`、没有关闭键，编号在左边仍有地方；点放大镜，搜索框占背包图标右边到右端；按住背包图标拖动，面板跟着动；Esc 或 `×` 退出搜索。

**Acceptance Scenarios**:

1. **Given** 面板 3 列，**When** 看标题栏，**Then** 没有关闭键；右端从左到右依次是放大镜、快照键（快照键贴着面板右边缘）；编号文字在它们左边仍有不少于 24 像素宽的位置，放不下时按现有规则截断并有悬停提示。
2. **Given** 面板 4 列及以上，**Then** 关闭键照旧显示，放大镜在快照键左边；搜索时搜索框止于关闭键左边。
3. **Given** 面板 3 列且在搜索，**Then** 搜索框从背包图标右边起一直到右端，可见文字区加 `×` 加（有位置时的）命中数；位置不够时命中数先让位（不显示，悬停搜索框可看到命中数），`×` 与文字区不让位。
4. **Given** 搜索中，**When** 按住背包图标拖动，**Then** 面板整体移动（搜索框以外、关闭键以外的标题栏部分仍是拖动把手；3 列时就是背包图标那一小块）；点在搜索框内是定位光标，不拖动。
5. **Given** 面板在拖动大小（缩放）时，**Then** 搜索状态保持，标题栏按新宽度重新排布，结果按新列数重新排列。
6. **Given** 面板 3 列没有关闭键，**Then** B 键与 Esc 仍能关闭面板（Esc 在搜索框有焦点时先用来退出搜索，见 FR-010）。

### User Story 3 - 在结果里照常操作 (Priority: P1)

玩家搜到物品后：点起来放到光标、右键拿一半、Shift 选一批、Ctrl 点转移到别处、Alt 点和主手互换、Delete 丢进垃圾桶、双击聚拢——都和没搜索时一样。

**Why this priority**: 搜索是为了"找到并用"；如果结果里的格子不能照常操作，搜索就只是个展示。

**Independent Test**: 搜出 3 个格子，对每一格分别做上述操作，结果与不搜索时点同一格完全一致（落到服务端的格子编号相同）。

**Acceptance Scenarios**:

1. **Given** 结果里显示着背包第 37 格的钻石镐，**When** 点它，**Then** 与不搜索时点第 37 格效果相同：钻石镐到光标。
2. **Given** 结果里有若干格，**When** 按住 Shift 点或拖过结果格子，**Then** 选中的是这些格子对应的背包格子，选框用黄色画在它们上面；与命中高亮边框可以同时看到（选中状态优先显示在内圈，命中边框在外圈，plan 定具体画法）。
3. **Given** 选中了结果里的几格，**When** Ctrl 点其中一格（或其它既有的转移操作），**Then** 与不搜索时一样转移选区对应的格子。
4. **Given** 结果里的一格，**When** Alt 点击，**Then** 与主手物品互换（与平时一样）。
5. **Given** 鼠标悬停在结果里的一格上，**When** 按 Delete，**Then** 那一格整栈进垃圾桶（与平时一样）。
6. **Given** 光标上有物品，**When** 点结果里一个有物品的格子，**Then** 合并或交换（与平时一样）；点空位（留位格子）则放入该格（见 User Story 5）。
7. **Given** 搜索框有文字，**When** 查询发生变化（含清除），**Then** 选区清空。
8. **Given** 光标上有物品，**When** 点结果区域里**没有格子的空白处**，**Then** 什么都不发生（不丢弃、不放入）。

### User Story 4 - 结果和原来的主区域不会搞混 (Priority: P2)

玩家看一眼就知道"现在显示的是搜索结果、不是完整背包"，也看得出工具区和扩展行里哪些格子命中。

**Why this priority**: 结果是从左上紧凑排起的，位置和原来的不一样；没有标识会让人以为东西"搬家了"。

**Independent Test**: 搜索时主区域命中格有高亮边框，搜索框边框同色；工具区里名字命中的格子（如自动拾取、垃圾桶）也有同色边框；扩展行里命中的格子出现在结果中且保留该行底色。

**Acceptance Scenarios**:

1. **Given** 有非空查询，**Then** 主区域每个有物品的命中格有一圈高亮边框，颜色与 Shift 选框的黄色明显不同；搜索框边框同色；框内右端显示命中数（主区域里当前有物品的命中格数）。
2. **Given** 有非空查询，**When** 左、右、下工具区里的某格物品名字命中，**Then** 那一格画同色边框；工具区的格子**不**被隐藏、位置不变。
3. **Given** 背包有食物扩展行与通用扩展行，查询命中其中的物品，**Then** 这些物品的格子混在主区域结果里，保留各自的行底色（食物行、通用行的底色），因此能看出它来自哪个扩展行。
4. **Given** 查询没有任何命中，**Then** 主区域不显示任何格子（或显示统一的"无结果"提示——plan 定），命中数为 0，搜索框边框仍是搜索色；`×` 与 Esc 照常可用。
5. **Given** 查询为空，**Then** 没有任何高亮与过滤。

### User Story 5 - 拿走再放回仍在原位 (Priority: P2)

玩家从结果里拿走一组物品，格子变空；想了想又放回去，物品回到原来的那个格子，而不是消失在不可见的位置。

**Why this priority**: 用户明确要求；否则拿起物品后版面跳动、放不回去。

**Independent Test**: 搜出一格 64 个圆石，点起来（光标上有 64 个圆石，那一格留成空位仍显示在原处）；点那个空位：圆石回到同一个背包格子。

**Acceptance Scenarios**:

1. **Given** 结果里有一格物品，**When** 把整栈拿到光标上，**Then** 那一格变空但仍显示在原位置（空位，不高亮），结果的排列没有移动；命中数减一。
2. **Given** 上述空位，**When** 把光标上的物品点在空位上，**Then** 物品放回同一个背包格子（与不搜索时点那个空格效果相同）。
3. **Given** 结果里有一个留位的空格，**When** 查询变化或关闭再打开面板，**Then** 结果集重算，空位消失（只显示当前真正命中的物品）。
4. **Given** 光标上有物品，**When** 查询变化使留位空格不再显示，**Then** 光标上的物品照常留在光标上；玩家可以清除搜索、让完整主区域回来再放入（本 feature 不提供"自动找空位"）。
5. **Given** 其它方式使背包内容变化（Ctrl 点物品栏里的物品转入背包、自动拾取、别处操作），**Then** 已显示的结果格子内容照常更新，但**新出现**的、本来会命中的格子不会自动加入结果，直到查询改动或面板重开。

### User Story 6 - 基础搜索语法 (Priority: P3)

玩家用几个词、或者"或"、"排除"、整段名字来缩小范围：`iron pick`（两词都含）、`iron|gold`（任一）、`-planks`（排除）、`"oak log"`（整段）。

**Why this priority**: 常用但可后置；先有 P1 的单词搜索就能用。

**Independent Test**: 背包里有 Oak Log、Stripped Oak Log、Oak Planks、Spruce Log、Iron Axe、Gold Axe：`oak log` → Oak Log 与 Stripped Oak Log；`"oak log"` → 同上（整段连续）；`log -stripped` → Oak Log、Spruce Log；`iron|gold` → 两把斧；`-planks` → 除 Oak Planks 以外的全部。

**Acceptance Scenarios**:

1. **Given** 查询由空格隔开的多个词，**Then** 物品必须同时满足每个词（并且）；词序无关；多词名字（如 Oak Log）用其中的词即可找到。
2. **Given** 一个词里含 `|`（如 `iron|gold`），**Then** 满足其中任一部分即可；空的部分（`iron|`）被忽略。
3. **Given** 词以 `-` 开头（如 `-planks`），**Then** 名字含该部分的物品被排除；只有排除词时，结果是"其余全部有物品的格子"；`-` 单独一个或 `-` 后面是空，被忽略。
4. **Given** 用双引号括起一段（如 `"oak log"`），**Then** 它是一个整体，必须按顺序连续出现（含空格）；引号里的空格与 `|`、`-` 都是普通字符；`-"oak log"` 表示排除这整段。
5. **Given** 引号没有闭合，**Then** 从开引号到查询末尾按一个整段处理，不报错。
6. **Given** 查询里的 `@`、`#`、开头的 `/`，**Then** 本 feature 把它们当普通字符（044 才赋予含义）。
7. **Given** 大小写不同（`PICK`、`Pick`），**Then** 结果相同；匹配范围是物品当前语言的显示名（含改过名的物品名）和物品注册名的路径部分（如 `diamond_pickaxe`），在其中做子串匹配。

### Edge Cases

- **搜索框空文字**：显示占位提示（如"搜索…"），不过滤；点 `×` 或按 Esc 关闭。
- **焦点离开后**：点任一结果格子、面板其它非输入区域，焦点离开搜索框；结果与文字保留，搜索框仍显示（有文字与 `×`），此时 B、E、T 等照常；再点搜索框回到编辑。
- **Esc 的分工**：搜索框有焦点时，Esc 只用来清空并关闭搜索框，不关面板；焦点不在搜索框时 Esc 照旧（关闭面板等），关闭面板即清空搜索。
- **B 键**：搜索框有焦点时 `b` 是字符；焦点离开后 B 照旧关闭面板（并清空搜索）。
- **面板被隐藏而不是关闭**：019 的宿主界面让位、020 配置为 OFF 的界面、聊天等界面期间面板只是隐藏，搜索状态保留；面板真正关闭（关闭键、B、Esc、退出世界、背包被拿走）才清空。
- **切换背包（按 B 打开另一只背包）**：当作面板关闭再打开，搜索清空。
- **背包内容在面板打开期间被别人改变**（多人、自动拾取）：已显示的结果格子内容更新；新命中的不自动加入（User Story 5.5）。
- **结果比可见行数少/多**：少时多余的位置不画格子（或画成与现有"填充格"相同的外观，plan 定）；多时出现滚动，滚动位置在查询变化时回到顶部。
- **改变面板大小**：搜索保持，按新列数重排结果；滚动位置夹到合法范围。
- **查询很长**：长度上限 100 个字符，超过的输入被忽略；显示时超出框宽的部分左侧截断，始终能看到光标附近。
- **只有排除词**（`-planks`）：见 US6.3；没有物品的格子不作为结果。
- **名字完全相同的多个格子**：各自是结果里的一格，按背包格子编号顺序排列。
- **扩展行的格子被拿走/行被隐藏**：行隐藏后其中的物品不再属于主区域格子，从结果中消失（044 的 `/hidden` 才能再看到它们）。
- **光标上有物品时打字搜索**：允许；光标上的物品不受影响。
- **标签面板、垃圾桶面板、黑名单页展开时**：搜索与它们并存；标签面板按选区显示，选区因查询变化清空，所以回到"请先选择物品"的状态。
- **搜索框打开时点放大镜的位置**：放大镜此时不显示；该位置属于搜索框。

## Requirements *(mandatory)*

### Functional Requirements

**标题栏与搜索框**

- **FR-001**: 标题栏 MUST 在快照键左边提供放大镜按钮（10×10 像素，悬停提示"搜索"，中英文）；点击后打开搜索框并给它焦点。
- **FR-002**: 搜索框打开时，标题栏 MUST 保留背包图标，图标右边到"关闭键左边（有关闭键时）或面板右边缘内侧（无关闭键时）"整段为搜索框；编号、放大镜、快照键隐藏；框内右端依次是命中数（空间足够时）与 `×`。
- **FR-003**: 面板为最小宽度（主区域 3 列）时 MUST 不显示关闭键；更宽时 MUST 显示。标题栏元素从右到左的让位优先级：关闭键 > 放大镜 > 快照键 > 编号；任何宽度下放大镜都必须可用（3 列时一定放得下）。
- **FR-004**: 面板 MUST 仍可通过标题栏拖动：搜索时，背包图标与搜索框、关闭键之外的标题栏部分是拖动把手；点击在搜索框内 MUST 只做光标定位、不拖动面板；放大镜与 `×` 点击不拖动。
- **FR-005**: 搜索框 MUST 实时过滤：每次文字变化立即重算结果，不需要回车。
- **FR-006**: 搜索框的输入规则：有焦点时 MUST 吞掉键盘事件（字符、退格、删除、方向键、Home/End、Ctrl+V 粘贴、Ctrl+A 全选等编辑键；B、E、T、Delete 等不得触发面板或游戏的其它功能）；字符不设限（含中文等任意可打印字符）；长度上限 100 个字符；没有焦点时 MUST 不拦截键盘。
- **FR-006a**: 搜索框的焦点规则：点放大镜获得焦点；点搜索框内获得焦点；点击搜索框以外的面板区域（含结果格子）时焦点离开、文字与结果保留；焦点离开后搜索框仍显示。
- **FR-007**: 搜索框空文字时 MUST 不过滤、不高亮，并显示占位提示。

**关闭与清除**

- **FR-008**: 搜索框有焦点时按 Esc，或点 `×`，MUST 清空文字、关闭搜索框、恢复完整主区域，且清空选区；此时 Esc MUST NOT 关闭面板。
- **FR-009**: 搜索状态（是否打开、文字、焦点、结果集、滚动）MUST 只存在于客户端会话；面板关闭、切换背包、退出世界时 MUST 清空；面板仅被隐藏（019 宿主让位、020 的 OFF 界面、聊天等）时 MUST 保留。
- **FR-010**: 焦点不在搜索框时，Esc 与 B 的既有行为 MUST 不变（关闭面板，随之清空搜索）。

**结果集与主区域显示**

- **FR-011**: 非空查询下，主区域 MUST 只显示"结果集"中的格子，从左上角起按背包格子编号升序紧凑排列；排列、滚动（行数 = 结果格数按列数向上取整）、滚动条/箭头沿用现有主区域的方式；查询变化时滚动回到顶部。
- **FR-012**: 命中判定：只有有物品的格子可以命中；空格子 MUST NOT 命中、MUST NOT 显示（留位格子除外，见 FR-014）。命中范围是主区域的格子，包括分类扩展行与通用扩展行里的格子（已显示的行；隐藏行不在其中）。
- **FR-013**: 命中格子 MUST 画一圈与 Shift 选框不同色的高亮边框；搜索框边框 MUST 同色；框内命中数 = 主区域里当前有物品的结果格数。扩展行里的格子 MUST 保留各自的行底色。
- **FR-014**: 结果集 MUST 只在以下时刻重算：查询变化、面板（重新）打开；面板大小改变只重新排列已有的结果集，不重算集合。从结果里拿走物品使一格变空时，该格 MUST 仍显示在原位置（留位，不高亮），点击它与不搜索时点那个空格效果完全相同（落到同一个背包格子）。
- **FR-015**: 背包内容因其它原因变化（转入、自动拾取、别人的操作）时，已在结果集里的格子 MUST 更新内容；新命中的格子 MUST NOT 自动加入，直到下一次重算。

**工具区**

- **FR-016**: 非空查询下，左、右、下三个工具区里名字命中的格子 MUST 画同色高亮边框；三个区 MUST NOT 被过滤、位置与行为不变。

**操作一致性**

- **FR-017**: 结果里的格子上的一切既有操作 MUST 与不搜索时对同一背包格子的操作完全一致，发往服务端的格子编号与区域相同：左右键点击、Shift 选区（含拖过多格）、Ctrl 转移、Alt（macOS Option）与主手互换、Delete 键、拖拽分配、双击聚拢、与光标物品的合并与交换。服务端 MUST 不改动，协议号 MUST 仍为 17。
- **FR-018**: 查询发生任何变化（含清空）时，选区 MUST 清空；选区 MUST 只含当前显示的格子编号。
- **FR-019**: 没有格子的空白处（结果区里没有格子的位置）被点击时 MUST 什么都不发生，光标上的物品保持不动。

**语法与匹配**

- **FR-020**: 查询按空格分成若干"项"，所有项 MUST 同时满足（并且）；一项内用 `|` 分成若干"备选"，满足任一即可；备选以 `-` 开头表示"名字不得包含其后的文字"；用双引号括起的一段是整体（其中的空格、`|`、开头的 `-` 都是普通字符，`-` 放在引号前表示排除整段）；引号未闭合时从开引号到末尾按整段处理。
- **FR-021**: 匹配 MUST 对物品的**当前语言显示名**（包含玩家改过名的物品的名字）和**物品注册名的路径部分**做不区分大小写的子串匹配；`@`、`#`、开头的 `/` 在本 feature 中是普通字符。
- **FR-022**: 空的项或备选（连续空格、`iron|`、单独的 `-`）MUST 被忽略；整条查询在忽略之后没有任何有效项时，等同于空查询（不过滤、不高亮）。只有排除项的查询，其结果是"所有有物品的格子中不被排除的"。

**图集、日志、文档**

- **FR-023**: 放大镜 MUST 用代码绘制（与快照键、关闭键一样，不新增贴图），风格与它们一致；完成后 MUST 按宪法 VI 用 `design/demo/tools/check_atlas_budget.sh` 度量图集（现 2048×1024），结果记进 DELIVERY，度量不了就写"未度量"。
- **FR-024**: MUST 提供中英文语言键（悬停提示"搜索"、"清除"、占位提示、命中数的悬停提示），语言键的两种语言 MUST 齐全且一致。
- **FR-025**: MUST NOT 新增服务端代码、网络包、配置项或命令；MUST NOT 增加运行时依赖。
- **FR-026**: 文档 MUST 更新：`README.md` 与 `README_CN.md`（搜索的用法与语法）、`docs/MCFloatingBackpack.md` 里面板说明处、`docs/plan/backpack-search.md`（状态改为 042 已规格/已实现）、本 feature 的 `DELIVERY.md`（中文，写明已验证/未验证/已知限制/测试数）。

### Key Entities *(include if feature involves data)*

- **搜索会话状态**：是否打开、查询文字、焦点、光标位置、结果集（有序的背包格子编号列表，含留位格子）、滚动位置；只存在于客户端会话，不进背包数据。
- **查询**：由"项"组成，项由"备选"组成，备选是"（可选的排除标记）+ 文字或整段"；纯数据结构，解析与匹配不依赖 Minecraft 类。
- **结果映射**：主区域"第几行第几列 → 背包格子编号"在搜索时的替代映射；无搜索时是恒等映射。
- **标题栏布局**：在给定面板宽度、是否有关闭键、是否在搜索的条件下，各元素（背包图标、编号区、放大镜、快照键、关闭键、搜索框、`×`、命中数）的位置与是否显示；纯算术。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 背包有 20 种以上物品时，玩家点放大镜、输入一个词，主区域在**下一帧内**只剩命中的物品（400 格以内的背包，肉眼无延迟）。
- **SC-002**: 面板缩到 3 列时，放大镜、搜索框、`×`、拖动、Esc 退出五件事**全部可用**，标题栏没有元素重叠或超出面板边缘（单元测试覆盖各宽度的布局算术，游戏里截图确认 3、4、9 列）。
- **SC-003**: 搜索结果里的格子上，第三个用户故事列出的 8 类操作（点击、右键、Shift 选区、Ctrl 转移、Alt、Delete、拖拽分配、双击聚拢）与不搜索时对**同一背包格子**的结果 **100% 一致**（发往服务端的格子编号相同）。
- **SC-004**: 从结果里拿走一整栈再放回，物品回到**原来的格子**（0 次落到别的格子或丢失）；查询变化时选区 **100%** 清空。
- **SC-005**: 搜索状态**不进入存档**（背包数据 0 字节增加），关闭面板或退出世界后 100% 清空，面板仅隐藏期间 100% 保留。
- **SC-006**: 基础语法的 6 种写法（单词、多词并且、`|` 或、`-` 排除、`"…"` 整段、大小写不同）在单元测试里有用例且全部通过；`@`、`#`、`/` 当普通字符也有用例。
- **SC-007**: 服务端与网络协议**零改动**（协议号仍 17，协议相关测试照常通过）；`./gradlew compileJava test` 通过。
- **SC-008**: 加入放大镜后（不新增贴图），共用方块图集仍为 **2048×1024**（度量记录在 DELIVERY）；没度量就写"未度量"，不声称通过。

## Assumptions

- 命中数只数"主区域里当前有物品的结果格"，工具区的命中高亮不计入。
- 搜索框的光标闪烁、选择、粘贴等编辑行为复用 018 标签文本框的编辑模型思路（光标、退格、方向键），但字符规则、长度与显示独立；具体复用方式留给 plan。
- 高亮边框的具体颜色在游戏里对照 Shift 选框后定（要求明显不同于黄色、在三种底色——主区域灰、扩展行底色、工具区底色——上都看得清）。
- "无结果"时主区域显示空白或统一提示，二者都可接受，plan 选一种。
- 本 feature 不改变"没有搜索时"的任何行为：关闭搜索后主区域、选区、滚动与 042 之前一致；有了关闭键的宽度规则变化（3 列去掉关闭键）是本 feature 唯一对非搜索场景的可见改动。
- 拼音、多语言名字、`@模组`、`#标签`、`/hidden` 的接口（查询项的"类型"）在设计时留扩展点，但本 feature 的代码里只有"词"这一种项，不为它们写任何实现或空壳。
- 容器自动验证里无法输入中文时，中文输入相关项写"未验证"，由用户在真机上确认。
