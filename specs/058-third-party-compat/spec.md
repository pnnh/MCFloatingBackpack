# Feature Specification: 第三方模组版本管理与集成终端主动兼容（面板 → 终端）

**Feature Branch**: `058-third-party-compat`

**Created**: 2026-11-20

**Status**: Draft

**Input**: 用户（2026-11-20）要求把精妙存储与集成终端加为可选运行时依赖，并分析能否为它们做主动兼容（Ctrl+拖动/点击快速存入、取出）；分析与全部决策记在 [docs/plan/third-party-compat.md](../../docs/plan/third-party-compat.md)（**不重新讨论**）。相关：012（通用的打开容器递送路径）、033/034/052（已有的可选第三方依赖）、057（登录提示与服务端配置的写法）。

## Clarifications

### Session 2026-11-20（方案阶段，用户已确认）

- Q: 集成终端先做哪个方向？ → A: 先做**面板 → 终端**；**终端 → 面板**以后另开 feature（060），集成终端与 AE2 的反向一起做。
- Q: 集成终端支持哪些页？ → A: 只做**物品存储页**；合成页、末影箱页、别的成分（流体、能量等）都不做。
- Q: 精妙存储要不要写代码？ → A: 不要。012 的通用路径已能双向使用（容器里验证过），058 只写文档。
- Q: AE2 呢？ → A: 058 只写文档：面板 → ME 终端靠通用路径已可用（容器里验证过）；终端 → 面板未验证、预计不可用，留给 060；AE2 不进版本范围表、不写专门代码。
- Q: 第三方版本怎么管？ → A: 在**我们自己的代码里**维护一张"第三方模组 → 受支持版本段列表"的范围表，**不**用 `neoforge.mods.toml` 的版本范围（读加载器源码证实：已安装的可选依赖版本不在范围里会让游戏起不来）。
- Q: 版本段是一段还是多段？ → A: 多段，段之间可以有空隙。我们只对做过验证的版本做主动兼容；硬依赖只有 Minecraft 1.21.1 与 NeoForge 21.1.251 及以上。
- Q: 版本在范围外怎么办？ → A: 该模组的主动兼容**不启用**（只剩通用路径），并警告：服务器日志一条 WARN，管理员（op 权限玩家）每次登录一条聊天提示。另有服务端配置项让管理员明知风险时强制启用，配置注释写明风险并提醒先备份。
- Q: 范围内但第三方 API 真的变了呢？ → A: 兼容代码入口兜底：第一次出错就在本次运行里关闭该兼容，记 ERROR 日志并通知在线管理员；物品不丢；不用反射探测。
- Q: "管理员"指谁？ → A: 拥有 op 权限的玩家（专用服务器上 `/op` 过的，单人游戏里开了作弊的）；专用服务器控制台只有日志。

## 背景

现状（已核对，读 012 的通用路径与容器里的验证记录）：

- 012 的通用路径对任意第三方界面都做同一件事：面板 → 容器时，服务端把物品临时放进玩家物品栏的一格，再调用当前界面自己的"Shift+点击物品栏"处理；容器 → 面板时，点击容器自己的格子。**两个方向都只对"有真格子、且服务端完成转移"的界面有效。**
- **精妙存储**（1.6.13）：双向可用。**AE2**（19.2.20）：面板 → ME 终端可用（容器里验证过），反向没验证。
- **集成终端**（1.11.2）：通用路径两个方向都无效（无害：什么也不移，物品留在面板里）。原因：它的存储页在服务端不处理"Shift+点击物品栏"，真正的移动由终端客户端发包驱动；网络里的物品也不是真格子。只有读源码的证据，游戏里还没搭网络验证过。
- 目前的可选第三方依赖（Curios、Accessories、LambDynamicLights 等）在 `neoforge.mods.toml` 里写了**下限**；这在加载器里是硬性的（版本更旧会拒绝加载）。给第三方模组写上限则更危险：玩家装了更新的版本，游戏直接起不来。
- 仓库里没有任何记录第三方模组"我们验证过哪些版本"的地方；第三方模组更新很频繁，新版本的 API 随时可能变。

本 feature 做三件事：**管得住**（一张版本范围表 + 范围外的警告与开关 + 出错兜底，以后每个第三方主动兼容都复用）、**用得上**（集成终端：Ctrl+点击/拖动面板里的物品存入终端当前页的物品网络）、**说得清**（README 与交付记录写明每个第三方模组哪个方向可用、哪个没验证）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 第三方模组版本不在已验证范围时，管理员被及时告知（Priority: P1）

服主给服务器装了一个比我们验证过的更新的集成终端。服务器启动时日志里出现一条警告，说明这个模组装的是哪个版本、我们只验证过哪些版本段、它比所有段都高、主动兼容没有启用。服主（op 玩家）进服时聊天里也收到同样意思的一条提示，并说明面板在它的界面上仍然能用，只是"存入终端"这类主动兼容没开。普通玩家什么也看不到。

**Why this priority**: 版本管理是这个 feature 的基础设施，也是 US2 的前提：没有它，主动兼容要么在不兼容的版本上硬跑，要么靠加载器的版本范围把游戏弄得起不来。

**Independent Test**: 用调试开关把某个第三方模组"伪造"成范围外的版本，启动一个世界：核对日志里的警告、op 玩家登录时的聊天提示、非 op 玩家没有提示、主动兼容没有启用；再伪造成范围内，核对一切正常、没有警告。

**Acceptance Scenarios**:

1. **Given** 表里某个模组已安装，版本落在某一个受支持的版本段内，**When** 服务器启动、op 玩家登录，**Then** 没有任何警告，主动兼容启用。
2. **Given** 已安装版本比表里所有版本段的下限都低，**When** 服务器启动，**Then** 日志出现一条 WARN：模组名、已装版本、受支持的全部版本段、"低于所有受支持版本"、"主动兼容未启用"。
3. **Given** 已安装版本比所有版本段的上限都高，**When** 服务器启动，**Then** 同上，说法为"高于所有受支持版本"。
4. **Given** 表里某个模组有两个不相邻的版本段，已安装版本落在两段之间的空隙里，**When** 服务器启动，**Then** 同上，说法为"落在两个受支持版本段之间"，并列出两个版本段。
5. **Given** 有范围外的已装模组，**When** op 权限玩家登录，**Then** 聊天里对每个范围外的模组收到一条提示（人话版，含"面板在它的界面上仍可用，只是主动兼容没启用"）；**每次登录**都发。
6. **Given** 同上，**When** 没有 op 权限的玩家登录（或单人游戏没开作弊），**Then** 聊天里没有任何提示；专用服务器控制台只有日志。
7. **Given** 表里的某个模组没有安装，**When** 服务器启动、玩家登录，**Then** 不检查、不提示、不写日志。
8. **Given** 已装版本的字符串里没有任何数字，**When** 检查，**Then** 视为范围外，警告里说明"无法判断版本"。

### User Story 2 - 在集成终端界面上，Ctrl+点击/拖动面板里的物品把它存入终端的物品网络（Priority: P1）

玩家打开集成动力学网络的终端部件，进入物品存储页，按 `B` 打开浮动背包面板（它叠在终端界面上）。他 Ctrl+点击面板里的圆石：圆石从背包里消失，进入网络的存储，终端的物品网格里随即出现它。拖动多个物品也一样。如果网络存不下（满了、离线），物品原样留在背包里。

**Why this priority**: 这是玩家直接看得见的功能，也是用户提出的目标。

**Independent Test**: 在容器里搭一个集成动力学网络（线缆 + 带物品的箱子/接口 + 终端部件），验证存入、存不下、离线、合成页与末影箱页五种情形（见验收场景）。

**Acceptance Scenarios**:

1. **Given** 终端当前在物品存储页，网络有空位，**When** 玩家 Ctrl+点击面板里的一组物品，**Then** 这组物品（或能放下的部分）从背包扣掉，进入网络；终端网格里出现它们；背包扣掉的数量 + 剩余 = 原数量。
2. **Given** 网络只能放下一部分，**When** 存入，**Then** 放不下的那部分仍在背包里，数量守恒。
3. **Given** 网络离线、没有存储，或通道不可用，**When** 存入，**Then** 物品原样留在背包里，不报错、不丢，玩家物品栏不受影响。
4. **Given** 终端当前在合成页或末影箱页，**When** Ctrl+点击面板里的物品，**Then** 不做特殊处理，沿用通用路径（无效果、无害）。
5. **Given** 终端当前页不是物品成分（流体、能量等），**When** Ctrl+点击，**Then** 同上，不做特殊处理。
6. **Given** 当前界面不是集成终端（例如箱子、精妙存储、AE2 终端），**When** Ctrl+点击，**Then** 行为与 058 之前完全一致（通用路径）。
7. **Given** 集成终端的版本在范围外（且没有被配置强制启用），**When** Ctrl+点击，**Then** 不做特殊处理，沿用通用路径，并且 US1 的警告已经发出过。

### User Story 3 - 范围外时，管理员明知风险可以强制启用主动兼容（Priority: P2）

服主知道自己装的集成终端比我们验证过的新，愿意承担风险。他在服务端配置里把"允许未验证版本"打开，重开世界。范围外的集成终端的主动兼容照常启用，但警告照旧出现，并明确写着"已被配置强制启用，风险自负"。配置文件的注释里写明：第三方 API 变了我们的代码可能出错、严重时让服务器崩溃，启用前请先备份存档，出问题先改回关闭。

**Why this priority**: 逃生口：我们的版本范围表总是落后于第三方的更新，服主不该只能干等。

**Independent Test**: 伪造范围外版本，配置设为 `true`：主动兼容启用、日志与聊天警告说"强制启用"；设回 `false`：关闭。

**Acceptance Scenarios**:

1. **Given** 配置项默认值，**When** 查看生成的配置文件，**Then** 该项为 `false`，注释里有"备份"与"可能崩溃"的风险说明、"出问题先改回 false"、"改动需重开世界"。
2. **Given** 配置为 `true`、已装版本在范围外，**When** 服务器启动、op 登录，**Then** 主动兼容启用；日志与聊天里的警告照常出现，措辞为"已被配置强制启用"。
3. **Given** 配置为 `true`、已装版本在范围内，**When** 服务器启动，**Then** 没有警告（范围内就是受支持）。

---

### User Story 4 - 第三方 API 真的变了，也不让服务器崩溃或丢物品（Priority: P2）

范围内（或被强制启用）的某个集成终端版本，内部 API 与我们编译时用的不一致（方法找不到、类找不到）。玩家第一次 Ctrl+点击时我们的兼容代码出错。此时：这一次操作不丢物品；该兼容在本次运行里被关闭；服务器日志写一条 ERROR（含异常）；在线的 op 玩家收到一条聊天说明。之后同类操作回到通用路径（无效果、无害）。服务器不崩溃。

**Why this priority**: 版本范围只能挡住"版本号看起来不对"，挡不住"次版本悄悄改了 API"。

**Independent Test**: 在测试里让桥抛出 `RuntimeException`/`LinkageError`，核对：物品未丢、第二次不再调用桥、日志与通知各一次。

**Acceptance Scenarios**:

1. **Given** 桥在存入时抛出运行时异常或链接错误，**When** 玩家 Ctrl+点击，**Then** 物品留在背包（原样）、桥被关闭、ERROR 日志一条、在线 op 玩家各收到一条聊天。
2. **Given** 桥已被关闭，**When** 再次 Ctrl+点击，**Then** 不再调用桥，沿用通用路径，**不重复**写 ERROR 或发聊天。
3. **Given** 关闭只在本次运行有效，**When** 重启服务器，**Then** 兼容按版本范围重新判断（可能再次启用）。

---

### User Story 5 - README 与交付记录说清每个第三方模组的支持情况（Priority: P2）

玩家和服主读 README 的兼容说明，能看到：精妙存储面板 ↔ 容器两个方向都可用（通用路径）；AE2 面板 → ME 终端可用（通用路径），反向未验证、预计不可用；集成终端面板 → 终端可用（主动兼容，只限物品存储页，受支持版本段列出），反向暂不支持。DELIVERY 记录哪些是在游戏里验证过的，哪些只有源码依据。

**Why this priority**: 兼容说明错了会误导玩家；并且需要有测试把文档与代码里的范围表对齐，防止漂移。

**Independent Test**: 读 README / README_CN 的兼容表与范围表，数字一致；对齐测试通过。

**Acceptance Scenarios**:

1. **Given** README 与 README_CN，**When** 读兼容说明，**Then** 精妙存储、AE2、集成终端三行的支持情况与方向与上面一致；集成终端一行列出受支持的版本段。
2. **Given** 范围表改了版本段，**When** 跑测试而 README 的兼容表没跟着改，**Then** 测试失败，指出不一致处。
3. **Given** DELIVERY，**When** 读验证记录，**Then** 集成终端的游戏内验证结果、精妙存储与 AE2 的通用路径验证、AE2 反向未验证，分别写明。

### Edge Cases

- 两个必需的辅助模组（集成动力学、公共能力）版本在范围外，而集成终端本身在范围内：整个集成终端兼容按"范围外"处理，警告里点明是哪个模组、哪个版本。
- 版本字符串带构建元数据或预发布后缀（`9.5.1+1.21.1`、`1.1.0-beta.54+1.21.1`）：只按前面的数字比较，后缀忽略；`1.12.0-beta` 与 `1.12.0` 在比较中相同（都不在 `[1.11.0, 1.12.0)` 内）。
- 版本段边界：下限包含、上限不含（`1.11.0` 在 `[1.11.0, 1.12.0)` 内，`1.12.0` 不在）。
- 玩家在存入过程中断线、切换维度、网络在存入瞬间被拆掉：桥只在服务端同步完成一次插入，返回剩余；失败时物品留在背包，不丢不重复。
- 终端界面打开时玩家切换了页（物品存储页 ↔ 合成页）：每次存入时重新判断当前页。
- 同一个 Ctrl+拖动一次提交多个物品：逐个按相同规则处理，每个独立守恒。
- 配置项在服务器运行中被修改：不生效，下次打开世界生效（与 057 的配置一致）。
- 客户端没有装集成终端而服务端装了（或反之）：客户端不改；面板的使用不依赖客户端是否装了该模组，主动兼容只在服务端存在。
- 范围外的模组很多（以后表里有很多行）：每个模组一条日志、每次登录每个模组一条聊天；不合并，不刷屏的处理留给以后表真的变大再做。
- 单人游戏：同一个进程既是服务端也是客户端；管理员判断与专用服务器一致（需开作弊）。
- 主动兼容被关闭或不适用时，012 的通用路径照旧工作，不因为本 feature 变慢或变坏。

## Requirements *(mandatory)*

### Functional Requirements

**版本范围表与检查（US1）**

- **FR-001**: 系统 MUST 维护一张"第三方模组 → 受支持版本段列表"的范围表，作为主动兼容受支持版本的**唯一事实来源**。每个版本段为 `[下限（含）, 上限（不含）)`；同一模组可有多段，段之间允许有空隙；同一模组的各段 MUST 按升序、互不重叠，且每段下限小于上限。
- **FR-002**: 范围表的每一行 MUST 能声明"同时要求的其它模组"，各自也带一组版本段；任一被要求的模组已装但不在其范围内，视为该行整体范围外，警告中指明是哪个模组。
- **FR-003**: 范围表的每一行 MUST 预留一个可选的"变体"标识，供以后同一模组不同版本段用不同适配代码时使用；本 feature 只有一个变体，不做按变体分派。
- **FR-004**: 版本字符串 MUST 被宽松解析：取开头的数字段按从左到右的数字比较；预发布后缀与构建元数据 MUST 被忽略；能正确处理 `1.11.2`、`9.5.1+1.21.1`、`1.1.0-beta.54+1.21.1`、`21.1.22`；没有任何数字的版本 MUST 被视为"无法判断"并归入范围外，警告里说明这一点。
- **FR-005**: 检查结果 MUST 区分四种：**在范围内**；**低于所有版本段**；**高于所有版本段**；**落在两个版本段之间的空隙里**。后三种为范围外，提示文字 MUST 各用不同的说法，并列出该模组的全部受支持版本段。
- **FR-006**: 没有安装的模组 MUST NOT 被检查，也 MUST NOT 产生任何日志或提示。
- **FR-007**: 服务器启动时，系统 MUST 对表里每个已安装的模组检查一次；每个范围外的模组 MUST 写一条 WARN 日志，含：模组显示名、已装版本、全部受支持版本段、四种结果中的哪一种、主动兼容是"未启用"还是"被配置强制启用"。
- **FR-008**: 拥有 op 权限的玩家（权限等级至少 2；单人游戏需开作弊）每次登录时，系统 MUST 对每个范围外的模组发一条聊天提示，内容与日志对应的人话版，并说明面板在该模组的界面上仍可用、只是主动兼容没有启用（强制启用时改为风险提示）。没有 op 权限的玩家 MUST NOT 收到这类提示；专用服务器控制台只有日志。
- **FR-009**: 范围外且未被配置强制启用时，该模组的主动兼容 MUST NOT 启用；012 的通用路径 MUST 保持不变。
- **FR-010**: 所有提示文字 MUST 走语言文件，中文与英文两份；日志与聊天里的版本号、模组名按实际值填入。

**强制启用开关（US3）**

- **FR-011**: 系统 MUST 提供一个服务端配置项"允许未验证版本"（`[compat]` 段、布尔、默认 `false`）。为 `true` 时，范围外的模组主动兼容照常启用，FR-007、FR-008 的警告照旧发出，措辞为"已被配置强制启用"。
- **FR-012**: 该配置项的注释 MUST 写明：第三方模组 API 变化后我们的代码可能出错，严重时让服务器崩溃；启用前应先备份存档；出问题请先改回 `false`；改动需重开世界。该配置在服务器启动时读取一次。

**出错兜底（US4）**

- **FR-013**: 每个第三方适配器的入口 MUST 捕获链接错误（方法/类缺失、不兼容的类变更）与适配器自己的运行时异常。捕获后 MUST：本次运行内关闭该兼容；写一条 ERROR 日志（含异常）；给在线的 op 玩家各发一条聊天；本次操作中的物品 MUST NOT 丢失、MUST NOT 重复。
- **FR-014**: 兼容已被关闭后，系统 MUST NOT 再调用该适配器，MUST NOT 重复写 ERROR 或重复发聊天；关闭状态只在本次运行有效，重启后按版本范围重新判断。
- **FR-015**: 兜底 MUST NOT 使用反射或启动时的特性探测。

**集成终端：面板 → 终端（US2）**

- **FR-016**: 服务端递送路径（把背包物品送入当前打开的第三方容器界面）MUST 在原有的通用路径之前，询问一组已注册的"网络存储桥"：若有桥认得当前界面且当前页受支持，则由桥完成存入，**不**停放物品、**不**调用界面自己的快速移动；否则 MUST 走原有通用路径。桥的接口为以后的"终端 → 面板"预留取出方法，但本 feature 不实现取出。
- **FR-017**: 集成终端的桥 MUST 只在以下条件**全部**满足时认领：当前界面是集成终端的存储类界面；当前页是服务端的"成分"页且成分为**物品**；当前页不是合成页，也不是末影箱页。
- **FR-018**: 桥的存入 MUST 对当前页所选通道的物品网络做一次插入，返回没放进去的剩余部分；网络离线、没有存储、通道不可用时 MUST 原样返回全部物品；MUST NOT 触碰玩家物品栏。
- **FR-019**: 存入的守恒 MUST 成立：背包扣掉的数量 = 进入网络的数量；剩余 = 原数量 − 进入网络的数量；任何失败路径下物品留在背包，不丢、不重复。
- **FR-020**: 服务端 MUST 沿用 012 已有的校验（界面是服务端当前打开的界面、背包是 `B` 键打开的那只、数量与位置合法）；桥只是替换"如何把物品放进容器"这一步。
- **FR-021**: 终端界面里的物品网格 MUST 因集成终端自己的同步机制看到存入的物品，我们 MUST NOT 为此新增网络包；客户端 MUST NOT 改动。
- **FR-022**: 集成终端桥的版本门 MUST 同时覆盖集成终端、集成动力学、公共能力三个模组；初版受支持版本段：集成终端 `[1.11.0, 1.12.0)`；集成动力学与公共能力各取开发时验证过的主.次版本构成的窄段（实现时按验证过的版本定）。以后验证了新版本就**加一段**，不要求改旧段。
- **FR-023**: 第三方模组的类型 MUST 只出现在专门的集成终端兼容包里，主代码其余部分 MUST NOT 引用；对第三方的编译依赖 MUST 为仅编译、不传递，且 MUST NOT 进入发布的 jar；其结构约束由现有的依赖规则测试覆盖（这四个模组的坐标都在已被规则列入的 Modrinth 组下，规则无需改，补一条测试证明新增的坐标被它检查到）。

**加载声明与防漂移（US1、US5）**

- **FR-024**: `neoforge.mods.toml` 里 MUST 为集成终端、集成动力学、公共能力、Cyclops 核心各加一条**可选**依赖声明，版本范围一律为 `[0,)`；范围的上限与下限只在我们自己的范围表里。
- **FR-025**: 系统 MUST 提供自动测试，保证：(a) `neoforge.mods.toml` 里范围表涉及的模组都是可选依赖且版本范围为 `[0,)`；(b) README 与 README_CN 的兼容表与范围表一致；(c) `build.gradle` 里这些模组的开发依赖版本落在对应版本段内。
- **FR-026**: 系统 MUST 提供一个调试开关，把指定第三方模组的"已装版本"伪造成给定值（写法沿用已有的 VersionDebug），用于在游戏里验证范围外的警告与关闭；该开关 MUST NOT 在发布版里默认起作用。

**文档与验证记录（US5）**

- **FR-027**: README 与 README_CN MUST 加兼容说明表：精妙存储面板 ↔ 容器双向可用（通用路径）；AE2 面板 → ME 终端可用（通用路径）、反向未验证预计不可用；集成终端面板 → 终端可用（主动兼容，仅物品存储页，列出受支持版本段）、反向暂不支持。兼容说明里还 MUST 如实写一句：按模组的档位（`modLevels`）是客户端配置；在专用服务器上，容器物品交换、Curios/Accessories 的背着来源和集成终端的存入这些服务端部分，暂时无法单独关闭（按模组的服务端档位留给 059）。
- **FR-028**: DELIVERY MUST 写清楚：哪些结论在游戏里验证过（精妙存储双向、AE2 正向、集成终端正向）、哪些只有源码依据或未验证（AE2 反向、集成终端的流体等其它页）。

**兼容档位（宪法 VII）**

- **FR-030**: 集成终端属于宪法 VII 的第 2 档（规格点名的知名模组），档位设置沿用客户端配置里"模组 → FULL/GENERIC/OFF"：**OFF** 仍然让面板不在集成终端的界面上显示（与 020 一致，无需改动）；**GENERIC/FULL** 在客户端没有区别（客户端没有为它写任何代码）。服务端的"存入终端"是否生效由服务端决定（宪法 VII：客户端设置不是安全边界），本 feature 里由 FR-009 的版本门、FR-011 的配置与 FR-013 的出错关闭三者决定，不新增按模组的服务端档位（用户 2026-11-20 确认：按模组的服务端档位单开 059，反向顺延为 060）；012 已有的服务端关口（`ServerCompatGate`）照常先问，仍恒为允许。

**不改什么**

- **FR-029**: 本 feature MUST NOT 改变背包的存储数据（数据修订号保持 6），MUST NOT 新增网络协议包（协议号保持 21），MUST NOT 为集成终端的合成页、末影箱页、其它成分类型、任何"终端 → 面板"方向、AE2 写专门代码，MUST NOT 引入对其它 Cyclops 模组的兼容。

### Key Entities *(include if feature involves data)*

- **第三方兼容条目**：一个第三方模组的"主动兼容登记"：模组标识、显示名、受支持的版本段列表、同时要求的其它模组（各带版本段列表）、可选的变体标识。
- **版本段**：`[下限, 上限)`，下限含、上限不含，两端是解析后的数字版本。
- **版本检查结果**：对一个已安装模组的判断：在范围内 / 低于所有段 / 高于所有段 / 落在空隙里 / 无法判断版本；外加是哪个被要求的模组造成的。
- **网络存储桥**：针对某个第三方模组的服务端适配器：能判断"这个界面当前页我是否处理"，并把一组物品存入对方的网络，返回剩余；为以后的取出预留。
- **适配器运行状态**：每个第三方适配器在本次运行里是"启用 / 因范围外未启用 / 因出错被关闭"之一。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在受支持版本的集成终端上，玩家 Ctrl+点击面板里的物品，**一次操作**后物品出现在终端网格里，并从背包扣掉对应数量；网络放不下或离线时背包里一个也不少（守恒，抽查 100% 一致）。
- **SC-002**: 把任一已装第三方模组伪造成范围外后，服务器日志**恰好**对每个范围外模组出现一条警告；op 玩家每次登录**恰好**对每个范围外模组收到一条聊天提示；非 op 玩家收到 0 条。
- **SC-003**: 对四种检查结果（范围内、过低、过高、落在空隙里）各至少有一组自动测试用真实的版本字符串覆盖，全部通过；版本字符串含构建元数据与预发布后缀时结论与去掉后缀一致。
- **SC-004**: 兼容代码出错的场景（方法缺失、链接错误、运行时异常）在测试里 **0 次**导致物品丢失或服务端崩溃；同一次运行里错误通知至多出现 1 次。
- **SC-005**: 在没有安装集成终端、精妙存储、AE2 的环境里，所有现有功能与测试的结果与 058 之前完全一致（无新增日志、无新增提示）。
- **SC-006**: 范围表、`neoforge.mods.toml`、README/README_CN、`build.gradle` 的开发依赖四处**任一处不一致都会让自动测试失败**。
- **SC-007**: 在容器里搭建集成动力学网络完成一轮游戏内验证：存入成功、部分存入、网络离线、合成页、末影箱页、范围外伪造六种情形全部与验收场景一致，结果记入 DELIVERY。

## Assumptions

- 集成终端的"物品存储页服务端不处理 Shift+点击物品栏、移动由客户端发包驱动"这一事实来自读 1.11.2 的源码，尚未在游戏里验证；058 的游戏内验证（SC-007）会同时验证这一点。若验证发现与源码判断不一致，回到方案阶段调整，不在实现里硬凑。
- 第三方模组的版本号至少以数字开头且各段用点号分隔，是普遍情形；不满足的按 FR-004 视为"无法判断"。
- 同一个模组范围内的次版本升级通常不破坏 API（语义化版本策略）；个别情形会破坏，由 FR-013 的出错兜底处理，不靠版本号预测。
- 管理员的定义（op 权限等级至少 2）与 031、057 一致；不引入新的权限系统。
- 通用路径（012）保持不动；桥只是它前面的一道可选分派，没有注册桥或桥不认领时与之前完全一致。
- 配置项的读取方式、默认值之外的校验与 057 的服务端配置保持同样的写法；"允许未验证版本"是单一开关，不做按模组的细分。
- 开发依赖已加入 `build.gradle` 的 `localRuntime`（不进发布的 jar，不影响 CI 的 `-PcleanRuntime` 构建）；CI 不会运行游戏内验证。
- 玩家端不需要安装任何额外东西；客户端不改动，终端界面是普通的容器界面，面板照常叠在上面。
- "终端 → 面板"（集成终端与 AE2）留给 060；它需要客户端识别悬停的网络条目并发包，工作量与版本敏感度更高，本 feature 不为它写任何客户端代码，只在桥的接口里预留位置。
