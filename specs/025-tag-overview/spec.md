# Feature Specification: 标签总览——查看与管理这只背包给哪些物品设置过哪些标签

**Feature Branch**: `025-tag-overview`

**Created**: 2026-11-08

**Status**: Draft

**Input**: User description: "标签管理器的\"标签总览\"：在标签管理器展开的面板标题栏右侧加一个菜单图标，点击后查看当前背包已为哪些物品（即使该物品当前不在背包里）设置了标签：先是物品列表（含标签数量，可按标签筛选），点击某个物品进入它的标签明细（可新增、删除标签，遵循每个分类最多 10 个标签和\"垃圾\"标签保护），列表页还能清空某个物品的所有标签（二次确认）。"

## 背景与已确认的决策

018 做了标签管理器：放在下方功能区，左键展开一个覆盖主区域的标签面板，**只能对 Shift 选中的、此刻在主区域里的物品**增删标签。标签本身按**物品分类**（物品注册 id，如 `minecraft:oak_log`）存在背包数据里，物品被移走标签仍在。后果是：玩家没有任何地方能**总览"这只背包给哪些物品设置过哪些标签"**——尤其是容量大的背包，忘了给哪些物品打过标签（比如想看哪些被标成"垃圾"、哪些被标成"宝物"）时，只能一个个把物品选进选区再看，而且物品必须此刻还在背包里。许多玩法（022 的一键倾倒、024 的自动拾取黑名单）都依赖标签，玩家需要方便地管理它们。

本 feature 在标签面板里加一个**"总览"视图**：列出这只背包标签数据里所有至少有一个标签的物品分类（不管它们现在在不在背包里），可按标签筛选，点进去查看和编辑某个分类的标签，也可以一键清空某个分类的标签。

已确认的决策（来自用户，不重新讨论）：

1. **入口**：标签面板（018：下方功能区的标签管理器左键展开，覆盖主区域）的**顶部状态行右侧**加一个菜单图标（"≡"一类的符号，悬停有提示）。点击在**选区视图**（018 原有的：对 Shift 选中的物品打标签）与**总览视图**之间切换；总览视图里有返回的办法回到选区视图。
2. **总览列表页**：列出当前背包标签数据里**所有至少有一个标签的物品分类**（不要求物品现在在背包里）。每行显示物品图标、名称、**标签数量**；悬停列出它的全部标签。物品很多时可以滚动。
3. **按标签筛选**（用户已选）：列表页顶部有一个筛选输入（文本框 + 下拉；复用 018 的预设标签、"本背包已用过的标签"与模糊匹配），选定一个标签后列表只显示带该标签的物品；可以清除筛选。这直接回答"哪些物品被标成了垃圾"。
4. **标签明细页**：点击列表里的物品进入。显示该分类的全部标签（点一个标签出现删除标记，点删除即移除）、末尾加号 → 文本框 + 下拉添加。规则**完全沿用**：每个分类最多 10 个标签（满了加号变灰）、标签字符规则（1～16 个小写可见 ASCII 字符）、022 的"垃圾"标签保护（受保护物品拒绝加"垃圾"标签，服务端同样拒绝）。有返回按钮回到列表页。**物品不在背包里也能编辑**。
5. **清空某个物品的所有标签**：列表页的行上提供"清空"操作，**需要二次确认**。

由我按已有惯例设计的部分（不再逐条询问用户，可在 plan 阶段微调）：

- **二次确认的形式**：行内两步确认——点"清空"后该行变成"确认清空？"，再点一次才执行；点别处、滚动、切换视图或隔几秒自动取消。不弹模态对话框，也不改动 022 的垃圾桶确认框。
- **排序**：列表按物品显示名排序（同名按注册 id）。已经不在游戏里的物品（比如移除了的模组）显示原始注册 id 与占位图标，仍可查看、删除标签、清空；**但不能再给它添加标签**（无法判断它受不受保护，且游戏里已没有这个物品）。
- **范围边界**：总览**只管已经有标签的物品分类**；不提供"给从未打过标签的物品加标签"（那仍然是选区视图里 Shift 选物品的做法）。明细页只能给该分类自己加/删标签。清空之后该分类没有标签了，就从列表里消失。
- **会话状态**：当前视图（选区/列表/明细）、列表的滚动位置、筛选标签、正在查看的物品，都只存在客户端会话里，不持久化；标签面板收起时保留；退出世界清空；换背包、或标签管理器离开功能区时回到选区视图。
- **图标**不新增贴图，只用填充和字体绘制（不影响宪法 VI 的图集预算）。
- **键盘**：总览里有两个文本输入（列表页的筛选框、明细页的添加框），沿用 018 的做法——只在文本框有焦点时拦截键盘，没有焦点不拦截任何键盘事件；022 的 Delete 键在标签面板展开时让位的规则同样适用于总览的两个视图。

已查证的事实（读本仓库源码；规格要尊重，不要重新猜）：

- 标签数据是 `物品注册 id → 标签列表` 的映射，存在背包数据里（018，`ItemTags`；最多 1024 个分类，每个分类最多 10 个标签）；服务端把它整份同步给客户端（`BackpackTagsPayload`，开会话时与每次变化后都发）。**所以总览所需的数据客户端已经有**，不需要新的同步。
- 018 现有的标签请求（`BackpackTagPayload`）携带的是**主区域的格子下标**，由服务端从背包真实内容解析成物品分类；它要求下方功能区有标签管理器，并在加"垃圾"标签时按 022 的保护列表拒绝。总览里的物品可能**不在背包里**，没有格子下标，所以需要一类**按物品注册 id 寻址**的新请求。
- 022 的保护列表是数据包可编辑的物品标签 `mcfloatingbackpack:never_trash`；判断"受保护"需要能从注册 id 解析出一个真实存在的物品。
- 标签面板的状态（展开、编辑、下拉、待删标签、滚动、文本缓冲）是客户端会话单例（`TagPanelState`），布局是纯几何（`TagPanelLayout`：顶部一行状态行 + 标签块自动换行 + 加号/文本框 + 下拉 + 按行滚动），文本缓冲、模糊匹配、标签规则都是不依赖 Minecraft 的纯类，可以复用。
- 024 的自动拾取黑名单页面与标签面板互斥，它的下拉候选里"本背包已用过的标签"读的就是同一份标签数据；本 feature 不改变这一点。
- 测试类路径里只有 JUnit（没有 Minecraft 类），所以筛选、排序、请求校验、清空的纯规则要放在不依赖 Minecraft 的纯类里才能单测。

## Out of Scope（本阶段不做）

- 批量编辑多个物品的标签；对列表里多个物品一起清空。
- 按物品**名称**搜索列表（本 feature 只按标签筛选）。
- 给**从未打过标签**的物品加标签（仍用选区视图）；给已不在游戏里的物品加标签。
- 标签重命名/合并、标签的导入导出、在主区域格子上显示标签角标。
- 修改 018 选区视图的任何行为；修改 022 的保护规则或垃圾桶的确认框；修改 024 的黑名单页面。
- 总览里的撤销（清空后不能恢复；二次确认就是它的保护）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 在标签面板里切换到"总览"，再切回来 (Priority: P1)

玩家展开标签面板，点状态行右侧的菜单图标进入总览列表；在总览里可以回到选区视图。

**Why this priority**: 这是总览的入口，其余所有操作都从这里开始。

**Independent Test**: 放好标签管理器，展开标签面板，点菜单图标，看到总览列表；返回，看到原来的选区视图；再关闭、重开面板，视图状态符合"会话状态"规则。

**Acceptance Scenarios**:

1. **Given** 标签管理器在下方功能区，**When** 左键展开标签面板，**Then** 面板顶部状态行右侧有一个菜单图标，悬停有提示（如"标签总览"）；面板仍是 018 的选区视图，行为不变。
2. **Given** 选区视图，**When** 点菜单图标，**Then** 进入总览列表页（覆盖主区域，与 018 同样的位置与尺寸）；图标变为"返回选区"的状态（悬停提示随之变化）。
3. **Given** 总览（列表或明细），**When** 点该图标（或明细页的返回按钮回到列表后再点它），**Then** 回到选区视图，选区（Shift 选中的格子）没有被改动。
4. **Given** 总览视图，**When** 点击面板外的主区域以外的地方，或按标签面板的收起手势（再次左键标签管理器），**Then** 面板照 018 的方式收起；再次展开时回到收起前的视图与滚动位置、筛选与正在查看的物品。
5. **Given** 总览视图，**When** 标签管理器被拿出功能区，或浮动面板关闭，**Then** 面板收起（018 既有规则）；再次打开时回到**选区视图**（换背包或工具离开功能区重置视图）。
6. **Given** 总览视图，**When** 玩家退出世界再进入，**Then** 视图、滚动、筛选都被清空，面板收起。
7. **Given** 024 的自动拾取黑名单页面已展开，**When** 展开标签面板，**Then** 黑名单页收起（既有互斥）；反之亦然。
8. **Given** 总览视图，**When** 在 020 配置为 OFF 的模组界面上，**Then** 与整个面板一起隐藏、不可点击，状态保留。

### User Story 2 - 看到这只背包给哪些物品打过标签（列表页） (Priority: P1)

玩家在列表页看到所有有标签的物品分类——即使这些物品现在不在背包里。

**Why this priority**: 这是本 feature 解决的核心问题。

**Independent Test**: 给几种物品打上标签，再把其中几种物品从背包里拿走；打开总览，仍能看到全部；换一只没打过标签的背包，列表为空。

**Acceptance Scenarios**:

1. **Given** 背包里给圆石打了 `stone`、给橡木原木打了 `wood` 和 `food`（随便举例），**When** 进入总览，**Then** 列表里有这两行，每行是物品图标、名称、标签数量（1 与 2）。
2. **Given** 上述圆石已经不在背包里（被取走或丢弃），**When** 进入总览，**Then** 圆石那一行仍在。
3. **Given** 列表里某一行，**When** 鼠标悬停，**Then** 提示里列出该分类的全部标签（预设标签按语言显示，自定义标签原样）。
4. **Given** 多个分类，**When** 查看顺序，**Then** 按物品显示名排序，同名的按注册 id；换语言后按新的显示名重排。
5. **Given** 分类很多超出面板高度，**When** 滚轮滚动，**Then** 列表按行滚动，滚到头不再动；滚轮被面板消费，不穿透。
6. **Given** 一只没有任何标签的背包，**When** 进入总览，**Then** 显示"无"之类的空状态提示，没有行。
7. **Given** 某个物品来自已被移除的模组（注册表里没有它），**When** 它在标签数据里，**Then** 列表里显示它的原始注册 id 和占位图标，不报错、不丢失。
8. **Given** 总览列表，**When** 在选区视图里给新物品打了标签再切回总览，**Then** 列表立即包含它（数据来自同一份实时同步的标签数据）。

### User Story 3 - 按标签筛选，找出"哪些被标成了垃圾" (Priority: P1)

列表页顶部有筛选输入；选一个标签后只显示带该标签的物品。

**Why this priority**: 用户的出发点就是"按标签找物品"；没有它列表只是半个答案。

**Independent Test**: 给若干物品打不同标签（其中几个有 `trash`）；筛选 `trash`，只剩那几个；清除筛选恢复全部。

**Acceptance Scenarios**:

1. **Given** 列表页，**When** 查看顶部，**Then** 有一个筛选输入（未选标签时显示提示文字，如"按标签筛选"），行为风格与 018 的添加框一致。
2. **Given** 点击筛选输入，**When** 它获得焦点，**Then** 下拉里按"预设标签在前、本背包已用过的标签在后"列出候选，输入文字时按 018 的模糊匹配过滤；回车或点击候选选定一个标签；ESC 取消。
3. **Given** 选定 `trash`，**When** 查看列表，**Then** 只显示分类标签里有 `trash` 的行；筛选输入处显示当前筛选的标签，并有清除的办法。
4. **Given** 已筛选，**When** 清除筛选，**Then** 列表恢复为全部分类。
5. **Given** 已筛选，**When** 在明细页里删掉该物品的这个标签再返回，**Then** 该物品不再出现在筛选结果里；筛选本身保持不变。
6. **Given** 筛选一个没有任何物品带的标签（比如用已用标签之外手输入的），**When** 查看列表，**Then** 显示"没有符合的物品"的空状态，并仍可清除筛选。
7. **Given** 筛选输入有焦点，**When** 玩家打字，**Then** 键盘被文本框接管且不触发别的快捷键（含 022 的 Delete 键）；没有焦点时不拦截任何键盘事件。
8. **Given** 筛选输入只接受合法标签字符，**When** 输入大写或空格，**Then** 被 018 的规则过滤（与添加框相同）。

### User Story 4 - 查看并编辑某个物品的标签（明细页） (Priority: P1)

点击列表里的物品进入明细页，增删它的标签；规则与 018/022 完全一致，物品不在背包里也能编辑。

**Why this priority**: 总览要能"管理"，不只是查看。

**Independent Test**: 在明细页给一个已不在背包里的物品加、删标签，试着加到 10 个，试着给受保护物品加 `trash`。

**Acceptance Scenarios**:

1. **Given** 列表页，**When** 点击某一行（不是它的"清空"），**Then** 进入该物品的明细页：标题行显示物品图标与名称、返回按钮；下面是它的全部标签块和末尾的加号。
2. **Given** 明细页，**When** 点一个标签，**Then** 该标签出现删除标记（与 018 同样）；点删除标记 → 该标签被移除；点别处取消删除标记。
3. **Given** 明细页，**When** 点加号，**Then** 加号变成文本框 + 下拉（预设 + 本背包已用标签，模糊匹配）；回车添加输入或高亮候选；ESC 取消；添加成功后文本框关闭、新标签出现。
4. **Given** 该物品已有 10 个标签，**When** 查看加号，**Then** 加号灰色，悬停提示该分类标签已满；服务端同样拒绝第 11 个（零变化）。
5. **Given** 该物品是受保护物品（022：本模组物品、潜影盒等），**When** 试图添加 `trash`，**Then** 被拒绝并提示（下拉里的"垃圾"变灰，与 018 同样）；添加其它标签不受影响。
6. **Given** 该物品当前**不在**背包里，**When** 增删标签，**Then** 照常成功，物品是否在背包里不影响。
7. **Given** 该物品已不在游戏里（注册表没有它），**When** 查看明细，**Then** 能看到并删除它的标签，**加号灰色**（提示"这个物品已不在游戏里，只能删除标签"）。
8. **Given** 明细页里删掉了该物品的**最后一个**标签，**When** 服务端确认，**Then** 该分类从标签数据里消失，明细页**自动回到列表页**（那一行不再出现）；要重新给它打标签用选区视图（总览只管已有标签的分类）。
9. **Given** 点返回，**When** 回到列表，**Then** 保持进入前的滚动位置与筛选。
10. **Given** 明细页的文本框有焦点，**When** 玩家打字，**Then** 键盘由文本框接管，不触发其它快捷键。

### User Story 5 - 清空某个物品的所有标签（二次确认） (Priority: P2)

列表页每行有"清空"操作；第一次点只是要求确认，第二次才执行。

**Why this priority**: 管理的便利功能，不影响查看与编辑；有二次确认避免误操作。

**Independent Test**: 在列表页对一行点"清空"，点别处取消；再点"清空"后确认；确认后该行消失、标签真的没了。

**Acceptance Scenarios**:

1. **Given** 列表页某一行，**When** 查看，**Then** 行的右端有一个"清空"按钮（悬停提示"清空这个物品的所有标签"），不影响点击行本身进入明细。
2. **Given** 点"清空"，**When** 第一次点击，**Then** 该行变成"确认清空？"状态（再点一次才执行），其它行不变；此时点别处、滚动、切换视图或隔几秒，该行自动恢复，**什么都没有被清空**。
3. **Given** 行处于"确认清空？"状态，**When** 再次点击，**Then** 该分类的所有标签被移除，该行从列表消失；其它分类不受影响。
4. **Given** 同一时刻只有一行可以处于"确认清空？"状态；**When** 点另一行的"清空"，**Then** 前一行恢复，新的一行进入确认状态。
5. **Given** 清空之后，**When** 在选区视图里选中该物品（若它在背包里），**Then** 它没有任何标签（共同标签为"无"）；022 的"一键倾倒"不再倾倒它。
6. **Given** 被清空的分类是受保护物品或已不在游戏里的物品，**When** 清空，**Then** 同样成功（清空是删除，不受"垃圾"保护限制）。
7. **Given** 服务端拒绝了清空（例如标签管理器已被拿走），**When** 客户端收到同步，**Then** 列表按服务端真实数据显示，不显示已经"清空"的假象。

---

### User Story 6 - 服务端权威、持久，不影响现有功能 (Priority: P2)

总览里的所有修改由服务端校验与执行；数据仍随背包保存；011～024 的功能保持原样。

**Why this priority**: 数据安全与回归。

**Independent Test**: 用两只背包、退出重进、升级、旧存档回归；构造非法请求（没有标签管理器、越界、非法标签、超过 10 个、受保护物品加 `trash`、对没有标签的分类加标签）确认零变化。

**Acceptance Scenarios**:

1. **Given** 总览里的增、删、清空，**When** 玩家退出世界再进入、关闭浮动面板、升级背包，**Then** 标签数据与操作之前一致（仍是背包自己的数据）。
2. **Given** 两只背包，**When** 在其中一只上改标签，**Then** 另一只不受影响；总览只显示当前背包的标签。
3. **Given** 服务端收到的请求，**When** 下方功能区**没有**标签管理器，**Then** 整个请求被拒绝，数据零变化，并补发当前标签同步让客户端追上真相。
4. **Given** 加标签的请求，**When** 目标分类**当前没有任何标签**（总览只允许编辑已有标签的分类），**Then** 被拒绝，零变化。
5. **Given** 加标签的请求，**When** 标签不合法（空、含大写、含空格、超过 16 个字符）、该分类已有 10 个标签、物品已不在注册表里、或 `trash` 加给受保护物品，**Then** 被拒绝，零变化，客户端被补发真实数据。
6. **Given** 删除或清空的请求，**When** 目标分类不存在（客户端数据过期）或标签不存在，**Then** 视为没有变化，不报错，客户端被补发真实数据。
7. **Given** 请求里带的物品 id 不是合法的注册 id 格式，**When** 处理，**Then** 整个丢弃，零变化。
8. **Given** 011～024 的现有功能（选区视图的增删标签、022 的倾倒与 Delete 键、024 的黑名单与拾取、垃圾桶、Ctrl 转移、拖动、缩放、滚动、020 兼容开关），**When** 重跑它们的验证项，**Then** 与之前一致（唯一变化：标签面板状态行多了一个菜单图标）。

---

### Edge Cases

- **标签数据很大**：最多 1024 个分类；列表按行虚拟滚动，不得因此卡顿；客户端按需布局。
- **同步延迟**：服务端处理一次增删/清空后补发整份标签；客户端在收到前可以先显示旧数据，收到后以服务端为准（不做乐观更新也可以，plan 决定）。
- **物品被标成同时命中多个筛选标签**：筛选一次只选一个标签，不做多标签组合。
- **筛选的标签已被全部清除**（别处删光）：列表为空时显示"没有符合的物品"，筛选仍可清除；不自动清除筛选。
- **在明细页时该分类被清空**（另一处修改同步过来，或删掉了最后一个标签）：明细页自动回到列表页，不停留在一个没有标签的页面上。
- **选区视图的 Shift 选区**：进入总览不改动选区；返回选区视图选区仍在。
- **窗口很窄**：列表行的名称按宽度截断，标签数量与"清空"按钮优先保留；悬停提示给出完整名称与标签。
- **本地化**：预设标签与界面文字按语言显示，存储始终是稳定的英文 id（018 的规则）。
- **既有"标签管理器离开功能区"**：面板收起并回到选区视图；总览里正在"确认清空？"的状态一并取消。
- **多个标签管理器遗留**（018 旧背包有 2 个）：功能取第一个，总览不受影响。

## Requirements *(mandatory)*

### Functional Requirements

**入口与视图切换**

- **FR-001**: 标签面板顶部状态行的右端 MUST 有一个菜单图标，只用填充与字体绘制，不新增贴图；悬停 MUST 有提示（选区视图下"标签总览"，总览视图下"返回选区"）。
- **FR-002**: 点击菜单图标 MUST 在选区视图与总览视图间切换；切换 MUST NOT 改动 Shift 选区；选区视图的全部既有行为（018、022 的保护提示）MUST 保持不变。
- **FR-003**: 总览 MUST 有"列表页"与"明细页"两层；明细页 MUST 有返回按钮回到列表页；返回 MUST 保持列表的滚动位置与筛选。
- **FR-004**: 视图状态（当前视图、列表滚动、筛选标签、正在查看的物品、行内确认状态）MUST 只在客户端会话里：标签面板收起时保留（行内"确认清空？"除外，收起即取消）；退出世界清空；标签管理器离开功能区、浮动面板关闭、换背包时 MUST 回到选区视图。
- **FR-005**: 总览 MUST 与 018 的标签面板、024 的黑名单页面遵守同样的互斥与显示规则（覆盖主区域、与面板网格对齐、展开期间主区域不可操作、点击与滚轮被消费不穿透、020 的 OFF 界面上整体隐藏）。

**列表页**

- **FR-006**: 列表 MUST 包含当前背包标签数据里**所有至少有一个标签**的物品分类，**不论物品当前是否在背包里**；每行 MUST 显示物品图标、名称、标签数量；已不在注册表里的物品 MUST 显示原始注册 id 与占位图标，不得丢失或报错。
- **FR-007**: 悬停一行 MUST 列出该分类的全部标签（预设按当前语言显示，自定义原样）。
- **FR-008**: 列表 MUST 按物品显示名排序，同名按注册 id；MUST 随语言变化重排；超出面板高度时 MUST 按行滚动。
- **FR-009**: 没有任何标签时 MUST 显示空状态提示，不显示行。

**按标签筛选**

- **FR-010**: 列表页顶部 MUST 有筛选输入（文本框 + 下拉）：下拉候选 MUST 是"预设标签在前、本背包已用过的标签在后"，输入文字时按 018 的模糊匹配过滤；选定一个标签后列表 MUST 只显示分类标签里含该标签的行；MUST 提供清除筛选的办法；筛选一次只选一个标签。
- **FR-011**: 筛选输入的字符规则与键盘接管 MUST 沿用 018：只允许合法标签字符、长度 ≤ 16；只在文本框有焦点时拦截键盘；ESC 取消；回车选定。
- **FR-012**: 筛选结果为空时 MUST 显示"没有符合的物品"的空状态，并仍能清除筛选。

**明细页**

- **FR-013**: 点击列表行（不是它的"清空"）MUST 进入该分类的明细页：显示物品图标与名称、返回按钮、该分类的全部标签块和末尾加号。
- **FR-014**: 明细页 MUST 支持删除标签（点标签出现删除标记，点删除移除）和添加标签（加号 → 文本框 + 下拉，回车添加，ESC 取消），交互与 018 一致；添加 MUST 沿用全部规则：标签字符规则、每分类最多 10 个（满则加号灰并提示）、022 的"垃圾"标签保护（受保护物品拒绝，下拉里"垃圾"变灰）。
- **FR-015**: 编辑 MUST NOT 要求物品当前在背包里；已不在注册表里的物品只能删除标签、不能添加（加号灰并提示）。
- **FR-016**: 明细页删掉某分类的最后一个标签后 MUST 自动回到列表页；列表里 MUST 不再出现没有标签的分类。

**清空**

- **FR-017**: 列表页每行 MUST 有"清空"操作；点击 MUST 先进入该行的"确认清空？"状态，**再点一次才执行**；点别处、滚动、切换视图或超过几秒 MUST 自动取消，什么都不改；同一时刻只有一行处于确认状态。
- **FR-018**: 确认后 MUST 移除该分类的**全部**标签，其它分类不受影响；对受保护物品、已不在游戏里的物品 MUST 同样有效（清空是删除，不受"垃圾"保护限制）；被清空的分类 MUST 从列表消失。

**服务端权威与同步**

- **FR-019**: 总览里的增、删、清空 MUST 由服务端校验并执行；客户端 MUST 只发"动作 + 物品注册 id + 标签"，MUST NOT 被信任"这个物品是什么"。新的请求 MUST 与 018 按格子下标的请求区分。
- **FR-020**: 服务端 MUST 校验：请求者持有该背包；**下方功能区有标签管理器**；物品 id 是合法的注册 id 格式；**添加**只能针对"标签数据里已经有至少一个标签"的分类，且物品必须仍在注册表里；标签满足 018 的标签规则；该分类不超过 10 个标签；022 的保护规则（受保护物品拒绝 `trash`）；**删除与清空**对不存在的分类/标签视为没有变化；任何一步失败 MUST 整个请求零变化，并补发标签同步，使客户端显示追上真相。
- **FR-021**: 成功后服务端 MUST 保存背包并把最新整份标签同步给客户端（沿用现有的标签同步）；网络协议版本 MUST 升级以隔离旧版本客户端。
- **FR-022**: 标签数据 MUST 仍存放在背包自己的数据里：随背包保存、升级保留、两只背包互不共享；本 feature MUST NOT 改变数据格式。

**文字与兼容**

- **FR-023**: 所有界面文字（菜单图标提示、列表标题与空状态、筛选提示与空状态、明细页标题与返回、清空与确认、已不在游戏里的提示）MUST 提供 `zh_cn` 与 `en_us` 两份。
- **FR-024**: 011～024 的现有行为 MUST 保持不变；唯一的可见变化是标签面板状态行右侧多了菜单图标。
- **FR-025**: 筛选、排序、行内确认状态机、请求校验与"清空/添加/删除"的结果 MUST 放在不依赖 Minecraft 类的纯类里，能单元测试。

### Key Entities

- **物品分类的标签**（018）：物品注册 id → 标签列表（≤ 10），随背包保存；本 feature 不改数据格式。
- **总览视图**：标签面板的第二个视图，分列表页与明细页；会话级状态，不持久化。
- **列表行**：一个有标签的物品分类（图标、名称、标签数量、清空操作）。
- **筛选标签**：列表页当前选定的单个标签（可无）。
- **行内确认状态**：某一行处于"确认清空？"；同一时刻至多一行；有超时。
- **按物品 id 寻址的标签请求**：新的客户端 → 服务端请求，动作为添加、删除、清空，携带物品注册 id（与 018 按格子下标的请求区分）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 标签面板展开后，状态行右端有菜单图标；点它进入总览、再点回到选区视图，**切换 10 次选区一次都没被改动**，018 选区视图的验证项结果与之前一致。
- **SC-002**: 给 5 种物品打标签后，把其中 3 种从背包里拿走：总览列表**仍列出全部 5 种**，每行标签数量正确，悬停显示完整标签。
- **SC-003**: 在 20 种有标签的物品里，选定 `trash` 筛选，**只显示带 `trash` 的那些**；清除筛选后恢复全部 20 种；筛选一个没有物品带的标签显示空状态。
- **SC-004**: 在明细页对一个**不在背包里**的物品增删标签均成功；加到 10 个后加号灰且服务端拒绝第 11 个（5 次尝试全部零变化）；对受保护物品加 `trash` 的 5 次尝试全部被拒绝且零变化。
- **SC-005**: 清空：第一次点击后 5 种取消方式（点别处、滚动、切换视图、超时、点另一行）都不改变任何数据；第二次点击后该分类标签数为 0 且行消失；对受保护物品和已移除模组的物品同样成功。
- **SC-006**: 非法请求（没有标签管理器、没有标签的分类上加标签、非法标签、超过 10 个、非法注册 id、已不在注册表的物品加标签）全部被丢弃且数据零变化，客户端随后显示的是服务端的真实数据。
- **SC-007**: 退出重进、关闭面板、升级、换背包后，总览里的标签与之前一致且两只背包互不共享；旧存档不受影响。
- **SC-008**: 总览里**键盘**：文本框有焦点时打字不触发其它快捷键（含 Delete 键），没有焦点时不拦截任何键盘事件；ESC 只取消编辑。
- **SC-009**: 重跑 011～024 的验证项，结果与之前一致（除 FR-024 说明的菜单图标）。
- **SC-010**: 本 feature **不新增任何贴图**，图集度量仍为 2048×1024（宪法 VI）；Windows/Linux 无法验证，登记为未验证。

## Assumptions

- **筛选单标签**：一次只筛一个标签，不做"同时带 A 和 B"的组合。
- **清空的确认超时**：约 3 秒（plan 定稿具体数值）；点别处、滚动、切换视图也取消。
- **明细页里删光最后一个标签**：自动回到列表页（该分类已不在标签数据里；服务端只允许给已有标签的分类添加，所以不能留在空明细页里再添加）。
- **不做乐观更新**：客户端等服务端的标签同步再更新显示（plan 可改为乐观更新，只要最终以服务端为准）。
- **已不在游戏里的物品不能加标签**：原因是无法判断保护列表；这也避免给不存在的物品凭空造数据。
- **依赖**：018（标签面板、标签规则、输入与布局组件）、022（保护规则与"垃圾"标签）、024（互斥关系）；不依赖任何第三方模组。
- 本功能是纯玩家可见的交互变化，按宪法 V 必须在客户端会话里逐场景验证（尤其是切换视图、物品不在背包时的列表与编辑、筛选、行内确认、保护规则、持久化与回归）；Windows/Linux 本机无法验证。
