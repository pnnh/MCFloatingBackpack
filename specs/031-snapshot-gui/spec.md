# Feature Specification: 快照管理界面（玩家与管理员面板）

**Feature Branch**: `031-snapshot-gui`

**Created**: 2026-11-09

**Status**: Draft

**Input**: 用户描述："现在开始开新 feature 实现玩家管理员面板。它基本是指令的 GUI 版本。注意权限上和命令一致，区分普通玩家和管理员。"经三个问题确认：形态 = 模组自己的独立界面；入口 = 命令 `/mcfb snapshot gui`、可改键的快捷键（默认不绑定）、浮动面板标题栏上的小按钮，三个都做；要有只读的快照内容预览。

## 背景与已确认的决策

030 做了世界之外的单个背包快照（`<实例目录>/mcfloatingbackpack/snapshots/<世界>/<UUID>-<编号>/<毫秒>.dat`，每只背包最近 5 份）和命令 `/mcfloatingbackpack snapshot …`（别名 `/mcfb`）：

- 所有玩家：`list [页]`、`info <背包>`，**只看自己的**；
- op（权限等级 2，服务器控制台等同）：`list all|owner <玩家>|inactive <天数>`、`restore <背包> [版本] [玩家]`（从快照给玩家一只**新背包**，不带标识，不覆盖原背包；在生存模式里等于复制物品，所以要权限）、`delete <背包> [版本]`、`delete <背包> confirm`、`trim <天数> [confirm]`（默认只预览，`0` 表示全部）。
- 背包用 4 位编号、完整 UUID 或 UUID 开头（≥6 个字符）指定，编号重复时列候选。

030 的结论同样适用于本 feature：原版与 NeoForge 都没有全局物品索引，所以**没有"管理员特殊功能"**，找不到箱子、未加载区块、离线玩家里的背包；管理员能做的和普通玩家的差别只在"有权制造物品、看别人的快照、清理文件"。

已确认的决策（来自用户，不重新讨论）：

1. **本 feature 是 030 命令的图形界面版本**：功能一一对应，**权限与命令完全一致**，区分普通玩家和管理员；权限由**服务端**判断，客户端只负责显示。
2. **形态是模组自己的独立界面（Screen）**，不依赖任何背包，也不放进浮动面板。原因：背包被销毁后玩家可能一只背包也没有，而浮动面板要有背包才能打开，最需要它的时候反而打不开。它不替换、不包装、不继承任何原版或其它模组的界面（宪法原则 I），也不是浮动面板的宿主界面（019）。
3. **入口三个都做**：①命令 `/mcfb snapshot gui`；②**可改键的快捷键，默认不绑定**；③**浮动面板标题栏上的一个小按钮**（面板打开时一键打开；按钮用代码绘制，**不新增贴图**，不动共用方块图集）。
4. **要有只读的内容预览**（命令版没有）：选中某一份快照就显示它的物品格子网格，物品悬停有原版提示。

由我按已有惯例设计的部分（可在 plan 阶段微调）：

- 界面分两块：左边是背包列表（分页），右边是所选背包的版本与内容预览；底部是一行状态文字，op 的按钮在预览下方。
- op 才有的**列表范围**：`我的` / `全部` 两个切换，另有两个过滤输入——所有者（玩家名）与不活跃天数；普通玩家的界面里这些控件**根本不存在**。
- **恢复**的目标默认是自己，op 可改为任一在线玩家；恢复、删除、清理都要先选中对象，没选中时按钮是灰的；**删除一份快照**直接执行，**删除这只背包的全部快照**与**清理**都要二次确认，清理要先显示预览数量。
- 预览只显示背包的**主区域格子**（工具区、标签、垃圾桶、黑名单不显示），并注明快照的档位与非空格数。
- 浮动面板标题栏的按钮在面板右上、关闭按钮左侧，悬停提示"背包快照"。

## Out of Scope（本阶段不做）

- 新增贴图、配方，改共用方块图集；浮动面板里的子页面。
- 直接修改在线玩家背包内容、遍历容器、离线存档——030 已确认做不到或不做。
- 快照目录配置、覆盖原背包、第二套权限体系（沿用权限等级 2）、快照搜索框。
- 在界面里编辑快照内容；从预览里把单个物品拿出来（只读）。
- 联机以外的任何特殊处理；第三方模组界面。

## 已查证的事实（读本仓库源码；规格要尊重）

- 服务端 030 已有：`SnapshotStore`（`groups()`、`versions(uuid)`、`readContents(uuid, time)`、`delete`、`deleteAll`）、`SnapshotService.flushAndWait()`、`SnapshotListing`（过滤、排序、分页、清理候选）、`BackpackSelector`、`AgeText`。命令的授权规则在 `SnapshotCommands`：`list`/`info` 对所有人开放但只匹配自己的背包，其它子命令 `requires(source.hasPermission(2))`。
- 网络：`BackpackNetwork.register` 用 `registrar.versioned("15")` 注册所有 payload；服务端处理在 `handleServer(payload, context)` 里 `context.enqueueWork(...)`，客户端处理在客户端侧。
- 快捷键：`FloatingBackpackKeys` 里已有 `TOGGLE`、`DELETE_TO_TRASH` 两个 `KeyMapping`，由 `registerKeys` 注册。
- 025 的标签总览有"代码绘制的菜单图标"与客户端列表滚动的先例；019 的 `PanelHostScreen` 是模组自己的 Screen 的先例（但它是透明宿主，不要继承它）。

## 尚未验证（plan 阶段先查证；验证前不得声称已满足）

- 网络包大小与分页：一页多少行、预览内容（最多 108 个物品栈）放进一个包是否在原版限制之内。
- 浮动面板标题栏上放按钮的位置与已有的关闭按钮、标题编号（`TitleIdLayout`）、背包等级图标的几何关系，以及点击的处理顺序。
- 快捷键"默认不绑定"的写法（`InputConstants.UNKNOWN`）与在聊天框等文字输入界面里不触发。
- `/mcfb snapshot gui` 通知客户端的做法（服务端发空 payload 给调用者）；控制台执行时的提示。
- 单人游戏（集成服务器）：关闭作弊时没有 op；开启作弊的房主是 op——界面按服务端判断的权限显示。
- 独立界面的物品格子绘制与悬停提示能复用 `FloatingPanelRenderer` / 原版 `GuiGraphics` 里的现成方法，不复制一份。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 打开界面，看到自己的快照 (Priority: P1)

**Independent Test**: 普通玩家（非 op）用三个入口中的任一个打开界面：左边列出自己用过的背包，选中一只后右边列出它的各个版本；op 才有的控件看不到。

**Acceptance Scenarios**:

1. **Given** 玩家用过 3 只背包，**When** 执行 `/mcfb snapshot gui`，**Then** 界面打开，列表里有这 3 只，最近用的在前，每行有 4 位编号、UUID 开头、档位、版本数、所有者、最后一份距今。
2. **Given** 玩家把快捷键绑定到某个键，**When** 在世界里按它，**Then** 界面打开；没绑定时什么都不发生；在聊天框、告示牌编辑等文字输入界面里按它不触发。
3. **Given** 浮动面板已打开，**When** 点击标题栏上的快照按钮，**Then** 打开同一个界面，关闭后浮动面板的状态（位置、大小、滚动）原样不变。
4. **Given** 玩家一只背包也没有，**When** 用命令或快捷键打开，**Then** 照样能打开并使用。
5. **Given** 列表超过一页，**Then** 可以翻页，页码显示正确，越界翻页无效果。
6. **Given** 玩家没有任何快照，**Then** 列表显示"没有快照"，不报错。
7. **Given** 按 ESC 或点关闭，**Then** 界面关闭，回到游戏。

---

### User Story 2 - 选中一份快照，预览它的内容 (Priority: P1)

**Independent Test**: 选中一只背包的某个版本，右侧显示该快照的物品格子网格，悬停有原版物品提示；预览是只读的。

**Acceptance Scenarios**:

1. **Given** 选中背包的第 2 份快照，**Then** 右侧显示这一份的主区域格子（物品图标与数量），并写明档位与非空格数。
2. **When** 鼠标悬停在某个物品上，**Then** 显示原版的物品提示。
3. **When** 点击预览里的格子，**Then** 什么都不发生，不能拿起或移动物品。
4. **Given** 快照里有带附魔或自定义名称的物品，**Then** 预览与提示里照常显示。
5. **Given** 快照的物品在当前游戏里已经不存在（模组被移除），**Then** 该格显示为空或占位，不崩溃，其它格正常。
6. **Given** 切换选中另一份快照，**Then** 预览随之更换；快照在选中期间被别处删除后，预览与状态文字给出明确的提示。

---

### User Story 3 - 管理员恢复一份快照为新背包 (Priority: P1)

**Independent Test**: op 选中一份快照，点"恢复"：目标玩家的物品栏里多一只新背包，内容与该快照相同，原背包不变。

**Acceptance Scenarios**:

1. **Given** op 选中背包的最新一份，**When** 点"恢复"，**Then** 自己得到一只同档位的新背包（没有标识，第一次使用时分配），状态文字报告成功。
2. **Given** op 把目标改成另一名在线玩家，**Then** 那名玩家得到新背包，op 自己没有。
3. **Given** 目标玩家物品栏满，**Then** 新背包掉在其脚下，不丢。
4. **Given** 没有选中任何快照，**Then** "恢复"是灰的。
5. **Given** 快照里的档位与任何背包档位都对不上，**Then** 拒绝并在状态文字里说明，不给任何东西。
6. **Given** 普通玩家，**Then** 界面里没有"恢复"按钮；伪造恢复请求被服务端拒绝，零变化。

---

### User Story 4 - 管理员删除快照 (Priority: P2)

**Independent Test**: op 能删一份快照，也能删这只背包的全部快照（需确认）；普通玩家没有这些控件。

**Acceptance Scenarios**:

1. **Given** op 选中第 3 份快照，**When** 点"删除这一份"，**Then** 只删这一份，列表与版本随之刷新。
2. **When** 点"删除全部快照"，**Then** 先出现确认（说明将删除几份），确认后才删；取消则零变化。
3. **Given** 删掉了一只背包的最后一份，**Then** 这只背包从列表里消失。
4. **Given** 被删的背包之后又被使用，**Then** 会重新写出快照（030 的行为，不在本界面处理）。
5. **Given** 普通玩家，**Then** 没有删除控件；伪造删除请求被服务端拒绝，零变化。

---

### User Story 5 - 管理员看全部、过滤、清理 (Priority: P2)

**Independent Test**: op 把列表切到"全部"，可按所有者名字或不活跃天数过滤；"清理"先显示预览数量，确认后才删。

**Acceptance Scenarios**:

1. **Given** op，**When** 切到"全部"，**Then** 列出所有玩家的背包；切回"我的"只列自己的。
2. **When** 输入所有者的玩家名，**Then** 只列该玩家最后使用过的背包；名字没有匹配时显示"没有快照"。
3. **When** 输入不活跃天数 30，**Then** 只列最新快照早于 30 天的背包。
4. **When** 在清理里输入天数并点"预览"，**Then** 状态文字显示将影响多少只背包、多少份快照，**什么都没删**；再点"确认删除"才删除；`0` 表示全部。
5. **Given** 普通玩家，**Then** 没有"全部"切换、没有过滤框、没有清理；伪造请求被服务端拒绝，零变化。

---

### User Story 6 - 权限与隔离 (Priority: P1)

**Independent Test**: 普通玩家在任何情况下都看不到别人的背包、用不了 op 的功能；服务端是唯一的权威。

**Acceptance Scenarios**:

1. **Given** 普通玩家，**Then** 列表、版本、预览只来自自己最后使用过的背包；别人的背包对他等同"不存在"（指定 UUID 也得到"没有匹配"，不泄露是否存在）。
2. **Given** 玩家在界面打开期间被取消 op（或获得 op），**Then** 下一次请求按当时的权限处理；界面在下一次刷新时更新控件。
3. **Given** 客户端被改造，发来越权或越界的请求（别人的背包、负页码、超大页、非法版本号、超长字符串），**Then** 服务端拒绝并零变化。
4. **Given** 界面和命令同时使用，**Then** 两者看到的快照和权限完全一致。

---

### Edge Cases

- 服务器没有运行快照服务（刚启动或正在关闭）：界面显示"快照没有在运行"，不报错。
- 预览很大（108 格）：必须在窄窗口与大 GUI 缩放下仍然完整可见或可滚动，不溢出屏幕。
- 同一编号对应多只背包：列表里每只各占一行（用 UUID 开头区分），界面不需要像命令那样"列候选"。
- 列表加载期间界面关闭、网络延迟：关闭后到达的响应被忽略，不弹界面。
- 快照在预览期间被写出新的一份：列表在下次刷新时更新，选中项仍然有效；选中项已被删时给出提示。
- 恢复得到的背包不带标识；其内容里的光标物品与工具区原样复制（与命令一致）。
- 单人游戏关闭作弊：玩家是普通玩家，只看到"我的"。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 界面是模组自己的独立 Screen：不依赖任何背包，不替换、不包装、不继承其它界面，也不是浮动面板的宿主界面；ESC 关闭；打开与关闭不改变浮动面板的任何状态。
- **FR-002**: 三个入口：命令 `/mcfb snapshot gui`（所有玩家可用；服务端通知调用者的客户端打开；控制台执行时给出"需要玩家"的提示）；可改键的快捷键（默认不绑定，在文字输入界面里不触发）；浮动面板标题栏上的小按钮（用代码绘制，不新增贴图）。
- **FR-003**: 所有玩家的界面内容：**我的**快照列表（每只背包一行：4 位编号、UUID 开头、档位、版本数、所有者、最后一份距今；最近的在前；分页）；选中背包后列出它的各个版本（第几份、距今、非空格数）；选中一份后显示**只读预览**（主区域格子，物品悬停有原版提示）。
- **FR-004**: 仅权限等级 2 的玩家：列表范围可切到**全部**，可按所有者名字、不活跃天数过滤；可**恢复**所选版本给自己或任一在线玩家（得到一只**新背包**，不带标识，不覆盖原背包，满物品栏则掉落）；可**删除一份**快照；可**删除这只背包的全部快照**（二次确认）；可**清理**（先预览数量、再确认；`0` 表示全部）。
- **FR-005**: 普通玩家的界面里**不显示**也**不响应** FR-004 的任何控件。
- **FR-006**: 服务端权威：所有数据（列表、版本、预览）由服务端按请求者的权限读取并发送；所有改动由服务端校验权限与参数后执行；客户端不读任何快照文件。每次请求前服务端先把待写的快照写出（`flushAndWait`）。
- **FR-007**: 普通玩家只能看到 `owner` 是自己的背包；对别人的背包，任何请求（含完整 UUID）都得到与"不存在"相同的响应。
- **FR-008**: 请求校验：页码、页大小、版本号、天数、所有者名字的长度与范围；越权、越界、非法的请求零变化，不抛异常，只记调试日志。
- **FR-009**: 预览内容最多 108 个物品栈，编码复用背包内容的现有编码；单个响应不超过网络包的大小限制，必要时分页或裁剪并在界面上说明。
- **FR-010**: 删除与清理都有确认步骤；没有选中对象时相应按钮是灰的；所有操作的结果（成功、失败原因）显示在界面底部的一行状态文字里。
- **FR-011**: 界面在窄窗口与大 GUI 缩放下不溢出；布局的几何是纯逻辑，可单元测试。
- **FR-012**: 中英文语言键齐全并一致；`/mcfb snapshot gui` 的消息带英文后备文本（控制台没有本模组的语言文件）。
- **FR-013**: 不新增贴图、配方、设置项；不改共用方块图集；协议版本升级，新增的请求与响应都有长度与范围校验。
- **FR-014**: 界面的行为与 030 命令一致：同一个玩家、同一时刻，界面里看到和能做的事与命令完全相同。

### Key Entities

- **列表行（Group）**：一只背包的最新快照元数据与版本数（030 已有）。
- **版本（SnapshotMeta）**：第几份、时间、非空格数、所有者名字、档位。
- **预览内容**：某一份快照的主区域格子（物品栈列表）与档位、非空格数。
- **界面状态**：当前范围（我的/全部）、过滤条件、页码、选中的背包与版本、恢复目标、状态文字、待确认的操作。
- **权限标志**：服务端随每次响应告诉客户端"请求者是否有权限等级 2"，仅用于决定显示哪些控件，不用于授权。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 玩家用三个入口中的任一个，两次点击以内能看到自己的快照列表。
- **SC-002**: 普通玩家在任何操作下都看不到别人的背包，也不能执行 op 的功能：服务端拒绝伪造请求，零变化。
- **SC-003**: op 从打开界面到把一份快照恢复成新背包，不超过 4 次点击。
- **SC-004**: 界面与命令对同一玩家、同一时刻给出相同的列表与结果。
- **SC-005**: 在 1.0 到 4.0 的 GUI 缩放与窄窗口下，所有控件与预览不溢出屏幕。
- **SC-006**: 所有纯逻辑（布局、权限判断、请求校验、分页与过滤的衔接）有单元测试；自动化测试全部通过；图集仍是 2048×1024。

## Assumptions

- 玩家看到的"权限"就是服务端的权限等级 2；界面不引入任何新的权限概念。
- 在线玩家列表用于选择恢复目标；离线玩家不能作为恢复目标（与命令一致，命令要求在线玩家）。
