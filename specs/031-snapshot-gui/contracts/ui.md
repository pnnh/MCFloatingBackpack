# Contract: 界面（`SnapshotScreen`）

## 布局（纯逻辑 `SnapshotScreenLayout`；坐标是 GUI 缩放后的像素）

```text
┌ 标题：背包快照 ─────────────────────────────── [关闭] ┐
│ [我的|全部]  所有者:[____]  不活跃天数:[__]   (op 才有) │
│ ┌ 列表（每页最多 8 行）──────┐ ┌ 版本 / 预览 ───────────┐ │
│ │ NF56 leather ×5 Dev 1m   │ │ 背包 NF56 ef233969 …   │ │
│ │ …                        │ │ #1 1m 12格  #2 …       │ │
│ │ [<] 1/3 [>]              │ │ ┌ 9 列物品格（可滚动）┐ │ │
│ └──────────────────────────┘ │ └────────────────────┘ │ │
│ (op)[恢复→自己▸] [删除这一份] [删除全部] 清理:[__] [预览] │
│ 状态文字（一行）                                         │
└──────────────────────────────────────────────────────┘
```

- 宽 `min(屏幕宽 − 16, 400)`，高 `min(屏幕高 − 16, 260)`，居中；缩放 4（480×270）与更小窗口都不溢出：预览区在高度不够时纵向滚动（鼠标滚轮），列表行数最少 4。
- 普通玩家的界面里 **op 控件（范围切换、两个过滤框、恢复、删除、清理、目标按钮）不创建**，不是灰色，是根本没有。
- 颜色与外框沿用 `FloatingPanelRenderer.drawVanillaPanel` 与 `drawSlotWell`。

## 交互

| 操作 | 结果 |
|---|---|
| 点列表行 | 选中该背包，请求版本；预览清空 |
| 点版本行 | 选中该份，请求预览 |
| 预览格悬停 | 原版物品提示；点击无反应 |
| 点 `<` `>` | 翻页（越界无效） |
| `恢复` | 发 `RESTORE`；成功/失败显示在状态行 |
| `删除这一份` | 直接发 `DELETE_ONE` |
| `删除全部` | 进入待确认：按钮变成"确认删除全部 (N 份)"与"取消"；确认才发 `DELETE_ALL` |
| `预览`（清理） | 发 `TRIM_PREVIEW`；状态行显示数量并出现"确认删除""取消"；确认才发 `TRIM_CONFIRM` |
| ESC / 关闭 | 关闭；待确认状态丢弃 |

- 选中的东西在刷新后消失（被删）→ 状态行提示，选中清空。
- 所有文字用语言键：`gui.mcfloatingbackpack.snapshot.*`（标题、按钮、状态码、列表行格式）；键盘：Tab 在输入框间切换，Enter 在过滤框里应用。

## 标题栏按钮（浮动面板）

`TitleButtonsLayout`：10×10，关闭按钮左边 2 px；面板太窄放不下时不显示；悬停提示 `panel.mcfloatingbackpack.snapshot.tooltip`；点击 → `SnapshotScreen.open()`（客户端直接开，不经服务端）。编号文字的右界让到这个按钮左边。

## 快捷键

`key.mcfloatingbackpack.snapshots`，默认不绑定，类别与已有按键相同（`key.categories.mcfloatingbackpack`）；按下（无界面或宿主界面在场）→ `SnapshotScreen.open()`。
