# Feature Specification: 搜索前缀语法（`@模组`、`#标签`、`/hidden`）

**Feature Branch**: `044-search-prefix-syntax`

**Created**: 2026-11-12

**Status**: Draft

**Input**: 用户确认（2026-11-12）的搜索方案第 3 节（`docs/plan/backpack-search.md`）：在 042 的基础语法上增加三个前缀——`@模组`（按物品所属模组）、`#标签`（背包自己的标签、原版与其它物品标签、NeoForge 的 `c:` 标签的并集）、查询最开头的 `/hidden`（查看被隐藏的物品）。建立在 042（`specs/042-backpack-search-core`）与 043（`specs/043-search-terms-provider-api`）之上。

## Clarifications

### Session 2026-11-12

- Q: `/hidden` 要显示什么？（plan 阶段读代码发现：服务端只把隐藏行的**摘要**——每个类别有几格非空——发给客户端，隐藏行里的物品本身不在客户端；原方案里"客户端已有隐藏行数据，不用新增同步"不成立。） → A: **摘要模式**：`/hidden` 只列出"哪些类别有隐藏物品、各几格"（沿用 037 的数据与说法），**不显示物品本身**；无网络改动、协议号仍 17。同步隐藏物品并显示灰色只读格子的做法**不做**（可另开 feature）。
- 沿用的确认（2026-11-12 方案第 3 节，不再讨论）：`@模组` 同时匹配命名空间与模组显示名，后面可跟关键词继续过滤；`#标签` 取背包标签、物品标签、`c:` 标签的并集，不带冒号按标签路径子串匹配，带冒号按完整 id 前缀匹配；`/hidden` 只能出现在整条查询的最开头；别处的 `/` 是普通字符。

## 背景

042 的搜索只会按物品的名字（当前语言显示名、注册名路径）找东西，043 又让别的模组能增加可搜的文字。但玩家常常想按"来源"找：某个模组的所有东西（`@mekanism`）、某一类东西（`#ingots`、`#垃圾`），或者想知道"我的东西为什么不见了"（取下了分类扩展后，那一行的物品被隐藏，037 用黄点提示过）。044 补上这三种查法，并让它们与 042 的"并且/或/排除/整段"自由组合。

## Out of Scope（本阶段不做）

- **隐藏物品本身的显示**：同步隐藏行里的物品、灰色只读格子、对隐藏物品的选取与操作（见 Clarifications）；`/hidden` 之后的 `@`、`#` 对隐藏行不起作用（见 US3）。
- 其它 `/` 指令（排序、整理等）；其它前缀（`$`、`%`、`&` 等）；标签或模组名的自动补全与下拉提示；Ctrl/Cmd+F。
- 修改背包标签、分类扩展、隐藏行的任何规则；搜索框的外观与标题栏布局（042）；搜索词提供者接口（043，提供者的词只参与普通词的匹配，不参与 `@`、`#`）。
- 服务端、网络包、协议号（仍 17）、配置、依赖、数据格式的改动；新贴图。

## 已查证的事实（读本仓库源码；规格要尊重）

- 042 的解析在 `SearchQuery`：每个"项"由若干"备选"组成，备选有 `negated` 与 `text`；`@`、`#`、开头的 `/` 现在是普通字符（`contracts/query-syntax.md` 的最后一行用例）。匹配只问 `TextMatcher.contains(小写文字)`，没有"这个物品属于哪个模组、带哪些标签"的信息，所以 044 要给匹配增加这类"物品属性"（具体形式 plan 定）。
- 客户端已有：物品的注册名（命名空间 + 路径）；`ClientBackpackView.tags()`（018：当前背包的标签，按物品）；世界的物品标签（随世界同步到客户端）。模组的显示名在客户端的模组列表里。
- **隐藏行**：`RowView.hidden` 只有摘要（`RowSet.HiddenSummary(类别, 非空格数)`）；037 的黄点提示用 `HiddenHint.lines(...)` 与语言键 `panel.mcfloatingbackpack.hidden.title/line/hint`（"%s: %s slots hold items"、"Put the matching category extension back into a tool area to get them back"）说明。隐藏物品本身**不在**客户端。
- 工具区命中框每帧调用同一个匹配入口（042 的 `SearchContext.toolMatches`），所以新属性的查询在渲染路径上也会被问到（需要便宜）。
- 042 的搜索状态（会话内、关闭面板即清空）与"拿走再放回"规则不变；044 不碰结果映射与选区规则。

## 尚未验证（plan 阶段先查证；验证前不得声称已满足）

- **背包标签（018）在客户端的数据形态**：`ItemTags` 能否回答"这个物品带哪些背包标签"（预设标签的 id 与当前语言名、自定义标签的名字），以及标签随背包同步的时机。
- **物品标签的客户端读取**：`ItemStack`/`Item` 的标签集合（含 `minecraft:`、`c:` 与其它模组的）在客户端是否完整；对 400 格每次按键重算的成本，以及是否需要缓存（按物品种类缓存，在标签数据重载时失效）。
- **模组显示名的来源**：`ModList` 里取显示名的方法与对"没有显示名"的退路；原版（`minecraft`）与 NeoForge 自身（`neoforge`）的显示名。
- **`/hidden` 摘要在主区域里怎么画**：3 列最窄面板里的文字排布与截断；与 037 黄点提示的文字复用。
- **前缀与 042 解析的结合**：引号内的 `@`、`#` 是普通字符；`-@mod`、`@a|@b` 这类备选里的前缀；`/hidden` 前的空白。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 按模组找物品：`@模组` (Priority: P1)

玩家的背包里有原版物品和几个模组的物品。输入 `@minecraft` 只剩原版物品；输入 `@mekanism ingot` 只剩 Mekanism 的、名字含 ingot 的物品；输入模组的显示名（`@Sophisticated`）也能命中。

**Why this priority**: 整理背包最常见的需求之一，也是最容易实现和验证的前缀。

**Independent Test**: 背包里放原版物品与两个模组的物品；输入 `@minecraft`、`@<模组 id 的一部分>`、`@<模组显示名的一部分>`、`@x name`，对照预期；不存在的模组 `@nosuchmod` 无结果。

**Acceptance Scenarios**:

1. **Given** 背包里有原版与某模组的物品，**When** 输入 `@minecraft`，**Then** 只有命名空间含 `minecraft` 的物品命中（子串、不区分大小写）。
2. **Given** 模组 id 为 `sophisticatedbackpacks`、显示名为 "Sophisticated Backpacks"，**When** 输入 `@sophisticated`，**Then** 它的物品命中（命名空间子串）；输入 `@"sophisticated backpacks"`——**引号在 `@` 之后**——也按显示名命中，见 FR-004。
3. **Given** `@mekanism ingot`（两项，空格 = 并且），**Then** 只留下既属于该模组、又在名字或注册名里含 ingot 的物品。
4. **Given** `@nosuchmod`，**Then** 没有任何格子命中，搜索框计数为 0。
5. **Given** 工具区里有该模组的物品，**Then** 工具区的命中框同样按 `@` 判断（042 的规则：工具区只加框、不过滤）。
6. **Given** 只输入 `@`，**Then** 视为空的备选，被忽略（与 042 的单独 `-` 一致）。

### User Story 2 - 按标签找物品：`#标签` (Priority: P1)

玩家输入 `#logs` 找所有原木，`#ingots` 找所有锭，`#垃圾` 或 `#trash` 找自己标成垃圾的东西，`#c:ingots/iron` 精确找铁锭。三类标签取并集：背包自己的标签（018）、物品标签（原版、别的模组的）、NeoForge 的 `c:` 标签。

**Why this priority**: 用户明确要求；也是让"按类别找"成立的关键。

**Independent Test**: 背包里放几种原木、木板、锭，并把一些物品标上预设标签"垃圾"与一个自定义标签；输入 `#logs`、`#ingots`、`#c:ingots`、`#minecraft:logs`、`#垃圾`/`#trash`、自定义标签名，对照预期。

**Acceptance Scenarios**:

1. **Given** 各种原木，**When** 输入 `#logs`，**Then** 所有路径含 `logs` 的物品标签（如 `minecraft:logs`、`minecraft:oak_logs`、`c:…`）下的物品命中（不带冒号：按标签 id 的**路径部分**子串匹配）。
2. **Given** 铁锭、金锭，**When** 输入 `#c:ingots`，**Then** 属于 id 以 `c:ingots` 开头的标签（含 `c:ingots/iron`、`c:ingots/gold`）的物品命中（带冒号：按**完整 id 前缀**匹配）。
3. **Given** 输入 `#minecraft:logs`，**Then** 只有 `minecraft:logs` 及 id 以它开头的标签下的物品命中。
4. **Given** 背包里把一些物品标成了预设标签"垃圾"（id `trash`），**When** 输入 `#垃圾`（中文界面）或 `#trash`，**Then** 这些物品命中（预设标签的当前语言显示名与 id 都能匹配，子串、不区分大小写）；自定义标签按它的名字匹配。
5. **Given** 一个物品同时属于背包标签与物品标签，**Then** 任一类标签命中即命中（并集）。
6. **Given** `#nosuchtag`，**Then** 无结果；只输入 `#`，视为空的备选，被忽略。
7. **Given** 工具区里有符合的物品，**Then** 工具区命中框同样按 `#` 判断。

### User Story 3 - 查看被隐藏的物品：`/hidden`（摘要） (Priority: P2)

玩家取下了某个分类扩展，那一行的物品被隐藏，面板上有黄点提示。输入 `/hidden`，主区域显示"哪些类别还有隐藏物品、各几格"（与黄点提示相同的数据与说法），告诉玩家"把对应的分类扩展放回去即可"。输入未知指令（如 `/foo`）则无结果并提示"未知指令"。

**Why this priority**: 回答"我的东西为什么不见了"；因为隐藏物品本身不在客户端，只做摘要，所以价值有限、排在 `@`、`#` 之后。

**Independent Test**: 背包装了分类扩展并在该行放了物品，再取下该扩展：输入 `/hidden`，主区域列出该类别与格数、不显示物品格子；没有隐藏物品时显示"没有隐藏的物品"；`/hidden fish` 按类别名过滤；`/foo` 与 `/` 显示"未知指令"；`a /hidden` 里的 `/hidden` 是普通字符。

**Acceptance Scenarios**:

1. **Given** 有隐藏的物品，**When** 输入 `/hidden`，**Then** 主区域**不再显示物品格子**，改为按类别逐行显示"类别名：N 格有物品"（与 037 黄点提示一致的数据与说法，按固定类别顺序），并给出"把对应的分类扩展放回工具区即可取回"的说明；搜索框计数显示隐藏格总数。
2. **Given** 没有任何隐藏物品，**When** 输入 `/hidden`，**Then** 主区域显示"没有隐藏的物品"，计数为 0。
3. **Given** `/hidden fish`（`/hidden` 后接普通词），**Then** 只列出类别的当前语言显示名或 id 含 `fish` 的行；`/hidden` 之后的词只过滤这些行，**不**当作物品名过滤。
4. **Given** `/hidden @mekanism` 或 `/hidden #x`，**Then** 没有行命中（`@`、`#` 对隐藏行不起作用，见 FR-012）。
5. **Given** `/foo`、`/`、`/h`（不是完整的已知指令），**Then** 没有任何结果，搜索框悬停提示"未知指令：…（可用：/hidden）"。
6. **Given** `apple /hidden` 或 `"/hidden"`，**Then** 那里的 `/hidden` 是普通字符，按物品名匹配（042 的行为）；只有**整条查询最开头**（允许前面有空白）的 `/hidden` 是指令。
7. **Given** `/hidden` 的显示状态，**Then** 工具区不加命中框；选区被清空；点击主区域不会对任何背包格子操作（没有格子可点）；按 Esc 或 `×` 清除后恢复完整显示。

### User Story 4 - 与基础语法自由组合 (Priority: P2)

玩家写 `@minecraft #logs`（并且）、`#logs|#planks`（或）、`-#planks`（排除）、`@mekanism -ingot`、`"@minecraft"`（引号里是普通字符）。前缀项与 042 的普通词在同一套"并且/或/排除/整段"规则里。

**Why this priority**: 前缀不能独立于基础语法，否则 042 的规则被破坏。

**Independent Test**: 查询解析的纯逻辑单元测试（见 FR-014）加游戏里抽查几条组合。

**Acceptance Scenarios**:

1. **Given** `@minecraft #logs`，**Then** 同时满足"属于 minecraft"与"带 logs 标签"。
2. **Given** `#logs|#planks`，**Then** 带 logs 标签**或**带 planks 标签的物品命中。
3. **Given** `-#planks`，**Then** 排除带 planks 标签的物品；`@mekanism -ingot` 是"该模组、且名字不含 ingot"。
4. **Given** `"@minecraft"`（整段，含引号），**Then** 是普通词，按物品名子串匹配（几乎不命中）；`@"minecraft"` 的写法见 FR-004。
5. **Given** 042 的所有既有写法（`oak log`、`iron|gold`、`-planks`、`"oak log"`），**Then** 结果与 042 完全一致（042 的测试不改而通过）。

### Edge Cases

- **前缀后面没有内容**：`@`、`#`、`-@`、`-#` 都是空的备选，被忽略（同 042 的单独 `-`）；`@ mekanism` 是 `@`（忽略）加普通词 `mekanism`。
- **大小写**：前缀后的内容不区分大小写。
- **提供者的词**（043）：只参与普通词的匹配，不参与 `@`、`#`。
- **物品没有任何标签**：`#任何` 都不命中它；`-#x` 不排除它。
- **标签数据尚未同步或为空**（刚进世界）：`#` 查询无结果，不报错。
- **模组没有显示名**：只按命名空间匹配。
- **工具区命中框**：每帧问同一入口，`@`、`#` 的判断必须便宜（按物品种类缓存，标签数据变化时失效）；`/hidden` 状态下工具区不加框。
- **`/hidden` 与 042 的状态**：进入与退出 `/hidden` 都走 042 的"查询变化"路径（清选区、回滚动、重算）；`/hidden` 状态下 `liveCount` 是隐藏格总数。
- **`/` 在中间**：`a/b`、`foo /hidden` 的 `/` 是普通字符。
- **查询超长**：沿用 042 的 100 个字符上限。
- **窄面板（3 列）**：`/hidden` 的文字行必须放得下（换行或截断加悬停提示，plan 定）；不得溢出面板。
- **选区与"拿走再放回"**：042 的规则不变；`@`、`#` 的结果与普通词结果的操作完全一样。

## Requirements *(mandatory)*

### Functional Requirements

**`@模组`**

- **FR-001**: 备选以未被引号括起的 `@` 开头（后面有内容）时，MUST 解释为"物品所属模组"条件：该物品的注册名**命名空间**，或所属模组的**显示名**，含有 `@` 之后的文字（子串、不区分大小写）即成立。
- **FR-002**: `@` 条件 MUST 与 042 的并且（空格）、或（`|`）、排除（`-` 在 `@` 之前，即 `-@mod`）、整段规则一致：每个 `@` 备选就是一个"属性备选"，参与同样的合并。
- **FR-003**: 单独的 `@` 或 `-@` MUST 视为空的备选（被忽略）。
- **FR-004**: `@` 之后紧跟引号（`@"sophisticated backpacks"`）时，引号内是该模组条件的整段内容（可含空格）；引号包住整个 `@…`（`"@minecraft"`）时是普通词。

**`#标签`**

- **FR-005**: 备选以未被引号括起的 `#` 开头（后面有内容）时，MUST 解释为"物品标签"条件，三类标签**取并集**：（a）当前背包的标签（018 的预设与自定义标签）；（b）物品标签（原版与其它模组的，随世界同步）；（c）NeoForge 的 `c:` 标签（属于物品标签，命名空间为 `c`）。
- **FR-006**: `#` 之后的文字**不含冒号**时，MUST 按标签的**路径部分**做子串匹配（物品标签与 `c:` 标签：取冒号后的路径；背包标签：见 FR-007）；**含冒号**时 MUST 按**完整标签 id 的前缀**匹配（不区分大小写）。
- **FR-007**: 背包标签 MUST 同时按它的 id 与它在当前语言里的显示名匹配（预设标签如 `trash`/"垃圾"；自定义标签按它的名字，含中文）；背包标签没有命名空间，所以**含冒号**的 `#` 查询对背包标签不命中。
- **FR-008**: `#` 条件 MUST 与 042 的并且、或、排除（`-#tag`）规则一致；单独的 `#` 或 `-#` 视为空的备选。
- **FR-009**: 物品没有任何标签时，`#` 条件不成立；标签数据不可用时 `#` 查询无结果、不报错。

**`/hidden`**

- **FR-010**: 整条查询去掉前导空白后以 `/` 开头时，MUST 作为指令解析：整个第一个"词"（到第一个空白为止，转小写）等于 `/hidden` 时是 `/hidden` 指令；其它（包括单独的 `/`、`/h`、`/foo`）是**未知指令**。其它位置的 `/`（含引号内）MUST 是普通字符。
- **FR-011**: `/hidden` 指令 MUST 让主区域改为"隐藏摘要"显示：不显示任何物品格子，按 037 的固定类别顺序、逐行显示"类别名：N 格有物品"（数据与说法与 037 黄点提示一致，不新增网络数据），并给出"把对应的分类扩展放回工具区即可取回"的说明；没有隐藏物品时显示"没有隐藏的物品"；搜索框计数显示隐藏格总数。
- **FR-012**: `/hidden` 之后的剩余文字 MUST 只当作对**类别行**的过滤：按并且（空格）规则，每个普通词要在该类别的当前语言显示名或 id 里出现；剩余文字里的 `@`、`#` 备选对类别行**不成立**（因此没有行命中）。
- **FR-013**: 未知指令 MUST 无任何结果（主区域为空、工具区无框、计数 0），搜索框悬停提示 MUST 说明"未知指令：<输入的指令>（可用：/hidden）"；不得崩溃。
- **FR-014**: `/hidden` 状态下 MUST：清空选区，工具区不加命中框，主区域没有可点击的背包格子（不对任何背包格子发请求）；退出（改查询、Esc、`×`）走 042 的"查询变化"路径。

**组合、解析与范围**

- **FR-015**: 解析 MUST 由 042 的纯类 `SearchQuery` 扩展：备选带"种类"（普通词 / 模组 / 标签）、`negated`、文字；整条查询另有可选的"指令"（`/hidden`、未知）。042 的全部解析与匹配测试 MUST 不改而通过；`@`、`#`、开头的 `/` 在引号内一律是普通字符。

## Assumptions

- **物品标签范围**：`#` 的物品标签**包含所有命名空间**（原版、`c:`、以及别的模组注册的物品标签），不只是原版与 `c:`；用户列出的原版与 `c:` 是其中最常用的两类。
- **模组显示名**：取模组元数据里的显示名（不随游戏语言变化）；没有时只用命名空间。
- **`@` 与注册名**：只看物品注册名的命名空间；不考虑方块、实体等其它注册表。
- **`/hidden` 之后的过滤**只对类别行有效；因为隐藏物品本身不在客户端，所以不可能按物品名过滤隐藏物品——这是摘要模式的已知限制，不是缺陷。
- **整条查询只有一个指令**：`/hidden` 之后若再出现 `/xxx`，那是普通字符（对类别行的过滤词）。
- 042 的"单独 `-`、`iron|` 等为空备选而忽略"的规则同样适用于 `@`、`#`。
- 本 feature 的游戏内自动验证在容器里做；真实输入法（中文标签名）上屏由用户在真机验证。
- 不另做版本号或协议变化；若将来要做"同步隐藏物品"，另开 feature 并走协议升级流程。
