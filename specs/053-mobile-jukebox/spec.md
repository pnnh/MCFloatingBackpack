# Feature Specification: 移动唱片机（右区工具，唱片扩展行当播放列表的极简播放器）

**Feature Branch**: `053-mobile-jukebox`

**Created**: 2026-11-13

**Status**: Draft

**Input**: 用户（2026-11-13）："移动工作台需求：参考旅行者背包……实现普通工作台、熔炉、唱片机这三种移动工作台扩展工具……只能放置在浮动背包面板的右侧扩展区域才会生效……点击展开右侧扩展面板（类似垃圾桶）……唱片机原版似乎没有可以打开的交互界面，我们需要自己实现：点击它展开'播放控制'扩展页面，作用是一个极简的音乐播放器，包含开始、暂停、上一曲、下一曲。它播放的，就是我们在之前需求中实现的'唱片扩展'行中放置的各个唱片。玩家可能放置了多个'唱片扩展'行，此时需要循环播放。"——可行性分析后确认：三个都是新物品；先做唱片机（本 feature），工作台与熔炉各自随后；唱片机不做暂停（原版没有单个声音的暂停，要碰内部接口），改成"倒带"；加上单曲循环与列表随机。全部规划见 [docs/plan/mobile-tools.md](../../docs/plan/mobile-tools.md)。

## Clarifications

### Session 2026-11-13（可行性分析阶段，用户已确认）

- Q: 是新物品还是直接用原版唱片机方块？ → A: **新物品** `mobile_jukebox`（移动唱片机），像垃圾桶、自动拾取一样；配方中等以上难度（见下）。
- Q: 放哪里、放几个？ → A: **只在右侧工具区生效**，**右区里最多放一个**；左区、下区放得下但不生效、不计入限制；不考虑皮背包右区格子少。
- Q: 控件有哪些？ → A: 上一曲、播放 / 停止、下一曲、**倒带**（从头重播当前曲，替代暂停）、**单曲循环**开关、**列表随机**开关。**不做暂停**（要碰声音引擎的内部接口）。
- Q: 播放列表读哪里？ → A: 按 B 打开的那只背包里**可见的**唱片扩展行（类别 `disc`）里的唱片；**多个唱片扩展行彼此不连续（中间夹着别的扩展行）也要完整读到**；**隐藏的唱片行不算**；默认列表循环。
- Q: 别的玩家听得到吗？ → A: **听不到**（客户端播放，与旅行者背包一致）；用户没有表示需要，按默认处理，若以后要另议。

## 背景

浮动背包的右侧工具区现在有垃圾桶：把它放进右区，左键点它（光标为空）会展开一页挂在面板右边的垃圾桶页，右键仍然是拿起。本 feature 加第二个同类工具：**移动唱片机**。它也是放进右区、左键展开一页——"播放控制"页，一个只有几个按钮的极简播放器，播放的是背包里"唱片扩展"行（036～038 的分类扩展，类别 `disc`）里放着的唱片。

原版没有"可以打开的唱片机界面"，声音由方块唱片机在世界里播放；这里是客户端自己播放（跟着玩家走），所以不需要网络包，也没有新的存储数据。旅行者背包的唱片升级也是这样做的：客户端创建一个跟着实体走的声音实例，只有"播放 / 停止"（见规划文档）。

## 物品与配方

- 物品 `mobile_jukebox`：中文"移动唱片机"，英文 "Mobile Jukebox"；堆叠 1；放在创造物品栏自动拾取之后；进 `never_trash`；16×16 手绘占位贴图（用户之后可用同名文件替换）；提示文字说明"放进右区，左键点它打开播放控制"。
- 配方（有序，`category: misc`，不加进度）：`IDI` / `NJN` / `IEI`，`I` 铁锭、`D` 钻石、`N` 音符盒（左右各一）、`J` 唱片机、`E` 绿宝石。

## 播放控制页

挂在面板右边缘、顶部与面板对齐（与垃圾桶页同一位置，**同一时间只展开一个**：展开唱片机页时垃圾桶页收起，反之亦然）。内容：标题栏；当前曲名与"第几首 / 共几首"；一排按钮：上一曲、播放 / 停止、倒带、下一曲；两个开关：单曲循环、列表随机；没有唱片时显示提示"唱片扩展行里没有唱片"。

| 控件 | 行为 |
|---|---|
| 播放 / 停止 | 没在播放 → 从当前那首的开头开始播放（第一次从列表第一首，随机模式从随机一首）；在播放 → 停止（记住当前曲目，不记进度） |
| 倒带 | 当前曲目**从头重新播放**（没在播放时等同"播放"） |
| 下一曲 / 上一曲 | 切到下一首 / 上一首并播放；顺序模式按列表顺序，到头循环；随机模式"下一曲"取洗牌里的下一首，"上一曲"回到上一首放过的 |
| 单曲循环 | 开：当前曲放完重放，不前进（"下一曲"按钮仍然能切走）；关：放完按列表前进 |
| 列表随机 | 开：每一轮把列表洗牌，每首各放一次，放完重新洗牌（避免同一首紧挨着重复）；关：按列表顺序，放完最后一首回到第一首 |

## 播放列表

- 取按 B 会打开的那只背包（手 → 背 → 物品栏）的 `extension_rows` 里，**可见的**、类别为 `disc` 的行；按行的先后、每行格子从左到右、空格跳过；其它类别的行（包括夹在两个唱片行之间的）一概跳过，所以非连续的唱片行也完整读到。
- 只有带原版 `JUKEBOX_PLAYABLE` 数据组件、且能解析出 `JukeboxSong` 的物品才算唱片（别的模组的唱片只要走这个组件也行；行里被手动标签放进来的非唱片物品不算）。
- 隐藏的唱片行（扩展件被拿走）不算；列表随背包内容变化：曲目变了，下一次需要"下一首"时才重新读（正在播的这首放完为止）；列表变空则停止。
- 一只背包的右区没有移动唱片机、或换成了别的背包：停止播放。

## 声音

- 客户端创建一个跟着玩家走的声音实例（`SoundSource.RECORDS`），音量跟随原版"唱片机 / 音符盒"滑条；开始播放前停掉原版背景音乐；显示原版的"正在播放：曲名"提示；播放完毕（用 `SoundManager.isActive` 轮询）按模式接下一首。
- 退出世界、断开连接、背包换了、工具被拿走、列表空了：停止并清空状态。
- 别的玩家听不到；没有新网络包，没有新存储数据。

## 已查证的事实（读本仓库与原版 / 旅行者背包）

- 垃圾桶是自定义物品，在右区时左键（光标空）切换它的页，右键拿起（`FloatingPanelInput`）；页的几何、渲染、输入在 `client/panel/trash/`；`ToolAreaRules` 给每个区限定某工具至多一个（旧背包多于上限时保留、不能再加）。
- `JukeboxSong.fromStack(HolderLookup.Provider, ItemStack)` 存在，`JukeboxSong` 有 `soundEvent`、`description`、`lengthInSeconds`；客户端有 `SoundManager.queueTickingSound`、`stop(id, source)`、`isActive(instance)`，`MusicManager.stopPlaying()`，`Gui.setNowPlaying(Component)`。
- 旅行者背包的唱片升级（读它的 jar）：`JukeboxWidget$MovingSound extends AbstractTickableSoundInstance`（跟着实体）、`queueTickingSound` 播放、`stop(id, SoundSource)` 停止、`setNowPlaying`、`JukeboxSong.fromStack`；只有播放 / 停止，没有暂停，也没发现向别的玩家广播。
- 原版没有"暂停单个声音"：`SoundEngine.pause()` 是全局的，单个声音要访问私有的 `instanceToChannel`，所以不做暂停。
- 唱片扩展行的数据在 035 的 `RowSet`（`visible` 列表，每行 `category` 与 9 个格子）；客户端的面板已经有这只背包的行（`ClientBackpackView`）。

## 尚未验证（plan 阶段先查证；验证前不得声称已满足）

- 客户端读行内容的确切入口（`ClientBackpackView` 的行视图，格子里的 `ItemStack`），以及"读到的是按 B 的那只背包"是否与面板显示的那只一致。
- 跟着玩家走的声音实例的衰减与音量：在自己头上放，要听起来是"在耳边"而不是定位偏移；与原版唱片的单声道 / 立体声的关系。
- 原版背景音乐在唱片开始时的行为（`MusicManager.stopPlaying()` 之后会不会马上又播）。
- 两个页（垃圾桶页、播放控制页）同位置互斥的实现：现有页的"点击归属"（`covers`）与按键处理是否要改成统一的页注册表。
- `ToolAreaRules` 里"右区至多一个垃圾桶"如何扩成"右区至多各一个"，且对 011～052 的测试影响最小。
- 创造模式、在容器界面（箱子、背包界面）、没有界面时的宿主界面里，点右区的唱片机是否都能展开页并响应按钮。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 移动唱片机物品：合成、放进右区、每种一个 (Priority: P1)

玩家用配方合成移动唱片机，放进背包面板右区，左键点它展开"播放控制"页。右区最多放一个；放在左区或下区没有效果。

**Why this priority**: 没有物品就没有播放器。

**Independent Test**: 创造栏取到；按配方合成；放进右区，左键点它页展开，再点一下收起；右键拿起；再放一个被拒并提示；放在左区或下区点它不展开页。

**Acceptance Scenarios**:

1. **Given** 配方表，**Then** 有一个有序配方，图样与材料与上面一致，结果 1 个；不加解锁进度。
2. **Given** 右区已有一个移动唱片机，**When** 再放第二个，**Then** 被拒并提示"右区已经有一个移动唱片机了"；同格替换允许；保存时已有多个的旧背包保留、不能再加。
3. **Given** 移动唱片机在左区或下区，**Then** 点它不展开页（也不计入右区的限制）。
4. **Given** 展开了垃圾桶页，**When** 展开唱片机页，**Then** 垃圾桶页收起（反之亦然）。
5. **Given** 中英文界面，**Then** 物品名与提示都有对应的语言键。

---

### User Story 2 - 播放控制：开始、停止、上一曲、下一曲、倒带 (Priority: P1)

玩家展开页，点播放，听到唱片扩展行里的第一首唱片；可以停止、切歌、倒带。

**Why this priority**: 这是功能的目的。

**Independent Test**: 开发运行里造一只右区带移动唱片机、唱片行里有 3 张唱片的背包；展开页点播放，听到并看到曲名；点下一曲、上一曲、倒带、停止，行为与表一致；容器自动验证读日志与客户端状态，听觉由用户确认。

**Acceptance Scenarios**:

1. **Given** 列表里有唱片，**When** 点播放，**Then** 播放第一首，显示"正在播放：曲名"，页上显示"1 / 3"；原版背景音乐不再同时响。
2. **Given** 正在播放，**When** 点停止，**Then** 声音停止；再点播放，从当前曲目的开头重新开始。
3. **Given** 正在播放，**When** 点倒带，**Then** 当前曲目从头重新播放。
4. **Given** 正在播放第 1 首，**When** 点下一曲，**Then** 播放第 2 首；**When** 点上一曲，**Then** 回到第 1 首；在列表两端循环。
5. **Given** 一首放完，**Then** 按模式自动接下一首（顺序：下一首，最后一首接第一首）。
6. **Given** 列表里没有唱片，**Then** 页上显示提示，所有按钮不起作用（不报错）。

---

### User Story 3 - 播放列表读全所有唱片扩展行，单曲循环与随机 (Priority: P1)

背包里放了多个唱片扩展行，中间还夹着别的扩展行；播放列表按顺序读到所有行里的所有唱片；可以单曲循环、可以列表随机。

**Why this priority**: 用户明确要求的核心逻辑。

**Independent Test**: 纯逻辑测试：给定行的列表（唱片行、别的行、隐藏行、空格），取出的播放列表等于预期；顺序、单曲循环、随机（洗牌）的"下一首、上一首"序列符合规则。

**Acceptance Scenarios**:

1. **Given** 可见行依次为：唱片行 A（3 张）、食物行、唱片行 B（2 张），**Then** 播放列表是 A 的 3 张 + B 的 2 张，顺序为行序加格子序，空格跳过。
2. **Given** 一个隐藏的唱片行，**Then** 它的唱片不在列表里；放回扩展件后（变成可见）下一次读取时进入列表。
3. **Given** 单曲循环开，**When** 当前曲放完，**Then** 重放同一首，不前进；点下一曲仍然切走。
4. **Given** 列表随机开，**Then** 每一轮列表里的每首各放一次，顺序随机；一轮放完重新洗牌；紧挨着的两轮之间尽量不让同一首相连；上一曲回到上一首放过的。
5. **Given** 播放中把当前这张唱片拿走，**Then** 这首放到结束，下一首从更新后的列表里取；列表变空则停止。
6. **Given** 行里有一个被手动标签放进去的非唱片物品，**Then** 它不在列表里。

---

### User Story 4 - 数据与版本兼容 (Priority: P2)

没有新的存储数据、没有新网络包；新物品让数据修订 3 → 4；老背包照常载入；快照（030）能保存与恢复带移动唱片机的背包。

**Why this priority**: 项目一贯的数据底线。

**Acceptance Scenarios**:

1. **Given** 本 feature，**Then** 协议号仍为 19；没有新的网络包、配置项、依赖；`DataRevision.CURRENT` 3 → 4（新的只能存在背包里的物品种类），在 DELIVERY 写明理由。
2. **Given** 旧背包，**Then** 照常载入、功能不变。
3. **Given** 带移动唱片机的背包做快照再恢复，**Then** 内容一致。

---

### Edge Cases

- **背包换了**（按 B 的背包变了）、**工具被拿走**、**右区的唱片机被换成别的**：停止并收起页。
- **正在播放时关闭面板或切换界面**：音乐继续（它是"跟着玩家的背景音乐"），页收起；再展开页，显示当前状态。
- **唱片被移到别的行**（仍可见的唱片行）：下一次读取时按新位置重算，曲目序号可能变化；正在播的不受影响。
- **与原版唱片机方块同时播放**：互不影响（各管各的声音）。
- **退出世界、断开连接**：停止；重进后是停止状态，开关（单曲循环、随机）恢复默认（关）。
- **音量为 0 / 静音**：照常"播放"（计时与曲目前进不变），由玩家的音量设置决定能否听到。
- **创造模式的光标、容器界面里**：展开页与按钮与垃圾桶页同样可用（plan 阶段验证）。
- **别的模组的唱片**：走 `JUKEBOX_PLAYABLE` 的才支持；靠自己逻辑的不支持，写进已知局限。
- **降级**：不支持（口径不变）。

## Requirements *(mandatory)*

### Functional Requirements

**物品、配方与放置**

- **FR-001**: MUST 有物品 `mobile_jukebox`（堆叠 1），中英文名与提示；创造栏在自动拾取之后；进 `never_trash`；16×16 手绘占位贴图与模型。
- **FR-002**: MUST 有一个有序配方：`IDI` / `NJN` / `IEI`（`I` 铁锭、`D` 钻石、`N` 音符盒、`J` 唱片机、`E` 绿宝石）；`category: misc`；不加解锁进度。
- **FR-003**: 移动唱片机 MUST 只在**右侧工具区**生效；右区里 MUST 至多放一个（服务端校验，客户端预览同口径，被拒时有提示；同格替换允许；旧背包已有多个时保留、不能再加）；放在左区或下区放得下但不生效、不计入限制；该限制 MUST 与垃圾桶的限制互相独立。
- **FR-004**: 左键点右区的移动唱片机（光标为空）MUST 展开或收起"播放控制"页；右键 MUST 仍是拿起；Shift / Ctrl 点击与拖拽按现有工具的规则不触发页。
- **FR-005**: 播放控制页 MUST 与垃圾桶页同一位置，同一时间 MUST 只展开一个（展开一个收起另一个）。

**播放列表**

- **FR-006**: 播放列表 MUST 取按 B 会打开的那只背包的 `extension_rows` 里**可见的**类别为 `disc` 的行：行序 + 格子序，空格跳过；其它类别的行一概跳过，**不连续的唱片行也要完整读到**；隐藏行 MUST NOT 计入。
- **FR-007**: 只有能解析出 `JukeboxSong`（带 `JUKEBOX_PLAYABLE` 组件）的物品 MUST 算唱片。
- **FR-008**: 列表 MUST 在每次需要"取下一首 / 上一首 / 第几首"时从当前背包内容读取（不缓存过期内容）；列表变空时 MUST 停止播放。

**播放控制**

- **FR-009**: MUST 有六个控件：上一曲、播放 / 停止、倒带、下一曲、单曲循环开关、列表随机开关；行为见上表。**MUST NOT 有暂停**。
- **FR-010**: 默认 MUST 是列表循环；单曲循环 MUST 优先于列表循环；列表随机 MUST 每轮洗牌、每首各放一次，上一曲回到上一首放过的。
- **FR-011**: 一首放完 MUST 按模式自动接下一首；没有唱片时所有按钮 MUST 不起作用且不报错，页上有提示。
- **FR-012**: 背包换了、工具被拿走、列表空了、退出世界或断开连接：MUST 停止并清空状态；单曲循环与随机开关 MUST 恢复默认（关）。

**声音**

- **FR-013**: MUST 在客户端用一个跟着玩家走的声音实例播放（`SoundSource.RECORDS`，音量跟随原版"唱片机 / 音符盒"滑条）；开始前 MUST 停掉原版背景音乐；MUST 显示原版的"正在播放"提示；MUST NOT 用反射或访问转换器去碰声音引擎的内部接口。
- **FR-014**: 别的玩家 MUST NOT 听到（没有声音广播）。

**数据与兼容**

### Key Entities *(include if feature involves data)*

- **移动唱片机（Mobile jukebox）**：新物品，无状态；只在右区生效，每个背包右区至多一个。

- **播放状态（Playback state）**：客户端会话内的当前曲目、是否在播放、单曲循环、列表随机、随机洗牌队列与已放过的历史；不存储、不同步。

## Assumptions

- 配方是第一稿，用户可以只改一个 JSON 与一张表；贴图是占位手绘，用户之后替换。
- "播放 / 停止"停止后再播放从当前曲目开头开始；是否记住进度不做（要碰内部接口）。
- "倒带"即"重头开始播放"，播放中与停止时都能点。
- 列表来自按 B 的背包，与面板显示的是同一只；别的玩家的背包不看。
- 本 feature 不做工作台与熔炉（054、055），不做高炉与烟熏炉；不做暂停、音量条、进度条、曲目点选。
