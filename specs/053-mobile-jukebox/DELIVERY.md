## 改了什么

- 物品 `mobile_jukebox`（`MobileJukeboxItem`，堆叠 1，右区才生效）、模型、手绘贴图（`make_mobile_tool_icons.py`，以后工作台、熔炉的图标加在同一个脚本里）、配方 `IDI/NJN/IEI`、中英文语言键、`never_trash`、创造栏（自动拾取之后）。
- 右区"各至多一个"：新的纯逻辑 `ToolSingleRules`（服务端 `BackpackClickPayload` 与客户端预览 `FloatingPanelInput` 各接一处），不改 `ToolAreaRules` 的签名；054、055 的工作台与熔炉各加一个判定即可。
- 纯逻辑：`PlaylistReader`（读可见的 `disc` 行，行序加格子序，跳过空格、非唱片、别的类别的行）、`JukeboxPlayer`（状态机：顺序、单曲循环、随机洗牌与历史、倒带、停止后再播放、列表变化与变空）、`JukeboxPanelLayout`（页几何）、`JukeboxPanelState`。
- 客户端：`JukeboxPlayback`（读**玩家背包栈**而不是面板视图，因为面板关闭时视图会清空；用歌曲数据里的 `lengthInSeconds` 加 20 tick 计时，游戏暂停时不累加）、`MobileJukeboxSound`（`RECORDS`、相对听者、不衰减）、页的输入与渲染（填充与文字，不用贴图；与垃圾桶页同位置，互斥）。
- 接线：`FloatingPanelInput`（点右区唱片机展开、与垃圾桶页互斥、`onPress` 先于面板命中测试）、`FloatingPanelRenderer`、`ClientBackpackView.hasMobileJukebox()`、`FloatingPanelEvents`（收起条件、关闭面板时页收起但音乐继续、登录 / 登出重置并停止、客户端 tick 驱动、滚轮被吞）。
- **数据修订 3 → 4**（新的只能存在背包里的物品种类，同 051 的理由）；**协议号不变（19）**；没有新网络包、存储字段、配置项、依赖、mixin，**没有反射与访问转换器**（`JukeboxWiringTest` 断言）。

## 游戏内验证（容器 `mcfb-c1`；**容器里 OpenAL 打不开，声音是空操作，但计时与状态照常走**）

测试数据：数据包 `c53` 里三首 6 秒的自定义歌曲（`c53:s1`～`s3`，`jukebox_playable` 组件），背包的唱片行 A（Short 1、Short 2、一根木棍、…）、食物行、唱片行 B（Short 3）。

| 项 | 做了什么 | 结果 |
|---|---|---|
| 页（B1） | 左键点右区的唱片机 | 页展开，显示"Player"、曲名、"Track n of 3"、四个按钮、两个开关；再点收起 |
| 读全与顺序（B2） | 播放，连点下一曲 | Short 1 → Short 2 → **Short 3（来自被食物行隔开的第二个唱片行）** → 回到 Short 1；木棍被跳过 |
| 自动接歌（B4） | 不点任何按钮等待 | 一首放完自动接下一首；精确计时：开始后约 3.5 秒仍是原曲，约 9 秒时已是下一首（6 秒 + 1 秒余量） |
| 单曲循环（B5） | 开单曲循环，等一整首 | 仍是同一首；关掉后继续往下 |
| 随机（B5） | 开随机，连点 6 次下一曲 | 每 3 次三首各出现一次 |
| 停止、倒带、上一曲（B3） | 停止（图标变播放）→ 播放 → 倒带 → 上一曲 | 停止后再播放仍在当前曲；倒带仍在当前曲；上一曲回到前一首 |
| 隐藏行（B6） | 把一个唱片扩展件拿出左区 | 出现黄点，列表从 3 首变 2 首（隐藏行的唱片不算），播放不中断 |
| 面板关着（B9） | 播放中按 B 关闭面板，约 9～12 秒后重开 | 曲目已向前走（音乐继续、自动接歌，读的是背包栈） |
| 页互斥与限制（B7） | 右区放唱片机与垃圾桶；点垃圾桶；再点唱片机；拿第二个唱片机放右区 | 垃圾桶页替换唱片机页，再点回来；播放状态保留；第二个被拒，聊天"The right area already has a mobile jukebox" |
| 停止条件（B8） | 右键把唱片机拿出右区，再放回，点开页 | 拿出时页收起并停止；放回后是停止状态（播放图标） |
| 数据（B10） | Save and Quit 后转储玩家数据 | 背包的 `data_revision` = **4**；唱片、行、唱片机、垃圾桶都在，木棍也保留（行里的东西不丢） |
| 图集 | `check_atlas_budget.sh` 前后各一次 | 都是 2048x1024 |

**没有验证**：声音是否真的在耳边、音量跟随"唱片机 / 音符盒"滑条、原版背景音乐是否被正确停掉、衔接是否自然（容器没有声音设备，**待用户确认**）；退出世界再进入后开关恢复为关（只靠代码与 `JukeboxWiringTest`：登录与登出各重置一次）；左区、下区的唱片机点了不展开页（只靠 `JukeboxWiringTest` 断言"必须在右区"）；创造模式的光标、容器界面（箱子等）里点页（容器里只在生存模式的物品栏界面试过）；别的模组的唱片；多人联机（客户端播放，别的玩家听不到）。

## 已知局限

- **没有暂停**（刻意不做，见 spec）：停止后再播放从当前曲开头开始。
- **别的玩家听不到**（客户端播放，与旅行者背包一致）。
- 没有身份 id 的背包（从没被注册过）用"来源 + 槽位"判断"是不是同一只背包"，从手里移到物品栏会被当成换了背包而停止；注册过的背包用身份 id，不受影响。
- 别的模组靠自己逻辑（不走 `JUKEBOX_PLAYABLE` 组件）的唱片不支持。
- 音量为 0 或静音时仍然"播放"（计时与曲目前进不变），只是听不到。

## 数据修订与协议号

数据修订 **3 → 4**：新的只能存在背包里的物品种类（与 051 的新扩展件同一理由）；旧版本读到带移动唱片机的背包会把它当未知物品，040/041 的降级保护生效，发布说明要提醒"降级前先备份存档"。协议号不变（19）：没有新的网络包。
