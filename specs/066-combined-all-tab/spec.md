# Feature Specification: 联合背包 · "全部"标签

**Feature Branch**: `066-combined-all-tab`

**Created**: 2026-11-24

**Status**: 已实现，容器部分验证（见 DELIVERY.md），待用户真机确认 T027

**Input**: 用户（2026-11-24）提出的"联合背包"玩法，全文见 [docs/plan/combined-backpack.md](../../docs/plan/combined-backpack.md)（决策已定，本规格不重新讨论）。本 feature 是第二期：在 065 的联合界面里加**"全部"标签**——把所有成员背包的主区域合成一个网格来存取；并让"全部"里面板标题栏上的搜索与整理按钮作用于整张网格（整理只改**显示**）；同时取消 065 的联合标题栏（用户 2026-11-24 决定：它作用不大）。相关：065（成员表、会话目标、标签栏、协议 23，已提交）、042（搜索）、047（整理）、018/051（分类行与灰格）、026/040（身份与保护）、064（嵌套）、024/053/054/055（自动拾取与移动工具，仍只对 B 打开的那只）。

## 背景

- 065 之后，玩家穿着联合背包按 U，可以在标签间切换**单只**背包，每个标签就是那只背包的完整面板。要把一堆东西分别存进几只背包、或者找一个东西到底在哪只背包里，仍要一只一只切。
- "全部"标签把成员背包的**主区域**（含各自的分类扩展行）按顺序排进**同一个网格**：像一只大背包一样存取，不用关心物品实际在哪一只里。物品**始终真实地存在各自的背包里**，联合背包自己依旧没有数据。
- 工具区、左右区、底部功能区、垃圾桶、标签管理、快照等**属于某一只具体背包的功能**，在"全部"里不提供，要用请点具体背包的标签（065 已有）。
- 因为"全部"里的物品来自不同的背包，必须让玩家一眼看出每个格子属于哪一只；"全部"里的搜索与整理只改变**显示**，不动任何数据。
- 服务端现状（065 已就绪）：会话目标 + 统一解析 `PanelTargets.resolve`；成员表每秒重算；`BackpackClickPayload` 等面板请求都落在会话目标那一只背包上。"全部"需要在此之上加：按"成员 + 格号"寻址、每成员一份同步、会话级内存光标。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 在"全部"里像一只大背包一样存取 (Priority: P1)

玩家穿着联合背包，身上有几只背包。按 U 打开联合界面，标签栏最前面是"全部"，默认选中它：下面是一个大网格，每只成员背包的主区域依次排列，每一只从新的一行开始。点击、拖动分摊、Shift/Ctrl 点击、从背包里取出、放入、滚动，都和单只背包的主区域一样，物品实际存进/取出对应的那只背包。

**Why this priority**: 这是联合背包的核心价值：不用关心东西在哪只背包里。

**Independent Test**: 游戏内穿联合背包、物品栏放 3 只内容不同的背包，U 打开，在"全部"里取出、放入、拖动、Shift 点击，再切到具体标签核对每只背包里的内容。

**Acceptance Scenarios**:

1. **Given** 穿着联合背包、物品栏里有背包 A、B、C，**When** 按 U，**Then** 打开联合界面，标签栏第一个是"全部"并被选中；网格按成员顺序依次排出 A、B、C 的主区域，各背包的格子首尾相连（不再每只从新的一行开始），A 的第一格在最左上。
2. **Given** 在"全部"里点击属于 B 的某个有物品的格子，**When** 左键，**Then** 拿起整组物品（光标上有它），B 的那一格变空；切到 B 的标签核对也是空的。
3. **Given** 光标上有物品，**When** 点"全部"里属于 C 的一个空格，**Then** 物品放进 C 的那一格；点已有同种物品的格子则按现有规则合并/交换；右键放一个、拖动分摊都与单只背包主区域一致。
4. **Given** 一只背包的某些格子被分类行限制（灰格），**Then** 在"全部"里它们同样画成灰格，放入同样被拒绝，规则与单只背包一致。
5. **Given** 在"全部"里对某格 Shift 点击，**Then** 与单只背包一致：物品按现有规则移到玩家物品栏（叠在容器界面上时按现有规则去容器）。
6. **Given** 在物品栏里对一组物品 Shift 点击（或叠在容器界面上从容器转移到背包），**When** 当前标签是"全部"，**Then** 物品按**成员顺序**逐只尝试放入：每只先试自己的分类行再试通用格，放不下再试下一只，全部放不下才留在原处；每只真正改动过的背包各自保存。
7. **Given** 网格比面板可见行数高，**When** 滚轮，**Then** 网格滚动；标签栏、面板标题栏与滚动条不错位。
8. **Given** 当前在"全部"，**Then** 面板只显示这个网格：移动工具、左右区、底部功能区、垃圾桶、标签管理、快照按钮**不画、不响应**；面板自己的标题栏在"全部"里**保留**（紧贴在标签栏下面，拖动与关闭照旧），但不画背包编号与快照按钮，只留搜索与整理两个按钮，它们在"全部"里作用于整张网格的显示（见 US4）。

### User Story 2 - 一眼看出格子属于哪只背包 (Priority: P1)

在"全部"里每个格子底色淡淡地染成它所属背包的颜色，这个颜色与标签栏里该背包的标签色块一致；鼠标悬停在某格时提示多一行"来自 ■A3F2（物品栏第 5 格）"，并且标签栏里对应的标签高亮。

**Why this priority**: 物品来自不同背包，尤其整理（US4）之后各背包的物品交错在一起，不能区分来源就不敢操作。

**Independent Test**: 游戏内 3 只背包各放一种物品，在"全部"里核对颜色、悬停提示与标签高亮；整理后再核对。

**Acceptance Scenarios**:

1. **Given** 3 个成员，**Then** "全部"里属于第 1、2、3 个成员的格子分别染成色表里第 1、2、3 色，与标签栏里各标签的色块一致；染色不遮住物品，画在选中高亮与灰格之下。
2. **Given** 悬停在某格，**Then** 提示的最后多一行"来自 ■编号（位置）"，位置说明与 065 标签提示一致（胸甲 / 专用槽 / 副手 / 物品栏第 n 格）；空格也显示来源。
3. **Given** 悬停在某格，**Then** 标签栏里该背包的标签高亮（鼠标移开恢复）。
4. **Given** 背包增减使成员顺序变化，**Then** 颜色按成员在标签栏的新位置顺延，标签色块与格子颜色始终一致。
5. **Then** 不画格子边框、不画分区标题行（排序后它们会失效或与选中框混淆）；色盲友好性靠悬停提示补足。

### User Story 3 - 光标跨背包：从 A 拿起、放进 B (Priority: P1)

在"全部"里，光标上的物品可以从一只背包拿起、放进另一只背包。光标是**会话里的内存状态**，不写进任何背包数据；关闭联合界面、切标签、下线、成员变化时，光标上的东西会被**冲洗**：先按成员顺序塞回成员背包，塞不下进玩家物品栏，再塞不下像原版一样丢在脚下。

**Why this priority**: 没有跨背包的光标，"全部"就只是只读视图；同时光标里的东西绝不能无声消失。

**Independent Test**: 游戏内在"全部"里从 A 拿起一组物品，分别在放进 B、直接切标签、直接按 U 关闭、把 A 丢掉这几种情况下核对物品去向（尤其是背包与物品栏都满时丢在脚下）。

**Acceptance Scenarios**:

1. **Given** 从属于 A 的格子拿起物品，**When** 放进属于 B 的格子，**Then** A 少了、B 多了；总数守恒。
2. **Given** 光标上有"全部"的内存光标内容，**When** 点其他标签（含具体背包标签），**Then** **先冲洗光标再切换**（不拒绝切换）：塞回成员背包、塞不下进物品栏、再塞不下丢在脚下；冲洗后光标为空。
3. **Given** 光标上有物品，**When** 按 U / 现有方式关闭联合界面，**Then** 同样先冲洗。
4. **Given** 光标上有物品，**When** 成员表变化（拾起/丢弃背包、被挪动）使成员列表改变，**Then** 先冲洗再按新成员表继续；不会把物品落到身份对不上的背包里。
5. **Given** 光标上有物品，**When** 玩家下线或服务端停止，**Then** 光标内容被冲洗（下线与正常停服）；**服务端在持有光标时崩溃，光标里的东西会丢**，与原版菜单携带物一致（规格里明示，不做崩溃恢复）。
6. **Given** 面板叠在别的容器界面上，**Then** 光标是菜单的携带物（沿用现有 PanelCursor 规则，不用内存光标）；携带物非空时与 065 一致不允许切标签。
7. **Given** 当前在**具体背包标签**，且光标是那只背包自己的光标（持久在背包数据里）非空，**When** 点任意标签，**Then** 与 065 一致拒绝切换并提示"先放下手里的物品"。
8. **Given** 光标上是浮动背包（或装了浮动背包的物品），**Then** 064 的嵌套规则照旧：放不进任何成员背包。
9. **Given** 从 A 拿起放进 B 是两次保存，**Then** 两次保存发生在**同一个服务端 tick 内**，二者之间物品只存在内存光标里；这是与现有面板光标相比唯一新增的窗口，规格里明示（见 FR-024）。

### User Story 4 - "全部"里的显示用搜索与整理 (Priority: P2)

"全部"标签里，面板标题栏上的搜索框与整理图标（就是单背包面板里那一套，位置与样式不变）作用于整张网格。搜索实时过滤整张网格并高亮命中（语法沿用 042：`@模组` `#标签` `/hidden`）；点整理图标把整张网格按 047 的规则**显示**成有序的样子（注册名顺序、分类行优先，非空格在前、空格在后）。这些只改变显示，**不搬动任何物品**。

**Why this priority**: 把十几只背包的东西找出来是最常见的需求；但没有它"全部"也能用，所以排在存取之后。

**Independent Test**: 游戏内在"全部"里输入搜索词、点整理，核对显示与点击落点（点击显示出来的某格，实际拿起的是对应背包的对应格）；切到具体标签核对数据没有被改动。

**Acceptance Scenarios**:

1. **Given** 在"全部"里输入 `@minecraft`，**Then** 只显示命中的格子，按位置压紧排列并高亮；点击某个命中格，实际作用在它真实的 (背包, 格号) 上。
2. **Given** 点整理图标，**Then** 显示按排序规则重排；**每只背包里的物品位置没有变**（切到具体标签核对）；堆叠没有被合并。
3. **Given** 整理后放入/取出物品，**Then** 数据变化不自动重排：放进去的物品留在它所在的显示位置，直到下次点整理。
4. **Given** 整理后成员表变化（增删背包），**Then** 排列表重算；其余时候不重算。
5. **Given** 整理后切到别的标签再回"全部"，**Then** 排列表保留，直到关闭联合界面；下次打开回到默认视图（各背包的格子首尾相连（不再每只从新的一行开始））。
6. **Given** 整理之后，**Then** 各背包的物品交错在一起，格子底色（US2）仍然标出每格来源。
7. **Given** 当前在具体背包标签，**Then** 面板标题栏里的搜索与整理照旧作用于那一只背包，整理是真正的整理（服务端），与"全部"里的显示用整理互不影响。

### User Story 5 - 内容实时同步、不超载 (Priority: P2)

联合界面开着时，成员背包的内容被别处改动（比如自动拾取往"B 会打开的那只"里存了东西），"全部"里一秒内看到；成员很多、内容很满时同步不会超过网络包上限、不会明显卡顿。

**Why this priority**: 自动连接的代价是内容会被别处改动；不同步，玩家会基于过期画面操作。

**Independent Test**: 开着"全部"，让自动拾取往 B 的那只背包里存东西，观察一秒内是否出现；放满 16 只背包后打开界面，观察是否卡顿、是否有包过大的日志。

**Acceptance Scenarios**:

1. **Given** 开着"全部"，**When** 自动拾取往 B 打开的那只背包里存入物品，**Then** 一秒内（或立即）出现在网格中对应位置。
2. **Given** 16 只都装满的成员，**When** 打开"全部"，**Then** 每只成员一个只含主区域的同步包，**每个都不超过现有单只背包整包的大小**，不会触发包过大。
3. **Given** 某成员的内容没变，**Then** 不重复推送（服务端按成员记住上次发出的内容，每秒比较一次，变了才推）。
4. **Given** 联合界面没打开的玩家，**Then** 零额外每 tick 开销。

### Edge Cases

- **默认标签**：打开联合界面默认选中"全部"（065 是选中"B 会打开的那只"所对应的标签）。理由：这是第二期的主功能；要找具体背包一次点击即可；需要用移动工具时再点具体标签。没有成员时"全部"为空网格并显示 065 已有的"没有背包"提示。
- **成员没有身份**：服务端用 `acquire` 给每个成员都分配身份才能保证"按引用 + 身份"的寻址与过期保护（和 065 选标签时一样，会改写物品栏里的那个栈）。**打开"全部"会一次性对所有成员做这件事**（最多 16 只），这意味着从没打开过的背包第一次被"使用"，触发 030/026 的现有通知；这是与 065 的差异，规格里明示，plan 核对。
- **040 保护中的背包**：已被 065 的成员表排除，"全部"里没有它们。
- **成员背包的分类行不同**：每只背包有各自的分类扩展行（051 的 19 类里启用了的），"全部"里每只背包的块按它自己的行数排列；灰格规则用各自的。
- **网格列数**：与面板的列数一致（"全部"里网格撑满整个面板）；各背包的格子首尾相连（2026-11-24 用户改：不再每只从新的一行开始，中间不留空位），只有最后一行的尾部可能不满，那几个位置不属于任何背包（空白、不可点）。
- **成员表变化时正在拖动**：拖动分摊进行中成员变了，本次拖动作废，已经放下的保持，其余按冲洗规则处理光标。
- **同一请求触及多只背包**：快速转移放入"全部"最坏要依次试 16 只；同一请求内每只背包最多解码一次、只保存真正改过的。
- **请求落点校验**：新请求带"成员下标 + 身份 + 格号"，服务端按**引用 + 身份**定位成员（不采信客户端的任何其他东西），身份对不上、下标越界、成员已不在表里时拒绝并重新同步成员表；不会改落到别的背包。
- **请求顺序**：沿用 065 的"加载中"规则：切到"全部"后、收到各成员的同步前，客户端不发面板请求。
- **嵌套**：从网格取出的物品、放入网格的物品都过 064 的检查；成员背包本身是物品栏里的物品，不会成为网格里的格子内容。
- **配置关闭**：`[combined].enabled=false` 时已有联合会话（含"全部"和内存光标）在下一次检查（每秒）结束，光标冲洗。
- **自动拾取、移动工具、唱片机**：仍只对"B 会打开的那只"生效，与看着"全部"还是哪个标签无关；"全部"里没有工具区，所以没有灰掉的控件。
- **降级**：不新增存档字段；`DataRevision` 不变；联合背包仍无数据。
- **语言键**：新增的标签名、提示、冲洗提示、空网格提示等中英文各一份。

## Requirements *(mandatory)*

### Functional Requirements

**"全部"标签与网格**

- **FR-001**: 联合界面的标签栏 MUST 在最前面增加"全部"标签；打开联合界面 MUST 默认选中它（成员为 0 时网格为空并显示 065 已有提示）。065 的"标签栏不留'全部'占位"随本期作废。
- **FR-002**: "全部"MUST 把成员表（沿用 065：最多 16 只、档位过滤、040 保护排除）里每只背包的**主区域**（含各自分类扩展行）依次排进一个虚拟网格，按成员在标签栏中的顺序；**各背包的格子首尾相连（不再每只从新的一行开始）**；网格列数与单只背包主区域相同；块末尾未填满的格子不属于任何背包（不可点、不画）。
- **FR-003**: 每个网格格子的限制 MUST 沿用其所属背包的规则（`canPlaceMain`、灰格 `GreyCellRules` 的分类行限制）。
- **FR-004**: "全部"里 MUST 不提供移动工具、左右区、底部功能区、垃圾桶、标签管理、快照；面板自己的标题栏在"全部"里 MUST 保留（拖动、关闭、搜索框、整理按钮），背包编号与快照按钮 MUST 不画不响应；搜索与整理按钮的含义见 FR-019。面板的实际外框尺寸与布局由 plan 定，观感由用户真机确认。

**寻址与存取**

- **FR-005**: 系统 MUST 提供纯逻辑的寻址表：全局格号 ↔ (成员下标, 成员内格号)，含前缀和与"块起始行"规则；可单测（顺序、块边界、末尾空位、成员数 0 与 16、成员行数不同）。
- **FR-006**: "全部"里 MUST 支持与单只背包主区域同样的存取手势：左键拿起/放下/合并/交换、右键拿一半或放一个、拖动分摊、Shift 点击、Ctrl 点击、双击收集（若单只背包主区域支持）、滚轮滚动；每种手势 MUST 复用现有单只背包处理体（拆出"针对某个引用应用点击"的可复用函数），**不复制一份规则**。
- **FR-007**: 新增的请求 MUST 带（成员下标、身份、格号 + 现有手势字段）；服务端 MUST 按**引用 + 身份**定位成员（与 065 的"声称引用与目标不一致则拒绝并重新同步"同思路），MUST NOT 采信客户端声称的其他位置；校验失败 MUST 拒绝并重新同步成员表与受影响成员的内容。
- **FR-008**: 同一请求内 MUST 每只成员最多解码一次（请求内缓存已解码成员），MUST 只保存真正改动的成员（各自 `saveInventory`）。
- **FR-009**: 放入"全部"的目标规则（适用于**没有指定格子**的放入：Shift 点击从物品栏放入、容器 → 面板的转移、网络终端取出；点了具体格子的放下仍落在那一格所属的背包）MUST 为：按成员顺序逐只尝试，每只走自己的"分类行优先、再通用格"的现有规则；放不下才试下一只；全部放不下才留在原处；MUST NOT 做"已有同种物品的背包优先"（留待以后）。
- **FR-010**: 064 的嵌套检查在"全部"里 MUST 照旧：直接禁止与深度扫描的结论与单只背包一致。
- **FR-011**: 063 式守恒检查 MUST 在"全部"的批量转移里成立：一次请求前后物品总数守恒（含"最坏依次试 16 只"的路径）。

**同步**

- **FR-012**: 切到"全部"（或打开联合界面默认进入"全部"）时，服务端 MUST 对每个成员各发一个**只含主区域**的同步包（每个不超过现有单只背包整包的大小，沿用 `MAX_SYNC_BYTES`），不把所有成员塞进一个包；增量更新 MUST 带成员下标。
- **FR-013**: 服务端 MUST 按成员记住**上次发出去的内容**，只对开着"全部"的玩家每秒比较一次，变了才推；比较 MUST 先比引用再比相等，MUST NOT 每次请求都重发所有成员。
- **FR-014**: 客户端 MUST 新增独立的多成员视图状态（暂名 `ClientCombinedView`，每个成员一份主区域内容、各自的灰格信息）；既有的单例背包视图 MUST 保持"镜像当前具体标签那一只"的含义，不改。
- **FR-015**: 切到"全部"或成员表变化后，到收到相应成员的同步前，客户端 MUST 不发任何面板请求（065 的"加载中"规则延伸）。

**光标**

- **FR-016**: 在"全部"里，光标 MUST 是**玩家会话里的内存光标**，MUST NOT 写进任何背包或物品数据；联合背包仍然无数据，`DataRevision` 不变。
- **FR-017**: 内存光标在以下时刻 MUST 被冲洗：关闭联合界面、切换标签（含切到具体标签）、玩家下线或服务端停止、成员表变化、联合会话结束（含 `enabled=false`）。冲洗顺序 MUST 为：先按成员顺序塞回成员背包（走各自的现有放入规则与嵌套检查）；塞不下进玩家物品栏；再塞不下像原版一样丢在脚下。MUST NOT 让物品无声消失（崩溃除外，见 FR-025）。
- **FR-018**: 面板叠在别的容器界面上时，光标 MUST 沿用现有规则（菜单携带物），不用内存光标；携带物非空时 MUST 与 065 一致拒绝切标签。具体背包标签里的光标（背包自己的）非空时 MUST 与 065 一致拒绝切标签并提示"先放下手里的物品"。

**界面**

- **FR-019**: 065 的**联合标题栏**（联合背包图标 + 标题 + 档位 + "+n" 的那一条）MUST 取消，标签栏直接贴在面板上沿；它承担的信息 MUST 移位：档位与"哪些背包未连接"的计数放进标签栏（"全部"标签的悬停提示，标签栏右端的"+n"徽标沿用）。在"全部"里面板自己的标题栏上的搜索与整理按钮 MUST 作用于整张网格（整理按钮只改显示，见 FR-021）；在具体背包标签里 MUST 照旧作用于那一只背包。
- **FR-020**: 搜索 MUST 沿用 042 的语法（`@模组`、`#标签`、`/hidden`）与现有搜索词缓存，过滤对象换成整张网格；命中格 MUST 按位置压紧显示并高亮；点击命中格 MUST 仍发真实的 (成员, 格号)。
- **FR-021**: 整理图标 MUST 由客户端按 047 的排序规则（注册名顺序、分类行优先）排出"显示位置 → (成员, 格号)"的**排列表**（一个包含全部格子的置换：非空格在前、空格在后）；显示 MUST 按排列表画，点击 MUST 按排列表翻译回真实位置再发送。整理 MUST NOT 合并堆叠、MUST NOT 搬动任何物品、MUST NOT 发给服务端任何新请求。
- **FR-022**: 排列表 MUST 只在点整理、成员表变化时重算；平时数据变化 MUST NOT 自动重排（防止物品在光标下乱跳）。切走"全部"再回来排列表 MUST 保留到关闭联合界面为止；下次打开 MUST 回到默认视图。
- **FR-023**: 格子 MUST 底色淡染成所属成员的颜色（按成员在标签栏位置查 065 已有的 16 色表；画在选中高亮与灰格之下）；悬停提示 MUST 追加一行"来自 ■编号（位置）"；悬停某格时对应标签 MUST 高亮；MUST NOT 画边框与分区标题行。

**跨背包写入**

- **FR-024**: 从背包 A 拿起放进背包 B 是两次保存，MUST 在同一个服务端 tick 内完成；二者之间物品只存在内存光标里。与现有面板光标（持久在背包数据里）相比，这是唯一新增的窗口，MUST 在 DELIVERY 里明示。
- **FR-025**: 服务端在持有内存光标时崩溃，光标里的物品 MUST 视为丢失（与原版菜单携带物一致）；规格明示，不做崩溃恢复，不为此写盘。

**其他约束**

- **FR-026**: 自动拾取、移动工具（唱片机、工作台、熔炉）、灯笼光、管子 MUST 仍只对"B 会打开的那只"生效，与当前标签无关；`BackpackRef.resolve` 的非面板调用 MUST 不变，065 的接线测试 MUST 继续成立。
- **FR-027**: 协议号 MUST 23 → 24（新包：按成员下标的主区域同步、"全部"里的点击/拖动/快速转移请求等）；`DataRevision` MUST 不变；MUST NOT 使用 mixin 或反射；第三方类型只允许在现有 `compat/` 包里。
- **FR-028**: 本期预计不新增贴图；若新增，MUST 按宪法 VI 在加入前后各测一次图集预算并记录。
- **FR-029**: 系统 MUST 有自动测试：寻址表与前缀和；成员同步缓存的"变了才推"判定；内存光标冲洗的顺序与守恒（塞回成员 / 物品栏 / 丢弃）；排列表是置换、稳定、仅在点整理与成员表变化时重算；搜索过滤与压紧映射；新包的解析入口接线测试（每个"全部"请求都经过成员定位与身份校验）；协议号相关旧测试的字面量更新。**游戏内验证**：见 quickstart（取出/放入/拖动/Shift 点击、光标跨背包与各冲洗时机、默认标签、染色与悬停提示、搜索与整理、成员变化、16 只满载、`enabled=false`）。
- **FR-030**: 文档 MUST 同步：README 两份（"全部"标签、搜索与整理只改显示、光标冲洗规则、崩溃会丢光标）、`docs/plan/combined-backpack.md` 的状态、DELIVERY 写清已验证与没验证的。

### Key Entities *(include if feature involves data)*

- **虚拟网格**：由成员主区域按顺序排成的、不存盘的视图；每格对应唯一的 (成员下标, 成员内格号)；块起始行规则决定空位。
- **寻址表**：全局格号 ↔ (成员下标, 成员内格号) 的前缀和表，纯逻辑，成员表变化时重算。
- **内存光标**：联合会话里的物品栈，不存盘；冲洗规则见 FR-017。
- **成员同步缓存**（服务端）：每个成员"上次发给该玩家的内容"，仅开着"全部"的玩家有。
- **排列表**（客户端）：整理产生的"显示位置 → (成员, 格号)"置换，会话级，不存盘。
- **多成员视图**（客户端）：每个成员的主区域内容与灰格信息，供"全部"显示与点击翻译。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 玩家用 U 打开后**一次点击都不用**就能在"全部"里看到并存取所有成员背包的主区域；把一组物品放入"全部"最多 1 次点击即落进某只背包。
- **SC-002**: "全部"里的任何操作，**0 次**落在别的背包上或让物品总数变化（含整理后、搜索压紧后、成员变化瞬间）；游戏内逐类手势验证，并有守恒测试。
- **SC-003**: 整理与搜索之后，所有背包内的物品位置与堆叠与操作前**完全一致**（只改显示），切到具体标签核对。
- **SC-004**: 光标冲洗在"关闭、切标签、成员变化、下线"四个时机都**不丢物品**（崩溃除外）；背包与物品栏都满时物品落在脚下，不消失。
- **SC-005**: 成员内容的外部变化在 **1 秒内**出现在"全部"里；联合界面没开的玩家**零**额外每 tick 开销；16 只满载打开不触发包过大。
- **SC-006**: 新增与既有测试全部通过（0 失败）；`DataRevision` 不变，旧存档无任何改动。
- **SC-007**: 染色与标签、悬停提示一致，玩家无需看文字就能说出一个格子属于哪只背包（主观项由用户真机确认，含颜色表在深色界面的可辨度）。

## Assumptions

- **不在本期**："已有同种物品的背包优先放入"、"不加入联合背包"开关、标签快捷键、成员上限配置、联合背包背部模型、EMI 排除区。**标题栏融合不再需要**：联合标题栏已取消（FR-019），面板标题栏留在标签栏下面；若用户仍希望把面板标题栏移到标签栏上方，另开 feature。
- 065 的成员表、会话目标、统一解析、标签栏、16 色表、颜色分配、"加载中"规则、协议 23、`[combined].enabled` 全部沿用；**065 的 T030（用户真机确认观感）尚未勾**，本期的颜色表与标签栏沿用其未确认状态，若用户确认时要求调整，一并改。
- U 键与 JEI/EMI 的"查看用途"键冲突由用户自行在控制设置里改键，不在本期处理。
- 默认选中"全部"（见 Edge Cases）；记住上次所选标签不做。
- 面板叠在容器界面上时，光标沿用菜单携带物规则；内存光标只用于联合界面单独（宿主界面）打开的情况（plan 核对两种模式的边界）。
- 成员最多 16 只、固定不配置；"全部"最多 16 个块。
- 从物品栏里没有身份的成员：打开"全部"时对所有成员 `acquire`（见 Edge Cases）；040 保护中的背包已被排除。
- 光标冲洗时的"塞回成员背包"走各背包自己的放入规则（含分类行、嵌套检查）；塞回的是任意可放入的第一只，不要求塞回拿起它的那只（plan 核对是否需要记住来源）。
- Plan 阶段需读码确认：服务端"上次发出的内容对象"能否用物品上 `BACKPACK_CONTENTS` 的记录做引用比较；`BackpackClickPayload` 处理体拆出可复用函数的边界（哪些检查留在外层）；042 的搜索与 `PanelLayout.mainMap` 的"布局格 → 槽号"映射能否被聚合网格直接复用；客户端 `FloatingPanelInput`/`FloatingPanelRenderer` 里直接读 `ClientBackpackView` 主区域的位置数；快速转移放入"全部"最坏依次试 16 只的开销；双击收集等手势是否在主区域存在。
- 配方、物品、成员表规则不变；本期不新增物品与贴图。
