# Feature Specification: 面板格子的物品提示（tooltip）

**Feature Branch**: `045-panel-item-tooltips`

**Created**: 2026-11-12

**Status**: Draft

**Input**: 用户（2026-11-12）发现：鼠标滑过浮动面板上的物品时不显示物品介绍 tooltip，而滑过原版自带物品栏时会显示。要求补上，主区域和三个工具区都加（用户已确认），作为单独的小 feature（搜索结果的灰格改版另做 046）。

## Clarifications

### Session 2026-11-12

- Q: 这是回归吗？ → A: **不是回归，是一直没做过。** 查了源码与整个 git 历史（M1 至今），面板渲染从来没有画过格子里物品的 tooltip。原版界面只给它自己的 `Slot` 画 tooltip，面板的格子是自己画、自己命中判断的，所以一直没有。
- Q: 做到哪些区域？ → A: **主区域和左、右、下三个工具区**（用户确认）。
- Q: 与搜索改版的关系？ → A: 分开做、分开提交（宪法 III）；搜索时结果格里的物品同样会显示 tooltip（本 feature 自然覆盖）。

## Out of Scope（本阶段不做）

- 垃圾桶面板（021）、标签面板（018）、标签总览（025）、拾取黑名单页（024）、快照界面（031，已有自己的 tooltip）里的物品提示。
- 改变 tooltip 的内容或样式：沿用原版对物品的提示（名字、描述、数据组件提示、F3+H 的高级提示、别的模组通过 `ItemTooltipEvent` 加的行）。
- 搜索结果的灰格样式（046）；服务端、网络包、协议号（仍 17）、配置、语言键、依赖、贴图。

## 已查证的事实（读本仓库源码；规格要尊重）

- 面板里所有"悬停提示"都是手写的（标题图标、按钮、037 的扩展行提示与黄点提示）；没有任何一处对格子里的物品画 tooltip。
- `PanelLayout.hit(x, y)` 回答"鼠标下是哪个真实槽位（区域 + 编号）"，对填充格（超出容量、搜索时没有结果的格子）返回 null；主区域按搜索映射走，所以搜索时悬停结果格也得到真实槽位。
- `ClientBackpackView.getStackInSlot(index)` 与 `getToolStack(area, index)` 给出格子里的物品；`FloatingPanelRenderer.cursorStack` 给出光标上拿着的物品（原版容器界面下是 `containerMenu.getCarried()`）。
- 037 的"扩展行格子提示"（`drawRowTooltip`）对扩展行里的**任何**格子（有无物品）都画，拿着物品时还会附上"放不进"的原因。
- 面板整体画在抬高的深度上（`OVERLAY_Z`，014 为避免与原版/JEI 的 tooltip 深度撕裂而定），其它 tooltip（黄点、行提示）已经在同一个位置用 `graphics.renderTooltip` 画，工作正常。
- `GuiGraphics.renderTooltip(Font, ItemStack, x, y)` 是原版画物品 tooltip 的入口，快照界面已在用。

## 尚未验证（plan 阶段先查证；验证前不得声称已满足）

- 面板挂在原版容器界面（物品栏、箱子）上与挂在 019 的透明宿主界面上时，tooltip 的位置与深度是否都正确（不被面板盖住、不撕裂）。
- 与 037 行提示同时命中同一格时的取舍（见 FR-003）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 悬停格子看物品介绍 (Priority: P1)

玩家打开面板，把鼠标移到主区域或任一工具区里有物品的格子上，弹出和原版物品栏里一样的物品提示（名字、描述、附魔、耐久等；开了 F3+H 就带高级提示）。

**Why this priority**: 这是用户明确要补的缺口，也是整个 feature 的全部价值。

**Independent Test**: 面板里放钻石镐（带附魔）、一个药水、一个带物品的潜影盒、以及工具区的垃圾桶：逐个悬停，提示与同一物品在原版物品栏里悬停时一致；按 F3+H 后出现高级提示。

**Acceptance Scenarios**:

1. **Given** 主区域某格有物品，**When** 鼠标悬停，**Then** 弹出该物品的原版 tooltip。
2. **Given** 左、右、下任一工具区的格子里有物品（自动拾取、垃圾桶、标签管理器、分类扩展等），**When** 悬停，**Then** 同样弹出它的 tooltip（本模组自己的物品含第 036 的类别说明行）。
3. **Given** 开启了 F3+H 高级提示，**Then** tooltip 带注册名与组件信息，与原版一致。
4. **Given** 格子是空的、或是填充格（超出容量、搜索时没有结果的格子），**Then** 不弹 tooltip。
5. **Given** 搜索框里有查询，**When** 悬停结果格子里的物品，**Then** 弹出该物品的 tooltip；悬停"留位"的空格不弹。

---

### User Story 2 - 该不弹的时候不弹 (Priority: P1)

tooltip 不能妨碍操作：光标上拿着东西时不弹（和原版一致）；拖拽分配预览时不弹；确认弹窗出现时不弹；标签面板或黑名单页盖住主区域时，主区域不弹；其它已有的 tooltip（按钮、黄点、扩展行提示）照常。

**Why this priority**: 弹窗型提示最容易挡住正在做的事，必须有明确的抑制规则并有测试保护。

**Independent Test**: 光标拿一组物品悬停格子：不弹物品 tooltip；展开标签面板后悬停主区域：不弹；开始拖拽分配：不弹；触发垃圾桶确认弹窗：不弹。

**Acceptance Scenarios**:

1. **Given** 光标上有物品，**When** 悬停任一格子，**Then** 不弹物品 tooltip（037 的扩展行提示照旧：拿着东西悬停扩展行仍显示行说明与"放不进"的原因）。
2. **Given** 正在拖拽分配（有预览），**Then** 不弹。
3. **Given** 垃圾桶确认弹窗正在等待回答，**Then** 不弹。
4. **Given** 标签面板或拾取黑名单页展开并盖住主区域，**When** 悬停主区域，**Then** 不弹物品 tooltip；悬停仍然露出的工具区里有物品的格子，照常弹。
5. **Given** 扩展行里**有物品**的格子，**When** 光标为空并悬停，**Then** 弹**物品** tooltip（不弹行提示）；**空**的扩展行格子仍弹行提示。

---

### Edge Cases

- **面板被拖到窗口边缘**：tooltip 的位置由原版的 `renderTooltip` 自己避开屏幕边界，不另做处理。
- **鼠标在格子之间的缝、标题栏、按钮上**：没有命中格子，不弹物品 tooltip（按钮等有自己的提示）。
- **物品被服务端同步更新、悬停期间格子变空**：下一帧不再弹，不报错。
- **工具区物品**：垃圾桶、自动拾取等本模组的物品有自己的名字与说明，沿用物品自己的 tooltip，不另写。
- **JEI 等别的模组**：本 feature 只画原版的物品 tooltip；别的模组通过 `ItemTooltipEvent` 加的行会自然出现。
- **面板挂在透明宿主界面上**：同样要弹；tooltip 不能被面板盖住。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 光标为空时，鼠标悬停在主区域或左、右、下工具区**有物品**的格子上，MUST 弹出该物品的原版 tooltip（内容与原版物品栏一致，含高级提示与别的模组加的行）。
- **FR-002**: 下列情形 MUST NOT 弹物品 tooltip：光标上拿着物品；拖拽分配预览中；垃圾桶确认弹窗等待回答；标签面板或拾取黑名单页盖住的主区域；格子为空；没有命中格子（缝、标题栏、按钮、填充格）。
- **FR-003**: 扩展行（037）里**有物品**的格子 MUST 弹物品 tooltip 而不是行提示；**空**的扩展行格子与"光标上有物品"时 MUST 仍按 037 弹行提示（含"放不进"的原因）。其它已有的 tooltip 不变。
- **FR-004**: 搜索时（042）悬停结果格子里的物品 MUST 弹 tooltip；"留位"的空格与灰格不弹。
- **FR-005**: tooltip MUST 画在面板内容之上、不被面板盖住、不与别的 tooltip 或原版界面撕裂；面板挂在透明宿主界面上与挂在原版容器界面上都要成立。
- **FR-006**: MUST NOT 新增服务端代码、网络包、协议号变化（仍 17）、配置项、语言键、依赖或贴图；`DependencyRulesTest` 照常通过；011～044 的行为与测试不变。
- **FR-007**: 抑制规则 MUST 写成不依赖 Minecraft 类的纯逻辑并有单元测试（各抑制条件的组合、扩展行取舍）；渲染接线用源码文本检查覆盖。
- **FR-008**: 文档 MUST 更新：`README.md` 与 `README_CN.md` 的面板说明里提一句悬停显示物品提示；本 feature 的 `DELIVERY.md`（中文：已验证 / 未验证 / 已知限制 / 测试数）。

### Key Entities *(include if feature involves data)*

- **悬停格子**：鼠标下的真实槽位（区域 + 编号）及其中的物品；来自 `PanelLayout.hit` 与客户端的背包视图。
- **抑制条件**：光标是否有物品、是否在拖拽预览、是否有确认弹窗、主区域是否被覆盖面板盖住；决定要不要弹。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 主区域与三个工具区各取 2 种物品（共 8 种）悬停，**8 次全部弹出**与原版物品栏一致的 tooltip（容器里截图抽查，内容逐项对照）。
- **SC-002**: 抑制规则的 6 种情形（光标有物品、拖拽预览、确认弹窗、盖住的主区域、空格、没有命中）**全部不弹**，且扩展行取舍（有物品弹物品、空格与拿着东西弹行提示）全部正确（单元测试 + 游戏里抽查）。
- **SC-003**: 搜索时悬停结果格子弹 tooltip、悬停留位空格不弹，各至少验证 1 次。
- **SC-004**: 面板在透明宿主界面与在原版容器界面（物品栏）上，tooltip 都完整可见、无撕裂（截图）。
- **SC-005**: 服务端与网络协议**零改动**（协议号仍 17）；`./gradlew compileJava test` 通过；011～044 的测试不改而通过。

## Assumptions

- tooltip 的内容完全沿用原版 `renderTooltip(Font, ItemStack, …)` 的结果，不自己拼行，所以"与原版一致"由原版保证。
- 创造模式下的物品栏界面（027）里面板同样弹 tooltip；其细节差异（如创造物品栏自己的 tooltip）不在本 feature 范围内。
- 不为悬停加延迟或开关（与原版物品栏一致，立即弹出）。
