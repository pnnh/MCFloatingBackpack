# Research: 下界合金背包前后面可区分

测量用的是随包的 `netherite_backpack.obj` 与 512 贴图，脚本为临时的纯 Python 渲染/统计（会话临时目录），结论都来自测量，不是目测。

## Decision 1: 背面 = z 最小的一面，只改背面中央背板

**Decision**: 背面是 z≈0.238 的那一面（`BackpackBackLayer` 按这个面贴躯干背面）。"背面中央背板"定义为：三个顶点都在 `z < zmin + 0.09`（背面浅浮雕层）且三角形中心 `0.2 < x < 0.8` 的三角形，共 4997 个（总 20267 个）。两侧口袋（x<0.2、x>0.8）、顶部、底部、正面不动。

**Rationale**: 背面所有凸起（翻盖、口袋、扣具）都落在 0.238–0.277 这一层里（沿中线测到的深度曲线：0.277 平面上的凸起只到 0.238），顶面、底面、侧壁的 z 范围大得多，不会被选中。侧口袋在背面视角下像真实背包的侧袋，留着不影响"这是背面"的判断。

## Decision 2: 贴图区域按 UV 掩码确定，只改"背面独占"的纹素

**Decision**: 把背面三角形和其余三角形分别栅格化到 512×512 的 UV 掩码：背面共占 47280 个纹素，其余占 167918，**共享 714**，背面独占 46566。只改独占纹素（再向外膨胀 1 格，且只膨胀到不被其他面使用的纹素），共享的 714 个不动。

**Rationale**: 贴图是 AI 生成的碎岛图集，背面的岛散在各处（见分析时的叠加图），但与正面几乎不共用（共享仅 1.5%）。只改独占纹素就能保证 FR-003/FR-004：其他面的外观逐像素不变。膨胀 1 格是为了避免 mipmap/线性过滤在岛边缘混入旧的金色。

## Decision 3: 用"3D 位置→图案"重画，而不是直接在 UV 上涂色

**Decision**: 对每个背面三角形，在 UV 空间逐纹素做重心插值，得到对应的 3D 位置 (x, y)，再用一个定义在背面平面 (x, y) 上的**程序化图案**取色：深色背板底（颜色从贴图里现有的非金色深灰纹素里随机取，保持颗粒风格）、边缘一圈更深的包边、两条竖向肩带垫（略亮、带暗色缝线虚线）、一条横向接缝、肩带上下端各一个小金色铆钉。

**Rationale**: 背面岛散得很碎，直接在 UV 上涂会让同一块背板在不同三角形上花纹不连续；按 3D 位置取色，整块背板的图案连续，浮雕侧壁也自然落在图案的线上。图案参考钻石、铁背面"平整 + 少量带子"的风格，金色只用于铆钉（占比远小于 3%）。

**Alternatives considered**: 纯色填充（太单调，像没做完）；复制正面背板的纹素（正面背板本身带有翻盖/扣具的细节，且难以映射）；在 Blender 里重新烘焙整张贴图（工作量大，会改动其他面）。

## Decision 4: 法线写入平面法线

**Decision**: 背面独占纹素的 `_n` 写成"平面"值：先取当前 `_n` 里大片平整区域的众数（实测中心像素 `(127,129,255,255)`），整块背板用它；缝线、肩带边缘不加法线细节。

**Rationale**: 009/010 的法线是 LabPBR（R、G 为 xy，B=AO=255，A=高度=255），平整区域接近纯色。背面写成平面，光影下就不会再看到翻盖/扣具的凸起轮廓（FR-002）；细节只靠基础色，避免本 feature 去新生成法线。

## Decision 5: 方案 A 先做，B 只在 A 不够时做

**Decision**: 先只改贴图；然后在 Blender（辅助）与游戏（决定性）里检查。方案 B（压平背面浅浮雕）只有在游戏里仍然能认出翻盖形状时才做，做法是把 0.277 平面与更深的凹处向外补到 z=0.238（只向外，不削 0.238 平面），不增加面。是否做 B 由用户游戏内的结论决定。

**Rationale**: 浮雕只有 ~0.04 个方块（不到 1 像素），贴图和法线都改平后，几何台阶在背面视角下几乎看不见；先做低风险的 A，避免在 114 条开放边的有机网格上动几何。

## Decision 6: 可重复与覆盖风险

**Decision**: 提供 `design/demo/tools/netherite_back_panel.py`：读当前 OBJ 与贴图，按上述规则重画并原地写回 `textures/item/netherite_floating_backpack.png` 与 `_n.png`。图案由固定随机种子生成，捐赠纹素取自掩码之外，所以**重复运行结果相同**（幂等）。`build_textures.py 512 --install` 会用 2048 原图覆盖五档贴图，下界合金需要重跑本脚本；DELIVERY 与 `design/demo/README.md` 里写明。

**Rationale**: 贴图是二进制，只靠提交很难看出改了什么；脚本可以重复，也方便之后需要微调图案。

## 仍不确定 / 需要游戏内确认

- 背面图案的风格是否"一眼是背面"（SC-002，用户确认）。
- 光影包下背面是否仍有凸起轮廓（可能需要方案 B）。
- 掉落物、第三人称、展示框里背面是否确实可见（背上时看到的是正面，背面贴躯干）。
- 共享的 714 个纹素与掩码边缘是否会在 mip 级别出现杂色边。
