# Feature Specification: 下界合金背包前后面可区分

**Feature Branch**: `015-netherite-back-distinct`

**Created**: 2026-11-05

**Status**: 实现完成；方案 A、B 均已由用户在游戏里确认没有问题（未逐项记录，见 DELIVERY.md）

**Input**: User description: "分析是否可以解决下界合金背包前后面几乎一样无法区分问题。是否可以直接编辑模型文件或者借助 blender，参考其它背包的模型，把其中一面做下编辑修改，使前后面在视觉上更容易区分。" 随后用户裁决："方案 A，必要时扩到 B。"

## 背景与已确认的决策

下界合金背包的网格是 AI 生成的，**前后两面几乎镜像对称**（009 第七轮就记录过：正反两面都有翻盖、金色扣具、口袋，"正面"是按钻石的朝向猜的）。分析阶段用纯 Python 渲染器（`design/demo` 之外的临时脚本）从前后两个方向渲染随包的 OBJ 与贴图，并测量了几何：

- 沿中线测量表面深度，前后两面的深度曲线互为镜像（前 0.847/0.886，后 0.277/0.238，两两之和恒为 1.124）；浮雕只有约 **0.04 个方块（不到 1 个像素）**，所以"翻盖、扣具、口袋"的辨识度几乎全靠**贴图**，不靠几何。
- 前面和后面采样的是**不同的贴图区域**（采样格重叠约 9%，钻石为 8%），改背面的贴图不会改变正面。
- 钻石、铁的背面是平整的，一眼能认出是背面；下界合金没有这种区别。
- 背上渲染按"近身面 z≈0.238 贴着躯干背面"计算（`BackpackBackLayer` 的 z 偏移），所以**背面（z 最小的一面）的最外平面不能变**。

用户已确认的决策：

1. 采用**方案 A（只改贴图，基础色 `_n` 法线都改）**为主；如果 A 在游戏里仍然不够（比如浮雕轮廓、光影下的法线凸起仍能把背面认成正面），再**扩到方案 B（压平背面的浅浮雕几何）**。
2. 只改**下界合金**一档，其他四档不动。
3. Blender 已可用，需要时使用。

## Out of Scope（本阶段不做）

- 其他四档（皮革、铁、金、钻石）。
- 重做背面网格（方案 C）：不值得，也不推荐。
- 改变正面、侧面口袋、顶部、底部的外观。
- 改变模型大小、背上位置、手持/图标的显示变换。
- 新增贴图、增大图集（贴图仍是 512×512，图集仍 2048×1024）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 一眼分出下界合金背包的前后 (Priority: P1)

玩家从下界合金背包的背面看它（掉落物旋转时、第三人称、物品展示框等能看到背面的场合），应当一眼看出这是**背面**：平整的深色背板，没有翻盖、扣具和口袋；从正面看仍然是现在的翻盖、金色扣具和口袋。

**Why this priority**: 这是用户提出的问题本身。

**Independent Test**: 在 Blender 与游戏里分别从前后两个方向看下界合金背包，并与钻石、铁的背面对照。

**Acceptance Scenarios**:

1. **Given** 下界合金背包，**When** 从背面（z 最小的一面）看，**Then** 看不到翻盖、金色大扣具和底部口袋，而是平整的背板；与钻石、铁背面的"平整"程度相当。
2. **Given** 同一个背包，**When** 从正面看，**Then** 外观与改动前一致。
3. **Given** 玩家把它背在身上，**When** 从后面看，**Then** 看到的仍是正面（与改动前一致），背面贴着躯干。
4. **Given** 打开了光影包，**When** 从背面看，**Then** 法线不再让背面出现翻盖、扣具的凸起轮廓。

---

### User Story 2 - 不破坏其他表现与预算 (Priority: P1)

改动不得影响下界合金背包的其他部分，也不得突破 010 的资源预算。

**Why this priority**: 贴图是共用图集的一部分（宪法 VI），模型的贴身位置和手持外观已经被多轮验证过。

**Independent Test**: 重跑图集度量、亮度对比，并在游戏里看图标、手持、背上。

**Acceptance Scenarios**:

1. **Given** 改动完成，**When** 运行 `design/demo/tools/check_atlas_budget.sh`，**Then** 图集仍为 2048×1024，退出码 0。
2. **Given** 改动完成，**When** 看图标、手持（第一/第三人称）、背上，**Then** 与改动前没有可见差别（背面可见的场合除外）。
3. **Given** 改动完成，**When** 检查背面最外平面，**Then** 仍在 z≈0.238，背上贴身位置不变，没有穿模或出现缝隙。
4. **Given** 若扩到方案 B，**When** 压平背面几何后，**Then** 没有出现新的可见裂缝或撕裂（手持视角也检查），面数不增加。

---

### Edge Cases

- **正反面共用贴图区域的那 9%**：只改仅被背面使用的纹素，不能动被其他面也用到的纹素。
- **背面的浅浮雕边缘（翻盖、口袋的侧壁）**：它们的法线面不朝 -z，会在背面轮廓上留下金色细线；方案 A 要一并处理，否则仍能认出翻盖。
- **法线贴图与基础色一致**：只改基础色而不改 `_n`，光影下仍能看到凸起。
- **贴图是 512 缩放出来的**：重新跑 `build_textures.py --install` 会用 2048 原图覆盖，本次改动会丢失；需要记录并提供可重复的脚本。
- **背面的"最外平面"**：压平（方案 B）时只能向外（补高到 z=0.238）或保持，不能削掉 0.238 平面。
- **扣具孔**：分析阶段没有发现，实现时用渲染确认——重画背板后正中出现一个透光的方孔（原来被扣具环框住，不显眼），所以加了补孔板（FR-011）。正面扣具的孔是原设计的一部分，不动。
- **前后判断**：背面 = z 最小的一面（贴身面），不是 009 里"猜的 +X"。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 背面（z 最小、贴着躯干的一面）的中央背板区域 MUST 不再显示翻盖、金色大扣具、底部口袋与角片的图案，改为平整的深色背板（可带暗缝线、肩带固定点之类的低对比细节，与钻石/铁的背面风格一致）。
- **FR-002**: 基础色贴图与 `_n` 法线贴图 MUST 同步修改：背板区域的法线 MUST 与平整背板一致，不得保留翻盖、扣具的凸起。
- **FR-003**: 正面、顶部、底部、两侧口袋与扣具的外观 MUST 与改动前一致（逐像素比较：只被背面使用的纹素之外的纹素不变）。
- **FR-004**: 只修改仅被背面三角形使用的纹素；被其他面共用的纹素 MUST NOT 被修改。
- **FR-005**: 贴图尺寸 MUST 保持 512×512，共用图集 MUST 保持 2048×1024；模型面数除 FR-011 的补孔板（4 个三角面）外 MUST 不增加。
- **FR-006**: 背面最外平面（z≈0.238）与整个模型的包围盒 MUST 不变，使 `BackpackBackLayer` 的贴身位置不需要调整。
- **FR-012**: 用户在方案 A 验证通过后要求继续做方案 B：背面中央背板内的浅浮雕 MUST 被压平，只向外抬到最外平面（zmin）或 zmin + 0.003，面数、UV、法线与包围盒 MUST 不变，手持视角漏光检查 MUST 与压平前相同。（FR-007 原本是"不够才扩"，这次由用户决定触发。）
- **FR-007**: 若方案 A 在游戏里不足以让背面一眼可辨（浮雕或光影下的法线仍暴露翻盖形状），MAY 扩到方案 B：压平背面的浅浮雕，只向外补到 z≈0.238 平面，不增加面、不留新裂缝。是否扩到 B MUST 由游戏内（或按报告条件的）观察决定并记录。
- **FR-008**: 本次改动 MUST 可重复：提供脚本，能对当前的下界合金贴图重新应用改动；`DELIVERY.md` MUST 记录 `build_textures.py --install` 会覆盖本次改动及应对方式。
- **FR-009**: 其他四档的模型与贴图 MUST 不被改动。
- **FR-011**: 背面中央扣具环里有一个贯穿网格的方孔（渲染测得孔口约 x 0.492–0.528、y 0.712–0.746）。把扣具重画成背板后，这个孔会变成背板正中一个透光的小方窗，所以 MUST 在孔后放一片薄板堵住（与 `patch_iron_slit.py` 同样的做法：板在孔后、比孔口大一圈、正反绕序各一份，UV 取自背板纹素）；这是方案 B 里唯一做的几何改动，不压平背面浮雕。
- **FR-010**: 背面朝向 MUST 以 `BackpackBackLayer` 的实际贴身方向（z 最小的一面）为准；不得依据 009 里"猜的 +X 正面"。

### Key Entities

- **下界合金背包模型**：`models/item/netherite_backpack.obj`（约 20k 三角面），贴图 `textures/item/netherite_floating_backpack.png` 与 `_n.png`（各 512×512）。
- **背面三角形**：法线朝 -z 且位于中央背板范围内的三角形；它们的 UV 区域就是要重画的贴图区域。
- **设计源**：`design/demo/obj_export/netherite_backpack*.obj/.png`（OBJ 走 Git LFS）与 `design/demo/work/orig2048/` 原图；本次默认不改源 OBJ。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在 Blender 中从背面（-z 方向）渲染的下界合金背包，与改动前相比，翻盖、金色大扣具、底部口袋的像素面积减少到可忽略（背板范围内金色像素占比不超过 3%）。
- **SC-002**: 从背面渲染的下界合金与钻石、铁的背面对照，肉眼一眼可辨"这是背面"（由用户确认）。
- **SC-003**: 所有不属于"仅背面使用的纹素"的像素在改动前后逐像素相同（基础色与 `_n` 各自比较）。
- **SC-004**: `check_atlas_budget.sh` 仍报告图集 2048×1024，退出码 0；`check_brightness.py` 下界合金亮度偏差仍在 ±10% 内。
- **SC-005**: 图标、手持、背上在游戏里与改动前无可见差别（由用户确认）；打开光影包时背面不再出现翻盖凸起（由用户确认，或记为未验证）。
- **SC-006**: 开发机（macOS）上完成；Windows/Linux 无差别，不单独验证。

## Assumptions

- **贴图改动范围是"背面中央背板"**，两侧口袋、顶部、底部保持原样（背面视角下它们仍会露出，像真实背包的侧袋）。
- **改贴图的方式**：对背面独占的 UV 区域，用同一贴图里已有的"平整深色背板"纹素（例如正面背板里没有磨损的部分）或程序化的深色噪点填充，再叠加少量缝线/肩带固定点；具体取样位置在实现时用渲染确认。
- **法线**：背板区域写入与周围平整区域一致的平面法线（`_n` 中 R≈127、G≈129、B=255、A=255 附近），不在这个 feature 里新生成细节法线。
- **先 A 后 B**：先做 A 并按报告条件检查；只有 A 不够才做 B，是否做 B 与原因记录在 DELIVERY。
- **依赖**：009（模型与坐标约定）、010（贴图预算与处理脚本）、`BackpackBackLayer`（贴身位置）。
- **验证条件**：按宪法 V，背面外观要在游戏里（掉落物旋转、第三人称、展示框、光影包开关）确认；Blender 渲染只是辅助，不能代替。
