# Quickstart: 009-sculpted-mesh-backpack-models

## 自动化校验（不启动游戏）

```bash
./gradlew compileJava test
```

只能保证没有破坏既有逻辑。**它不能证明外观正确**——本功能全部是玩家可见的外观，宪法 V 条要求在客户端会话里目视验证。

## 资源加载检查（半自动）

```bash
rm -f run/logs/latest.log
./gradlew runClient      # 等到主菜单出现后关闭
grep -in "exception\|error\|caused by" run/logs/latest.log
```

期望：没有关于 `mcfloatingbackpack` 的模型、OBJ、贴图的异常。本机偶尔会有联网获取皮肤超时（`sessionserver.mojang.com`），与本功能无关。这一步能抓到"OBJ 解析失败 / 贴图变量没解析 / 文件缺失"，抓不到"贴图错位、朝向反了、透光"。

## 客户端会话验证（必须实际执行）

```bash
./gradlew runClient
```

进入一个创造模式世界；用 JEI 搜 `floating backpack`（005 的开发用 JEI）或创造物品栏取出五个等级的背包。

### 第一部分：五档外形、图标/手持/背上一致（US1、SC-001、SC-002）

1. 把五个等级各放在快捷栏，确认**图标**显示的是正面（有扣具和口袋的一面），五档能区分。
2. 逐个拿在手上，第一人称和第三人称（F5）查看，确认和图标是同一只包、朝向正面。
3. 逐个装备到胸甲栏，F5 绕到身后，确认背上是同一只包、从身后看到正面。
4. 请 **5 名观察者**不看物品名称区分五档（沿用 006 SC-003）——本项至今没做过。

### 第二部分：背上的贴身与完整性（US2、SC-003、SC-004）

对**每个等级**分别做：

1. F5 绕到**侧面**，看背包与后背之间是否有明显缝隙（标准：不超过约 1 像素）。重点看钻石（翻盖向后包，预期有约 0.05 方块的间隔）和金（最高，看是否超出躯干）。
2. 从**身后**、**侧面**各看一遍，找细缝：是否能透出天空或人物皮肤。对已知开放边较多的金（325）、钻石（169）、铁（122）要格外仔细。
3. **仰视**：把视角抬到最低，从下往上看，确认底部是封闭的平面；下界合金的下口袋底部应是金色斑点的平板，而不是凹进去的空腔。
4. 记录：每个等级的观察结果，包括看到的缺陷位置，写进 `DELIVERY.md`。

### 第三部分：光照与光影包（US3、SC-005、SC-006、SC-007）

1. 白天背着/拿着背包，然后用 `/time set night` 或走进洞穴，确认背包亮度随环境降低，夜里不发光。
2. 白天对照 `design/demo/*.jpg` 的效果图，主观判断亮度是否接近；如果偏暗或偏亮明显，记录是哪个等级。
3. （可选）安装 Iris/Oculus（NeOculus）和一个支持 PBR 的光影包，确认背包表面有法线带来的凹凸；没装光影包的环境确认外观无异常。

### 第四部分：既有玩法不受影响（FR-013）

1. 打开浮动面板，确认容量与行数仍对应等级（36/54/72/90/108）。
2. 面板与箱子、物品栏之间互拖物品仍可用。
3. 升级配方仍能把背包升一档并保留内容。

### 第五部分：性能粗测（已知限制 3）

1. 在 F3 界面记录背着下界合金背包（面数最多）时的帧率，对比不背包。
2. 多人情形（局域网开两个客户端）下两人同时背不同等级背包，观察帧率。

这一部分只是粗测，没有预设通过线；目的是给"性能预算"这个已知限制提供第一组真实数据。
