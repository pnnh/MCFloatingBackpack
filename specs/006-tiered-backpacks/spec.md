# Feature Specification: 分级浮动背包

**Feature Branch**: `006-tiered-backpacks`

**Created**: 2026-10-25

**Status**: Implemented（玩法部分）；**外观部分已被 [009-sculpted-mesh-backpack-models](../009-sculpted-mesh-backpack-models/spec.md) 取代**

**Input**: User description: "启动 Speckit，实现计划文档 M7 分级背包。现有背包模型只是简单立方体，视觉简陋。参考市面背包与旅行者背包，为各等级重新制作背包模型与物品缩略图，贴图至少 32×32。可用生图与建模辅助。"

> **修订记录（2026-11-04，009 对齐）**：本 spec 写成之后，五档背包外观改成了雕刻网格模型（见 009）。下面凡标注 **【009 修订】** 的条款，原文保留以便追溯，但**以 009 与当前源码为准**；没有标注的条款（容量、升级、开关、面板、互拖等）不受影响，仍然成立。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 五个等级、格子随等级增加 (Priority: P1)

玩家可以获得五种浮动背包：皮革、铁、金、钻石、下界合金。打开后主仓格子数分别为 36、54、72、90、108（均为 9 列）。打开方式与现有皮革背包相同：身上有背包时，游戏画面中按快捷键或主手右键即可开关；暂停等游戏菜单中不显示。服务端仍以该物品实例为库存权威。

**Why this priority**: 分级格子是 M7 的核心玩法，没有它则只有换皮。

**Independent Test**: 创造取出五只背包，分别打开，数清行数（4 / 6 / 8 / 10 / 12 行）。向铁背包放入第 37 格物品，皮革背包没有第 37 格。

**Acceptance Scenarios**:

1. **Given** 玩家主手为皮革浮动背包，**When** 按快捷键打开，**Then** 面板为 4 行 × 9 列（36 格），且不进入独占界面。
2. **Given** 玩家持有铁 / 金 / 钻石 / 下界合金浮动背包，**When** 打开对应实例，**Then** 主仓分别为 54 / 72 / 90 / 108 格。
3. **Given** 玩家身上没有任何浮动背包，**When** 按快捷键，**Then** 面板不打开，并有需要背包的提示。
4. **Given** 身上同时有低等级与高等级背包，**When** 按快捷键，**Then** 仍按既有扫描顺序打开第一只（主手 → 副手 → 胸甲 → 物品栏），面板尺寸对应该只的等级。

---

### User Story 2 - 锻造升级并保留内容 (Priority: P1)

生存玩家从已有皮革背包起步，在锻造台逐级升级到铁、金、钻石、下界合金。升级消耗低一级背包和对应材料，产出高一级背包；原有物品留在新背包前部格子，新增格子为空。不能通过升级把物品弄丢，也不能把高等级降回低等级。

**Why this priority**: 分级若不能从低级长上去，生存向没有成长路径。

**Independent Test**: 皮革背包装满若干标记物品 → 锻造成铁 → 打开后标记物仍在，且多出空行。缺少材料时锻造不产出。

**Acceptance Scenarios**:

1. **Given** 皮革背包内已有物品，**When** 按配方锻造成铁背包，**Then** 得到铁背包，原物品仍在，空出的新格子为空。
2. **Given** 铁、金、钻石背包，**When** 分别用金、钻石、下界合金材料升级，**Then** 各升一级且内容保留。
3. **Given** 材料不足或放入的不是相邻低一级背包，**When** 尝试升级，**Then** 不产出新背包，原背包与材料留在锻造台。
4. **Given** 任意等级背包，**When** 玩家寻找降级配方，**Then** 不存在把高等级变回低等级的配方。

---

### User Story 3 - 可辨认的背包外形与图标 (Priority: P1)

每个等级在物品栏、手持和第三人称背部都像一只背包，而不是棕色方块。外形参考常见旅行背包：包身、顶盖、肩带、扣具；等级之间用材质和配色区分（皮革棕、铁灰金属、金色镶边、钻石青、下界合金暗色带紫边）。物品图标清晰到能单独认出等级，贴图细节不低于 32×32 像素。

> **【009 修订】** 当前五档背包是雕刻网格模型，**没有肩带**（用户明确决定），有包身、顶盖、前口袋、两侧口袋与扣具；贴图为 1024×1024。"像背包而不是方块""等级用材质配色区分""图标能认出等级"这几条意图仍然成立。

**Why this priority**: 用户明确指出当前立方体占位不可接受，且多等级若长得一样就无法辨认。

**Independent Test**: 把五只背包放在快捷栏，不看名字也能靠图标区分；装备到胸甲后按 F5，背部可见背包轮廓（带、盖、包身），不是立方体。

**Acceptance Scenarios**:

1. **Given** 创造物品栏中的五个等级，**When** 玩家查看物品图标，**Then** 五个图标形状都是背包，配色互不相同，且没有一张仍是纯色方块。
2. **Given** 玩家手持任一等级，**When** 第一人称看手持物，**Then** 可见背包立体外形，不是缺材质紫黑块或平板方块。
3. **Given** 胸甲栏装备任一等级，**When** 切换第三人称，**Then** 背部可见该等级配色的背包（肩带与包身可辨），五个等级并排截图可区分。**【009 修订】** 肩带部分取消：背上可见的是无肩带的包身、顶盖与口袋，其余意图不变。
4. **Given** 物品图标与背负贴图，**When** 检查资源尺寸，**Then** 贴图像素边长不低于 32。**【009 修订】** 该下限仍成立，当前贴图为 1024×1024，已远高于下限；贴图过大带来的问题见 009 已知限制 1。

---

### User Story 4 - 创造栏与既有玩法不回退 (Priority: P2)

创造模式物品栏能一次拿出全部五个等级。升级后的背包仍可丢弃、装箱、换手，内容跟着物品走。浮动面板仍可在游戏画面单独打开，也可叠在容器界面上；暂停菜单不显示。与原版容器的互拖仍然可用。

**Why this priority**: 分级不能拆掉已经能玩的打开方式与跨界面取放。

**Independent Test**: 铁背包存入箱子再取出，格子数与内容不变；打开原版物品栏后，面板格子与玩家物品栏可以互拖。

**Acceptance Scenarios**:

1. **Given** 创造模式物品栏，**When** 打开本模组分类，**Then** 五个等级都在其中，取出即可用。
2. **Given** 已装物品的金背包，**When** 丢弃再捡起或放入箱子再取出，**Then** 仍是金背包且内容一致。
3. **Given** 面板在游戏画面中打开，**When** 按 ESC 或再次按快捷键，**Then** 面板关闭，ESC 不因此打开暂停菜单；若此时打开暂停菜单，面板不留在菜单上。
4. **Given** 打开原版物品栏或箱子，**When** 同时开着对应等级的浮动面板，**Then** 仍可在面板与容器之间移动物品。

---

### Edge Cases

- 面板打开时把当前背包升级或换成另一等级：面板尺寸与内容改按新实例显示，或先关闭再打开，不得继续按旧格子数写入。
- 高等级面板（尤其 12 行）在较小窗口中必须仍能点到每一格（整体可拖、位置受屏幕限制，必要时可滚动），不能有格子画在屏幕外且无法操作。
- 升级时若低级背包的光标上还拿着面板光标物品：该物品进入新背包的空位或退回玩家物品栏，不得删除。
- 锻造台中途拿走材料或背包：不产生半成品，不复制背包。
- 主手是低级、箱子里是高级：快捷键只打开身上扫描到的那只，不会打开箱子里的。
- 死亡掉落：背包作为普通物品掉落，内容仍在该物品上。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供五个可区分的浮动背包物品：皮革、铁、金、钻石、下界合金。
- **FR-002**: 系统 MUST 使主仓容量固定为皮革 36、铁 54、金 72、钻石 90、下界合金 108，且均为 9 列。
- **FR-003**: 系统 MUST 把容量与内容保存在对应物品实例上，并由服务端校验一切取放；玩家身上不得再出现与物品无关的全局背包。
- **FR-004**: 系统 MUST 保留现有打开规则：无背包则拒绝并提示；有背包则可在游戏画面用快捷键或主手右键开关；暂停及同类游戏菜单中不显示面板。
- **FR-005**: 系统 MUST 在多只背包时按主手 → 副手 → 胸甲 → 物品栏顺序只打开第一只，面板尺寸对应该只的等级。
- **FR-006**: 系统 MUST 提供从皮革到下界合金的逐级升级，每级只升一档，并保留已有物品到新背包的前部格子。
- **FR-007**: 系统 MUST 在材料或等级不匹配时拒绝升级，且 MUST NOT 提供降级配方。
- **FR-008**: 皮革背包 MUST 保留一条不依赖高等级材料的生存合成途径；更高等级通过升级获得，而不是另起一条丢弃旧背包内容的合成。
- **FR-009**: 创造物品栏 MUST 能直接取出全部五个等级。
- **FR-010**: 每个等级 MUST 有独立的背包外形与物品图标：能看出包身、顶盖与肩带，五个等级配色可区分，不得使用单一立方体占位。**【009 修订】** 肩带要求被取代——当前五个等级都是无肩带设计；包身、顶盖、配色可区分、不得是单一立方体这几条仍成立。
- **FR-011**: 物品图标与背负/手持所用贴图 MUST 不低于 32×32 像素。**【009 修订】** 下限仍成立，当前为 1024×1024，不再是实际约束；"背负用贴图"现在与物品是同一张（背部直接渲染物品自己的模型）。
- **FR-012**: 胸甲栏装备后，第三人称 MUST 显示与该等级一致的背部背包；手持时 MUST 显示同一套外形。
- **FR-013**: 浮动面板 MUST 随等级改变行数，并在较小窗口下仍能操作全部格子。
- **FR-014**: 系统 MUST 保持浮动面板为叠层，不占用当前界面；与原版容器的物品互拖在分级后仍然可用。

### Key Entities

- **分级背包物品**：五个等级之一。决定容量、外观、图标，以及它能升级成的下一等级。
- **背包内容**：绑定在该物品上的主仓格子与尚未放下的面板光标物品。格子数等于该等级容量。
- **升级配方**：低一级背包 + 对应材料 → 高一级背包，内容迁移，不复制物品。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 测试员打开五个等级时，格子数分别为 36、54、72、90、108，误差为 0。
- **SC-002**: 每一级升级后，升级前放入的全部测试物品仍在新背包中（抽样至少每级 5 个不同堆叠），无复制、无丢失。
- **SC-003**: 在不看物品名称的情况下，5 名观察者能凭图标和背部外形区分全部五个等级（每人 5/5）。
- **SC-004**: 物品图标与背负贴图的宽和高都不小于 32 像素；背部与手持都不再呈现为单一立方体。**【009 修订】** 数值下限仍成立（当前 1024×1024）；"不再呈现为单一立方体"已满足。
- **SC-005**: 无背包时快捷键打开失败；有背包时在游戏画面 1 次按键内打开，再按快捷键或 ESC 可关闭。
- **SC-006**: 将一包物品从最高等级面板拖入原版箱子再拖回，数量与种类不变。

## Assumptions

- 格子数采用计划文档已决议的放大档：皮革 36、铁 54、金 72、钻石 90、下界合金 108。不新增 9 格或 18 格基础档。
- 现有皮革浮动背包就是皮革档，不另做一个重复的皮革物品。其合成配方保留。
- 升级材料默认为：皮革→铁用铁锭，铁→金用金锭，金→钻石用钻石，钻石→下界合金用下界合金锭。数量取生存可承受的一小撮（铁/金各 4 锭，钻石 2 颗，下界合金锭 1 颗），在锻造台完成。
- 升级只接受「恰好低一级」的背包，不能跳级，也不能用散件直接合成高等级空包。
- 外观方向对齐常见旅行背包（双肩带、翻盖、扣具、略鼓的包身），五个等级是同一结构的材质变体，不是五套无关主题皮肤。**【009 修订】** 当前五个等级是五个各自独立的雕刻网格模型（结构相近、尺寸与配色随等级变化），**无肩带**，不再是"同一模型 + 换贴图"。
- 贴图允许手绘像素或由概念图转像素，但入库前必须去底、对齐，并且达到 32×32 下限。不要求 64×64 以上写实贴图。**【009 修订】** 当前贴图是从 AI 生成的 3D 模型烘焙出的 1024×1024 写实贴图，与"不要求 64×64 以上写实贴图"的取向相反；这带来共用方块图集膨胀的问题，记录在 009 已知限制 1，尚未解决。
- 打开、ESC、游戏内单独显示、暂停菜单隐藏等行为沿用当前已验收的浮动面板，不退回「必须先开物品栏」。
- 不迁移已经不存在的玩家全局背包数据。

## Out of Scope

- 左侧工具栏、右侧升级插槽，以及磁铁、拾取、虚空等功能升级。
- Curios / 饰品背部槽。
- 管理员按玩家名打开背包的指令。
- 把背包放成世界方块、漏斗交互、流体罐、睡袋。
- 旅行者背包的主题皮肤与生物能力。
- 与旅行者背包之间的物品自动迁移。
