# Feature Specification: 第一个扩展工具——标签管理器

**Feature Branch**: `018-tag-manager`

**Created**: 2026-11-05

**Status**: Draft

**Input**: User description: "现在尝试实现第一个背包扩展玩法。设计一种新的\"扩展工具\"，它的名称叫做\"标签管理器\"。它只能放在背包主区域下方的\"功能区\"里。当点击它之后会在上方（实际上会覆盖部分或完整背包主区域内容，但是宽高要和面板进行网格对齐）展开一个工具面板，在这个面板内管理主背包区选中的单个或多个物品的标签，再次点击收起（面板中的数据不要清空以便后续再次点击打开）。注意多选时仅展示所有选中物品共同拥有的标签（或者无）。在这个标签管理工具面板，支持对选中物品的标签进行查看、增加和删除（点击标签后出现 X 删除图标或文字）。在标签列表最后有一个加号，点击可以新增标签。点击加号之后加号变成一个支持下拉选择的文本框（带一定的关键词模糊匹配功能），按 ESC 键取消添加变回加号，按回车键将用户输入的内容或者选择的预设标签添加到选定物品上。预设几种内置标签，比如石头、木材、食物、矿物、垃圾等等（你可以帮我进行有限的扩充，但不要扩充太多）。用户输入的标签仅允许大小写英文字母、数字、下划线中划线和其它常见的英文符号。注意每个物品分类最多打 10 个标签。如果多选物品之后点击打开\"标签管理器时\"先校验是否选中物品中已经有大于等于 10 个标签，如果存在这种情况，加号按钮是灰色不可点击状态。鼠标滑过提示哪些物品标签超出，不支持批量新增。实际上标签管理器仅仅是配合之前已经实现的 Shift 选区功能为背包中的物品设置标签。注意标签数据是存储在背包模组的数据结构里，即使玩家将物品移走，标签仍然存在。换句话说它不是把标签加在具体某个物品上，而是物品分类上（比如 minecraft:oak_log）。有了这个选区功能，下一步我会计划实现\"垃圾桶功能\"……不过这个垃圾桶功能依赖之前的选区和现在正在规划的标签功能，本阶段暂不实现。"

> **019 已完成（2026-11-05），本文已按它简化**：本 feature 依赖 `specs/019-fallback-host-screen/`——没有容器界面时面板挂在兜底的透明宿主界面上，不再有无界面的 HUD 模式。因此原来的 `TagInputScreen`（HUD 下编辑文本时临时开的输入屏幕）、对宪法 I 的例外、Complexity Tracking 条目和"HUD 键盘捕获"都**不再需要**：宿主与容器界面都是界面，文本框的键盘走同一条 `ScreenEvent.KeyPressed.Pre`/`KeyReleased.Pre`/`CharacterTyped.Pre`（可取消）路径，先于宿主自己的按键处理，所以编辑时打出的 `e`、`t` 不会触发宿主的"让出再重放"。另一个变化：宿主在场时玩家本来就不能移动（019 的已确认取舍），所以"没有焦点时 WASD 照常"改为"没有焦点时标签功能不拦截任何键盘事件"。

## 背景与已确认的决策

016 在主区域外侧加了三个工具区（左=输入、右=输出、下=功能），014 加了 Shift 选区。本 feature 做**第一个真正的扩展工具**：一个叫"标签管理器"的物品，放进**功能区**（下区）后，可以为主区域里选中的物品**分类**（不是具体某个堆叠）打标签。标签将来会被"垃圾桶"等玩法使用（本阶段不做）。

已确认的决策：

1. **标签管理器是一个物品**：**只有放在功能区（下区）才有功能**；放在主区域、左区、右区（包括被 Ctrl 快速转移、拖动等放进去）时它只是一个**普通物品**，没有任何功能（用户补充，见 Clarifications）。
2. **点击分工（用户已确认）**：功能区里的标签管理器，**左键 = 展开/收起标签面板**，**右键 = 拿起/放下**（因为它只有 1 个，右键点击等同于整组拿起，现有点击规则基本不用改）。
3. **标签面板的范围（用户已确认）**：展开时**完整覆盖主区域**（宽高与主区域的格子网格对齐），**展开期间主区域不可操作**——先用 Shift 选好物品再展开，要改选区先收起。收起后面板里的界面状态（输入框内容、滚动位置）保留。
4. **预设标签（用户已确认）**：以**稳定的英文 id** 存储（`stone`、`wood`、`food`、`ore`、`trash` 等），界面按语言显示（中文：石头/木材/食物/矿物/垃圾；英文：Stone/Wood/…）。将来的垃圾桶靠 `trash` 这个 id 识别，换语言不影响数据。用户自定义标签只能英文，原样存储。
5. **标签归属（用户已确认）**：**每只背包各自保存**，标签存在背包物品的数据里，跟着背包走，两只背包互不共享。
6. **自定义标签不允许大写字母**（用户补充）：将来的标签过滤要靠稳定、没有歧义的标签名，大小写容易手误，所以标签全部是小写。
7. 标签挂在**物品分类**上（物品注册 id，如 `minecraft:oak_log`），不挂在具体堆叠上；玩家把物品移走，标签仍然存在。
8. 多选时只显示所有选中物品**共同拥有**的标签（没有共同标签就显示"无"）。
9. **每个物品分类最多 10 个标签**。
10. **有合成配方**（用户要求设计，参考精妙背包与旅行者背包的升级组件，见 FR-020）；**图标只是一张贴图**（像原版的面包：拿在手上、掉在地上、物品栏里都是同一张平面贴图，不做 3D 模型）。
11. **键盘接管看焦点**（用户补充）：只有文本框获得焦点时才拦截键盘；其他时候标签功能不拦截任何键盘事件（019 之后没有无界面的 HUD 模式，面板下面始终有宿主或容器界面，宿主本身不允许移动）。

已查证的事实（读本仓库源码）：

- 016 的服务端"放物品规则钩子"`ToolAreaRules.canPlace` 目前恒为真；用户决定标签管理器**可以放进任何区域**（只是放在主区域等处时没有功能），所以本 feature **不需要**修改放入规则：放入规则保持不变，功能由"这个物品在功能区里"这一事实触发。
- 选区（014）只在客户端、按主区域格子下标保存，服务端不知道；所以标签请求必须带上被选中的**格子下标**，由服务端解析成物品 id。
- 面板是叠层，下面始终有宿主界面或容器界面（019）；面板热键与 ESC 由宿主/现有钩子处理。文本输入需要在**文本框获得焦点时**通过可取消的 `ScreenEvent` 键盘事件接管字符和按键，其余时候标签功能不拦截。
- 精妙背包、旅行者背包的升级组件配方都是"先做一个基础件（精妙：铁锭 + 皮革 + 线；旅行者：线 + 皮革），再加主题材料"的两段式（例如精妙的过滤升级 = 基础件 + 红石粉 + 线；旅行者的合成升级 = 基础件 + 工作台 + 箱子）；我们的背包配方本身是皮革 + 线 + 箱子。
- 现有的背包数据组件 `BackpackContents` 保存主格子、光标和三个工具区；标签将作为新的可选字段加入，旧背包读成空。

## Clarifications

### Session 2026-11-05

- Q: 标签管理器放在功能区时，"点击展开/收起"和"点击拿起"冲突，怎么分工？ → A: **左键展开/收起，右键拿起/放下**。
- Q: 展开的面板覆盖主区域多少，展开期间主区域能不能操作？ → A: **完整覆盖主区域，展开时主区域不可操作**（先选好再展开）。
- Q: 预设标签叫"石头、木材……"但用户自定义只允许英文，预设怎么存？ → A: **存稳定的英文 id，界面按语言显示**；自定义标签原样存储。
- Q: 标签数据属于谁？ → A: **每只背包各自保存**。

### Session 2026-11-05（用户补充）

- 自定义标签**不再允许大写字母**（全部小写），因为后续的标签过滤需要稳定、没有歧义的名称，大小写容易手误。
- 标签管理器**允许放进主区域**（它只是普通物品，没有任何功能）；只有放进下方的功能区才有功能。这也解决了 Ctrl 快速转移等途径可能把它放进主区域的问题。
- 键盘接管**看当前 UI 的焦点**：只有文本框获得焦点时才响应并拦截键盘事件，否则标签功能不拦截。
- 请**设计合成配方**（参考精妙背包、旅行者背包的升级组件）；图标**只要一张贴图**（可用 ludo.ai MCP 或其他自绘方式一次性生成）。

## Out of Scope（本阶段不做）

- **垃圾桶功能**（按"垃圾"标签一键移动、移入背包时自动进垃圾桶）：依赖本功能，另开 feature。
- 在背包格子上**显示标签**（角标、提示文字等）、按标签**筛选/搜索/排序**、标签**重命名**、批量清空。
- 玩家级/世界级共享标签，多只背包之间同步标签。
- 编辑**主区域以外**物品的标签（只管主区域选中的物品）。
- 一个背包里放**多个**标签管理器的特殊规则（可以放，各自都是展开同一套面板，见 Edge Cases）。
- **按区域限制标签管理器的放入**（用户决定不限制）；将来别的扩展工具要不要限制区域，另行决定，`ToolAreaRules` 钩子保留。
- 标签管理器的 **3D 模型**、手持/展示框的特殊外观（只有一张平面贴图）。
- 输入法（IME）输入中文等；本阶段文本框只接受英文输入。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 标签管理器放进功能区才有功能，点击展开/收起面板 (Priority: P1)

玩家合成（或从创意栏拿到）"标签管理器"，把它放进面板下方的功能区；左键点击它，在主区域位置展开一个覆盖整个主区域的标签面板，再次左键点击收起。放在其他区域时它只是一个普通物品。

**Why this priority**: 这是扩展工具的入口，所有标签操作都从这里开始。

**Independent Test**: 合成或拿到物品，试着放进主区域、左区、右区、功能区；只有功能区里左键能展开/收起；右键把它拿起。

**Acceptance Scenarios**:

1. **Given** 标签管理器在光标上，**When** 单击功能区的一个格子，**Then** 它被放进去。
2. **Given** 标签管理器在光标上，**When** 单击主区域、左区、右区的格子，**Then** 它照常被放进去，**只是一个普通物品**；左键点击这些格子里的它，就是照常拿起，**不会展开任何面板**。
3. **Given** 标签管理器在玩家物品栏里，**When** 用 Ctrl 快速转移把它转进面板，**Then** 它进入主区域，同样只是普通物品，没有任何功能；在主区域里的它不影响选区、不影响其他任何操作。
4. **Given** 标签管理器在功能区，光标为空，**When** 左键单击它，**Then** 在主区域位置展开标签面板，不拿起物品。
5. **Given** 面板已展开，**When** 再次左键单击标签管理器，**Then** 面板收起；再次展开时，上次的输入框内容与滚动位置仍在。
6. **Given** 标签管理器在功能区，**When** 右键单击它，**Then** 它被拿起（和现有点击规则一致），面板如果展开则收起。
7. **Given** 标签面板展开，**When** 查看它，**Then** 它完整覆盖主区域，宽高是格子的整数倍并与面板网格对齐；左区、右区、功能区、标题栏、缩放手柄仍然可见可用。
8. **Given** 标签面板展开，**When** 在被覆盖的主区域上点击或拖动，**Then** 不会触发主区域的任何操作（点击被面板消费），也不会改变选区。
9. **Given** 标签面板展开，**When** 拖动缩放手柄改变面板大小，**Then** 标签面板跟着主区域的大小变化，仍与网格对齐。
10. **Given** 标签管理器被拿走、或被换出功能区，**When** 它离开功能区，**Then** 面板自动收起；把它放回功能区后可以再次展开。
11. **Given** 一份按 FR-020 配方摆好的材料，**When** 在工作台合成，**Then** 得到 1 个标签管理器；创意栏与 JEI 里也能找到它，JEI 里能看到这个配方。
12. **Given** 标签管理器，**When** 查看它的外观（物品栏、手持、掉落物、展示框），**Then** 都是同一张平面贴图（像原版的面包），没有 3D 模型。

### User Story 2 - 查看选中物品的标签 (Priority: P1)

玩家用 Shift 在主区域选好物品，展开标签面板，看到这些物品的标签：选一个物品看到它的全部标签，选多个只看到共同拥有的标签。

**Why this priority**: 看到标签是增删的前提，也是多选语义的核心。

**Independent Test**: 给几种物品打上不同标签，选中单个、多个（含重复同种物品、空格子），检查展示。

**Acceptance Scenarios**:

1. **Given** 选中一个有物品的格子，**When** 展开面板，**Then** 显示该物品分类的全部标签，最后是加号。
2. **Given** 选中多个格子里是不同分类的物品，**When** 展开面板，**Then** 只显示**所有**选中物品共同拥有的标签；没有共同标签则显示"无"（以及加号）。
3. **Given** 选中的多个格子里有多格是同一种物品（如三格圆石），**When** 展开面板，**Then** 它们只算一个分类，不重复计算。
4. **Given** 选区里混有空格子，**When** 展开面板，**Then** 空格子被忽略。
5. **Given** 选区里一个有物品的格子都没有（或没有选区），**When** 展开面板，**Then** 显示"请先在主区域用 Shift 选择物品"之类的提示，加号不可用。
6. **Given** 面板展开，**When** 标签显示不下，**Then** 标签自动换行，放不下的部分可以滚动查看。

### User Story 3 - 增加标签：加号、下拉文本框、回车添加、ESC 取消 (Priority: P1)

点击标签列表最后的加号，它变成带下拉的文本框：输入关键词会模糊匹配预设标签；回车把输入的内容或选中的预设标签添加到所有选中物品的分类上；ESC 取消，变回加号。

**Why this priority**: 增加标签是这个工具的主要用途。

**Independent Test**: 选一个物品，点加号，分别用预设（下拉选择、模糊匹配输入）和自定义标签添加；ESC 取消；输入非法字符。

**Acceptance Scenarios**:

1. **Given** 加号可用，**When** 点击它，**Then** 它变成文本框并获得键盘焦点，下方出现预设标签的下拉列表。
2. **Given** 文本框里输入 `wo`，**When** 查看下拉，**Then** 只列出模糊匹配的预设（如 `wood`、`weapon`），匹配不区分大小写，同时匹配预设的英文 id 和当前语言的显示名称。
3. **Given** 下拉里有预设，**When** 鼠标**点击**其中一项，或用方向键选中后按回车，**Then** 该预设标签被添加到所有选中物品的分类上，文本框变回加号，面板里立即出现该标签。（2026-11-05 验证后修订：点击即添加。）
4. **Given** 文本框里输入了自定义的 `my_tag-1`（没有选中下拉项），**When** 按回车，**Then** 该标签被添加到所有选中物品的分类上（原样存储）。
5. **Given** 文本框里有内容，**When** 按 ESC，**Then** 添加被取消，文本框变回加号，不添加任何标签；**面板不关闭，游戏也不弹出暂停菜单**。
6. **Given** 文本框，**When** 输入非法字符（**大写字母**、空格、中文等不在允许范围内的字符），**Then** 这些字符不会进入文本框（被拒绝，可有轻微提示）；允许的是**小写英文字母**、数字、下划线、中划线和其他常见的可见 ASCII 符号（不含大写字母、不含空格）；长度 1～16。
7. **Given** 要添加的标签与已有标签重复，**When** 按回车，**Then** 不会重复添加（标签全是小写，所以不存在大小写歧义）。
8. **Given** 多选了 3 种物品，**When** 添加一个标签，**Then** 它被添加到这 3 个分类上；其中已经有该标签的分类不重复添加。
9. **Given** 文本框为空，**When** 按回车，**Then** 什么都不添加（保持文本框或变回加号均可，不报错）。
10. **Given** 文本框获得焦点，**When** 输入 `w`、`a`、`s`、`d`、`e` 等字符，**Then** 它们只进入文本框，不触发玩家移动、打开物品栏等任何游戏按键。
11. **Given** 文本框**没有**焦点（面板展开但还没点加号，或已取消/添加完成），**When** 按键，**Then** 标签功能不拦截任何键盘事件：宿主界面自己的行为照旧（E 等打开界面的按键仍会让出，世界动作键被吞掉），浮动面板自己已有的热键（切换面板、ESC 关闭面板）保持原样。
12. **Given** 文本框有焦点，**When** 点击文本框以外的位置、按 ESC、按回车或标签面板收起，**Then** 文本框失去焦点，键盘立刻恢复给游戏。

---

### User Story 4 - 删除标签 (Priority: P2)

点击面板里的一个标签，它旁边出现"✕"，点击"✕"把该标签从选中物品的分类上删除。

**Why this priority**: 有增就要有删，但不如增加常用。

**Independent Test**: 给物品打两个标签，点其中一个出现 ✕，点 ✕ 删除；多选时检查共同标签的删除。

**Acceptance Scenarios**:

1. **Given** 面板里有标签，**When** 点击其中一个，**Then** 它旁边显示"✕"（图标或文字）。
2. **Given** 某个标签显示了"✕"，**When** 点击"✕"，**Then** 该标签从**所有**选中物品的分类上移除（多选时显示的都是共同标签，所以每个分类都有它），面板里它消失。
3. **Given** 某个标签显示了"✕"，**When** 点击面板的其他位置或另一个标签，**Then** "✕"消失（不删除）。
4. **Given** 删除后某个分类的标签数降到 10 以下，**When** 查看加号，**Then** 加号恢复可用。

---

### User Story 5 - 每个分类最多 10 个标签，满了加号变灰 (Priority: P2)

展开面板（或选区变化后）先校验选中的物品里有没有分类已经有 10 个标签；有则加号灰色不可点，鼠标移上去提示是哪些物品超出，且不支持批量新增。

**Why this priority**: 是明确的数据上限与批量操作规则。

**Independent Test**: 给一个物品打满 10 个标签；单选它、与其他物品一起多选，检查加号状态与提示；删除一个标签后检查恢复。

**Acceptance Scenarios**:

1. **Given** 选中的物品里至少有一个分类已有 10 个标签，**When** 展开面板，**Then** 加号是灰色、点击无效。
2. **Given** 加号是灰色，**When** 鼠标移到加号上，**Then** 弹出提示，列出**标签已满的物品名称**，并说明"标签已满的物品不支持批量新增"。
3. **Given** 多选了 3 种物品，其中 1 种已满，**When** 查看加号，**Then** 仍然是灰色（不支持批量新增），提示里只列出已满的那 1 种。
4. **Given** 某分类恰好 9 个标签，**When** 单选它添加 1 个，**Then** 添加成功，它达到 10 个，之后加号变灰。
5. **Given** 服务端收到的添加请求会让某个分类超过 10 个（例如客户端状态过期），**When** 处理请求，**Then** 服务端拒绝整个请求，不改变任何数据（客户端校验只是体验，不是权威）。

---

### User Story 6 - 标签跟着背包走、跟着分类走，并且不影响现有功能 (Priority: P2)

标签保存在这只背包的数据里：关闭面板、退出游戏、把物品移出背包后标签仍在；换另一只背包不共享；背包升级保留；旧背包没有标签也能正常使用。

**Why this priority**: 标签是持久数据，是将来垃圾桶等玩法的基础。

**Independent Test**: 打标签后取走物品、关闭面板、退出重进、升级背包、换背包，检查标签；回归 011～017 的验证项。

**Acceptance Scenarios**:

1. **Given** 给橡木原木打了 `wood` 标签，**When** 把背包里所有橡木原木取走，**Then** 再放回橡木原木后展开面板，标签仍在。
2. **Given** 打了标签，**When** 关闭面板、退出世界再进入，**Then** 标签仍在。
3. **Given** 两只背包，**When** 在其中一只上打标签，**Then** 另一只上看不到这个标签。
4. **Given** 打了标签的背包，**When** 用锻造台升级，**Then** 标签保留。
5. **Given** 在 018 之前保存的旧背包，**When** 打开，**Then** 没有任何标签，没有报错。
6. **Given** 主区域、工具区的现有操作（点击、拖动、选区、Ctrl 转移、缩放、滚动），**When** 重跑 011～017 的验证项，**Then** 与之前一致（唯一变化：标签管理器这个物品只能放功能区；展开面板期间主区域不可操作）。

---

### Edge Cases

- **选区含的格子被服务端同步改变**（例如物品被移走）：面板按最新内容重新计算分类，不报错。
- **标签管理器被放进功能区的多个格子**：允许，每个都能展开同一套面板（展开状态是一份，不是每个工具各一份）；收起任意一个即收起面板。
- **面板展开期间关闭浮动面板（Esc/关闭按钮/热键）**：浮动面板关闭；下次打开时标签面板是收起的，但输入框内容与滚动位置保留（界面状态属于会话，不属于背包数据）。
- **文本框获得焦点时按 ESC**：只取消添加，**不关闭**浮动面板，**不弹出暂停菜单**；没有文本框焦点时 ESC 的行为保持原样（关闭浮动面板）。
- **文本框获得焦点时的其他按键**：Backspace、方向键、Home/End、粘贴（Ctrl/Command+V，非法字符——包括大写字母——被过滤）按文本框的常规行为处理；鼠标点击文本框以外的位置：取消添加并失去焦点。
- **没有焦点时不拦截**：只要文本框没有焦点，标签功能对键盘事件一律不拦截；宿主与容器界面各自的按键规则（019）不受影响。
- **预设 id 与用户输入冲突**：用户输入 `stone`（与预设 `stone` 完全相同）时就是预设 `stone`，不会产生两个；因为全部小写，不存在大小写歧义。
- **标签管理器在主区域/左区/右区**：只是普通物品，没有功能；不会展开面板，也不会让已展开的面板继续存在（面板只认功能区里的它）。
- **标签显示宽度**：标签最长 16 个字符，面板里一行放不下时换行；最小的主区域（3×3）里标签列表可以滚动。
- **多选时删除与添加的竞态**：删除一个已经不存在的标签、添加一个已经有的标签，都按幂等处理，不报错。
- **已被移除的模组物品**：它们的标签数据保留，不清理，不报错。
- **物品分类的粒度**：只按物品 id；同一个 id 的不同附魔、命名、耐久视为同一分类。
- **总量**：每个背包的标签数据随使用增长，每个分类最多 10 个、每个标签最长 16 个字符，不再设其他上限。
- **服务端权威**：所有增删由服务端校验并执行；客户端只发"被选中的格子下标 + 标签"，不发物品 id。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供一个名为"标签管理器"的物品，出现在创意栏和 JEI，并有合成配方（FR-020）；中文名"标签管理器"，英文名 "Tag Manager"；最大堆叠 1。
- **FR-002**: 标签管理器 MUST **可以放进任何区域**（主区域、左区、右区、功能区，以及玩家物品栏等），包括通过 Ctrl 快速转移、拖动、双击收集等途径进入主区域；放入规则 MUST 保持 016 的现状（本 feature 不增加任何放入限制）。**只有当它在功能区（下区）里时才有标签管理的功能**；在其他区域里它只是普通物品，没有任何功能。
- **FR-003**: 光标为空时，左键单击**功能区里**的标签管理器 MUST 展开/收起标签面板，MUST NOT 拿起它；右键单击 MUST 与现有规则一致（拿起整组）；光标上有物品时的左键单击按现有的点击规则处理（交换/合并），不展开面板；在主区域、左区、右区里的标签管理器，所有点击与普通物品完全一样。
- **FR-004**: 展开的标签面板 MUST 完整覆盖主区域，宽高 MUST 是格子的整数倍并与面板网格对齐；展开期间主区域 MUST NOT 响应点击、拖动、滚轮和选区手势（被面板消费），主区域的选区 MUST 保持不变；左区、右区、功能区、标题栏、关闭按钮、缩放手柄、整体拖动 MUST 保持可用；缩放面板时标签面板 MUST 跟随主区域大小。
- **FR-005**: 标签面板 MUST 能再次左键点击标签管理器收起；收起后面板的界面状态（输入框内容、滚动位置）MUST 保留；标签管理器离开功能区、浮动面板关闭时 MUST 收起标签面板。
- **FR-006**: 面板 MUST 显示选中物品的标签：单个分类显示它的全部标签；多个分类只显示**所有**分类**共同拥有**的标签（没有则显示"无"）；同种物品只算一个分类；空格子被忽略；没有选中任何有物品的格子时显示提示，加号不可用。
- **FR-007**: 标签列表的最后 MUST 有一个加号；点击可用的加号 MUST 变成带键盘焦点的文本框，并显示预设标签的下拉列表，列表按输入做**不区分大小写的模糊匹配**，同时匹配预设的英文 id 和当前语言的显示名称。
- **FR-008**: 按回车 MUST 把下拉里选中的预设标签（若有选中项）或文本框里输入的内容（校验通过）添加到**所有选中物品的分类**上，然后文本框变回加号；已经拥有该标签的分类不重复添加；空输入不添加。
- **FR-009**: 按 ESC MUST 取消添加、文本框变回加号，且 MUST NOT 关闭浮动面板、MUST NOT 打开暂停菜单；点击文本框以外的位置同样取消添加。
- **FR-010**: 自定义标签 MUST 由 1～16 个字符组成，仅允许**小写**英文字母、数字、下划线、中划线和其他常见的可见 ASCII 符号（不含**大写字母**、不含空格）；不合法的字符（包括大写字母）MUST NOT 被接受，MUST NOT 被自动转成小写；服务端 MUST 再次校验，含大写字母的标签整个请求被拒绝。
- **FR-011**: 点击面板里的标签 MUST 在其旁显示"✕"；点击"✕" MUST 把该标签从**所有**选中物品的分类上移除；点击别处 MUST 取消显示"✕"而不删除。
- **FR-012**: 每个物品分类的标签数 MUST NOT 超过 10。展开面板时和选区/数据变化后，只要选中物品中有任一分类已有 ≥ 10 个标签，加号 MUST 为灰色且不可点击；鼠标悬停在灰色加号上 MUST 弹出提示，列出标签已满的物品名称，并说明不支持批量新增。服务端 MUST 拒绝会让任一分类超限的请求（整个请求不生效）。
- **FR-013**: 系统 MUST 内置一组**有限**的预设标签：`stone`、`wood`、`food`、`ore`、`trash`、`tool`、`weapon`、`armor`、`plant`、`redstone`（共 10 个）；预设以稳定的英文 id 存储，界面按语言显示（`zh_cn`：石头、木材、食物、矿物、垃圾、工具、武器、盔甲、植物、红石；`en_us`：Stone、Wood、Food、Ore、Trash、Tool、Weapon、Armor、Plant、Redstone）；自定义标签原样存储。
- **FR-014**: 标签数据 MUST 以**物品注册 id**为键、标签列表为值，保存在**该背包**的数据里：物品被移出背包、面板关闭、退出重进后标签仍在；MUST NOT 与具体堆叠绑定；两只背包互不共享；升级保留；018 之前保存的旧背包读成空。
- **FR-015**: 标签的增加与删除 MUST 由服务端校验并执行：请求携带被选中的主区域**格子下标**与标签，服务端把下标解析成物品 id，校验下标范围、标签合法、不超限、请求者确实持有该背包；客户端 MUST NOT 被信任提供物品 id；标签数据 MUST 同步到客户端用于显示。
- **FR-016**: 键盘接管 MUST 以**当前 UI 的焦点**为准：只有标签文本框**获得焦点**时，键盘字符与按键才 MUST 只作用于文本框（MUST NOT 触发打开物品栏、聊天、热键等游戏按键，也 MUST NOT 触发宿主的"让出再重放"）；文本框**没有焦点**时标签功能 MUST NOT 拦截任何键盘事件；浮动面板已有的热键（切换面板、ESC 关闭面板）保持原样；文本框在 ESC、回车、点击文本框以外、标签面板收起、浮动面板关闭、标签管理器离开功能区时 MUST 失去焦点；在宿主界面（没有容器界面时）与容器界面两种情况下 MUST 一致。
- **FR-017**: 011～017 的现有行为 MUST 保持不变（选区、Ctrl 转移、拖动手势、缩放、滚动、工具区存放等）；工具区除"标签管理器只能放功能区、左键点击它展开/收起"外，其余点击规则不变。
- **FR-018**: 所有界面文字（物品名、预设标签、提示、占位文字、"无"、提示语）MUST 提供 `zh_cn` 与 `en_us` 两份。
- **FR-019**: 新增的资源 MUST 只有标签管理器的**一张 16×16 物品贴图**（平面物品，像原版的面包：物品栏、手持、掉落物、展示框都是这一张贴图，不做 3D 模型）与语言条目；贴图 MUST 一次性生成（用 ludo.ai MCP 或其他自绘方式，最后整理成 16×16 像素风）；共用方块图集的尺寸 MUST 保持不超预算（宪法 VI），实现完成时跑一次图集度量并记录，生成方式与来源记录在 DELIVERY。
- **FR-020**: 标签管理器的**合成配方** MUST 是一个 3×3 有序配方，用原版常见材料、成本相当于精妙背包/旅行者背包里一个中等的升级组件（它们都是"基础材料：线 + 皮革"再加主题材料），主题是"标签"（吊牌 = 纸 + 线，墨水，书）：
  ```text
  线   纸  线
  皮革 书  皮革      → 1 个标签管理器
  纸   墨  纸
  ```
  即 2 线（`c:strings`）、2 皮革（`c:leathers`）、1 书（`minecraft:book`）、2 纸（`minecraft:paper`）、1 墨囊（`minecraft:ink_sac`，或黑色染料）。配方不依赖精妙背包、旅行者背包的任何物品（宪法 IV）。

### Key Entities

- **标签管理器**：扩展工具物品，只能放在功能区；左键展开/收起标签面板。
- **标签**：一个全小写的字符串（预设是稳定的英文 id，自定义是 1～16 个可见 ASCII 字符，不含大写字母和空格），判重就是字符串相等。
- **物品分类**：物品注册 id（如 `minecraft:oak_log`）；标签挂在分类上。
- **背包标签数据**：该背包保存的"分类 → 标签列表"映射，每个分类至多 10 个标签。
- **标签面板**：覆盖主区域的叠层，显示选中物品的（共同）标签、加号/文本框；有会话级的界面状态（输入框内容、滚动位置、是否展开）。
- **预设标签**：内置的 10 个标签（id + 中英文显示名）。
- **选中物品集合**：来自 014 的选区，解析为去重后的物品分类集合（忽略空格子）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 标签管理器放进功能区后左键能展开/收起面板；放进主区域、左区、右区（含 Ctrl 快速转移进主区域）时它被正常放入，但在这三个区域里左键点击它只是拿起，**展开面板的次数为 0**。

- **SC-003**: 单选显示该物品的全部标签；对 3 种物品多选，只显示三者共同的标签（交集），3 个场景（有交集、无交集、含重复同种与空格子）都符合。
- **SC-004**: 添加（预设下拉选择、预设模糊匹配、自定义）、ESC 取消、回车添加、删除（点击标签出 ✕、点 ✕）全部按规则工作；给一个分类添加到 10 个标签后，加号变灰，悬停提示列出该物品。
- **SC-005**: 把物品从背包取走、关闭面板、退出重进、换背包，标签的归属与保留符合 FR-014；升级后标签保留；旧背包无标签无报错。

- **SC-007**: 服务端对非法请求（越界下标、非法标签——含大写字母或空格的、会超 10 个）全部拒绝且数据**零变化**。

- **SC-009**: 图集度量仍为 2048×1024（新增只有一张 16×16 平面贴图），退出码 0；配方在工作台里能合成出 1 个标签管理器。
- **SC-010**: 在开发机（macOS）上以上流程均可完成；Windows/Linux 无法验证，登记为未验证。

## Assumptions

- **只按物品 id 分类**：不区分附魔、命名、耐久等组件。
- **标签规则**：1～16 个字符，可见 ASCII 去掉大写字母和空格（小写字母、数字、`_`、`-` 和其他常见符号）；全部小写，所以判重就是字符串相等；预设标签的 id 全部小写。输入大写字母时**拒绝**而不是自动转小写（用户说"不再允许输入大写字母"；若想改成自动转小写，只需改文本框的输入过滤）。
- **下拉匹配**：子串/子序列匹配，对预设的显示名称不区分大小写，同时匹配预设 id 与当前语言的显示名称。
- **加号的行为**：回车添加成功后，文本框变回加号（需要连续添加就再点一次加号）。
- **预设扩充**：在用户给的"石头、木材、食物、矿物、垃圾"之外，只再加 `tool`、`weapon`、`armor`、`plant`、`redstone` 五个，共 10 个，足以覆盖常见分类又不繁琐。
- **获取方式**：合成配方（FR-020）、创意栏、JEI。配方按"成本相当于一个中等升级组件"设计：2 线 + 2 皮革 + 1 书 + 2 纸 + 1 墨囊，全部是原版早期材料；以后平衡可以改，不影响其他规则。
- **多个标签管理器**：功能区可以放多个，展开状态只有一份；这是最简单的行为，不为此设计特殊规则。
- **"数据不要清空"的含义**：指标签面板的界面状态（输入框内容、滚动位置）在收起后保留；标签数据本身本来就保存在背包里。
- **文本输入的范围**：只接受允许的字符（小写英文字母、数字、符号；键盘字符与粘贴），不支持输入法（IME）；粘贴时非法字符（包括大写字母）被过滤。
- **"焦点"的含义**：用户说"当焦点在浮动面板、在文本框时才响应相关键盘事件"。这里把键盘**输入**的焦点定为文本框（点击加号后获得）；浮动面板自己已有的热键与 ESC 关闭照旧，但在文本框没有焦点时都不额外拦截任何键盘事件。
- **图标**：一张 16×16 的平面贴图，用 `item/generated` 这类平面父模型即可（和原版面包一样），具体怎么生成留给 plan。
- **依赖**：014（Shift 选区）、016（功能区与工具区存放）、017（面板尺寸规则）。本 feature **不修改**任何放入规则：标签管理器可以放进任何区域，功能由"它在功能区里"触发。
- 本功能是纯玩家可见的交互与存储结构变化，按宪法 V 必须在客户端会话里逐场景验证，尤其是展开/收起、文本框与键盘接管、ESC、持久化、联机重进；Windows/Linux 本机无法验证。
- **026 补充**：所有读写背包内容的服务端入口（含本功能的标签请求）先过 026 的可用性检查（背包编号与登记表；唯一的拒绝是被管理员删除的背包），被拒绝时请求零变化，详见 `specs/026-backpack-id/`。
