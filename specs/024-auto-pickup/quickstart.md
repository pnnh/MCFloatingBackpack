# Quickstart: 自动拾取验收步骤

按宪法 V，下面的玩家可见行为都要在客户端会话里逐项验证；单元测试和编译不能代替。未验证的项在 tasks/DELIVERY 里保持"未验证"。

## 准备

```bash
pgrep -f "fml.modFolders=mcfloatingbackpack" || echo "没有游戏在跑"   # 有就不要启动第二个，也不要杀用户的游戏
./gradlew test                                                            # 纯逻辑与资源测试（含依赖规则）
./gradlew runClient                                                       # 默认带 JEI；-PnoJei 去掉 JEI
./gradlew runClientCompat                                                 # 带精妙背包 + 旅行者背包（F 组需要）
```

进创造模式世界。从创意栏拿：浮动背包 ×2（A、B）、自动拾取、标签管理器、垃圾桶；另备一堆圆石、泥土、橡木原木、一个附魔钻石镐、一个箱子；用 `/give` 或创意栏准备掉落物（Q 键丢出，或 `/summon item`）。

## A. 物品与配方

- **Q1** 创意栏"浮动背包"页里有"自动拾取 / Auto Pickup"，名字随语言切换；最大堆叠 1。
- **Q2** 工作台摆 `铁锭 末影珍珠 铁锭 / 红石粉 漏斗 红石粉 / 铁锭 钻石 铁锭` → 得到 1 个自动拾取；摆错（缺一样、换材料）得不到；JEI 里能看到这个配方。
- **Q3** 物品栏、手持、掉落物、展示框都是同一张平面贴图（漏斗 + 珍珠），无 3D 模型。
- **Q4** 图集度量（先 `pgrep`，再 `design/demo/tools/check_atlas_budget.sh`）：仍为 2048×1024；度量不了就写"未度量"。

## B. 放进左侧区 → 掉落物进背包

- **Q5** 背包 A 左侧区放进自动拾取，**关着浮动面板**，走近一堆圆石掉落物：圆石出现在 A 的主区域（打开面板看），**玩家物品栏里没有**；有拾取动画与声音。
- **Q6** 先有一格 32 个圆石：再捡 64 个 → 先叠满那一格，再占新格；总量对。
- **Q7** 把自动拾取放进主区域 / 右区 / 下区：捡东西 → 全部进玩家物品栏，A 的主区域不变；从左侧区拿走后同样。
- **Q8** 主区域塞满：捡 64 个圆石 → 全进物品栏。主区域只剩 1 个空位、掉落物是 64 个未叠满的圆石且只能放下 20 个 → 20 个进背包，44 个进物品栏（总量 64）。
- **Q9** 物品栏也满、背包也满：物品留在地上，不丢失、不复制。
- **Q10** 刚丢出的物品（有拾取延迟）：走开再走回来，拾取的时机与不带自动拾取时一致。

## C. 激活背包（按 B 打开的那只）

- **Q11** 手持背包 A（左侧区**没有**自动拾取）、物品栏里有背包 B（左侧区**有**）：按 B 打开的是 A；捡东西 → 进物品栏，B 不动。
- **Q12** 把 A 从手里收起（只剩 B）→ 下一次拾取起进 B；再把 A 拿到手上 → 下一次拾取起又进物品栏。面板开着与关着结果一致。
- **Q13** 两只都放了自动拾取：只有手持的那只（按 B 打开的那只）生效。

## D. 页面与互斥

- **Q14** 左侧区的自动拾取：左键 → 主区域上展开黑名单页面（标题行"自动拾取黑名单 0/64"，标签区"无"，末尾加号）；再次左键收起；右键拿起，页面收起。
- **Q15** 光标上有物品时左键它 = 交换 / 合并，不展开页面；在主区域 / 右区 / 下区里它只是普通物品，左键只是拿起。
- **Q16** 页面展开时点主区域任意处：不穿透（没选中、没转移、没拖动）；滚轮在页面上滚动页面。
- **Q17** 下区放标签管理器，展开标签页 → 再展开黑名单页：标签页收起；反过来也一样；垃圾桶面板可以与黑名单页同时展开。
- **Q18** 页面展开时拿走自动拾取、或关闭浮动面板：页面收起，重新打开是收起的；移到 020 配置为 OFF 的模组界面上，页面随面板隐藏、回来后恢复。
- **Q19** 左侧区已有一个自动拾取：再放第二个（空格 / 别的物品的格子）被拒绝并在聊天区提示；用它自己的格子交换成功；Alt 交换主手同样被拒；其它区域放多个照旧允许。

## E. 黑名单过滤

- **Q20** 用标签管理器给背包 A 里的圆石打 `stone`、给橡木原木打 `wood`；展开黑名单页，点加号 → 下拉里有预设（石头、木材……）和本背包已用过的标签；添加 `stone` → 标签块出现；点它出现删除标记，点删除即移除。
- **Q21** 黑名单 `stone`：走近圆石 → **不被拾取**（也不进物品栏），反复走过始终留在地上；走近泥土 → 进背包；删掉 `stone` 后圆石被拾取。
- **Q22** 一个物品有两个标签，只有一个在黑名单 → 不被拾取；在标签管理器里删掉该标签后恢复被拾取。
- **Q23** 在黑名单里加 `trash`（022 的预设），给垃圾打 `trash` 标签 → 垃圾留在地上。
- **Q24** 自己 Q 键丢出的黑名单物品，走过去也不被拾取。
- **Q25** 加到 64 个标签（可批量输入不同字符串）：加号变灰，悬停提示已满；再添加不了；重复添加同一标签不重复也不报错。
- **Q26** 文本框焦点：输入时 `e`、`t`、数字不触发别的快捷键；ESC 取消、回车添加；没有焦点时键盘不被拦截（按 B 能关面板，宿主界面的按键让出再重放照常）。022 的 Delete 键：页面展开时不删主区域物品。

## F. 与精妙背包 / 旅行者背包同时拾取（`runClientCompat`；**只验证安全性，不验证分配**）

> 版本以开发期 jar 为准：精妙背包 3.26.19、旅行者背包 10.1.40。本模组不检测它们，只是晚一步出手；下面看的是"不崩溃、总量守恒、行为符合 research Decision 6 的表格"。

- **Q27** 背包 A 左侧区放自动拾取，玩家**没有**携带任何其它背包 → 正常拾取（Q5）。
- **Q28** 带着装了**拾取升级且没有过滤器**的精妙背包，走近掉落物 → 大多被精妙背包拿走；A 拿到的很少或为 0；总量对（背包 + 对方 + 物品栏 + 地上 = 原数量）。
- **Q29** 对方升级装了**过滤器**（只放行某物品）：不在过滤器里的物品进 A 的主区域，而不是玩家物品栏。
- **Q30** 对方升级放行某物品、且该物品命中 A 的黑名单 → 被对方拿走（黑名单只管本模组）。
- **Q31** 旅行者背包穿在身上、装了拾取升级：同上；它和精妙背包同时开着时可能各拿一部分，不崩溃、不复制。
- **Q32** 旅行者拾取升级的 `tick` 吸取 / 精妙磁铁：物品在你碰到之前就被吸走（预期行为，A 拿不到）。
- **Q33** 同时背着三个都开着自动拾取的背包，走过 20 次掉落物：不崩溃、总量守恒；各拿多少不作要求。
- **Q34** 没安装这两个模组（`runClient`）：功能完整可用，启动日志无关于它们的错误；专用服务器/局域网无条件则写"未验证"（协议 `"12"`）。

## G. 持久与回归

- **Q35** 黑名单有标签：关面板、退出世界重进、自动拾取取走再放回、锻造台升级背包、换另一只背包——黑名单随背包保留、互不共享；024 之前保存的旧背包黑名单为空、无报错。
- **Q36** 多人：一名玩家的自动拾取只影响他自己；别人的物品栏与背包不变。
- **Q37** 回归 011～023 的验证项（点击、拖动均分/收集、选区、Ctrl 转移、缩放、滚动、标签、垃圾桶与 022 的删除手段、020 的兼容开关、宿主界面、023 的配方）：结果与之前一致；唯一变化是左侧区限放 1 个、标签页与黑名单页互斥。

## H. 成本粗测（宪法 VI，写进 DELIVERY；测不了就写"未测量"）

- **Q38** 每个拾取事件的额外成本：无背包的玩家 / 有背包但没有自动拾取 / 激活，各记一个粗略数量级（`System.nanoTime` 对 10 万次调用求平均，调试日志里看）。
- **Q39** 高频拾取的同步量：一次拾取 64 个不同掉落物，抓一下客户端收到的容器同步字节数（背包物品栏格子重发）；如明显过大，登记为后续"拾取批处理"的依据。
