# Quickstart: 背包在 GUI 里用平面图标验收步骤

按宪法 V，玩家可见行为都要在客户端会话里验证；未验证的项在 tasks/DELIVERY 里保持"未验证"。

## 准备

```bash
pgrep -f "fml.modFolders=mcfloatingbackpack" || echo "没有游戏在跑"   # 有就不要启动第二个，也不要杀用户的游戏
./gradlew test
python3 design/demo/tools/render_backpack_icons.py                # 重新生成图标（输出确定，不应有差异）
./gradlew runClient
```

## A. 帧率对照（US1、SC-001、SC-002）

**与 2026-11-08 完全相同的条件**：同一个位置、同一个视角、人物不动、F3 打开、同样的渲染距离与分辨率。

- **A1** 快捷栏里放 8 只背包（五档混放也可以）：记下 F3 的 fps。
- **A2** 把背包全部移到物品栏上三行（不开界面时不画），记下 fps。**改动前：约 22 对约 101。**期望：两者相差不超过约 10%。
- **A3** 物品栏里放很多只背包，打开物品栏界面：fps 不再是约 15。
- **A4** 把手里拿一只背包（3D 模型）：记下 fps，应该只比空手略低（一只 3D 模型）。

## B. 外观（US2、US3）

- **B1** 五档背包各一只并排放在快捷栏：一眼能分出皮革、铁、金、钻石、下界合金；边缘干净、没有白边；物品栏界面（暗）与世界（亮）下都清晰。
- **B2** 与手持的 3D 模型对照：外形与配色一致。
- **B3** **手持**（第一人称、第三人称，主手与副手）：与改动前一致。
- **B4** **背在背上**（穿在胸甲位）：外形与位置与改动前一致。
- **B5** **展示框**里放一只：仍是 3D 模型。
- **B6** **掉在地上**的背包：**仍是 3D 模型**，与改动前一致（同时掉很多会掉帧，正常游玩不会）。
- **B7** 面板标题栏的等级图标：平面图标，悬停仍是等级名称；打开箱子与 JEI：里面的背包是平面图标。

## C. 回归与度量

- **C1** 011～027 的验证项（点击、拖动、转移、标签、垃圾桶、自动拾取、编号显示、创造界面）结果与之前一致。
- **C2** 图集度量（先 `pgrep`，再 `design/demo/tools/check_atlas_budget.sh`）：宽、高都不超过 2048；记录数值（改动前 2048×1024）。
- **C3** **ESC 菜单**：打开系统菜单时 fps 是否还从约 100 掉到约 60；记录，不要求修复。
