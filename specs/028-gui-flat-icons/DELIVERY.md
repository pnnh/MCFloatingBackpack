## 实现摘要

- **模型重组**（每档三个文件）：`<tier>_floating_backpack.json` 改成 `neoforge:separate_transforms` 入口（`gui_light: front`，`base` → `_3d`，`perspectives` 只有 `gui` → `_icon`）；原来的内容原样搬到 `<tier>_floating_backpack_3d.json`；新建 `<tier>_floating_backpack_icon.json`（`item/generated`）。**`perspectives` 里没有 `fixed`**：背在背上的渲染（`BackpackBackLayer`）用 `ItemDisplayContext.FIXED`，展示框也用它；测试明确检查它们不在。
- **图标**：`design/demo/tools/render_backpack_icons.py`（纯 Python + PIL）。读 OBJ 与皮肤贴图，按原来的 GUI 视角（`[30, 225, 0]`）正交投影，Z 缓冲、背面剔除、逐像素采样皮肤、柔和方向光，4× 超采样后按覆盖采样平均到 32×32（颜色只取被覆盖的样本，没有暗边）；五档共用一个缩放（每像素 23.47 个方块单位）以保持相对大小，各自按剪影居中，最外一圈像素透明（图集接缝）；输出确定，约 1 秒。已目视检查五张图：五档互相可区分，朝向与配色与 2026-11-08 快捷栏截图里的外观一致。
- **`ground`（掉落物）保持 3D**：最初的假设是掉落物也换成图标，**用户 2026-11-09 验证帧率达标后要求保持 3D**（同时掉落很多时帧率会降，但正常游玩不太可能）。已去掉入口 JSON 里的 `ground` 并把测试改成"`perspectives` 不含 `ground`"。图集里的图标不变。

## 与 plan/spec 的偏离

- **FIXED 不换**（与最初设想的"GUI、地面、展示框"不同）：`BackpackBackLayer` 用 `FIXED`，所以展示框也保持 3D。已写进 spec 的决策与 research D1。

## 已知限制与未验证项

- Windows/Linux 未验证（只有 macOS 本机）；光影下未验证。
- 展示框里的背包、背在背上与**掉落物**仍是 3D 模型（有意）；同时掉落很多只背包时帧率会下降（用户接受，正常游玩不会发生）。
- 图标是 32×32 的离线渲染，没有立体感；如果观感不满意，可以调脚本里的 `AMBIENT`、`DIFFUSE`、`LIGHT` 与 `MARGIN` 后重新运行。
- ESC 菜单掉帧（约 100 → 60 fps，原因不明）本 feature 不处理，只在验证时复测记录。
- 主因（GUI 里的网格提交）已由 T007 的结果证实：换成平面图标后帧率从约 22 回升到 90 以上。
