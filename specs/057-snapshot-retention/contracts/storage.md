# Contract: 快照存储（文件名、文件头、状态文件、读取规则）

## 目录

`<服务器目录>/mcfloatingbackpack/snapshots/<世界名>/`（不变）：

```text
<世界名>/
├── state.properties                      # 新（本 feature）
├── <uuid>-<id>/                          # 每只背包一个文件夹（不变）
│   ├── 1794899246892.dat                 # 变更（也是版本 1 的旧文件）
│   ├── 1794899300000-t.dat               # 定时
│   └── 1794800000000-u.dat               # 升级前
└── …
```

## 文件名

`<time>.dat` / `<time>-t.dat` / `<time>-u.dat`，`<time>` 是毫秒时间戳（十进制）。`SnapshotFiles.parseTime(name)` 返回时间，**不认识的名字返回 -1**（临时文件 `….tmp`、别的后缀、以后的版本新增的后缀都是）；新增 `SnapshotFiles.kindOf(name)`。同一时间已有同名文件时用 `freeTime`（现有）顺延，不同类别可以同一毫秒（后缀不同，互不冲突）。

## 文件头（压缩 NBT 复合标签）

| 键 | 类型 | 说明 |
|---|---|---|
| `version` | int | **2**（本 feature 起）；旧文件是 1 |
| `uuid` | UUID | 背包身份 |
| `owner` / `ownerName` | UUID / string | 最近使用者 |
| `capacity` | int | 背包格数 |
| `time` | long | 与文件名一致 |
| `slots` | int | 主区域非空格数 |
| `kind` | string | `TIMED` / `CHANGE` / `UPGRADE`；缺失按 `CHANGE` |
| `from_mod_version` / `to_mod_version` | string | 仅 `UPGRADE` |
| `contents` | tag | 背包内容，原样 |

## 读取规则

1. 读不出（IO 错误、不是 NBT）：跳过，日志 WARN（现有）。
2. `version` **大于 2**：跳过——**列表不显示、保留与淘汰与容量清理都不碰、绝不删除**；日志 INFO，每个文件每次运行一次。
3. `version` 1 或 2：读头；`kind` 缺失或不认识 → `CHANGE`；与文件名后缀不一致时**以文件名为准**。
4. 恢复与预览用 `contents`；解码失败的格子由 `LenientStacks` 留空，次数计入 `LostCells`。

## 写入规则

- 先写 `<name>.tmp`，再原子改名（现有）。
- 写完后按 [rules.md](./rules.md) 对该背包该类别做保留清理。

## 钉住（升级前）的文件操作

对一只背包的最新一份快照 `F`（认得的、非 `-u`）：

1. `tag = NbtIo.readCompressed(F)`；
2. `tag.putString("kind","UPGRADE")`；`tag.putString("from_mod_version", 旧)`；`tag.putString("to_mod_version", 新)`；`tag.putInt("version", 2)`；**不动 `contents`**；
3. 写 `<time>-u.dat.tmp`，改名为 `<time>-u.dat`；
4. 重新读 `<time>-u.dat`，取 `contents`，与第 1 步读到的 `contents` 比较 `equals`：相等 → 删 `F`；不等或读失败 → 删 `<time>-u.dat`，保留 `F`，日志 ERROR；
5. 最新一份已是 `-u`：读出、只改 `to_mod_version`、写回同名（先写临时再改名），同样先校验。

不经过 `BackpackContents.CODEC`。

## state.properties

```properties
# generated by MCFloatingBackpack; safe to delete (it is written again; the notices may repeat once)
last_mod_version=0.2.0
change_id=3
from_version=0.1.0
pinned=7
notified=11111111-1111-1111-1111-111111111111,22222222-2222-2222-2222-222222222222
```

- 只由主线程读写；写法：临时文件 + 原子改名。
- 缺失、不是 properties、`change_id` 不是整数：当"没有记录"：不钉住，写入当前版本（`change_id=1`、其余空），日志 INFO。
- `notified` 里的坏条目忽略；超过 10000 个丢最早的（WARN 一次）。
- 删除这个文件的后果：下次启动当"没有记录"（不钉住）；已发过的提示可能重复一次。
