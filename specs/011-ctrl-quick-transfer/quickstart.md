# Quickstart: 011 Ctrl 快速转移验收

> **019 说明**：019 起"没有打开任何界面（HUD）"的场景，指的是面板在**透明宿主界面**上（按 B 打开后不能移动和转向）；验证步骤与预期结果不变。详见 `specs/019-fallback-host-screen/`。

## 构建与自动化检查

```bash
./gradlew compileJava test
```

只能证明纯逻辑（搬运算法、手势状态机、请求校验）正确，**不能证明手势在游戏里可用**。宪法 V 条要求下面的客户端会话验证。

## 客户端会话验证（必须实际执行）

```bash
./gradlew runClient
```

进创造模式世界，取出皮革和铁两档背包，物品栏里放几种物品（含满堆叠、半堆叠、不可堆叠的物品）。macOS 上"Ctrl"指 **Command 键**（见 spec 假设）。

### 一、Ctrl+点击（US1、US2）

1. 按 B 打开面板，按 E 打开物品栏。Command+点击物品栏里的一个满堆叠 → 整堆进入背包，物品栏该格清空。（FR-001、SC-001）
2. 背包里已有同种半堆叠时重做：先并入已有堆叠，再占空格；总数不变。（FR-006）
3. Command+点击面板里的一个槽位 → 物品进入玩家物品栏/快捷栏（先并入已有堆叠）。（FR-002）
4. **不开任何界面**（只有 HUD 上的面板），Command+点击面板槽位 → 同样进入物品栏。（FR-002）
5. 背包塞满后再 Command+点击物品栏里的物品 → 能并入已有堆叠的部分被转移，放不下的留在原处；总数不变。（FR-006、SC-003）
6. 物品栏塞满、没有可并入的堆叠，Command+点击面板槽位 → 物品留在背包，什么都不丢。
7. 光标上拿着物品时 Command+点击 → 不触发快速转移（按现有拖放规则处理）。（FR-007）

### 二、Ctrl+拖动（US3）

1. 物品栏快捷栏一行放 9 个不同物品，按住 Command 和左键从第 1 格滑到第 9 格 → 9 个堆叠依次进入背包，整个操作 3 秒内完成。（FR-003、SC-002）
2. 滑动过程中**松开 Command** → 立即停止；之后滑过的格不再处理。再试**松开鼠标**。（FR-005）
3. 从物品栏格开始滑，途中经过面板的槽位 → 面板槽位被忽略，不会把刚存入的东西取出来。（FR-004）
4. 来回快速滑过整个物品栏（36 格）→ 无断线、无报错、无物品丢失。（FR-013、SC-007）
5. 从面板格开始滑，物品依次进入物品栏；同一个槽位在一次拖动里只处理一次。（FR-003）
6. 从一个**空格**开始滑过去，后面的有物品的格照常处理。

### 三、不能被影响的（US4、FR-008、FR-009、FR-016、FR-017）

1. 面板可见，打开物品栏，**Shift+点击**物品栏里的物品 → 在物品栏与快捷栏之间转移（原版），**不**进入背包。（SC-004）
2. 面板可见，打开箱子，Shift+点击玩家物品栏里的物品 → 进入箱子（原版）。（SC-004）
3. 面板可见，Command+点击**箱子自己的格子** → 不触发转移（FR-017）；点击箱子时玩家物品栏里的格子仍可 Command+点击存入背包。
4. 面板**隐藏**时 Command+点击/拖动 → 与没有本功能时一致。（FR-008、SC-005）
5. 创造模式物品栏界面（点开"创造模式物品栏"那个界面）里 Command+点击 → 不触发转移。（FR-011）
6. 盔甲槽、副手槽、合成格、合成输出槽上 Command+点击 → 不触发转移。（FR-011）
7. **回归**：`./gradlew runClientCompat` 下打开精妙背包、旅行者背包的界面，Command+点击它们画出来的任何槽位（包括其中的玩家物品栏格子）→ **不被我们拦截**，保持它们原有行为；它们自己的 Shift+点击、Shift+拖动仍正常。（FR-016）
7a. 同一个界面打开、浮动面板可见时，Command+点击**面板自己的槽位** → 物品进入玩家物品栏（面板侧不受界面类型限制，FR-002）。
8. 面板与物品栏界面重叠：光标在面板范围内 → 当作面板槽位；范围外 → 当作物品栏槽位。（FR-015）

### 四、同步与总数（FR-012、FR-014、SC-003）

- 做 50 次以上转移（含背包满/物品栏满的部分转移）后，用 `/give` 之前与之后各清点一遍，相关物品的总数**完全相等**。
- 转移后面板与物品栏界面显示与服务端一致；关闭再打开面板、重进存档，内容不变。
- 不能出现"客户端显示成功，重进后物品又回来了/消失了"。

### 五、平台

- 本机验证 macOS（Command）。Windows/Linux（Ctrl）**无法在本机验证**，按 `Screen.hasControlDown()` 的原版判定推断，登记为未验证。
- macOS 上物理 Ctrl+左键会被原版重映射成右键，**不是**本功能的手势，不应触发转移。
