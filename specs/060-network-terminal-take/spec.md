# Feature Specification: 网络终端 → 面板（集成终端与 AE2 的"取出"方向）

**Feature Branch**: `060-network-terminal-take`

**Created**: 2026-11-20

**Status**: Draft

**Input**: 用户（2026-11-20）要求让浮动背包的 Ctrl+点击快速存取在集成终端与 AE2 上"两个方向都要"；058 做了面板 → 集成终端，059 做了按模组的服务端档位，本 feature 做反方向。相关：012/013（面板与打开的容器之间的快速交换与光标合并）、058（网络存储桥与版本范围表）、059（服务端档位与拒绝提示）。

## Clarifications

### Session 2026-11-20（前几个 feature 的讨论里用户已确认）

- Q: 集成终端与 AE2 的"终端 → 面板"做不做、什么时候做？ → A: 做，两个方向都要；058 只做正向，059 做服务端档位，本 feature（060）做反向。
- Q: 手势是什么？ → A: 与正向对称：面板可见时，在终端的物品列表里 Ctrl+点击一个条目；只做 Ctrl+点击，不做拖动。
- Q: 取多少？ → A: 该物品的一组（至多一个满堆叠）；右键取一半/单个不做。
- Q: 哪些页、哪些终端？ → A: 集成终端只做物品存储页（与 058 相同的条件）；AE2 做 ME 终端的存储界面；合成页、末影箱页、别的成分类型、AE2 的合成/样板/无线终端以外的界面都不做。
- Q: AE2 拖住集成终端怎么办？ → A: 集成终端是 P1，AE2 是 P2；若 plan 阶段发现 AE2 不可行，AE2 降级为只写文档、不做代码，不影响集成终端。
- Q: 要新网络包吗？ → A: 要（协议号 21 → 22）：终端条目不是菜单格子，现有的按格子号的取出请求用不上。

## 背景

现状（已核对）：

- **正向**（058）：面板里的物品 Ctrl+点击可以存入集成终端的物品存储页；AE2 的 ME 终端靠 012 的通用路径也能存入（验证过）。
- **反向目前不能一步完成**：集成终端与 AE2 终端里的网络条目都不是真正的菜单格子——网格由客户端终端屏幕绘制，条目在服务端的菜单里没有对应的 `Slot`。012 的"从容器取出"（Ctrl+点击容器自己的格子）因此找不到可点的目标：集成终端服务端的存储页对"快速移动"返回空；AE2 的网格条目由客户端的条目表绘制，反向在容器里试过没有成功。
- 玩家现在只能分两步：先普通点击条目把物品拿到光标，再点面板的格子放进背包（013 的光标合并）。
- 服务端已经有：058 的"网络存储桥"接口（认得哪个菜单、把物品存入网络），且预留了"取出"；059 的服务端档位（按模组的 OFF/GENERIC/FULL）与拒绝时的聊天提示；012 现有的"从容器取出"请求的前置条件（背包仍有效、菜单是客户端点击的那一个、光标为空、经背包注册表获取背包）。

本 feature 做：面板可见时，在这两种终端的物品列表里 Ctrl+点击一个条目，一步把该物品的一组取出并放进背包；取出多少、放不下怎么办、出错怎么办都不让物品凭空消失或复制；服务端档位、版本范围、出错兜底沿用 058/059 的规则。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 在集成终端里 Ctrl+点击条目，一步取进背包 (Priority: P1)

玩家打开集成动力学网络的终端（物品存储页），按面板键让面板叠在上面，把鼠标移到终端列表里一个物品条目（比如"圆石 128"）上 Ctrl+点击：网络里减少一组（64 个），背包的主区域里多一组；终端列表里的数量随之更新，面板里出现这一组。网络里不足一组就取全部。

**Why this priority**: 这是用户明确要的功能，也是 058 正向的对称功能；集成终端的网络环境已经搭好、可在容器里验证。

**Independent Test**: 容器里用 058 的网络试验台（物品接口 + 箱子里放 128 个圆石 + 终端存储部件）：Ctrl+点击"圆石 128"一次，网络剩 64、背包多 64；再点一次，网络剩 0、条目消失；点只有 10 个的条目，取 10 个。

**Acceptance Scenarios**:

1. **Given** 终端在物品存储页，面板可见，网络里有某物品 128 个，背包有空位，**When** 玩家 Ctrl+点击该物品的条目，**Then** 网络里该物品减少 64，背包里增加 64（先进"接受该物品的行"，再进主区域，与面板里其它物品进背包的规则一致），终端列表与面板的显示随之更新。
2. **Given** 网络里该物品只有 10 个，**When** Ctrl+点击，**Then** 取走 10 个，条目从列表消失。
3. **Given** 该物品的最大堆叠数是 16（例如末影珍珠），网络里有 40 个，**When** Ctrl+点击，**Then** 取 16 个（"一组"以该物品的最大堆叠数为准）。
4. **Given** 背包只能放下一部分，**When** Ctrl+点击，**Then** 放得下的部分进背包，放不下的部分**退回网络**，网络与背包的总数不变。
5. **Given** 背包完全放不下，**When** Ctrl+点击，**Then** 什么也不变（取出的全部退回网络）。
6. **Given** 终端在合成页或末影箱页，**When** Ctrl+点击，**Then** 手势不处理，沿用原有行为。
7. **Given** 面板不可见，**When** 玩家 Ctrl+点击终端条目，**Then** 行为与改动前完全一致（集成终端自己的 Ctrl+点击含义不变）。
8. **Given** 鼠标不在任何条目上，**When** Ctrl+点击，**Then** 不拦截、不发请求，沿用原有行为。

### User Story 2 - 在 AE2 的 ME 终端里同样的手势 (Priority: P2)

玩家打开 AE2 的 ME 终端，面板可见，Ctrl+点击网格里的一个条目：从 ME 网络里取出一组放进背包，规则与 US1 相同。

**Why this priority**: 用户要两个方向都支持，但 AE2 的客户端条目表与服务端提取接口都更复杂、依赖更多，所以排在集成终端之后；若不可行允许降级为文档（见 Assumptions）。

**Independent Test**: 容器里用 058 搭过的 ME 终端（ME 箱子 + 创造能量元件 + 线缆 + 终端部件），箱子里放一批物品：Ctrl+点击条目，网络减少一组、背包增加一组。

**Acceptance Scenarios**:

1. **Given** ME 终端的存储界面，面板可见，网络里有某物品 128 个，**When** Ctrl+点击该条目，**Then** 网络减少一组、背包增加同样数量，与 US1 的数量与放不下的规则一致。
2. **Given** 网络断电（没有能量）或终端没有提取权限，**When** Ctrl+点击，**Then** 取不到东西，什么也不变，不报错。
3. **Given** 条目是可合成但网络里数量为 0 的（只显示可合成的），**When** Ctrl+点击，**Then** 不取、不触发合成。
4. **Given** 鼠标不在 ME 网格的条目上（在合成网格、样板编码区、按钮等处），**Then** 手势不处理。

---

### User Story 3 - 服务端档位、版本范围、出错时都不出事 (Priority: P1)

这个手势对其它模组做了专用处理，所以要受 058/059 的约束：服务端把某个模组设为 OFF 时拒绝并提示；GENERIC、版本不在已验证范围、客户端设置为 OFF/GENERIC 时不启用；兼容代码出错时关闭、记录并通知，物品不丢。

**Why this priority**: 取出是"从别的模组的系统里拿东西"，一旦出错最容易丢物品或复制物品。

**Independent Test**: 服务端配置 OFF/GENERIC、伪造版本到范围外、客户端把该模组设为 OFF/GENERIC，各验证一次手势的表现；纯逻辑测试里让桥抛异常，核对物品守恒与关闭。

**Acceptance Scenarios**:

1. **Given** 服务端把终端所属的模组设为 OFF，**When** 玩家 Ctrl+点击条目，**Then** 服务端拒绝（网络与背包都不变），玩家收到 059 的拒绝提示（每次打开的界面一条）。
2. **Given** 服务端设为 GENERIC，**Then** 不取（取出的专用处理关闭），不报错、不提示"拒绝"（GENERIC 只是关专用适配）。
3. **Given** 已装版本不在范围表里且没有被配置强制启用，**Then** 服务端不取；客户端同样不启用手势（不拦截、不发包，Ctrl+点击照旧）。
4. **Given** 客户端把该模组设为 OFF（面板本来就不在它的界面显示）或 GENERIC，**Then** 手势不启用，不发包。
5. **Given** 兼容代码在取出时抛出异常或链接错误，**Then** 该兼容在本次运行里关闭，写一条 ERROR 日志，在线 op 收到一条聊天；已经取出但还没放进背包的物品 MUST NOT 丢失（退回网络，退不回时放进玩家物品栏或掉落在玩家脚下），也 MUST NOT 复制。
6. **Given** 面板的背包已不是 `B` 键会打开的那只、或玩家当前打开的菜单不是终端菜单、或玩家光标上拿着东西，**Then** 服务端不取。
7. **Given** 请求里的物品种类或数量不合法（数量不是正数、超过该物品最大堆叠数、物品不存在），**Then** 服务端不取，不信任客户端报的"网络里有多少"，一切以服务端对网络的实际查询为准。

### User Story 4 - README 与交付记录写清能用什么 (Priority: P2)

README 的兼容表里集成终端与 AE2 两行的"终端 → 面板"改成可用，写清手势（面板可见时在终端列表里 Ctrl+点击条目）、只限物品存储页/存储界面、受支持的版本段；DELIVERY 写清哪些验证了、哪些没验证。

**Why this priority**: 文档写错会误导玩家；表与范围表要对齐（058 的防漂移测试扩到 AE2）。

**Independent Test**: 读 README 两份的兼容表与范围表一致；防漂移测试通过。

**Acceptance Scenarios**:

1. **Given** README.md 与 README_CN.md，**Then** 集成终端与 AE2 两行的"终端 → 面板"为可用，说明手势与限制，AE2 的版本段列在表里。
2. **Given** 范围表加了 AE2 的版本段而 README、`neoforge.mods.toml`、`build.gradle` 没跟着改，**Then** 防漂移测试失败。

### Edge Cases

- **条目在点击瞬间已被别人取走**（网络里实际数量比客户端显示的少）：服务端按实际数量取，取不到就什么也不变；不信任客户端报的数量。
- **同一个 Ctrl+点击重复发送**：每个请求独立处理，每次最多一组，不累积。
- **同时有多只背包**：取进的是 `B` 键会打开的那只（面板对应的），与其它面板操作一致。
- **背包的某些行只接受某类物品**：取出的物品按面板里其它物品进背包的同一规则分配（先进接受它的行，再进主区域）。
- **取出的物品带数据**（命名、附魔、成分）：按完整的物品种类取，不能丢数据，也不能把不同数据的同种物品合并成一个。
- **网络里该物品有多个不同数据的变体**：条目就是一个具体变体，只取被点的那个。
- **终端换了页/换了频道**：每次取出时重新判断当前页与所选频道（集成终端）；页不是物品存储页就不处理。
- **玩家在请求处理前关闭了终端或切换了菜单**：菜单不匹配，服务端不取。
- **取出后需要把物品退回网络但网络已满/离线**：退不回的部分放进玩家物品栏，再不行落在玩家脚下，不能消失（与 012 取出路径的兜底一致）；这种情况写 WARN 日志。
- **AE2 终端的"只显示可合成"条目**：数量为 0，不取、不触发合成。
- **客户端装了模组、服务端没装（或反之）**：协议号不同不会进入同一个服务器（协议号 22）；手势只在客户端检测到终端屏幕且服务端可用时才发请求。
- **面板可见但鼠标悬停的条目属于被模组其它功能占用的位置**（例如集成终端的条目上叠着 JEI 的提示）：只以终端自己的悬停判断为准。

## Requirements *(mandatory)*

### Functional Requirements

**手势与请求（US1、US2）**

- **FR-001**: 当且仅当：浮动面板可见，玩家打开的是集成终端的物品存储页（与 058 相同的条件：存储类界面、当前页是物品成分的存储页、不是合成页、不是末影箱页）或 AE2 的 ME 终端存储界面，鼠标悬停在终端列表里的一个网络条目上，该条目的网络内数量大于 0，玩家 Ctrl+左键点击：客户端 MUST 拦截这次点击（终端自己不再处理它），并向服务端发一个"从网络终端取一组"的请求；其余情形 MUST NOT 拦截、MUST NOT 发请求，行为与改动前完全一致。
- **FR-002**: 请求 MUST 携带：当前打开的菜单编号、被点条目的物品种类（含其数据）、以及一个由各终端自己解释的不透明条目标识（AE2 用它传条目序号，集成终端不用）。请求 MUST NOT 携带数量：服务端自己把数量定为该物品的最大堆叠数（FR-007），不信任也不需要客户端报数量。请求包本身 MUST NOT 含任何第三方模组的类型；识别悬停条目、把它变成"（物品栈，数量）"的客户端代码 MUST 只放在各自的 `compat/<modid>/` 下（宪法 VII）。
- **FR-003**: 本 feature MUST 把网络协议号从 21 升到 22（理由：条目不是菜单格子，现有的按格子号的取出请求无法表达，需要一个新的请求包）；MUST NOT 为其它目的再改协议。
- **FR-004**: 只做 Ctrl+左键点击；MUST NOT 做拖动、右键取一半/单个、Shift 点击以外的组合键。MUST NOT 做集成终端的合成页、末影箱页，MUST NOT 做其它成分类型（流体、能量等）；AE2 方面，凡是显示 ME 网格（共用同一个菜单基类与同一套提取）的终端界面（普通 ME 终端、合成终端、样板编码终端、无线终端等）一律按同一规则支持，但不为它们各自的别的功能（合成、样板编码）做任何事。

**服务端处理（US1、US2、US3）**

- **FR-005**: 服务端收到请求后 MUST 先做与 012 现有取出请求相同的前置检查：玩家的面板背包仍有效（是 `B` 键会打开的那只）、玩家当前的菜单就是请求里的菜单、玩家光标为空、经背包注册表取到背包；任一不满足则不处理。
- **FR-006**: 服务端 MUST 先问 059 的门禁（动作"从容器取出"，菜单所属模组）：有效档位 OFF 时 MUST 拒绝，并按 059 的规则给玩家发一条（每个玩家每次打开的界面至多一条）聊天提示；有效档位不是 FULL、版本不在已验证范围（且没被配置强制启用）、或该兼容在本次运行里因出错被关闭时，MUST NOT 使用专用的取出（不取、不报错）。
- **FR-007**: 服务端 MUST 验证请求：物品种类存在，数量为正且不超过该物品的最大堆叠数，菜单是终端菜单且当前页是受支持的页；MUST NOT 信任客户端报的网络内数量，实际取出的数量只由服务端对网络的实际提取结果决定。
- **FR-008**: 网络存储桥接口 MUST 增加"取出"能力：给定玩家、菜单、物品种类与数量，返回实际取到的物品栈（取不到返回空）；对一个模组的桥是否被问，MUST 沿用 058/059 的规则（版本门、强制启用、出错关闭、有效档位为 FULL）。
- **FR-009**: 取到的物品 MUST 放进玩家正在使用的那只背包（先进接受该物品的行，再进主区域，与面板里其它物品进背包的规则一致）；放不下的部分 MUST 退回网络；退不回的部分 MUST 放进玩家物品栏，再不行落在玩家脚下并写 WARN 日志。任何情况下物品 MUST NOT 凭空消失、MUST NOT 被复制：网络里减少的量 = 背包里增加的量 + 退回/落地的量的反面（即守恒）。
- **FR-010**: 取出完成后，背包 MUST 同步到客户端（与其它面板操作相同），终端列表的更新 MUST 由终端模组自己的同步机制完成；本 feature MUST NOT 为终端列表另发包。
- **FR-011**: 兼容代码在取出过程中抛出 `LinkageError` 或 `RuntimeException`（或返回不合法的结果）时，MUST 沿用 058 的兜底：本次运行里关闭该兼容，写一条 ERROR 日志，在线 op 各收到一条聊天，已取出的物品按 FR-009 处置，不用反射。

**客户端启用条件（US3）**

- **FR-012**: 客户端 MUST 只在以下条件都满足时启用手势：该模组已安装且客户端自己安装的版本在范围表的已验证范围内（客户端不发警告，警告是服务端的事；服务端的"强制启用"配置客户端看不到，所以客户端在范围外时一律不启用）；客户端配置里该模组不是 OFF 或 GENERIC。不满足时手势不拦截、不发包。服务端不因此信任客户端：FR-005～FR-007 的检查不变。

**范围表与加载声明（US2、US4）**

- **FR-013**: AE2 MUST 加入第三方版本范围表（已验证的版本 19.2.20，取窄段，初版 `[19.2.0, 19.3.0)`；GuideME 不进表）；`neoforge.mods.toml` MUST 为 AE2 加可选依赖（`optional`、`[0,)`）；`build.gradle` MUST 为 AE2 加仅编译依赖（不传递），与已有的开发运行依赖同版本；058 的防漂移测试 MUST 扩到 AE2。**若 AE2 在 plan 阶段被判不可行（见 Assumptions），则 AE2 不进表、不加依赖，只写文档。**

**文档与测试（US4）**

- **FR-014**: README.md 与 README_CN.md 的兼容表里，集成终端与 AE2（若实现）两行的"终端 → 面板"MUST 改成可用，写明手势（面板可见时在终端列表里 Ctrl+点击条目）、只限物品存储页/存储界面、受支持的版本段；058/059 在 README 里关于"反向暂不支持"的说明 MUST 同步；AE2 不做时 MUST 如实写明原因。
- **FR-015**: 系统 MUST 有自动测试：取出数量的计算、放不下时退回的守恒（含退回失败的兜底顺序）、桥的取出分派遵守 058/059 的出错与档位规则、请求的校验规则、请求包的编解码（含非法值）；接线测试（第三方类型只在 `compat/<modid>/`、协议号 22、请求只在客户端手势下发送且不含第三方类型、客户端启用条件）；README 与范围表对齐的防漂移测试。

### Key Entities *(include if feature involves data)*

- **网络条目**：终端列表里的一行：物品种类（含数据）与它在网络里的数量；由各终端模组的客户端屏幕提供，本 feature 只把它变成通用的"（物品栈，数量）"。
- **取出请求**：客户端 → 服务端的一个新请求：菜单编号、物品种类、一个不透明的条目标识（数量由服务端定）。
- **取出结果**：服务端实际取到的物品栈；与背包放不下的部分、退回网络的部分、落地的部分一起满足守恒。
- **网络存储桥（扩展）**：在 058 的"认领菜单、存入"之外多一个"取出"。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在集成终端的物品存储页上，面板可见时对一个有 128 个物品的条目 Ctrl+点击一次，**一步**之内背包增加 64 个、网络减少 64 个（总数守恒）；连续点两次，网络里清空、条目消失。
- **SC-002**: 背包放不下时，放不下的部分**全部**退回网络，背包与网络的物品总数在每一种放不下的情形（部分放得下、完全放不下）里都与取出前一致（抽查 100% 守恒）。
- **SC-003**: 服务端档位 OFF 时 Ctrl+点击条目 **0 次**成功取出，每次打开界面玩家**恰好收到 1 条**提示；GENERIC、版本范围外、客户端 OFF/GENERIC 时 **0 次**取出且手势不拦截（Ctrl+点击行为与改动前一致）。
- **SC-004**: 兼容代码出错的各种情形（抛异常、链接错误、不合法的结果）在测试里 **0 次**导致物品丢失或复制，同一次运行里错误通知至多 1 次。
- **SC-005**: 在没有安装集成终端和 AE2 的环境里，所有现有功能与测试的结果与改动前一致（无新增日志、无新增提示）。

- **SC-007**: 容器里完成一轮游戏内验证：集成终端的取出、部分取出（条目不足一组）、背包放不下退回、网络离线、服务端 OFF/GENERIC、范围外伪造版本全部与验收场景一致（AE2 若实现，同样一轮），结果记入 DELIVERY。

## Assumptions

- **集成终端是 P1，AE2 是 P2**：AE2 的悬停条目识别（客户端的条目表）与服务端提取（存储接口、能量、权限）都比集成终端复杂、依赖更多。若 plan 阶段发现 AE2 无法用公开 API（不用反射、不用 mixin）可靠实现，AE2 降级为"README 如实写明反向仍不支持、不做代码、不进范围表"，集成终端照常交付，不拖住。
- 识别悬停条目 MUST 只用各终端屏幕的公开 API（不用 mixin、不用反射）；若某终端不提供这样的 API，该终端的手势不做并如实记录。
- 物品种类在请求里用 Minecraft 的物品栈序列化（通用），不用任何第三方的序列化类型；不同终端各自把条目变成物品栈。
- "一组"= 该物品的最大堆叠数，由服务端定；条目不足一组就取全部。
- 服务端请求的前置检查沿用 012 现有取出请求的做法（背包有效、菜单编号匹配、光标为空、经背包注册表）；该请求没有额外的频率限制，每个请求只取一个条目的一组，这里也不加。
- 集成终端的 B 键被终端自己的"平衡合成网格"键吞掉（058 已发现）：玩家需要改键才能在这些界面上呼出面板；游戏内验证用 F9。本 feature 不处理这个冲突。
- 058 的版本门、`allowUntestedVersions`、出错兜底与 059 的档位沿用；取出与存入共用同一个桥与同一套"是否启用"的规则。
- 游戏内验证沿用 058 的集成动力学网络试验台与（AE2 的话）058 搭过的 ME 终端，在容器里做；手感待用户确认。
