# Feature Specification: 浮动背包窗口化改造（第一阶段：缩放与关闭）

**Feature Branch**: `007-floating-window-chrome`

**Created**: 2026-11-02

**Status**: Draft

**Input**: User description: "浮动背包窗口化改造：1) 标题栏显示背包等级名称而非固定文案；2) 标题栏增加关闭按钮；3) 右下角可拖拽缩放面板尺寸（带光标提示，3x3 到当前自适应上限之间，可持久化）；4) 点击下层已打开容器的真实槽位时应穿透到该容器，而不是被浮动面板拦截，面板自身控件仍正常响应；5) 支持原版标准 Shift+点击在浮动背包与玩家物品栏/已打开容器之间双向快速转移物品。背景：高等级背包格子多，面板强制置顶遮挡玩家物品栏，干扰拖拽操作，目标是让浮动面板更像一个可缩放、可关闭、不会死板挡住下层界面的窗口。"

## Clarifications

### Session 2026-11-02

- Q: 本阶段是否需要实现"点击下层容器槽位时穿透浮动面板"（原规划中的 User Story 2）？ → A: 不需要，推迟到后续 feature；本阶段依赖手动缩放面板尺寸（User Story 1）+ 已有的手动拖动面板位置来缓解遮挡问题。
- Q: 本阶段是否需要实现 Shift+点击在浮动背包与原版容器/物品栏之间的双向快速转移（原规划中的 User Story 4）？ → A: 不需要，推迟到后续 feature；精妙背包、旅行者背包能支持这种转移是因为它们打开时下方的"物品栏"是自己绘制的假界面（**【011 修订】此说法不准确**：检查两个模组的 jar 后确认，它们的玩家物品栏是菜单里绑定真实 `Inventory` 的真实 `Slot`，只是画在自己的界面里；它们容易做是因为界面与菜单都是自己的，存储区和玩家物品栏在同一个菜单里，原版 QUICK_MOVE 机制自己就能搬。本模组的难点是存储不在任何菜单里，见 011），而本模组浮动背包下方打开的是真实原版 Screen，拦截其原生 Shift+点击并同时操作两个库存的复杂度明显更高，留待单独规划。
- Q: 面板缩放时，行数与列数是否需要同步缩放，各自的下限是多少？ → A: 行、列可以独立调整，不要求同步缩放（例如可以只调小列数、保持行数不变）；行、列各自的下限都是 3；上限仍为当前"按屏幕可用空间自适应"算法算出的结果；当设置的可见行数或列数小于背包实际总行列数时，通过滚动条访问被隐藏的格子。
- Q: 调整列数后，滚动条应该横向、纵向分别独立出现，还是始终只有纵向滚动条？ → A: 始终只有纵向滚动条，不存在横向滚动条。调整尺寸的本质不是开一个可以双向滚动的"窗口"，而是改变背包容器在屏幕上按多少列重新排布格子：总容量按当前列数重新换算出"虚拟总行数"（总容量 ÷ 当前列数，向上取整），纵向滚动条的长度/滑块比例按"当前列数下的虚拟总行数"与"当前可见行数"计算，和现有纵向滚动条是同一套逻辑，只是输入的总行数会随列数设置变化。

## Out of Scope（本阶段不做）

- **点击下层容器槽位的穿透判定**：不在本阶段实现浮动面板与下层已打开容器（物品栏、箱子等）之间"点击命中哪一方"的几何判定逻辑。面板与容器重叠时若需要点击下层槽位，玩家需手动缩小或拖动浮动面板以避开遮挡。此能力留待后续单独 feature 规划。
- **Shift+点击双向快速转移**：不在本阶段实现浮动背包与原版容器/物品栏之间的 Shift+点击快速转移。浮动面板内的操作目前仍只支持已有的拖拽转移方式。此能力留待后续单独 feature 规划。**【011 修订】** 已由 011 以 **Ctrl 手势**（macOS 为 Command 键）实现 Ctrl+点击与 Ctrl+拖动，范围是玩家物品栏 36 格 ↔ 浮动背包；Shift 手势保持原样、没有被占用（见 `specs/011-ctrl-quick-transfer/`）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 按需调整浮动面板的行数与列数 (Priority: P1)

玩家打开一个格子数很多的高等级浮动背包时，面板占据了大片屏幕、遮挡了想要同时查看的区域。玩家希望能像调整普通窗口一样，拖拽面板右下角把它缩小到只显示自己需要的行数和列数（两者可以分别调整，不必同步缩放），之后也能随时拖大回去。

**Why this priority**: 这是当前最直接的干扰来源——面板尺寸完全由内容量和屏幕空间决定，玩家没有任何手段主动让它变小。结合玩家已有的手动拖动面板位置的能力，解决这一项就能在不引入"点击穿透"等更复杂机制的情况下，大幅缓解遮挡问题。

**Independent Test**: 打开一个格子数较多的浮动背包，分别单独拖拽缩小列数（保持行数不变）、单独拖拽缩小行数（保持列数不变），再同时拖拽缩小到 3 行 3 列，之后拖大到接近屏幕可用空间上限，验证面板尺寸随拖拽实时变化、物品不丢失、超出当前可见范围的物品仍可通过滚动条访问。

**Acceptance Scenarios**:

1. **Given** 浮动面板已打开且显示默认行列数，**When** 玩家按住面板右下角的缩放控件并拖拽，**Then** 面板显示的行数与列数可以分别独立变化（例如只改变列数、行数保持不变），不要求两者同步缩放。
2. **Given** 玩家持续向左上方拖拽缩放控件，**When** 某一维度（行或列）达到 3，**Then** 该维度不再继续减小，另一维度若未达到下限仍可继续缩小。
3. **Given** 玩家持续向右下方拖拽缩放控件，**When** 某一维度达到"当前屏幕可用空间下能显示的最大值"，**Then** 该维度不再继续增大，且面板任何时候都不会超出屏幕边界。
4. **Given** 玩家调整了可见列数，**When** 面板重新渲染，**Then** 背包格子按新的列数重新排布（总容量 ÷ 当前列数、向上取整得到新的虚拟总行数），玩家可以通过**纵向**滚动条访问到所有被隐藏在当前可见行数之外的格子；不出现横向滚动条。
5. **Given** 玩家已将面板调整为某个自定义的行列尺寸，**When** 玩家关闭并重新打开浮动面板（或重新进入游戏），**Then** 面板恢复为玩家上次设置的行列尺寸，而不是默认尺寸。

---

### User Story 2 - 一键关闭浮动面板 (Priority: P2)

玩家暂时不需要浮动面板时，希望能直接在面板标题栏上点击一个关闭按钮将其收起，而不必回忆或重新绑定快捷键。

**Why this priority**: 提供一个始终可见、不需要记忆按键的收起方式，是对 P1 缓解遮挡问题的补充手段，实现简单、风险低。

**Independent Test**: 打开浮动面板，点击标题栏右侧的关闭按钮，验证面板立即隐藏；再次通过原有开关方式重新打开，验证面板内容（物品、位置、尺寸）保持不变。

**Acceptance Scenarios**:

1. **Given** 浮动面板处于可见状态，**When** 玩家点击标题栏右侧的关闭按钮，**Then** 浮动面板立即隐藏，等同于使用开关快捷键关闭。
2. **Given** 浮动面板已通过关闭按钮隐藏，**When** 玩家重新打开浮动面板，**Then** 面板中的物品、上次的位置与行列尺寸均保持不变。

---

### User Story 3 - 标题栏显示背包等级名称 (Priority: P3)

玩家打开不同等级的浮动背包（皮革、铁、金等）时，希望标题栏能显示对应背包的名称，而不是固定不变的"Floating Backpack"字样，便于分辨当前打开的是哪一个等级的背包。

**Why this priority**: 纯展示性改进，价值与风险都最低，放在最后交付不影响其它项。

**Independent Test**: 分别打开不同等级的浮动背包，验证标题栏文字随背包等级变化为对应的背包名称。

**Acceptance Scenarios**:

1. **Given** 玩家打开某个特定等级的浮动背包，**When** 面板渲染标题栏，**Then** 标题栏文字显示该背包对应的名称，而不是固定文案。
2. **Given** 玩家切换到另一个不同等级的浮动背包，**When** 面板重新渲染标题栏，**Then** 标题栏文字相应更新为新背包的名称。

---

### Edge Cases

- 面板的行数或列数被缩小后，背包中仍有超出当前可见范围的物品：应可通过纵向滚动条继续访问，不得丢失或隐藏物品的存在；不引入横向滚动条。
- 玩家调整列数导致格子重新排布（虚拟总行数变化）：当前的纵向滚动位置需要按新的虚拟总行数重新夹紧（不能滚动到超出新范围之外的空白区域），但不要求保留"调整列数前第几行可见"这类精确的滚动位置记忆。
- 当前屏幕分辨率/缩放下，"自适应上限"本身小于 3（极端小窗口）：面板尺寸下限（行、列各自最小 3）优先保证，允许面板在此情况下超出理论自适应上限，但仍不得超出屏幕边界而无法操作。
- 玩家在拖拽缩放面板的同时，面板内容发生变化（例如服务端同步了新的物品数据）：缩放操作应继续完成，不应被内容更新打断或导致尺寸状态错乱。
- 调整光标提示的平台不支持系统提供的缩放光标样式：改用默认光标显示，但拖拽缩放功能本身仍必须可用。
- 玩家只调整了列数、没有调整行数（或反之）：另一维度必须保持玩家原有设置不变，不能被联动重置为默认值。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须在浮动面板右下角提供一个可拖拽的缩放控件，允许玩家通过按住拖拽实时调整面板显示的行数和列数。
- **FR-002**: 面板的行数与列数必须可以分别独立调整，不要求两者同步缩放。
- **FR-003**: 面板可调整的行数与列数，下限各自为 3；上限各自不得超过系统当前根据屏幕可用空间计算出的最大可显示值，且任何情况下面板都不得超出屏幕边界。
- **FR-004**: 系统必须按玩家设置的列数，把背包格子重新排布成对应的虚拟行数（总容量 ÷ 当前列数，向上取整）；当虚拟总行数大于当前可见行数时，系统必须提供**纵向**滚动条让玩家访问所有被隐藏的格子；任何情况下都不得出现横向滚动条。
- **FR-005**: 玩家通过拖拽设置的面板行列尺寸必须与面板位置一样被持久化保存，并在下次打开该浮动面板（含重新进入游戏后）时沿用。
- **FR-006**: 当鼠标悬停在缩放控件上时，系统必须提供光标层面的视觉提示，告知玩家此处可拖拽缩放；若当前运行环境不支持该视觉提示，系统必须回退到默认光标显示，且缩放功能本身不受影响。
- **FR-007**: 系统必须在标题栏提供一个可点击的关闭控件；点击后立即隐藏浮动面板，效果等同于现有的开关快捷键。
- **FR-008**: 系统必须将浮动面板标题栏的文字替换为当前打开背包对应等级的名称，不再使用固定不变的文案。**【008 修订】** 标题栏文字已被 008 取代：现在是等级图标，悬停显示等级名称（007 当时的人工验证 6 因此改为按 008 的图标验证）。
- **FR-009**: 浮动面板与已打开容器界面之间现有的拖拽转移物品能力，在本功能交付后必须继续保持可用，不受面板缩放、关闭等改动影响。

### Key Entities

- **浮动面板窗口状态**：描述浮动背包面板当前的位置、尺寸（行数、列数可分别记录）、可见性，以及它所对应的背包引用；缩放与关闭操作改变的就是这一状态，且需要持久化。
- **背包物品栏**：浮动背包自身的格子与物品堆叠集合，总容量固定不随面板缩放变化；格子在面板上排布成的"虚拟行数"随玩家设置的列数变化（总容量 ÷ 当前列数，向上取整），缩放后超出可见行数范围的格子仍属于该物品栏，需通过纵向滚动条访问。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 玩家可以分别独立调整浮动面板的行数和列数，各自在 3 到当前屏幕最大可显示值之间任意设置，面板内容显示始终完整、无错位或裁切异常。
- **SC-002**: 玩家可以通过一次点击，在不依赖快捷键的情况下隐藏浮动面板。
- **SC-003**: 面板的行列尺寸、位置在玩家重新打开容器界面或重新进入游戏后，与上次设置保持一致。
- **SC-004**: 当按当前列数重新排布后的虚拟总行数大于可见行数时，玩家可以通过纵向滚动条访问到所有被隐藏的格子，不丢失任何物品的可见性；整个过程不出现横向滚动条。
- **SC-005**: 本功能的改动不会影响玩家已有的"浮动背包与已打开容器之间拖拽转移物品"能力，物品数量在改动前后保持一致。
- **SC-006**: 玩家打开不同等级的浮动背包时，标题栏文字能够正确反映当前背包的等级名称，便于玩家分辨。**【008 修订】** 现为等级图标 + 悬停名称，判定意图（能分辨等级）不变。

## Assumptions

- 面板缩放以整行/整列为最小调整单位（与现有槽位网格对齐），不支持任意像素级的自由缩放。
- 关闭按钮的行为等同于现有的"隐藏浮动面板"开关操作，不会清空背包内容或重置位置/尺寸等已保存状态。
- 面板尺寸的自适应上限计算方式沿用现有"根据屏幕可用空间自动计算"的逻辑，本功能只是让该上限同时成为可调范围的边界，不改变该计算本身的触发时机（仍为每帧/每次布局时重新计算）。
- 调整列数不是开一个可以双向滚动的"窗口"，而是改变背包格子在屏幕上的排布列数：总容量按当前列数重新换算出虚拟总行数，滚动条机制复用现有"纵向滚动条"的既定实现（track/thumb/travel/ratio），不新增横向滚动条，也不新增 `totalCols` 这类可变字段——背包的总容量本身不随面板缩放变化，变化的只是"每行放几个格子"。
- "点击下层容器槽位穿透"与"Shift+点击双向快速转移"（见 Out of Scope）不在本阶段范围内，不作为本次验收依据。
