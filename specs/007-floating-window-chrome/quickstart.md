# Quickstart: 007-floating-window-chrome

## 自动化校验（纯逻辑，不启动游戏）

```bash
./gradlew test compileJava
```

覆盖范围：`FloatingPanelState`/`PanelSlots` 的行列独立缩放边界（3 下限、自适应上限）、列数变化后的虚拟总行数/坐标换算、resize 手柄命中测试，延续 `PanelLayoutTest`/`PanelClampTest` 的既有纯逻辑测试模式，不需要启动 Minecraft。

## 客户端会话验证（宪法 V 条要求，必须实际执行）

```bash
./gradlew runClient
```

1. 获取任意等级的浮动背包（建议先用铁或金等级，行数足够多方便观察缩放效果），打开浮动面板（默认热键 `B`）。
2. **独立缩放验证**：
   - 只拖拽缩小列数（保持行数不动），确认行数未受影响。
   - 只拖拽缩小行数（保持列数不动），确认列数未受影响。
   - 继续拖拽到行、列都到达 3，确认两个方向都不再继续缩小。
   - 反向拖大，确认在"当前屏幕可用空间下的最大行/列数"处停止，且面板任何时候都不超出屏幕边界。
3. **滚动条验证**：调小列数后，确认格子按新列数重新排布（原来一行 9 个变成一行更少个），背包右侧只出现**纵向**滚动条、不出现横向滚动条；滚动条能正常拖动，并能访问到所有因为重新排布而被裁切到可见范围之外的格子（可以先在背包里放满不同种类的物品，方便肉眼确认没有物品"消失"，也方便确认重新排布后物品还是同一件、顺序没有错乱）。
4. **持久化验证**：调整到一个自定义的行列尺寸后，关闭并重新打开浮动面板；再完全重启一次 `./gradlew runClient`（或重进存档），确认尺寸与位置都恢复为上次设置，而不是默认值。
5. **关闭按钮验证**：点击标题栏右侧的关闭按钮，确认面板立即隐藏，效果与按热键 `B` 关闭一致；重新打开后确认物品、位置、尺寸均未丢失。
6. **标题栏文字验证**：分别打开皮革、铁、金、钻石、下界合金等级的浮动背包（可用创造模式背包或指令获取），确认标题栏文字分别显示对应的本地化背包名称（参考 `assets/mcfloatingbackpack/lang/zh_cn.json` 里的 `item.mcfloatingbackpack.*_floating_backpack` 文案），而不是固定的"浮动背包"文案。
7. **光标回退验证（macOS 特别关注）**：鼠标悬停在缩放手柄上时观察光标形状；开发机是 macOS，GLFW 对角缩放光标在该平台可能不受支持（见 [research.md](./research.md) Decision 4）——如果光标没有变化属于已知的平台限制，**但缩放拖拽功能本身必须依然可用**，这是本项验证的关键判定点，光标视觉效果本身不是阻塞项。
8. 确认现有的"浮动背包与已打开容器之间拖拽转移物品"能力（004/003 已实现）不受本次改动影响：随便打开一个容器或物品栏，试一次跨界面拖拽，确认行为与改动前一致。

## 已知限制（本阶段不覆盖）

- 点击下层容器槽位的穿透判定、Shift+点击双向快速转移：均不在本阶段范围，见 [spec.md](./spec.md) 的 `## Out of Scope`。
- 对角缩放光标在不支持的平台上会回退为默认箭头光标，这是预期行为，不是 bug。
