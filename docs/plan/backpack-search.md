# 背包搜索（规划，2026-11-12，已与用户确认主要决策）

**状态**：042（搜索核心）已规格、方案、任务，实现与自动验证完成，等用户在游戏里确认；043 已改方案（见第 4 节，2026-11-12），已实现、AI 自动验证（临时假提供者）并经用户确认；044（`@模组` `#标签` `/hidden` 摘要）已实现、AI 自动验证并经用户确认（2026-11-12）。

目标：在浮动面板标题栏加一个搜索功能：实时过滤主区域、高亮命中格子，支持英文、中文、拼音，支持 `/hidden`、`#标签`、`@模组` 等语法。分三个 feature 做：042 搜索核心、043 搜索词提供者接口（多语言与拼音由别的模组提供）、044 特殊语法。服务端与网络协议都不用改（协议号仍是 17）：面板上点击、选区、Ctrl 转移、Alt 换左手发给服务端的都是背包槽位号，搜索只改变客户端"第几格显示哪个槽位"。

## 1. 标题栏（042）

- 面板最窄是主区域 3 列，总宽 104 像素。现有布局：背包图标 x=4～20，编号文字，快照键，关闭键。
- **最小尺寸（3 列）去掉关闭键**（用户同意：B 键、ESC 已能关闭）。其它宽度保留关闭键。去掉后右端顺序是 `[放大镜][快照]`，编号在它们左边。
- 搜索框激活后：保留左边的背包图标（仍是拖动把手），**图标右边到右端整段变成搜索框**，编号、放大镜、快照键隐藏；有关闭键的宽度下搜索框止于关闭键左边。搜索框右端内嵌 `×`（清除）和命中数。3 列时搜索框约 78 像素（约 13 个字符）。
- 实时过滤，不用回车。键盘规则沿用 018 标签框：有焦点时吞键（B、E、T、Delete 不触发其它功能）；Ctrl+V 可粘贴；字符不设限，中文输入法上屏的字可进。
- **Esc**：清空并关掉搜索框。**点结果格子**：焦点离开搜索框（B、E 恢复可用），文字与结果保留，靠 `×` 清除。
- 搜索状态只存在于会话：关闭面板或退出世界就清空。不做 Ctrl/Cmd+F。

## 2. 结果的显示与交互（042）

- 主区域：格子映射改为"命中格子的槽位号列表"，紧凑地从左上角排起，滚动按结果行数算。空格子不显示，所以搜索时不能往没显示的空位放东西。
- 区分标识：命中格子画一圈**与 Shift 选框不同颜色**的边框（具体色号进游戏对照后定），搜索框边框同色，框内右端显示命中数。
- 左、右、下三个工具区：只高亮命中的格子，不过滤。
- 分类扩展行、通用扩展行：格子在主区域的槽位号空间里，命中混在结果中，保留各自的行底色以看出来源。
- **拿走再放回**：结果集只在"查询变化、面板重开"时重算。拿走一组物品后那格变空，但仍留在原位置显示（空位），把物品放回就回到原来的槽位。如果拿起物品后又改了查询、那个空位已经不显示，则需要清除搜索才能放回（不做"自动找空位"，那要新增服务端动作）。
- Shift 选区、Ctrl 移动、Alt 换左手、Delete、双击聚拢等：与平时一致（都按槽位号）。**查询一变就清空选区**，避免 Ctrl 转移作用到看不见的格子。

## 3. 语法（042 做基础，044 做前缀）

参考 JEI 的搜索（凭记忆，实现前再核对 JEI 的文档与源码）：空格分隔的各词是"并且"；`|` 表示"或"；`-` 开头表示排除；`"…"` 括起的是整段（含空格的名字用它）。JEI 的 `&` 是资源 id 前缀，所以不用 `&` 当"并且"。

- **空格 = 并且**：`oak log` 会匹配名字里同时含 oak 与 log 的物品（Oak Log、Stripped Oak Log），多词名字不会搜不到；要精确整段用 `"oak log"`。
- `iron|gold`：或；`-planks`：排除。
- **`@模组`**：按物品所属模组匹配，既匹配命名空间也匹配模组显示名（`@minecraft`、`@sophisticated`）。后面可跟关键词继续过滤：`@mekanism ingot`。
- **`#标签`**：同时匹配三类标签（取并集）：
  1. 背包自己的标签（018 的预设与自定义标签；预设标签按当前语言显示名与 id 都能匹配，如 `#垃圾`、`#trash`）；
  2. 原版的物品标签（`minecraft:logs` 等）；
  3. NeoForge 的 `c:` 标签（`c:ingots/iron` 等）。
  不带冒号时按子串匹配标签的路径部分（`#logs`、`#ingots`）；带冒号时按完整 id 前缀匹配（`#c:ingots`、`#minecraft:logs`）。标签数据都已在客户端（背包标签随背包同步，物品标签随世界同步）。
- **`/hidden`**：只能出现在整条查询的**最开头**，像聊天指令；后面可以接普通查询：`/hidden`、`/hidden apple`、`/hidden @minecraft #food`。别处的 `/` 当普通字符。未知的 `/xxx` 显示无结果，搜索框悬停提示"未知指令"。
  - **更正（2026-11-12，044 specify 时读代码）**：原方案写"结果是隐藏行里的物品，灰色只读格子；客户端已有隐藏行数据，不用新增同步"，**不成立**——服务端只把隐藏行的摘要（每个类别几格非空）发给客户端，隐藏物品本身不在客户端。**用户选择摘要模式**：`/hidden` 只列出"哪些类别有隐藏物品、各几格"（沿用 037 的数据与说法），不显示物品本身，无网络改动、协议号仍 17；同步隐藏物品另开 feature。`/hidden` 之后的普通词只过滤类别行。

## 4. 多语言与拼音（043，2026-11-12 改方案）

**最初的方案已作废**（本模组读 en_us/zh_cn、打包 PinIn、`search.chinese` 配置、修订宪法 VII）。用户的理由：这类能力别的模组已经有（名字表、拼音），本模组再做一遍是重复建设；兼容的主动权在对方。

**现方案（用户确认）**：

- 本模组**只搜当前语言的显示名与注册名**（042 的行为），**不读别的语言文件、不做拼音、不打包任何库**，也不再有 `search.chinese` 配置、不再改宪法。
- 本模组公开一个很小的 API 包（`pnnh.mcfloatingbackpack.api`）：一个"搜索词提供者"函数式接口 `ItemStack → 一组字符串`，加一个注册入口（调用方模组 id + 提供者），带 `API_VERSION`。别的模组把返回的词（各语言名、全拼、首字母……）交给背包搜索，背包统一转小写后做子串匹配。
- 接入方向：**被兼容的一方提供 API，兼容方 `compileOnly` 依赖、运行时可选**，在它自己的 `compat/mcfloatingbackpack/` 里接入。所以**不用** NeoForge 的 `InterModComms`（它是平台内部通道，跨版本更不稳）。
- 参数用 `ItemStack`（药水、附魔书等名字由数据组件决定的物品也能处理）。
- 容错与控制：提供者抛异常只影响那个物品、WARN 只记一次、累计出错会话内停用；按 `ItemStack` 缓存，资源重载时清；`[compat] modLevels` 里该模组 id 设 `GENERIC`/`OFF` 即忽略它的词（宪法 VII 要求对别的模组的主动交互受此控制）。
- 没有提供者时与 042 完全一致，README 只说明"其它模组可通过公开接口增加可搜索的文字"，不点名具体模组。
- **职责边界（用户 2026-11-12 澄清）**：本模组只公开并维护 API 与契约；任何具体模组的接入、联动是否正常是对方的事，**不进本模组的规格、README 推荐、测试与验收**。多语言与拼音能力的范围与演进完全由提供者一侧决定。
- 游戏内验证只能用容器里的临时假提供者（不进发布 jar），DELIVERY 如实写明没有验证任何真实模组。
- 设计细节：`specs/043-search-terms-provider-api/`（契约 `contracts/search-terms-api.md`，版本号用方法 `apiVersion()` 而不是常量，`modLevels` 在查询时应用，按"物品+数据组件补丁"缓存，宪法不改）。

## 5. 拆分与顺序

| 编号 | 内容 | 依赖 |
|---|---|---|
| 042 | 标题栏（放大镜、搜索框、最小尺寸去关闭键）、实时过滤、结果映射、高亮、工具区高亮、扩展行、选区与拿走放回规则、基础语法（空格并且、`\|` 或、`-` 排除、引号）；匹配用当前语言名 + 注册名 | 无 |
| 043 | 搜索词提供者接口（公开 API 包、注册表、容错、缓存、`modLevels` 控制、开发者说明）；本模组不做拼音与多语言 | 042 |
| 044 | `@模组`、`#标签`（三类标签并集）、`/hidden` 与只读格子、未知指令提示 | 042 |

043 与 044 互不依赖，可以交换顺序。每个 feature 按 Spec Kit 走 specify → plan → tasks → implement；放大镜最终是代码绘制（042 无新贴图）；043 要定公开 API 的稳定性规则，看宪法是否需要补一条治理条文。

## 6. 测试思路

- 纯逻辑：查询解析（词、引号、`|`、`-`、前缀、`/hidden` 位置）、匹配、结果映射（槽位号列表、滚动、拿空后留位、查询变化清空选区）、标题栏布局算术（各宽度下各元素位置，3 列无关闭键），不依赖 Minecraft 类，写单元测试。
- 游戏里：用容器里的自动验证做实时过滤、高亮、选区、Ctrl 转移、拿走放回；中文输入用 xdotool 输入 Unicode 试一下，不行就由用户在真机上验证；拼音与中文界面的切换用 `options.txt` 里的 `lang` 改语言。
