# 规划：移动工作台、移动熔炉、移动唱片机（2026-11-13，用户已确认主要决策）

状态：规划文档，决策已与用户确认。**移动唱片机（053）、移动工作台（054）已实现**（`specs/053-mobile-jukebox/`、`specs/054-mobile-crafting-table/`，等用户确认手感），之后是移动熔炉（055）。按 Speckit 一次只做一个 feature。

## 玩法（三个工具共同的规则）

- 三个都是**新物品**（像垃圾桶、自动拾取，不是直接用原版方块）：`mobile_crafting_table`（移动工作台）、`mobile_furnace`（移动熔炉）、`mobile_jukebox`（移动唱片机）。
- **只在面板右侧工具区生效**；左区、下区放得下但不生效、不计入限制。不考虑皮背包右区格子少（格子少本身就是取舍，或升级背包）。
- **每种在右区最多放一个**（沿用 `ToolAreaRules` 的"每区某工具至多一个、旧背包保留不能再加"口径，三种互相独立，也与垃圾桶的限制独立）。
- 左键点它（光标为空）才触发；右键仍然是拿起（与垃圾桶一样）。
- 按 B 会打开的那只背包（手 → 背 → 物品栏）的右区才算。
- 每个物品都进 `never_trash`；创造物品栏排在自动拾取之后；贴图沿用 Pillow 手绘占位。
- 每个 feature 若新增"只能存在背包里的物品种类"，按 `release-process.md` 的规则递增数据修订（053：3 → 4）。

`I` = 铁锭，都是有序配方。

## 实现路线（用户已选）

### 工作台与熔炉：做法 A——服务端打开原版界面

- 点工具 → 客户端发"打开工具"请求（新网络包，协议 19 → 20）→ 服务端校验（该工具确在按 B 的背包的右区）→ 打开**原版**的合成菜单 / 熔炉菜单，客户端是原版界面；浮动面板照常叠在上面。
- **工作台**：`CraftingMenu(id, 背包, ContainerLevelAccess.create(世界, 玩家位置))` 的子类，重写 `stillValid`（原版会检查脚下是不是工作台）。不能用 `ContainerLevelAccess.NULL`：它的 `execute` 什么也不做，合成结果算不出来。无存储数据，合成格的东西关界面时原版自己还给玩家。配方书、JEI 配方转移、合成统计、进度、别的模组的配方都自动可用。
- **熔炉**：原版 `FurnaceMenu(id, 背包, 容器, 数据)` + 我们自己的容器与 `ContainerData`；不能复用 `AbstractFurnaceBlockEntity.serverTick`（点燃与熄灭时会 `level.setBlock` 往世界里写熔炉方块），烧制规则自己写（几十行）。**状态记在工具物品自己的数据组件上**（3 个格子、燃烧与烧制的"完成时间"、已用配方）。
- **后台烧用"补算"，不 tick**：存的是游戏时间戳，打开或读取时按过去的时间一次性推算（烧了几个、剩多少燃料、进度）。这与旅行者背包的做法一致（见下）。
- 只做普通熔炉（不做高炉、烟熏炉）。

### 唱片机：纯客户端

- 播放列表 = 按 B 的背包里**可见的**唱片扩展行（类别 `disc`）里的唱片：行的顺序、格子从左到右、空格跳过；**多个唱片扩展行不连续（中间夹着别的扩展行）也要完整读到**；隐藏行不算；别的类别的行不看。唱片取自原版 `JUKEBOX_PLAYABLE` 组件（`JukeboxSong.fromStack`），别的模组的唱片只要走这个组件也能播。
- 点工具 → 右侧展开"播放控制"页（与垃圾桶页同位置，**同一时间只展开一个**）：上一曲、播放 / 停止、下一曲、**倒带**（从头重播当前曲；**不做暂停**，因为原版没有单个声音的暂停，要碰内部接口）、**单曲循环**开关、**列表随机**开关、当前曲名与序号。
- 默认列表循环（放完最后一首回到第一首）；单曲循环优先于列表循环；随机时每轮每首各放一次（洗牌），"上一曲"回到上一首放过的。
- 声音：客户端 `AbstractTickableSoundInstance` 跟着玩家走（`SoundSource.RECORDS`，音量跟随原版"唱片机/音符盒"滑条），播放前停掉原版背景音乐，显示原版的"正在播放"提示。**别的玩家听不到**（客户端播放；与旅行者背包一致）。
- 没有存储数据、没有网络包；开关与列表位置只在本次游戏会话里记着。

## 旅行者背包是怎么做的（读它的 jar，本仓库开发运行里有）

- 它的合成、熔炉（含高炉、烟熏炉）、唱片机等是"升级"，**嵌在它自己的背包菜单与界面里**（自己的格子与控件，`CraftingUpgrade` 用自己的合成容器）。我们的面板是叠在原版界面上的浮层，不能照搬，所以工作台与熔炉改走"打开原版界面"。
- **熔炉**：`AbstractSmeltingUpgrade` 有 `getBurnFinishTime()`、`getCookingFinishTime()`（**绝对游戏时间**）、`getTickRate()`、`tick(player, level, pos, ticks)`，状态存在升级物品自己的数据组件里（`setStackData`），按固定频率检查，不是每 tick 改。我们的"补算"是同一思路，而且更省（不需要后台 tick）。
- **唱片机**：客户端 `JukeboxWidget$MovingSound extends AbstractTickableSoundInstance`（构造参数是实体和声音事件，跟着实体走），`SoundManager.queueTickingSound` 播放，`SoundManager.stop(声音id, SoundSource)` 停止，`Gui.setNowPlaying` 显示曲名，`JukeboxSong.fromStack` 取歌曲；**没有暂停**，只有播放与停止。我没有发现它向别的玩家广播声音。这证明唱片机的做法不需要碰内部接口。
