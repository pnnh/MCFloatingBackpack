# 人工验证合并清单（005–010）

宪法 V 条要求：玩家可见的行为必须在真实客户端会话里验证。005–010 各自的 `quickstart.md` 都有手工清单，
但分散在六处、互相有重复。这份清单把它们按"一次游戏会话能做完什么"重新排序，合并重复项，每一步标出
对应的任务编号。做完后按文末格式把结果告诉我，我再写进各自的 `DELIVERY.md` 并勾选任务。

> 本清单只是**合并索引**，判定标准以各 `quickstart.md` 为准；有出入时以 quickstart 为准。
> 我（Claude）没法看游戏画面，下面每一项都需要你在游戏里看。

```bash
./gradlew runClient          # 会话 S1（默认，带 JEI）
```

## 会话 S1：`./gradlew runClient`（大头，约 30–40 分钟）

### S1-A　门禁与基本流程（005 T024）

- [ ] **A1** 新档、清空物品栏，按 **B** → 面板不出现，有提示。
- [ ] **A2** 主手拿皮革背包，**不先按 E**，按 **B** → 面板打开；再按 **B** 或 **ESC** 关闭，**ESC 不进入暂停菜单**。
- [ ] **A3** 主手持背包、没瞄准方块时右键 → 面板切换。
- [ ] **A4** 暂停菜单、设置菜单上不显示面板；按 E 打开原版物品栏时，面板能与它共存。
- [ ] **A5** 多背包顺序：主手和背包格 12 各放一只，按 B → 操作的是**主手那只**；清空主手后按 B → 打开槽 12 的那只。

### S1-B　内容随物品（005 T024）

- [ ] **B1** 放入几件物品，关闭；丢出背包再捡起、再打开 → 内容一致。
- [ ] **B2** 把背包放进箱子再取出 → 内容一致。

### S1-C　胸甲与背负（005 T024）

- [ ] **C1** 装进胸甲栏，F5 → 背部可见背包（**现在是雕刻网格模型，不是占位**）。
- [ ] **C2** 仅胸甲有背包时按 B → 能打开；卸下且身上没有别的背包 → 按 B 无效。
- [ ] **C3** 预期失败应发生：无背包时 Shift 存取无效；打开面板后把唯一背包丢出再点槽位 → 被拒绝或面板关闭。

### S1-D　五档格子与升级（006 T027）

- [ ] **D1** 五档分别拿主手按 B：行数应为 **4、6、8、10、12**，每行 9 格（36/54/72/90/108）。
- [ ] **D2** 小窗口：调高 GUI 比例或缩小窗口，打开下界合金（12 行）→ 滚轮能滚到第一行和最后一行，每格都能点。
- [ ] **D3** 升级保留物品：皮革放 ≥5 种物品（含一个堆叠），锻造台**模板槽留空**，基底=皮革背包，附加=**铁块** → 铁背包，原物品都在，皮革背包与铁块各少 1。同样走一遍 铁+金块→金、金+钻石→钻石、钻石+下界合金锭→下界合金。
- [ ] **D4** 负面：模板槽放东西、或基底与材料不配套 → 没有结果；没有"高等级变回低等级"的配方。
- [ ] **D5** 回归：把装了东西的金背包丢出再捡起，内容仍在；主手皮革、背包格有下界合金时按 B → 打开的是皮革（36 格）。

### S1-E　面板窗口行为（007 T019，8 步）

用铁或金背包（行数多，好观察）。

- [ ] **E1** 只拖拽缩小**列数** → 行数不变；只缩小**行数** → 列数不变；缩到行、列都是 3 → 不再缩小。
- [ ] **E2** 反向拖大 → 停在"当前屏幕可用空间下的最大行/列数"，面板任何时候都不超出屏幕。
- [ ] **E3** 滚动条：调小列数后格子按新列数重排，只出现**纵向**滚动条、**没有横向**滚动条；能拖到所有被挤出可见范围的格子；先放满不同物品，确认重排后物品**没有消失、顺序没有错乱**。
- [ ] **E4** 持久化：调到自定义尺寸 → 关闭再打开 → 尺寸与位置保持；**完全重启**客户端（或重进存档）后仍保持。
- [ ] **E5** 关闭按钮：点标题栏右侧关闭按钮 → 立即隐藏，与按 B 一致；重新打开后物品、位置、尺寸都在。
- [ ] **E6** 标题栏：（008 之后是图标，见 S1-F）
- [ ] **E7** macOS 光标：悬停缩放手柄看光标形状；**光标没变属已知平台限制，不算失败；拖拽缩放本身必须可用**（这是判定点）。
- [ ] **E8** 与 003/004 回归：随便开一个箱子或物品栏，跨界面拖一次物品，行为与以前一致。

### S1-F　标题图标（008 T009 第一部分，无需 JEI）

- [ ] **F1** 打开任意背包 → 标题栏显示的是**图标**而不是文字。
- [ ] **F2** 缩到最窄（3 列）→ 图标完整、不溢出、不被裁切。
- [ ] **F3** 悬停图标 → 弹出正确的**背包等级名称**，移开后消失（本项同时覆盖 007 E6 的"按等级命名"）。
- [ ] **F4** 换不同等级的背包 → 图标与提示相应更新；007 的缩放、关闭按钮、拖拽转移不受影响。

### S1-G　背上外观细节（009 T021，对**每个**等级）

> 图标、手持、背上"整体没问题"已确认；这里查的是**细节缺陷**。

- [ ] **G1** F5 绕到**侧面**：背包与后背之间的缝隙是否不超过约 1 像素。**重点：钻石**（预期有约 0.05 方块间隔）、**金**（看是否超出躯干）。
- [ ] **G2** 从**身后**、**侧面**各看一遍，找细缝：能否透出天空或人物皮肤。**重点：金**（325 条开放边）、钻石（169）、铁（122）、下界合金（114）。看到了请记**哪个等级、哪个位置**。
- [ ] **G3** **仰视**：视角抬到最低从下往上看，底部应是封闭的；下界合金下口袋底部应是金色斑点平板，不是空腔。
- [ ] **G4** 其它几档的**手持**第一人称有没有像铁那样的透光缝（只有铁被确认过）。

### S1-H　光照与亮度（009 T022 前半、SC-005、SC-007）

- [ ] **H1** 白天背着/拿着背包，再 `/time set night` 或走进洞穴 → 背包亮度随环境降低，**夜里不发光**。
- [ ] **H2** 白天对照 `design/demo/*.jpg` 效果图 → 亮度是否接近；偏暗或偏亮明显请记**哪个等级**（亮度修正都是估算值）。

### S1-I　既有玩法回归（009 T023、010 T018，FR-013、FR-007）

- [ ] **I1** 容量与行数对应等级（同 D1，可合并做）。
- [ ] **I2** 面板与箱子、物品栏之间互拖物品仍可用；放在 JEI/物品栏上的互拖也试一次。
- [ ] **I3** 升级配方仍能升一档并保留内容（同 D3，可合并做）。

### S1-J　性能粗测（009 T024，已知限制 3）

没有通过线，只是给"性能预算"提供第一组真实数据。

- [ ] **J1** 站在同一位置、同一视角，按 **F3** 记录帧率：**不背包** vs **背着下界合金背包**（面数最多，约 2 万）。
- [ ] **J2** （可选）局域网开两个客户端，两人同屏各背不同等级背包，记录帧率。
- [ ] **J3** 同时记下：渲染距离、分辨率、是否开着光影（S1 默认没开）。

## 会话 S2：`./gradlew runClientCompat`（约 10 分钟，008 T009 第二部分）

- [ ] **K1** 打开一个容器界面（物品栏或箱子），让 JEI 物品列表显示。
- [ ] **K2** 把浮动面板拖到与 JEI 物品列表**重叠**：JEI **不再**在面板覆盖区域摆格子/弹提示框；拖回不重叠处，该区域恢复正常。
- [ ] **K3** **撕裂修复**：把面板放在不盖住任何 JEI 物品、但靠近 JEI 列表边缘的位置，悬停名字很长或带描述的物品 → 提示框背景和文字的叠放顺序**一致**（要么整体盖住面板，要么被面板整体盖住；**不能背景被挡、文字却穿透**）。这是当时 bug 报告的具体场景。
- [ ] **K4** 悬停面板自己的图标、槽位 → 面板自己的提示正常，不受 JEI 影响。
- [ ] **K5** （顺带）精妙背包/旅行者背包的界面里，浮动面板互拖仍可用（004 回归）。

**无 JEI 回归**（008 第三部分）：默认 `./gradlew runClient` 启动，日志里没有 JEI 相关的错误或警告，浮动背包全部功能（含标题图标）正常。→ 可以顺手在 S1 开始前后 `grep -i jei run/logs/latest.log` 看一眼。
