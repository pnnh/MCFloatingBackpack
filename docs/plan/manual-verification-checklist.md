# 人工验证剩余清单（005–010）

宪法 V 条要求：玩家可见的行为必须在真实客户端会话里验证。005–010 各自的 `quickstart.md` 有完整的手工清单，
这份文件只保留**还没验证**的项；已验证的项已经记录到各自的 `specs/*/DELIVERY.md` 并勾选了任务。
判定标准以各 `quickstart.md` 为准。验证后把编号和结果告诉 Claude，由它写入 DELIVERY.md 并勾选任务。

## 准备

```bash
./gradlew runClient          # 会话 S1（默认，带 JEI）
./gradlew runClientCompat    # 会话 S2（再带精妙背包 + 旅行者背包）
```

进一个**创造模式**世界，用创造分类或 JEI（搜 `floating backpack`）取出五档背包各一只。

## 会话 S1：`./gradlew runClient`

### 升级（006 T027、009 T023、010 T018）

- [ ] **D3** 升级保留物品：皮革放 ≥5 种物品（含一个堆叠），锻造台**模板槽留空**，基底=皮革背包，附加=**铁块** → 铁背包，原物品都在，皮革背包与铁块各少 1。同样走一遍 铁+金块→金、金+钻石→钻石、钻石+下界合金锭→下界合金。（同时覆盖原 I3）
- [ ] **D4** 负面：模板槽放东西、或基底与材料不配套 → 没有结果；没有"高等级变回低等级"的配方。

### 性能粗测（009 T024，已知限制 3）

没有通过线，只是给"性能预算"提供第一组真实数据。

- [ ] **J1** 站在同一位置、同一视角，按 **F3** 记录帧率：**不背包** vs **背着下界合金背包**（面数最多，约 2 万）。
- [ ] **J2** （可选）局域网开两个客户端，两人同屏各背不同等级背包，记录帧率。
- [ ] **J3** 同时记下：渲染距离、分辨率、是否开着光影。

### JEI / 依赖（005 T024 余项）与无 JEI 回归（008 T009 第三部分）

- [ ] **M1** `runClient` 中 JEI 能搜到浮动背包。
- [ ] **M2** `mods.toml` 没有把 JEI 标为 required；无 JEI 的实例（`./gradlew runClient -PnoJei`）能启动本模组，浮动背包全部功能（含标题图标）正常，`run/logs/latest.log` 里没有 JEI 相关的错误或警告（`grep -i jei`）。
- [ ] **M3** 玩家不再拥有无物品的全局 Attachment 背包（005 回归第 2 条）。

## 需要找人的项

**5 名观察者盲测**（一次测完，覆盖 006 T027 的 SC-003、009 T020、010 T012）：

1. 给每人看五个等级的背包（手持或背上都行），**不告诉名称**，让他们说出每个是哪一档 → **每人需 5/5**（SC-005）。
2. 只给他们看**皮革**背包近景，问：是否"近看略软但不糊"？→ **≥80%（5 人里至少 4 人）认为是**（SC-003）。
3. 记录每人的两项结果。

**文档走查**（010 T022）：请另一个人（或你自己"只看文档"）按 `design/demo/README.md` 与 `specs/010-backpack-texture-budget/contracts/texture-budget.md`，看能否在 **10 分钟内**测出图集尺寸并判断是否超预算；记录卡住的步骤。
