# 005 — 浮动背包游戏性改造：道具化 / 分级 / 工具栏 / 升级 / 模型

**文档版本**：0.2.0  
**状态**：演进参考（部分已拆分实现）  
**目标平台**：Minecraft 1.21.1 + NeoForge  
**对标参考**：[Traveler's Backpack（Modrinth）](https://modrinth.com/mod/travelersbackpack)（下称 TB）  
**前提**：`specs/001`～`004` 已完成「浮动 Overlay + 玩家 Attachment 库存 + 跨 GUI 拖放」的技术底座。

> **与 Speckit 的关系（2026-10-25）**  
> - 已开做：[`specs/005-item-backpack/`](../../specs/005-item-backpack/spec.md) — **A / C / E**（道具化门禁、物品绑定库存并丢弃 Attachment、胸甲栏背负、开发期 JEI）。本期单物品皮革档 **36** 格。  
> - **M7 已开规格**：[`specs/006-tiered-backpacks/`](../../specs/006-tiered-backpacks/spec.md) — 五档格子、逐级锻造升级、非立方体外观与至少 32×32 图标/贴图。  
> - **仍延后（本文仅参考，不保证实现）**：**D** OP 指令、功能升级、左右侧栏、Curios、Attachment 迁移。  
> - 格数：皮革 36 / 铁 54 / 金 72 / 钻石 90 / 下界合金 108。

## 1. 背景与目标

### 1.1 现状（技术 MVP）

| 点 | 当前行为 |
|----|----------|
| 打开方式 | 任意时刻按 `B` 即可开关浮动面板 |
| 存储绑定 | 玩家 Attachment 固定 **27** 格（`BackpackInventory.SIZE`） |
| 道具形态 | **无**背包物品；无合成、无手持/背负模型 |
| 面板布局 | 单一网格；无左侧工具快捷栏、无右侧升级区 |

这适合验证 Overlay 与同步，但**不符合**「背包是可获得的游戏道具」这一生存向玩法预期。

### 1.2 改造目标（玩法）

1. **道具化**：浮动背包是可合成 / 创造获取的物品；未持有（或不满足打开条件）时按 `B` 无效。
2. **打开条件**：主手持有可右键打开；物品在物品栏中时可按 `B` 打开；后续 Curios「背部」槽装备后也可按 `B`。
3. **分级**：基础 / 皮革 / 铁 / 金 / 钻石（可选下界合金），不同格子数与合成成本。
4. **TB 风格侧栏**：左侧**快捷工具栏**；右侧**升级面板**（功能升级插槽）。
5. **表现**：物品栏图标；手持 / 背负可见 3D 模型（Curios 为后续）。
6. **保留差异化**：继续以**浮动 Overlay** 为主交互，而非再做一个独占全屏的 TB 式 `Screen`（可与其它容器共存）。

### 1.3 非目标（本规划明确不做或后置）

| 项 | 说明 |
|----|------|
| 完整复刻 TB | 不照搬流体罐、睡袋、水管、45+ 外观皮肤、生物能力等；只借鉴「分级 + 工具槽 + 升级槽」骨架 |
| 与 TB 同存时的功能合并 | 两模组可并存；不把 TB 背包内容自动迁入本模组 |
| 一阶段 Curios 强制依赖 | Curios 为**可选**软依赖；首期用手持 / 物品栏即可打开 |
| 世界实体方块背包 | TB 可放置为方块；本模组首期不做，避免与浮动定位冲突 |

## 2. 旅行者背包对照摘要

来源：Modrinth 介绍、1.21.1 更新说明、社区指南（数值以 TB 配置默认为参考，本模组可自定）。

### 2.1 TB 核心机制

| 机制 | TB 做法 | 对本模组启示 |
|------|---------|--------------|
| 打开 | 主手右键；装备后默认 `B` | 打开门禁与快捷键绑定到「拥有合法背包实例」 |
| 装备 | GUI「Equip」或 Curios/Trinkets Back 槽 | 先做物品栏/手持；再做 Curios |
| 分级 | Leather → Iron → Gold → Diamond → Netherite | 锻造台或配方升级；保留内容 |
| 槽位增长 | 库存 / 工具槽 / 升级槽随等级增加（可配置） | Overlay 网格需按等级变尺寸 |
| 左侧工具槽 | 工具/武器；可滚轮快捷切换 | 左侧窄条 + 快捷键（可后置滚轮） |
| 右侧升级 | Crafting / Magnet / Pickup / Void / Feeding / Furnace / Tanks… | 先做 2～3 个高价值升级，避免一次做满 11 种 |
| 模型 | 背负渲染 + 物品模型 | 需物品 JSON + 可选 Geo/自定义渲染 |
| 放置世界 | 可成方块、漏斗交互 | **首期不做** |

### 2.2 TB 默认等级规模（参考，非照抄）

常见默认量级（可配置；不同版本略有差异）：

| 等级 | 库存格（约） | 工具槽 | 升级槽 |
|------|--------------|--------|--------|
| Leather | 27 | 2 | 2 |
| Iron | 45 | 3 | 3 |
| Gold | 63 | 4 | 4 |
| Diamond | 81 | 5 | 5 |
| Netherite | 99 | 6 | 6 |

浮动 Overlay 若一次铺满 81～99 格，会遮挡视野。**本模组建议**：等级仍拉开差距，但默认尺寸略保守，或支持「分页 / 滚动 / 缩放」。

## 3. 总体可行性结论

**结论：可行。** 工程重点从「Overlay 能不能浮」转为「库存从玩家 Attachment 迁到背包物品实例 + 条件打开 + UI 分区 + 资源管线」。

| 能力 | 可行性 | 依据 / 注意 |
|------|--------|-------------|
| 背包物品 + 合成 / 创造获取 | **高** | 标准 `Item` 注册 + recipe JSON；创造模式标签页 |
| 仅持有时才允许 `B` / 右键打开 | **高** | 客户端门禁 + **服务端校验**（防作弊发包） |
| 分级与不同格子数 | **高** | 物品组件 / NBT 存 tier 与 `ItemStackHandler`；升级时迁移内容 |
| 左侧工具快捷栏 | **中高** | 独立槽位数组 + Overlay 左栏；快捷切换可二期做 |
| 右侧升级面板 | **中** | 升级物品 + 插槽逻辑；每种升级是独立系统（磁铁/合成等） |
| 物品栏 2D 图标 | **高** | 手绘 / 像素风资源；也可用 Cursor 生图再缩放到 16×16 |
| 手持 / 背负 3D 模型 | **中高** | Blockbench / Blender（已具备官方/社区 MCP）建模 → 导出；背负需 Layer / Curios 渲染 |
| Curios「背」槽 | **高（软依赖）** | Curios NeoForge `9.5.x+1.21.1` 成熟；`compileOnly` API + 可选 runtime |
| 保持与其它 GUI 共存的浮动特性 | **高（已验证）** | 继续走 Overlay，不改回独占 Screen |
| 完整 TB 升级全家桶 | **中低（工作量）** | 逐个做；用配置开关裁剪 |

**相对风险最高的两项**：① 库存绑定模型迁移（数据兼容与「玩家身上到底哪一个背包在响应 B」）；② Overlay 在高等级下的信息密度与点击命中。

## 4. 架构迁移：从「玩家背包」到「道具背包」

### 4.1 推荐数据模型

```text
Player
  └─（可选）ActiveBackpackRef：当前响应快捷键的背包来源
        · MAIN_HAND / OFF_HAND
        · INVENTORY_SLOT(i)
        · CURIOS_BACK          （后期）

ItemStack（浮动背包物品）
  └─ Data Component / 自定义附件
        · tier: BASIC | LEATHER | IRON | GOLD | DIAMOND | NETHERITE?
        · storage: ItemStackHandler（主仓）
        · tools: ItemStackHandler（左侧工具）
        · upgrades: ItemStackHandler（右侧升级）
        · uuid: 实例 ID（联机追踪 / 日志）
```

**原则**：

- **服务端权威**仍在物品组件（或等价持久化）上，不在「假客户端格子」。
- 玩家 Attachment 中的旧 27 格数据：提供**一次性迁移**（首次登录写入「基础背包」物品并清空 Attachment，或配置关闭）。
- 同一玩家物品栏可能有多只背包：`B` 打开规则需明确（见 4.2）。

### 4.2 打开规则（建议默认）

优先级从高到低（可配置）：

1. 主手是本模组背包 → 可右键 / 可 `B`
2. 副手是本模组背包 → 可 `B`（右键是否打开副手背包：建议否，避免挡方块交互）
3. Curios Back 槽有本模组背包 → 可 `B`（后期）
4. 物品栏中**第一只**本模组背包 → 可 `B`
5. 否则：`B` 无效果（可 actionbar 提示「需要浮动背包」）

创造 / 作弊：创造物品栏直接给出各等级物品；不绕过「必须拥有物品」规则（创造栏拿出即拥有）。

### 4.3 对现有代码的冲击面

| 模块 | 影响 |
|------|------|
| `BackpackInventory` / `BackpackAttachments` | Attachment 降级为迁移用或删除；库存挂到 Item |
| `BackpackClickLogic` / 网络 Payload | 包内携带「目标背包标识」（槽位 / hand / curios） |
| `ClientBackpackView` / Overlay | 按 tier 改行列数；增加左/右栏命中区 |
| `FloatingBackpackKeys` | 增加「是否允许打开」查询 |
| 新增 | `FloatingBackpackItem`、等级枚举、合成与锻造配方、升级物品、渲染 |

工作量评估：**中大型重构**，但 Overlay / 点击翻译协议可复用。

## 5. 分级与合成（草案，供评审改数）

名称可本地化；ID 建议稳定：`floating_backpack_basic` 等，或单一物品 + `tier` 组件。

### 5.1 推荐档位（略保守于 TB，利于浮动 UI）

| 等级 | 主仓 | 工具槽 | 升级槽 | 合成思路（草案） |
|------|------|--------|--------|------------------|
| 基础 Basic | 9（1×9）或 18 | 1 | 0～1 | 线 + 箱子 + 皮革碎片等，早期可得 |
| 皮革 Leather | 27（3×9） | 2 | 2 | 基础背包 + 皮革升级件；或直接合成 |
| 铁 Iron | 36（4×9） | 3 | 3 | 皮革背包 + 铁升级（锻造台） |
| 金 Gold | 45（5×9） | 3～4 | 4 | 铁背包 + 金升级 |
| 钻石 Diamond | 54（6×9） | 4～5 | 5 | 金背包 + 钻石升级 |
| （可选）下界合金 | 63 | 5～6 | 6 | 钻石背包 + 下界合金升级 |

评审可选项：

- **A**：与 TB 同档（27/45/63/81/99）— 内容对标强，Overlay 需滚动/分页。  
- **B**：上表保守档 — 更贴合「常驻浮动」可读性（**推荐默认**）。

升级路径建议对齐 TB 1.21：**锻造台**「背包 + 等级升级物品」保留内容与升级插件。

### 5.2 创造 / 作弊

- 创造物品栏分类「浮动背包」：各等级成品 + 升级模板 + 功能升级物品。  
- `/give` 支持组件指定 tier（若用单一物品 ID）。

## 6. UI：左侧工具栏 + 右侧升级面板

### 6.1 布局（浮动面板内）

```text
┌────────┬──────────────────────────┬────────┐
│ Tools  │     Storage grid         │ Upgrades│
│ (竖排) │     (按等级行列)          │ (竖排)  │
└────────┴──────────────────────────┴────────┘
        ▲ 仍可整体拖动；位置持久化
```

- **左侧 Tools**：仅允许工具 / 武器（可配置白名单）；点击逻辑复用现有槽位点击；二期：快捷键或滚轮切到主手（TB 的 Z+滚轮可对标但非 MVP）。
- **右侧 Upgrades**：放入「升级物品」；取出需确认或 Shift（防误卸）；空槽显示占位图标。
- **中部 Storage**：继续支持与原版 / 第三方容器互拖（004 通路）。

### 6.2 功能升级（分期）

**一期（建议 3 个）**

| 升级 | 行为 | 难度 |
|------|------|------|
| 磁铁 Magnet | 吸引附近掉落物（可进主仓） | 中（服务端 tick） |
| 拾取 Pickup | 拾取物优先入背包（过滤器后期） | 中 |
| 虚空 Void | 指定物品直接销毁 / 过滤器 | 中低 |

**二期**

| 升级 | 行为 | 难度 |
|------|------|------|
| 合成 Crafting | 面板内 2×2 或 3×3 | 中高（额外 UI） |
| 喂食 Feeding | 自动吃背包内食物 | 中 |
| 熔炉 Furnace 等 | 便携加工 | 高（进度/燃料/同步） |

流体罐、睡袋、水管等 **不进入本路线图**，以免与 TB 同质化且膨胀范围。

## 7. 美术与资源管线

### 7.1 物品栏图标（2D）

- 规格：通常 **16×16**（可先 32×32 再最近邻缩小）。
- 风格：建议方块像素风，与原版 UI 一致；各等级用边框色 / 扣具区分（棕 / 铁灰 / 金 / 青钻）。
- **Cursor 生图**：Cursor 提供图像生成能力（对话中可显式要求「生成物品图标」）。适合出概念稿；**入模前仍需**手工像素对齐、去底、检查透明边，不能直接当最终 `textures/item/*.png` 而不审。
- 不依赖「Grok 网页」；以 Cursor 当前会话的生图工具为准即可。

### 7.2 三维模型（手持 / 背负）

| 阶段 | 内容 | 工具 |
|------|------|------|
| 白盒 | 简单箱包尺寸、挂点 | Blockbench（MC 标准）或 Blender |
| 定稿 | UV、材质、各等级变体 | 同上；可用已配置的 **Blender MCP** 辅助迭代 |
| 导出 | `model` JSON + 贴图；手持 display transforms | 原版物品模型流程 |
| 背负 | 玩家后背 Layer 或 Curios 渲染器 | 需独立渲染钩子 |

**注意**：MC 物品模型与「高精度 Blender 角色级资产」管线不同；Blender 更适合概念与烘焙，最终仍常落到 Blockbench / 方块像素拓扑。评审时可决定「主 Blockbench、Blender 辅」或反之。

### 7.3 声音与粒子（可选）

打开/关闭面板短音效；升级成功粒子 — 低优先级。

## 10. 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| Attachment → 物品迁移丢物 | 严重 | 备份 NBT；迁移命令；默认生成「基础背包」装入旧物品 |
| 多背包时打开错目标 | 中 | 明确优先级；可选「上次打开的 uuid」 |
| 高等级格子过多 | 可读性差 | 保守默认格数；滚动/缩放；配置 |
| 升级系统爆炸 | 工期失控 | 一期只做 3 个升级；其它配置禁用 |
| 模型工期 | 视觉空洞 | 先方块白盒 + 等级染色；并行生图图标 |
| Curios 版本漂移 | 编译失败 | 软依赖 + CI 可选 profile |
| 与 TB 同时安装键位冲突 | 体验差 | 默认键可改；文档提示改键 |
| 联机作弊伪造「有背包」 | 刷物 | 所有打开与点击服务端验持有 |
