# 背包重新建模 — 设计草稿（未应用到代码）

皮革（基础款）一档的原型，对应你截图里反映的问题。还没有改动 `src/main/resources` 下的任何正式文件。

> 这个目录原来叫 `temp/`，现在改名成 `design/` 并且加进了 Git 里跟踪（之前是被 `.gitignore` 整个排除
> 的）——因为要持续跟踪设计相关的内容，不再是一次性临时产物。脚本生成的 `__pycache__/`（Python 编译
> 缓存）之类的构建副产物仍然会被忽略，具体规则见仓库根目录的 `.gitignore`。

## 根因（不是猜的，读了现有模型文件确认的）

`floating_backpack.json` 里背包主体箱体只到 `z=7`，而两条肩带箱体延伸到 `z=5.6`（更往外凸出）。
肩带中间（`x` 5.2~10.8、`y` 4~8.5 这块区域）在 `z<7` 完全没有任何箱体填充——这是真实的几何镂空，
不是贴图问题，侧面/背面斜着看正好能穿透过去看到背后的场景。

## 这次做的改动（相对原模型）

1. **背包主体箱体加深**：`z` 从 7 改到 5.8，正好接上肩带的深度，彻底堵住那个洞。
2. **翻盖箱体同步加深**：`z` 从 6.2 改到 6，确保和主体衔接处不留缝。
3. **新增一个前置口袋箱体**（原创形状，不是照抄旅行者/精妙背包的任何具体设计）：纯粹为了打破"一块平板"的观感，让轮廓有层次。
4. 肩带、扣具位置基本保持不变——**肩带本来就是笔直竖着的两根箱体**，不存在"歪斜"问题；你截图里 concept_1 那张图肩带看起来歪，是 ludo.ai 生成那张参考图本身的画面问题，不是我们模型的问题。
5. **新增左右两个侧边小口袋箱体**（根据你"更偏向 concept_1 的丰富度，但肩带要 concept_2 那种笔直"的反馈）：与主体真实重叠贴合（已用坐标数值核实，不是视觉上看起来贴合而已）。
6. **贴图从纯平涂升级为带细节的像素风**：每个面加了细微颗粒噪点、面板内缩一圈的缝线描边、口袋/主体四角的铆钉小黑点、扣具上的一个高光像素——不再是纯色色块。
7. **主体改成上窄下宽的三段收分箱体**（`body_bottom`/`body_mid`/`body_top`，一个比一个窄）：原来主体是单个等宽箱体，从上到下一样宽，渲染出来更像柜子/抽屉而不是背包——你指出这一点之后改的。口袋/侧边口袋也相应挪到了最宽的 `body_bottom` 上。Minecraft 方块模型没法做真正的曲面，三段阶梯式收分是这种像素风格下模拟"软包轮廓"的标准做法。
8. **收分幅度加大**：顶部最窄处宽度从 8.8 缩到 8.0，底部最宽处从 10.8 加到 11.6，总差值从 2.0 加到 3.6；侧面（深度）也加了一点轻微收分（底部最深 12.4，顶部最浅 11.6，差值只有 0.8，明显没有宽度那么夸张），对应你给的两张侧面截图反馈。
9. **肩带凸起间距恢复**：排查发现，第一轮"补洞"把背包主体加深到 `z=5.8` 后，顺带把肩带原本凸出主体约 1.4 格的立体感也几乎抹平了（只剩 0.2 格），这就是为什么肩带看起来完全贴死在主体上——这其实是两件独立的事：主体够深才能挡住洞，肩带凸出多少是另一回事，互不冲突。现在把肩带的前沿从 `z=5.6` 挪到 `z=4.8`，在不影响补洞效果的前提下恢复了立体感。
10. **贴图材质大幅细化**（这是本轮的重点）：
    - 皮革面不再是"纯色+噪点"，改成每个面随机撒 2~4 块柔和过渡的斑驳色块（模拟皮革鞣制不均匀的色差），叠加细颗粒噪点，边缘再做一圈简易 AO 压暗——综合起来才是"看起来像材质"的关键，单独任何一项都不够。
    - 缝线从"实心内缩描边"改成真正的虚线描边（`draw_dashed_rect`），现在主体三段、翻盖、前口袋、侧口袋的正反面都有虚线缝边。
    - 新增磨损高光斑点（`apply_scuffs`），随机撒在大面板上，模拟皮革磨损发亮的痕迹。
    - 扣具从纯色改成对角渐变（一角高光、对角阴影）+ 中间一条暗色"扣针"竖线，比之前单一高光像素更有金属质感。
    - 铆钉从纯黑点改成"暗金属+一个高光像素"的小圆点观感。
11. **配色从"单一棕色"改成多色调搭配**（这是最新这轮的重点，见下面单独一节）。

## 配色从单一棕色改成多色调搭配

你指出现在的配色几乎是清一色的模拟皮革棕色，对照精妙背包/旅行者背包的截图，它们都是"皮革主色 + 明显
不同的硬件/金属色 + 一点点高饱和度的点缀色"这种组合，不是通篇一个颜色深浅的渐变。改动如下：

- **拆成一套按部件分类的调色板**，不再是过去那种"一个 LEATHER_BASE 到处用"：主体（`BODY_*`）、翻盖
  （`FLAP_*`，比主体更深更偏红，像是不同鞣制批次的皮料）、肩带（`STRAP_*`，比主体更深的暗棕，不再是
  近黑色的"缝线色"）、小包（`POUCH_*`，比主体浅一档，让人一眼看出是另外装上去的配件而不是主体的一部
  分）各自独立，视觉上能分出层次。
- **新增一个灰色"硬件"色系**（`HARDWARE_*`）：扣具改用这个颜色（原来的金色扣具改成了偏冷的金属灰），
  并且在主体最宽（`body_bottom`）和中段（`body_mid`）的接缝处画了一圈灰色腰带（前后左右四个面都有，
  不只是正面两条杠），模拟皮革包常见的金属/帆布加固带。
- **新增一个高饱和度点缀色**（`ACCENT_*`，皮革档用黄铜色）：在扣具两侧各点了一个小装饰扣，参考的是精
  妙背包那种彩色宝石/铆钉点缀的做法，但做成了黄铜色小方块而不是复制它们的宝石造型。

**关于后续分档配色**：`TIER_PALETTES` 这个字典现在是唯一的颜色入口，皮革档是 `TIER_PALETTES["leather"]`
这一份；body/flap/strap/pouch/hardware/accent 这几支色系全部由 `shade()` 从这 5 个基础色推导出来，不
是每个面单独写死颜色。以后出铁/金/钻石/下界合金档，理论上只需要在 `TIER_PALETTES` 里加一条新记录（比
如 `accent` 换成对应颜色：铁→淡钢灰、金→亮金、钻石→青色、下界合金→紫红色，这是直接照搬 Minecraft 自
己这几种材质已有的颜色印象，不是我随便定的），`hardware`/`body`/`flap`/`strap` 这几个也可以按档位适当
调整饱和度/明暗，但不需要重写任何绘制逻辑——这一点还没有实际验证过（目前只实现了皮革一档），下一步
真要套其他四档配色时，如果 `shade()` 推导出来的某些中间色阶在视觉上不够好看，可能还需要手动微调，不
能保证纯换一个 `TIER_PALETTES` 条目就一定完美，这点先如实说明。

## 三个小包的可拆卸设计（为后续"升级组件"玩法铺路）

你提出：主体上左、右、后（`pouch_left`/`pouch_right`/`pouch_back`，原来叫 `pocket` 的那个现在改名
成 `pouch_back` 了）这三个小包，将来应该是可以独立安装/拆卸的升级组件，类似旅行者背包的储罐和工具
栏——基础皮革背包默认不显示这三个包，从低到高档不只是换配色、加格子，连模型外观和功能都要跟着升级。

**这一阶段（模型/美术）做的事**：把这三个小包在脚本里标成 `"detachable": True`，`build()` 支持
`include_pouches=False` 生成一个完全不含这三个小包的"基础款"变体（新增的 `leather_prototype_base.json`
/`leather_prototype_base_texture.png`），分别建到 Blender 里并排对比，确认：
- **基础款单独看也是一个完整的造型**，不会因为少了三个包就显得"缺了一块"——主体收分、翻盖、肩带、扣
  具本身已经足够撑起一个背包的基本观感。
- 拿掉小包后主体表面不会露出任何没处理过的接缝或贴图错位（小包都是贴在主体表面的独立凸起箱体，不会
  对主体本身的几何/贴图产生任何依赖）。

**这一阶段明确不做的事**（需要你确认后续是否要单独立一个 feature 规划）：真正的"安装/拆卸"是一套新
玩法机制——物品、合成配方、背包数据里要记录"装了哪些升级"、以及 Java 渲染代码要能按这份数据动态决定
画不画某个小包——这些都是游戏逻辑/工程层面的东西，不是这次美术原型阶段该碰的。现在做的只是**把模型
准备好**：三个小包已经是独立的、可以干净拿掉而不破坏主体的箱体组，为将来接入这套机制打好基础。

## 用 Blender 做了真实验证（depth-tested，不是简易预览）

本机 Blender MCP 这次连上了。按 `leather_prototype.json` 里的箱体数据，在你当前 Blender 场景里新建了一个独立的
`FloatingBackpack_Prototype` collection（没有碰你原有的任何物体），真实建出了全部 8 个箱体、贴上了生成的贴图，用
Blender 自己的材质着色渲染确认：

- **背面完全看不到洞了**——之前 `render_preview.py`（我自己写的简化渲染器，没有真正的深度遮挡）看到的"洞已修复"只是初步判断，这次用 Blender 真实渲染交叉验证过，结论一致。
- **肩带是笔直竖直的两根箱体**，不存在歪斜问题。
- **侧边口袋确认贴合在主体上**——中间有个插曲：第一次用 Blender 建出来口袋是悬空分离的，一开始以为是模型数据有问题，后来用代码打印了各箱体在 Blender 世界坐标系里的实际坐标数值，发现是我自己建模脚本里"箱体缩放算成了一半大小"的 bug（不是 `leather_prototype.json` 本身的问题），修好重新生成后再核对坐标，确认口袋和主体有真实重叠，渲染结果也对得上了。

这个 collection 还留在你的 Blender 里，你可以自己转一转、凑近看细节；不需要的话直接在 Outliner 里删掉
`FloatingBackpack_Prototype` 这个 collection 就行，不会影响你原来的场景。

## 排查"浅灰竖条"：独立 Blender 文件 + 二分法，最终发现是阴影

你反馈说这条竖条正反面都挺明显，不像是我之前猜的"场景里其它物体干扰"。为了彻底排除"你 Blender 场景
里原有 ~80 个物体"的干扰，新写了 `build_isolated_blend.py`，用**全新的、完全空白的场景**（不依赖你
当前打开的 Blender、也不读取你场景里任何已有数据）独立搭建背包、打光、渲染，并存成一个独立的
`backpack_prototype.blend` 文件。跑法（在普通终端里，不是在你正打开的 Blender 里）：

```bash
/Applications/Blender.app/Contents/MacOS/Blender --background --factory-startup --python build_isolated_blend.py
```

结果：**空场景里这条竖条照样出现**，说明确实是我们自己的东西导致的，之前"可能是场景里其它物体"的猜测是错的，在这里先纠正。

接下来用二分法（脚本支持 `SKIP_ELEMENTS=xxx,yyy` 环境变量临时排除某些箱体，一项项排查）定位：依次尝试
"只留两三个箱体"的组合，发现必须同时具备 `flap` + `body_top` + `body_mid` + `strap_right` 这四个箱体
才会复现——缺任何一个都不会出现。这个"必须凑齐好几个互相搭叠的箱体才会出现"的特征，和"UV 采样到空白
区域"或"真正的几何镂空"这类问题的特征对不上（那类问题通常只需要缺陷箱体自己存在就会复现，和别的箱体
在不在没关系），反而很像**阴影**——翻盖（`flap`）比它下面的 `body_top` 更往外、更往前凸出一截，刚好
会在光照下在肩带和主体的夹角处投下阴影。

直接验证：把脚本里太阳光和补光的阴影投射关掉（`light.use_shadow = False`）重新渲染全部箱体——**竖条
完全消失**。确认了：这是我自己随手搭的单盏太阳光 + 一盏补光在 Blender 里投射出的阴影，灰蓝色恰好是世
界背景色在阴影区域里透出来的颜色，跟我们的模型、UV、贴图都没有关系，也不会在 Minecraft 游戏里出现
（原版物品/背包模型不会给自己的箱体之间投这种实时阴影）。`isolated_front.png`/`isolated_back.png`（默
认光照，阴影保留，方便你对照）和 `isolated_noshadow_front.png`/`isolated_noshadow_back.png`（关掉阴
影后）这两组渲染图都留着，可以直接对比。

## 怎么本地预览（不改代码的前提下）
